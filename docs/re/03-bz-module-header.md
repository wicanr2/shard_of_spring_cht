# 03 — `bz` 模組標頭與重定位

日期:2026-08-13
輸入:十一支遊戲 EXE + `BRUN30.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))
接續:[`02-loader-stub.md`](02-loader-stub.md)

## 結論

遊戲 EXE 的 `seg000` 開頭是一份 **`bz` 模組標頭**,`+0x16` 是模組本體的大小(paragraphs)。
`BRUN30.EXE:sub_14BDD` 讀 MZ 的重定位表,依每一筆的 segment 值落在門檻的哪一側,
決定它是**模組內部參考**還是**對執行期的呼叫**,分別修補成不同的基底。

## 1. 標頭欄位

位置:模組節區的位移 0(檔案上是 MZ 標頭之後、第一個 `bz` 出現的段落)。

| 位移 | 大小 | 內容 | 信心等級 |
|---|---|---|---|
| `+0x00` | 2 | 簽章 `0x7A62`(小端 = `bz`) | **已確認** |
| `+0x02` | 8 | 模組名,空白補齊 | **已確認** |
| `+0x0A` | 2 | 最後一段的起點(paragraph) | **已確認**([`09`](09-bz-segment-map.md))|
| `+0x0C` | 2 | 第 4 段起點 | **已確認**([`09`](09-bz-segment-map.md))|
| `+0x12` | 2 | 重定位分類門檻(見 §3) | **已確認**(是 `sub_14BDD` 的 `cx`) |
| `+0x16` | 2 | **模組本體大小,單位 paragraph** | **已確認**(見 §2,11/11) |
| `+0x24`,`+0x26`,`+0x28`,`+0x2A` | 各 2 | 節區邊界 | **已確認**([`09`](09-bz-segment-map.md))|
| 其餘 | — | 未讀 | 未知 |

⚠ **`+0x32` / `+0x34` / `+0x54` 不屬於這份標頭。** `sub_14BDD` 開頭的
`mov es, word ptr ds:0CACh` 先把 `es` 指向 **`BRUN30` 自己的控制區塊**,
`es:32h` / `es:34h` / `es:54h` 讀的是那一份;之後才 `mov es, di` 換成模組節區。
**一支函式裡 `es` 換過基底,後面的 `es:xx` 就不再是同一個結構** ——
不看 `es` 什麼時候被重設就抄位移,會把兩個結構混成一個。

## 3. 重定位(`BRUN30.EXE:sub_14BDD`,`0x14BDD`–`0x14CB8`)

**信心等級:已確認**(逐條指令讀出)。

```
cx = 模組標頭 +0x12          ; 分類門檻
dx = 模組標頭 +0x16          ; 模組大小(paragraphs)
di = 模組節區基底
si = 第二區基底
bp = BRUN30 自己的 DS
n  = MZ 標頭 +0x06 讀來的重定位項數
```

每一筆重定位項(4 bytes = `offset:segment`,從 MZ 標頭 `+0x1E` 起連續讀):

```
ax = 該項的 segment
bx = 該項的 offset
若 ax <  cx:  es = ax + di            ; 模組內部 → 直接加模組基底
              若 es:[bx] < cx  →  es:[bx] += di
              否則 es:[bx] = es:[bx] − dx + bp
若 ax >= cx:  es = ax − dx + si       ; 落在第二區
              (同樣依 es:[bx] 與 cx／dx 的關係二選一修補)
迴圈 n 次
```

**`+0x12` 是「這個位址屬於誰」的分界線。** 六支主要遊戲模組的值都是 `0x66DC`
(`MENU.EXE` 是 `0x66E8`),遠大於任何模組的實際大小 ——
所以那不是模組內的位址,是 linker 給執行期保留的記號值。

`START.EXE` 與 `MTEST.EXE` 的 `+0x12` 是 **0**,代表它們**每一筆重定位都走第二條路**
(全部指向執行期)。這與它們幾乎沒有自己的程式碼相符
(`START` 的模組本體只有 384 bytes)。

**這就是模組怎麼呼叫執行期的機制** —— `docs/re/01` §3 看到的 `INT 3Dh` / `INT 3Fh`
後面跟著 `90 90`,與這裡的「就地修補」是同一件事的兩面:
linker 先擺一個佔位形式,載入時再改寫成真正的目標。

⚠ 但**「`INT 3Dh` 的語意」仍然是未知**。上面這段只證明了重定位會改寫程式碼,
沒有證明改寫的就是那兩個 `INT`。不要把兩件事接起來寫成一句話。

## 4. 這一輪的直接可用結果

已經可以精確算出**模組本體在檔案裡的位置與長度**:

```python
hdr_paras = u16(exe, 0x08)                  # MZ 標頭大小(paragraphs)
bz        = exe.find(b"bz", hdr_paras*16, hdr_paras*16 + 64)
size      = u16(exe, bz + 0x16) * 16        # 模組本體 bytes
body      = exe[bz : bz + size]
```

下一步是把這段餵給 IDA 當程式碼分析。**進入點尚未解出**,
所以還不能直接宣告「從 `bz + N` 開始是程式碼」。
