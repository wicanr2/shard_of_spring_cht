# 111 — 狀態編號就是法術系別,位移 84 = 狀態剩餘回合

日期:2026-08-14
接續:[`110-display-offset-census.md`](110-display-offset-census.md)
子系統:**D. 角色資料** × **J. 戰鬥規則**

## 結論

法術命中時,`CMBT 0x16663`–`0x16683` **在同一瞬間寫兩個屬性**:

```
016663  mov di, ds:93A4h        ; 目標單位
016669  add di, 0B4h            ; + 180 = 12 × 15 → 屬性 12
01666F  mov [di+6822h], bx      ; 屬性 12 = bx

016675  mov bx, [di+72FCh]      ; ★ SPELLS.DAT 欄2 = 法術系別
01667C  add ax, 78h             ; + 120 = 8 × 15 → 屬性 8(狀態)
016683  mov [di+6822h], bx      ; 屬性 8 = 法術系別
```

**狀態編號直接就是法術系別。**

## 1. 三筆對照,零誤差

`MENU.EXE` 的狀態表(`' OK,Poisoned,Bound,Still Air,Frozen,D E A D'`)
以 **0 起算**:

| 法術(效果類別 11 = 束縛)| 系別 | 狀態表`[系別]` | |
|---|---:|---|:-:|
| `CHAINS` | 2 | **`Bound`** | ✅ |
| `STILL AIR` | 3 | **`Still Air`** | ✅ |
| `FREEZE` | 4 | **`Frozen`** | ✅ |

`STILL AIR` 那一筆是**字面相同**;`CHAINS`→`Bound`(鎖鏈→被縛)、
`FREEZE`→`Frozen`(冰凍→凍結)是同義。**三筆全中。**

而系別的名字([`94`](94-skill-tables.md) §3)是
`Fire` / **`Metal`** / **`Wind`** / **`Ice`** / `Spirit` ——
金屬系綁人、風系定身、冰系凍結,**狀態名與系別名一一對應**。

> 這也解釋了 [`91`](91-e-closure.md) §2 為什麼「類別 11 的三個法術分屬三個系別」:
> **不是巧合,是設計 —— 每個系別各有一個束縛法術,而狀態就是系別。**

## 2. 位移 84 = 狀態剩餘回合

`CHARS.DAT` **位移 84 → 屬性 12**([`81`](81-chars-record-to-combat-attributes.md)),
而屬性 12 **與狀態在同一條指令序列裡被寫**。

| 證據 | |
|---|---|
| 寫入時機 | 與屬性 8(狀態)相鄰 20 bytes 內 |
| 出貨資料 | 五個角色的位移 84 **全為 0**,而狀態也全為 `0`(`OK`)—— **一致** |
| 形狀 | 一個狀態效果需要「是什麼」+「還剩多久」兩個欄位 |

**位移 84 = 與狀態同時被設定的一個值。**
**已解**:[`121`](121-offset-84-is-strength.md) —— 是**狀態效果的強度**
(屬性 12 的值是一次以「法術最低消耗」為運算元的除法結果)。「剩餘回合」作廢。
⚠ 沒有看到「每回合遞減屬性 12」的程式碼 —— 那是升到已確認要補的一步。
