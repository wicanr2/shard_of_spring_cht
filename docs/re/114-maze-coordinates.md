# 114 — 位移 79 / 81 是迷宮座標,`104` 又錯一筆

日期:2026-08-14
接續:[`113-d-status-and-remaining.md`](113-d-status-and-remaining.md)
子系統:**D. 角色/隊伍資料**

## 結論

```
0106C6  mov ax, ds:351Eh        ; 位移 81
0106C9  dec ax                  ; − 1
0106CA  mov ds:8DC0h, ax
0106CF  mov ax, ds:351Ch        ; 位移 79
0106D2  mov ds:8DC2h, ax
        …
        mov ax, 51h             ; ★ 81
        imul word ptr [bp-8]    ;   × 位移79
        add ax, bx              ;   + (位移81 − 1)
        mov di, ax / shl di, 1
        mov ax, [di+6822h]      ;   取迷宮格子
```

**`81 × 位移79 + (位移81 − 1)`** —— 而 `81` 正是迷宮網格的列數
([`50`](50-sqz-maze-format.md)/[`55`](55-sqz-decoder-from-code.md):`.SQZ` 解碼器的 `mov di, 51h`,
索引公式 `欄 × 81 + 列`)。

| 位移 | 語意 | 信心 |
|---:|---|---|
| **79** | **迷宮內的欄(x)** | **已確認** |
| **81** | **迷宮內的列(y)**(存 1-based,用時 −1)| **已確認** |

## 1. ⚠ 第三次推翻 [`104`](104-groups-fields-from-context.md)

[`104`](104-groups-fields-from-context.md) 用語境字串法判位移 79 = 「當前迷宮編號」,
理由是它附近有 `DE5EFF.BIN` / `DE51EFF.BIN`(每個迷宮一個的事件檔)。

**又是「靠近」不是「夾住」**([`112`](112-light-counter-verified.md) §1)——
迷宮座標當然會出現在載入迷宮事件檔的程式碼附近。

[`104`](104-groups-fields-from-context.md) 一共四筆:
**位移 25 錯、31 錯、79 錯、45 對** —— **1/4**。

> **判準:一個方法錯到 3/4 時,它不是「有時候會錯」,是「不能用」。**
> [`107`](107-clock-is-four-levels.md) 撤兩筆時我寫的是「這個方法弱一級」;
> [`112`](112-light-counter-verified.md) 找到「夾住」這個分界後,
> 我以為那條分界救得回這個方法 —— **但四筆裡只有一筆有夾住的形狀。**
> **能救回一筆的分界,不等於這個方法可用。**

## 2. 順帶:[`101`](101-groups-record-status.md) 的直覺是對的

[`101`](101-groups-record-status.md) §1 曾寫:

> `ds:351Ch` / `ds:351Eh` 與世界座標 `ds:3518h` / `ds:351Ah` **在 DS 裡緊鄰**,
> 形狀像**第二組座標**。⚠ **未驗證**,只記形狀。

**那個直覺是對的**,而 [`104`](104-groups-fields-from-context.md) 用一個更弱的方法把它推翻了。

⚠ **這不代表「DS 相鄰」變成好證據** —— [`101`](101-groups-record-status.md) §2
同一篇裡用相鄰性猜「六個連續 word = 隊伍成員」,**那一筆是錯的**。
相鄰性在同一篇筆記裡一對一錯。**它仍然只是提示,不是證據。**
