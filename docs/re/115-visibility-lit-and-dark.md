# 115 — 位移 59 / 61 是「有光」與「無光」的能見度

> ✅ **結論已由 [`117`](117-annotation-was-right.md) 確認**:`0x10511` 的 `cmp ds:365Ah, 0` 證實條件就是光源。
> ⚠ 但當時那行註解是**猜的**([`116`](116-contradiction-in-115.md) §2 的方法批評仍然成立)。

日期:2026-08-14
接續:[`114-maze-coordinates.md`](114-maze-coordinates.md)
子系統:**D. 角色/隊伍資料**

## 結論

`USERLIB 0x10516`–`0x10561` 是一個**二選一**,兩邊各讀一個記錄位移:

```
010516  jle → 0x1051B                  ; 光源 ≤ 0
01051B  … mov word ptr ds:3010h, 61    ; 讀位移 61
01052A  call loc_10073                 ; CVI
01052D  mov ds:35B2h, ax               ; → 能見度
010530  mov word ptr ds:365Ah, 0       ; 光源計數歸 0

010539  (else,光源 > 0)
010542  … mov word ptr ds:3010h, 59    ; 讀位移 59
010548  call loc_10073
01054B  mov ds:35B2h, ax               ; → 能見度
01054E  dec word ptr ds:365Ah          ; 光源計數 − 1

010552  mov ax, ds:35B2h / mov ds:3050h, ax
```

| 位移 | 語意 | 信心 |
|---:|---|---|
| **59** | **有光源時的能見度**(取用時光源 −1)| **已確認** |
| **61** | **無光源時的能見度**(光源歸 0)| **已確認** |

`ds:35B2h` 正是 [`105`](105-visibility-fields.md) 看到的
「狀態列 `Visibility =` 的兩個候選值之一」——**兩邊接上了。**

## 1. 位移 59 從消去法升到已確認

[`105`](105-visibility-fields.md) 的理由是「槽 33 只讀四個變數,
狀態列上唯一需要二選一的欄位是能見度」——**消去法**。
[`110`](110-display-offset-census.md) §1 還撤回過一次錯誤的升級(距離 2170 bytes)。

現在看到的是**直接的因果**:光源狀態決定讀哪一個位移,結果存進
`ds:35B2h`,而 `ds:35B2h` 就是狀態列的候選值。**三段接起來,沒有跳躍。**

## 2. 光源計數也對上了

`ds:365Ah` = **位移 45 = 光源剩餘回合**([`112`](112-light-counter-verified.md))。
這段程式碼**每次取能見度就把它減一**,用完就歸 0 並改用「無光」的能見度 ——
**與 `'You now have about … turns of light.'` 完全一致。**

[`112`](112-light-counter-verified.md) 是從**顯示端**驗證的,這裡是**消費端**。
**兩端獨立對上。**

## 4. D 只剩兩項

1. **位移 25** —— 每次時鐘推進被 `dec`、`MENU` 比 `2`;語意未解
2. **位移 23** —— 「補給品」來自 [`104`](104-groups-fields-from-context.md) 的語境字串法,
   而該方法在這個檔上的命中率是 **1/4**([`114`](114-maze-coordinates.md) §1)——
   **必須重驗,不能沿用**

⚠ 位移 83(能見度來源旗標)的判讀也應該回頭看:
[`105`](105-visibility-fields.md) 說它在 `ds:35B2h`/`ds:35B4h` 之間選,
但本篇看到的分岔條件是**光源**,不是位移 83。
**兩處可能是不同的分岔** —— 標為待釐清。
