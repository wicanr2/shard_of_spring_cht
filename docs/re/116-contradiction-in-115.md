# 116 — 位移 25 的形狀,與 [`115`](115-visibility-lit-and-dark.md) 的一個未驗證假設

日期:2026-08-14
接續:[`115-visibility-lit-and-dark.md`](115-visibility-lit-and-dark.md)
子系統:**D. 角色/隊伍資料**

## 1. 位移 25:載入時被夾在下限上

`MENU 0x11998`:

```
01199C  call sub_1008C             ; 從記錄讀出
01199F  mov ds:3658h, ax           ; 位移 25
0119A2  cmp word ptr ds:3658h, 2
0119A7  jle → 0x119AC
0119AC  mov word ptr ds:3658h, 19h ; ≤ 2 → 直接設成 25
```

**讀進來之後,若 ≤ 2 就重設為 25。** 加上 [`107`](107-clock-is-four-levels.md) §1
的「每次時鐘推進都 `dec`」——

**形狀:一個會隨時間耗盡、耗盡後被補回 25 的計數器。**
⚠ **語意仍未解**(補給?燃料?)。**形狀不是語意。**

> ⚠ **本節的「矛盾」不成立**([`117`](117-annotation-was-right.md)):`MENU` 是初始化路徑、
> `USERLIB` 是每回合消費路徑,兩者不可比。**但「那行註解是猜的」這個批評成立。**

## 2. ⚠ [`115`](115-visibility-lit-and-dark.md) 的分岔條件是我假設的

[`115`](115-visibility-lit-and-dark.md) §1 寫:

```
010516  jle → 0x1051B      ; 光源 ≤ 0
```

**那個註解沒有證據。** dump 從 `0x10514` 開始,**`cmp` 在更前面,我沒有看到它**,
只因為兩個分支各自動了光源計數就推斷條件是光源。

而 `MENU 0x119B2` 有一個**看得見的** `cmp`:

```
0119B2  cmp word ptr ds:365Ah, 1    ; 光源
0119B7  jl → 0x119BC                ; 光源 < 1
0119C7  mov word ptr ds:66D0h, 59   ; ★ 讀位移 59
```

**光源不足時讀的是位移 59** —— 與 [`115`](115-visibility-lit-and-dark.md)
的「光源 > 0 → 位移 59」**方向相反**。

| 來源 | 條件 | 讀哪個位移 |
|---|---|---|
| [`115`](115-visibility-lit-and-dark.md)(條件為**推測**)| 光源 > 0 | 59 |
| 本篇(條件**可見**)| 光源 < 1 | 59 |

**兩者不能同時成立。** 可能是兩段不同用途的程式碼,也可能是
[`115`](115-visibility-lit-and-dark.md) 把 59 / 61 指反了。

**處置**:位移 59 / 61 的**「哪個是有光、哪個是無光」降為未定**;
「兩者都是能見度、由光源狀態二選一」這一層仍然成立。

> **判準:註解裡的因果詞(「因為光源」)要能指到一條指令。**
> 我在 [`115`](115-visibility-lit-and-dark.md) 寫「`; 光源 ≤ 0`」時,
> **`cmp` 不在我 dump 的範圍裡** —— 那個分號後面的字是我加的,不是讀到的。
> **反組譯筆記裡最危險的東西不是錯誤的結論,是自己補的註解**:
> 它下一輪會被當成一手事實引用。
