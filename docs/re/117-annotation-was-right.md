# 117 — 那個註解是對的,但寫的時候不該是對的

日期:2026-08-14
接續:[`116-contradiction-in-115.md`](116-contradiction-in-115.md)
子系統:**D. 角色/隊伍資料**

## 結論

把 `0x10516` 之前的指令 dump 出來:

```
010511  cmp word ptr ds:365Ah, 0    ; ★ 光源計數
010516  jle → 0x1051B               ; 光源 ≤ 0 → 位移 61
010518  jmp → 0x10539               ; 光源 > 0 → 位移 59
```

**[`115`](115-visibility-lit-and-dark.md) 的註解「光源 ≤ 0」完全正確。**

| 位移 | 語意 | 信心 |
|---:|---|---|
| **59** | **有光源時的能見度** | **已確認**(恢復)|
| **61** | **無光源時的能見度** | **已確認**(恢復)|

## 1. `MENU` 那一處是另一條路

[`116`](116-contradiction-in-115.md) §2 拿來反駁的是
`MENU 0x119B2`(`光源 < 1` → 位移 59)。

`MENU` 是**載入/開局**的路徑,`USERLIB 0x10511` 是**每回合消費**的路徑。
兩段程式碼做的不是同一件事,**條件方向不同不構成矛盾** ——
是我把兩個不同情境的分岔擺在同一張表裡比。

> **判準:兩段程式碼的條件方向相反時,先問「它們是不是同一件事」。**
> [`116`](116-contradiction-in-115.md) §2 那張對照表把
> `MENU`(初始化)與 `USERLIB`(每回合)並排,**表格的形式讓它們看起來可比**,
> 而它們不可比。**排版會製造出資料裡沒有的對立。**

## 2. 但 [`116`](116-contradiction-in-115.md) 的方法批評仍然成立

**結論對,不代表當時有資格寫。**

[`115`](115-visibility-lit-and-dark.md) 寫下 `; 光源 ≤ 0` 時,
`cmp` 確實不在 dump 範圍內 —— 那一行是**猜的**,只是猜對了。

若不是 [`116`](116-contradiction-in-115.md) 去查,它會以「已確認」的身分
被後面每一輪引用,而**沒有人會知道它從來沒被讀過**。

> **判準:一條猜對的註解和一條猜錯的註解,在筆記裡長得一模一樣。**
> 這正是 [`86`](86-scanner-fixed-conclusion-restored.md) §4
>(「結論正確不等於推理正確」)的第二次出現 ——
> 兩次都是**先靠弱證據得到正確答案,後來才補上強證據**。
> 差別在:那一次是工具的預設值,這一次是我手打的分號後面。
