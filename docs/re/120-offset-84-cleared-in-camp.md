# 120 — 位移 84 在 `CAMP` 被清成 0

日期:2026-08-14
接續:[`119-attribute-12-never-decremented.md`](119-attribute-12-never-decremented.md)
子系統:**D. 角色資料**

## 1. 唯一的寫入端

`CAMP 0x12398`:

```
012398  mov bx, ds:7072h        ; 角色索引
01239E  shl bx,1 / shl bx,1     ; × 4 → 字串陣列
0123A0  add bx, 34E0h           ; 角色記錄
0123AA  mov word ptr ds:66C8h, 0    ; ★ 值 = 0
0123B0  mov word ptr ds:66CAh, 54h  ; ★ 位移 84
0123B9  call loc_10043              ; MID$ 寫回
```

**把某個角色的位移 84 清成 0。** `CMBT 0x170E8` 有另一處同形狀的寫入。

## 2. 這證明了什麼、沒證明什麼

| 成立 | 不成立 |
|---|---|
| 位移 84 是**會被清除**的臨時狀態,不是永久屬性 | 它是不是「剩餘回合」—— **清成 0 對任何一種判讀都合理** |
| 與 [`111`](111-status-code-equals-school.md) 的「與狀態同時被設定」一致 | |

**位移 84 = 一個與狀態綁在一起、會被設定也會被清除的值。**
[`119`](119-attribute-12-never-decremented.md) 把「剩餘回合」降為假設,
本輪**沒有把它升回來** —— 清零不是遞減。

> **判準:一個對所有候選答案都成立的觀察,不縮小候選集合。**
> 「它會被清成 0」聽起來像進展,但**剩餘回合、效果強度、來源法術**
> 三種判讀都預期會被清零。**觀察要能分開候選,才算證據。**
> 這是 [`83`](83-hp-is-attribute-3.md) §3 那條判準的第三次應用。

## 3. D 的最終狀態(本階段)

| 項目 | 狀態 |
|---|---|
| `CHARS.DAT` 94 bytes × 25 筆 | ✅ 從 `OPEN` 讀出,大小整除 |
| `CHARS.DAT` 欄位 | 名稱、種族、職業、速度、力量、智力、體質、命中能力、最大/當前生命值、最大/當前法力、武器/防具格號、狀態、等級、十個技能旗標、背包、角色編號 —— **全部有語意**;位移 84 為**假設** |
| `GROUPS.DAT` 90 bytes × 5 筆 | ✅ 同上 |
| `GROUPS.DAT` 欄位 | 補給、時鐘四級、世界座標、迷宮座標、朝向、光源、兩種能見度、光源選擇、逃跑旗標 —— **13 / 14**;位移 25 未解 |
| 讀端 / 寫端 / 存檔流程 / 兩記錄的奇偶判別 | ✅ 全部 |

**D 不標 RE-DONE。** 兩項缺口:

1. **`GROUPS.DAT` 位移 25** —— 每回合遞減、≤2 時補回 25;語意未解
2. **`CHARS.DAT` 位移 84** —— 判讀停在「與狀態綁定的臨時值」,
   三個候選(剩餘回合 / 強度 / 來源)沒有分開

兩項都需要**能分開候選的觀察**,不是再多一個相容的觀察。
