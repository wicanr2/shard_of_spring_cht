# 121 — 位移 84 是狀態效果的**強度**,不是剩餘回合

日期:2026-08-14
接續:[`120-offset-84-cleared-in-camp.md`](120-offset-84-cleared-in-camp.md)
子系統:**D. 角色資料** × **J. 戰鬥規則**

## 結論

屬性 12 被寫入前,`bx` 是**一次除法的結果**:

```
016645  mov bx, [di+73C8h]   ; ★ SPELLS.DAT 欄5 = 法術最低消耗點數
016649  INT 3Fh; 71
01664E  INT 3Fh; 57          ; 整數 → 浮點累加器
016654  mov bx, di           ; 除數
016656  INT 3Fh; 8D          ; ★ 除法([`77`](77-runtime-arithmetic-api.md))
01665B  INT 3Fh; 77          ; 浮點 → 整數(結果在 bx)
01666F  mov [di+6822h], bx   ; → 屬性 12(= `CHARS.DAT` 位移 84)
```

**一個由「法術最低消耗」參與的除法** —— 這一次三個候選被分開了:

| 候選 | 判定 |
|---|---|
| 狀態剩餘回合 | ❌ 持續時間不會是消耗點數的商 |
| 來源法術編號 | ❌ 那會是法術索引,不需要除法 |
| **效果強度 / 倍率** | ✅ **投入點數相對於最低消耗的比值** |

**位移 84 = 狀態效果的強度。信心:證據充分。**

與 [`74`](74-spell-and-item-columns.md) §1 的施法機制一致 ——
玩家自己決定投多少點,投得多**威力**就高(欄4 × 點數);
而狀態類法術把「投了多少倍的最低消耗」存進屬性 12,當成效果強度。

## 1. 這才是 [`120`](120-offset-84-cleared-in-camp.md) 要的那種觀察

[`120`](120-offset-84-cleared-in-camp.md) §2 說「一個對所有候選都成立的觀察,
不縮小候選集合」,而「清成 0」正是那種。

**除法不是。** 三個候選裡只有一個會產生商。

> **判準:要分開候選,去找那個「只有其中一個會做」的動作。**
> 讀值、清零、與狀態同時寫入 —— 三個候選都會;
> **除以一個消耗點數 —— 只有「倍率」會。**
> 找判別觀察時,先問「哪一種候選會做別人不會做的事」。

## 2. `CHARS.DAT` 完成

**94 bytes 裡所有被程式碼碰過的位置都有語意**,位移 84 是最後一個。

| 位移 | 語意 | 位移 | 語意 |
|---:|---|---:|---|
| 2–11 | 名稱 | 30 / 32 | 最大 / 當前法力 |
| 12 | 角色編號 | 34 / 36 | 武器 / 防具背包格號 |
| 14 | 種族碼 | 38 | 狀態(= 法術系別編號)|
| 15 | 職業碼 | 40 | 等級 |
| 16 / 18 / 20 / 22 | 速度 / 力量 / 智力 / 體質 | 42–51 | 十個技能旗標 |
| 24 | 命中能力 | 54+2i | 背包第 i 格 |
| 26 / 28 | 最大 / 當前生命值 | **84** | **狀態效果強度** |

## 3. D 只剩一項

**`GROUPS.DAT` 位移 25** —— 每次時鐘推進被 `dec`、載入時若 ≤ 2 就補回 25;
語意未解。

依 §1 的判準,下一步要找的是**「只有某一種候選會做的動作」**,
而不是再多一個「遞減」或「被讀出」這種所有候選都相容的觀察。
