# 131 — 世界地圖的可通行性:八條規則,含**方向性**的海岸線阻擋

日期:2026-08-15
接續:[`129-world-tile-dispatch.md`](129-world-tile-dispatch.md)
子系統:**F. 世界地圖**
輸入:`WRLDMOVE.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))
工具:`tools/bool_chain.py`(本輪為此寫的,見 §4)

## 結論

可通行性判定在 `WRLDMOVE.EXE` `0x10334`–`0x10572`。
**八條規則,任何一條成立就不可通行。**

[`spec/05`](../spec/05-world-scene.md) §5 原本記「可通行性未解,M2 不實作」——
**已解,規格已更新。**

## 1. 變數

| 位址 | 語意 |
|---|---|
| `ds:0CD58h` | 目標 Y |
| `ds:0CD5Ah` | 目標 X |
| `ds:0CD5Ch` | **結果**:`0` = 不可通行、`0FFFFh` = 可通行 |
| `ds:0CD5Eh` | **目標格**的地形值 |
| `ds:0CD62h` | **現在格**的地形值(由 `ds:0CD60h` 複製而來)|
| `ds:3520h` | 朝向(`1`北 `2`東 `3`南 `4`西,[`re/70`](70-key-chains-all-modules.md))|

流程:先檢查 X 範圍 → 樂觀設為可通行 → 逐條檢查,命中就設 0 並返回。

## 2. 八條規則

| # | 條件(成立 = **不可通行**)| 位址 |
|---:|---|---|
| 1 | `X < 5` 或 `X > 98` | `0x10334` |
| 2 | `10 ≤ 目標值 ≤ 12` | `0x10380` |
| 3 | 目標值 ∈ {20, 21} **且** 現在值 ∉ [1, 4] | `0x103A4` |
| 4 | 現在值 ∈ {20, 21} **且** `15 ≤ 目標值 ≤ 18` | `0x103E8` |
| 5 | **朝北**且 現在值 ∈ {15, 16} 且 目標值 ∈ {17, 18} | `0x1042A` |
| 6 | **朝東**且 現在值 ∈ {15, 18} 且 目標值 ∈ {16, 17} | `0x10479` |
| 7 | **朝南**且 現在值 ∈ {17, 18} 且 目標值 ∈ {15, 16} | `0x104C8` |
| 8 | **朝西**且 現在值 ∈ {16, 17} 且 目標值 ∈ {15, 18} | `0x10517` |

**信心等級:已確認**(每一條由 `tools/bool_chain.py` 從指令還原,逐條核對)。

### 規則 2 對上了 [`129`](129-world-tile-dispatch.md)

`10 ≤ 值 ≤ 12` 阻擋 —— 其中 **11 是海洋(6,933 格,55.6%)**。
所以「海洋不能走」不再是常識,是規則。

⚠ 但**範圍是 10–12 不是只有 11**。值 10(30 格)與 12(8 格)同樣阻擋,
而它們的語意仍然未知。**不要把這條寫成「海洋不能走」** ——
那會漏掉另外兩個值。

### 規則 5–8:15/16/17/18 是海岸線的四個朝向

四條規則的結構是對稱的:

| 朝向 | 從 | 到 | 阻擋 |
|---|---|---|:-:|
| 北 | {15, 16} | {17, 18} | ✓ |
| 南 | {17, 18} | {15, 16} | ✓ |
| 東 | {15, 18} | {16, 17} | ✓ |
| 西 | {16, 17} | {15, 18} | ✓ |

解開來:

| 值 | 擋住的方向 | 幾何 |
|---:|---|---|
| 15 | 北、東 | **東北角** |
| 16 | 北、西 | **西北角** |
| 17 | 南、西 | **西南角** |
| 18 | 東、南 | **東南角** |

**四個值各擋兩個相鄰方向,而且是乾淨的旋轉 —— 海岸線的四個轉角。**
兩塊相鄰的海岸磚之間形成一道牆,把陸地圍起來。

⚠ 本表第一版把 17 與 18 寫反了(寫成「南、東」與「南、西」)。
規則表(§2 上表)本身是對的,錯的是我從它**推導**出來的這一張。
抓到的方式是把推論也寫成測試(`TestCoastTileBlocksTwoDirections`)——
64 種列舉的測試通過,而推論表的測試失敗。

> **判準**:**推論要跟規則分開測。** 規則抄對了不代表推論推對了,
> 而推論往往才是實作與文件實際引用的那一層。

> **判準**:看到「四個值 × 四個方向」的對稱規則,先假設它們是
> **同一個東西的四個朝向**,而不是四種不同的地形。
> [`53`](53-world-tiles-towns-and-draw-renderer.md) 從渲染圖判定 15–18 是「海岸線」,
> 方向是對的;**這一輪補上了它們彼此的關係**。

### 規則 3–4:20/21 是單向的通道

值 20/21(合計 5 格)**只能從地形 1–4 進入**(草原與森林),
而且**進去之後不能走到海岸線**。

語意未解,但形狀像**橋、渡口或關口**。⚠ 不要據此命名。

## 3. ⚠ X 的範圍是 5–98,不是 0–102

規則 1 把可走的 X 限制在 **5 ≤ X ≤ 98**,而地圖寬 103(0–102)。
**兩側各有 4–5 欄玩家永遠到不了。**

這與 [`spec/05`](../spec/05-world-scene.md) §2.1 的「值 0 只在上緣與左緣」
是**兩件不同的事**:值 0 是資料側的邊界,X 範圍是程式碼側的限制。
⚠ **Y 沒有對應的檢查** —— 只有 X 被限制,原因未解。

## 4. 為此寫的工具:`tools/bool_chain.py`

MS BASIC 把布林運算式編成一個極度規律的形狀:

```
cmp  <運算元>, <立即數>
mov  <暫存器>, 0
j<cc> short +1
dec  <暫存器>        ; 暫存器 = TRUE 當且僅當 j<cc> **沒有**跳
```

**條件與助憶碼是相反的** —— `jge` 對應的是 `<`。
我第一次讀這段時就把 `jge`/`jl` 讀反了,而讀反之後的規則**仍然像一條合理的規則**,
不會有任何訊號。

工具把整段還原成可讀的判斷式。八條規則裡有六條含三層以上的巢狀
`AND`/`OR`/`NOT`,**逐條用眼睛解幾乎必錯**。

> **判準**:反組譯裡**形狀規律的東西一律寫工具**,不要用眼睛解。
> 判斷標準不是「難不難」,是「**錯了看不看得出來**」——
> 這種布林鏈錯了會產生另一條看起來合理的規則,沒有任何警訊。
