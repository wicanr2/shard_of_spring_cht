## 1. 派工鏈的末段:值 11 是被**跳過**的那一個

```
0112C2  cmp  word ptr ds:0CF96h, 0Bh
0112C7  jnz  short loc_112CC          ; ≠ 11 → 往下畫
0112C9  jmp  loc_112EB                ; == 11 → 什麼都不畫
0112CC  mov  di, [bp+8] / mov si, [bp+6] / …
0112DC  mov  bx, ds:0CF92h            ; 地形值
0112E0  shl  bx, 1
0112E2  shl  bx, 1
0112E4  add  bx, 0C980h               ; ← 0xC980 + 4×值
0112E8  INT  3Eh                      ; DRAW
```

所以整條鏈是:

```
值 1–9    → PUT 點陣圖(0xCA1C + 92×(值−1),來自 fastwrld.bin)
值 11     → 什麼都不做
其餘      → DRAW 巨集(0xC980 + 4×值 的字串描述子)
```

**三條路徑涵蓋所有值,沒有缺口。**

海洋佔全圖 **55.63%**,而最省的畫法就是不畫 ——
底色本身就是海。這比「替海洋準備一張點陣圖」更快,
也解釋了為什麼 `fastwrld.bin` 只有九張而地形值有 39 個。

### 取值的那一段(`sub_11136`)

```
011136  di = 0x67 × [bp+0Ah]      ; 103 × y
011148  di += [bp+0Ch]            ; + x
01114A  di <<= 1                  ; word
01114C  ax = [di + 6822h]         ; 取地形值
011150  ds:0CF92h = ax
011153  if ax < 10:  ds:0CF94h = [bp+8] − 16     ; 點陣路徑才要的螢幕座標
011169  ds:0CF96h = ds:0CF92h
```

`0CF92h` 與 `0CF96h` 是**同一個地形值的兩份副本**,`0CF94h` 是螢幕座標。
`(y × 103 + x) × 2 + 0x6822` 與 [`52`](52-world-map-reader-and-shared-grid.md) §1 一致。

## 2. 載入迴圈:`FOR I = 10 TO 38`

`0x10EE9`–`0x10F51` 依序處理三個檔案。形狀都是

```
mov bx, <目標位址>   / INT 3F:57    ; 位址 → 浮點(BLOAD 的載入位址)
mov bx, <檔名描述子> / INT 3F:55    ; 路徑前綴 + 檔名(字串串接,docs/re/38 §1)
                      INT 3E:1A     ; ★ 真正的載入
```

**`3F:55` 是字串串接不是開檔**,它組出來的是 `<路徑>檔名`;
把檔案讀進來的是後面那個 `INT 3E:1A`。目標位址另有
[`52`](52-world-map-reader-and-shared-grid.md) 獨立佐證。

| 檔案 | 檔名描述子 | 載入位址 |
|---|---|---|
| `wrldmap.bin` | `ds:0CF2Eh` | **`0x6822`**(與 [`52`](52-world-map-reader-and-shared-grid.md) 一致)|
| `wrlditem.pic` | `ds:0CF3Eh` | 逐行讀,見下 |
| `fastwrld.bin` | `ds:0CF4Eh` | **`0xCA1C`**(九張 × 92)|

`wrlditem.pic` 的讀取迴圈:

```
010F18  mov ax, 0Ah              ; I = 10
010F1E  mov bx, 1
010F21  INT 3F:B6                ; LINE INPUT #1
010F24  mov bx, ds:0CF18h        ; I
010F2A  shl bx,1 / shl bx,1
010F2E  add bx, 0C980h           ; 目標 = 0xC980 + 4×I
010F32  INT 3F:5A                ; 指派字串
010F35  inc dx / mov ax,dx
010F38  mov ds:0CF18h, ax
010F3B  cmp ax, 26h              ; 38
010F3E  jle short loc_10F1E
```

**`FOR I = 10 TO 38`,而繪製時的索引就是地形值本身。**

這是 [`54`](54-f-closure.md) §2「第 k 行 = 圖塊 k + 10」的**程式碼側直接證據**。
該結論原本只有資料側的空行對照,現在兩側都有,而且上界確定是 **38**
—— 檔案剛好 29 行,不多不少。

> **判準**:一條「編號對編號」的規則,資料側對得上還不夠,
> 要去找**寫下這個對應的那段程式碼**。
> 這條規則我曾推翻兩次都推錯([`130`](130-retro-why-the-tile-map-was-missed.md)),
> 而讓它變得不可動搖的不是第三次資料側驗算,是這 10 行迴圈。

## 3. 涵蓋率 100%,而且是雙向對上的

| 來源 | 值 | 格數 | 佔比 |
|---|---|---:|---:|
| 不畫(地圖邊界)| 0 | 224 | 1.80% |
| `FASTWRLD` 點陣 | 1–9 | 4,830 | 38.75% |
| **底色(不畫)** | **11** | **6,933** | **55.63%** |
| `WRLDITEM` 向量 | 10、12–38 | 476 | 3.82% |
| | | **12,463** | **100.00%** |

`wrlditem.pic` 的 29 行裡有 **6 行是空的**,對到值 11、14、19、22、33、34。
其中五個(14/19/22/33/34)在全圖出現 **0 次**;唯一「空行但有格子」的是
值 11,而它在程式碼裡被明確跳過。

**29 行 / 6 個空行 / 5 個零出現值 + 1 個明碼跳過 —— 全部咬合。**
偏移錯一格,兩邊立刻對不上。這比 [`54`](54-f-closure.md) §2 當時的檢定更強,
因為它是**雙向**的。

### 反過來也有例外,而且是預期中的

值 **23、26、29 有巨集,但地圖上一格都沒放**。
它們與 24/25/27/28 是同一族建築,差別在**有沒有門**:

```
值 23  C2E3NF3BU4C3E4F4C1BG2NG3F4
值 28  C2be2bu2E3NF3BU4C3E4F4C1BG2NG3F4bd2c2d2l2u2r2
                                      ^^^^^^^^^^^^^ 多出來的門
```

而 24+25+27+28 合計 **11 格**,正好是 `MAZEDATA.BIN` 的 11 個地城入口
([`51`](51-mazedata-and-world-entrances.md) §2)。
所以這三個是**沒被放上地圖的變體**,不是偏移錯。

實作端把這三個寫成明列的例外
(`engine/internal/original/draw_test.go` 的 `unusedWrldItem`),
清單變動會讓測試失敗。

### 值 35–38 也是海岸線

它們的巨集與 15–18 同一族(`C1` + 一串 `M±x,±y`),合計 36 格。
⚠ 但 [`131`](131-world-passability.md) 的阻擋規則**只涉及 15–18**,
35–38 不阻擋任何方向。**兩者形狀像但行為不同,不要合併。**

## 4. 顯示模式有兩種

`0x110A9`:

```
mov bx, ds:379Ch
and bx, bx
jnz → mov dx, 3D8h / mov ax, 0Ah / out dx, al
```

`ds:379Ch` 不為 0 時把 CGA 模式暫存器寫成 **`0x0A`**,
而 [`49`](49-h-closure.md) 記的是 `0x0E`。**兩者是不同的調色盤。**

依 [`CLAUDE.md`](../../CLAUDE.md) §1.2 的邊界,這裡只記**效果**(有兩套調色盤,
由一個旗標選),不往下追暫存器語意。`CONFIG.SOS` 的 `C,C` 是候選來源,**未驗證**。

## 5. 檢討:`129` 為什麼把結論 3 寫成「已確認」

`129` 寫的是「值 11 的圖形在 `0xCFA6`,另一區,間距 682」——
**這條鏈上根本沒有 `mov bx, 0CFA6h` 這道指令。**

錯誤的形狀是這樣的:前九筆是整齊的
`cmp N / mov bx, <位址> / INT 3E`,間距固定 92。
第十筆的比較數是 `0Bh`,而它後面**沒有** `mov bx, imm` ——
我把這個「表格的第十列」直接補完了,順手填了一個看起來合理的位址。

> **判準**:一張規律的表,**最後一列最可能不是同一種東西**。
> 前九筆完全同形會建立一個很強的預期,而那正是讀最後一筆時要提高警覺的理由 ——
> 「跳出迴圈的那一支」在編譯輸出裡幾乎總是長得不一樣。

第二個訊號被漏掉了:`129` §6 自己寫著「`0xCFA6` 由誰填 —— **未解**」。
**一個位址查不到任何寫入端,第一個假設應該是「它不是位址」**,
而不是「寫入端還沒找到」。同一個形狀在 `docs/re/42`(`0x66DC`)已經踩過一次。
