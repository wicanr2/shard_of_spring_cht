# 133 — `CHARS.DAT` 位移 1 = 所屬隊伍編號

日期:2026-08-15
子系統:**D. 角色／隊伍資料與存檔**
輸入:`CHARS.DAT`、`CHARUTIL.EXE`、精訊中文手冊
(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

`CHARS.DAT` 位移 1 是**該角色所屬的隊伍編號**(ASCII 數字 `'1'`–`'5'`)。
出貨檔的五個角色全是 `'5'`,其餘 20 槽是 `'*'`。

**信心等級:證據充分。**
([`100`](100-chars-attributes-closed.md)、[`122`](122-d-closure.md)、
[`formats/01`](../formats/01-chars-dat.md) 原本都標「未解」,已訂正。)

## 1. 四條互相獨立的證據

| # | 證據 | 來源 |
|---|---|---|
| 1 | 出貨的五個角色,位移 1 **全部是 `'5'`** | `CHARS.DAT` |
| 2 | 手冊:「在遊戲磁片中有一個已經組好的特別隊伍 **PARTY＃5**」 | 精訊手冊 p.6 |
| 3 | 角色名冊的欄位標題有 **Party 欄** | `CHARUTIL.EXE` `0x0320D` |
| 4 | 手冊:「最多可以組成 **5 支**隊伍」;`GROUPS.DAT` 正好 **5 筆** | 手冊 p.7 + [`formats/02`](../formats/02-groups-dat.md) |

`CHARUTIL.EXE` 的字串:

```
0x0320D   ' #) Name       Party         #) Name       Party'
0x03013   'm#) Name        Race   Class   Level   Status'
0x02F69   'Party #0'
0x03132   'No party #'  →  0x03148  'to disband !'
```

第一條是**兩欄並排的名冊**(25 個角色分兩欄列出),而
「Party」是那張表唯一需要、卻在 [`formats/01`](../formats/01-chars-dat.md)
裡沒有對應欄位的資料 —— 位移 1 是記錄裡唯一沒有語意的欄位。

> **判準**:一個欄位解不出來時,先去看**畫面上有什麼欄位沒有來源**。
> 這一題在資料側盯了很多輪(值是 `'5'`,像等級又不是等級),
> 而答案在「這個模組會印出什麼」裡 —— 一次字串 dump 就有。

## 2. 手冊同時解掉了三個上限

| 手冊 | 對上 |
|---|---|
| 「最多可以組成 5 支隊伍」 | `GROUPS.DAT` 5 筆 × 90 bytes |
| 「一個隊伍中可以有 1～5 個人」 | `ds:34F8` 隊伍人數上限 5([`43`](43-common-block-and-array-indexing.md))|
| 「鍵入 1～5 中的一個數字來選擇你已經組好的隊伍」 | 位移 1 的值域 `'1'`–`'5'` |

三個「5」原本是三個獨立的觀察,現在是同一件事。

## 3. `'*'` 的語意:**假設**

20 個未使用的角色槽,位移 1 是 `'*'`、其餘 93 bytes 全是空白。
兩種讀法在出貨資料上**分不開**:

| 讀法 | 支持 |
|---|---|
| `'*'` = 沒有隊伍 | 手冊的 D)ISBAND 解散隊伍後角色仍存在,總得有個值表示「無隊伍」 |
| `'*'` = 空的角色槽 | `CHARUTIL` 有 `'Is deleted !'`(`0x030CE`),刪除時可能寫 `'*'` |

出貨檔裡「無隊伍」與「空槽」剛好重合(五個角色全都有隊伍),
**所以資料側永遠裁不出來**。⚠ 不要因為兩種讀法都合理就挑一個寫進規格。

**實作上不需要裁決**:引擎判斷槽位是否有人用**名稱是否全空白**,
與位移 1 無關(見 [`spec/06`](../spec/06-party-and-save.md) §2)。
