# 135 — `GROUPS.DAT` 的第 5 筆是真的存檔,位移 1–18 是成員槽

日期:2026-08-15
接續:[`134-groups-load-routine-and-gold.md`](134-groups-load-routine-and-gold.md)
子系統:**D. 角色／隊伍資料與存檔**
輸入:`GROUPS.DAT`、`MENU.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

1. **`GROUPS.DAT` 出貨檔不是全空白** —— 第 1–4 筆是,**第 5 筆是完整的存檔**,
   正是手冊寫的 **PARTY #5**。[`formats/02`](../formats/02-groups-dat.md) 的
   「出貨檔整份是空白(450 個 `0x20`)」**是錯的**,已訂正。
2. **位移 1–18 是九個成員槽**:位移 `2i−1`(`i` = 1…9)存角色編號,
   有效值 **1–32**,其餘(出貨檔用 `99`)略過。**已確認**(讀出指令)。
3. 這筆存檔同時**印證**了世界座標、朝向編碼與時鐘下界。

## 1. 怎麼發現的

M3 的往返測試斷言「出貨的五筆都是空白」——**第 5 筆讓它掛了**。

> **判準**:把「已知的資料長相」寫成測試,而不是寫進註解。
> 這條斷言原本是 [`formats/02`](../formats/02-groups-dat.md) 的一句話,存在很多輪都沒人踩到;
> 變成 `assert` 之後**第一次執行就爆**。

## 2. 第 5 筆的內容

```
位移  1  01 00 02 00 03 00 04 00 05 00 63 00 63 00 63 00 63 00
位移 19  00 00 16 87 14 00 36 00 01 00 01 00 04 00 02 00 08 00
位移 37  08 00 20 20 03 00 20 20 00 00 20 20 20 20 20 20 20 20
位移 55  20 20 20 20 03 00 02 00 20 20 00 00 20 20 00 00 20 20
位移 73  20 20 20 20 20 20 20 20 20 20 63 00 20 20 20 20 20 20
```

| 位移 | 值 | 欄位 |
|---:|---:|---|
| 1,3,5,7,9 | 1,2,3,4,5 | **成員的角色編號** |
| 11,13,15,17 | 99,99,99,99 | 空的成員槽 |
| 19–22 | **75** | 金幣(MBF)|
| 23 | 20 | 補給 |
| 25 | 54 | 遭遇倒數 |
| 27/29/31/33 | 1 / 1 / 4 / 2 | 時鐘:月/日/時/時以下 |
| 35/37 | **8 / 8** | 世界座標 |
| 41 | **3** | 朝向 = 南 |
| 45 | 0 | 光源剩餘回合 |
| 59/61 | 3 / 2 | 有光 / 無光的能見度 |
| 83 | 99 | 沒有攜帶光源 |
| 39,43,47–57,63–77,85–90 | `0x20` | **從未被寫過** |

⚠ 「沒寫過的欄位保持 `0x20`」是這個檔案格式的常態 ——
記錄是用空白字串建立、再逐欄覆寫的。所以
**「值是 8224」等於「這個欄位還沒被用過」**,不是一個數值。

## 3. 位移 1–18 = 九個成員槽

`MENU.EXE` `0x114B0`–`0x1151E`:

```
0114BB  mov  bx, ds:6EB6h      ; 迴圈變數 i
0114BF  shl  bx, 1             ; ×2
0114C1  dec  bx                ; −1        →  位移 = 2i − 1
0114C4  mov  ds:66D0h, ax
0114C7  call sub_1008C         ; CVI(MID$(rec, 2i−1, 2))
0114CA  mov  ds:7786h, ax
        cmp  ds:7786h, 21h     ; 33   →  只有 值 < 33
        cmp  ds:7786h, 0       ;      且 值 > 0  才算數
        (兩個條件 AND;不成立就跳過這一槽)
        …
011500  shl  bx,1 / shl bx,1
011504  add  bx, 34E0h         ; 成員陣列 = ds:34E0 + 4×i(4 bytes = 字串描述子)
011519  cmp  word ptr ds:6EB6h, 9
01151E  jle  → 迴圈頭          ; **FOR i = 1 TO 9**
011525  cmp  word ptr ds:34F8h, 5   ; 人數上限 5
```

**九個槽,人數上限五人。** 兩個數字都是直接讀出來的,不是推的。

⚠ **九與五不一致,原因未解。** 陣列開得比上限大是常見寫法,但這裡沒有證據
說明為什麼是九。⛔ 不要把它讀成「曾經允許九人」——那是故事,不是結論。

⚠ **有效編號上限 32,而名冊只有 25 槽**([`formats/01`](../formats/01-chars-dat.md))。
兩個上限對不上,**未解**。⛔ 不要據此改任何一邊。

`ds:34E0` 正是 [`43`](43-common-block-and-array-indexing.md) 定出的 COMMON 區起點 ——
成員陣列就放在最前面。

## 4. 這筆存檔印證了三件先前的結論

| 結論 | 出貨存檔怎麼印證 |
|---|---|
| 位移 35/37 = 世界座標 | (8, 8) 是森林(值 4);越界或海洋都會馬上露餡 |
| 位移 41 = 朝向,`3` = **南** | (8, 9) —— 正南方一格 —— 是**城鎮**(值 30)|
| 時鐘四級的下界 1 / 1 / 4 / — | 出貨值 1 / 1 / **4** / 2,「時」的下界 4 這個怪數字對上了 |

第二條特別值得記:手冊說 PARTY #5 是「想在最快的時間開始本遊戲」用的隊伍,
而它站在**一座城鎮的正北方一格、面向那座城鎮**。
`y+1 = 南`([`spec/05`](../spec/05-world-scene.md) §6)在這裡有了一個獨立的檢查點。

> **判準**:一份「真實的存檔」是最便宜的交叉驗證來源 ——
> 它是原版自己寫出來的,所有欄位必然自洽。
> 這一筆同時檢查了**四個**先前分別解出的欄位,成本是讀 90 個位元組。
> 而它在專案裡躺了很久,因為 [`formats/02`](../formats/02-groups-dat.md) 說「整份是空白」。
