# 141 — 世界地圖的兩軸接反了:121 東西 × 103 南北

日期:2026-08-15
接續:[`139-oracle-reaches-gameplay.md`](139-oracle-reaches-gameplay.md)、[`54-f-closure.md`](54-f-closure.md)
子系統:**F. 世界地圖**
輸入:`WRLDMAP.BIN`、`GROUPS.DAT`、`TOWNDATA.DAT`(SHA-256 見 [`00-inputs.md`](00-inputs.md))、DOSBox 實跑

## 結論

`WRLDMAP.BIN` 的 12,463 格與**跨距 103** 都是對的,
但**哪一條軸是東西**接反了:

| | 先前(`19`/`54`/`formats/05`)| 正解 |
|---|---|---|
| 尺寸 | 103 東西 × 121 南北 | **121 東西 × 103 南北** |
| 索引 | `y × 103 + x` | **`x × 103 + y`** |
| 跨距 103 是 | 往南一格 | **往東一格** |

**信心等級:已確認** —— DOSBox 實跑的一次陽性 + 一次陰性(§1),
外加城鎮清單逐間吻合(§2)。

⚠ **這個錯不會有症狀。** 轉置過的地圖仍然是一塊連續陸地、仍然有海岸線、
仍然畫得出來 —— 只是整張圖轉了 90°。
`CLAUDE.md` §6「⚠ 寫反了地圖仍然畫得出來,只是轉了 90 度,不會有任何錯誤訊息」
這句警語**早就寫在程式碼註解裡**(`internal/world/world.go` 的 `At`),
而它警告的正是這一次真的發生的事。

## 1. 裁決:走到城鎮那一格

出貨存檔 PARTY #5 的座標是 `GROUPS.DAT` 位移 35 / 37,**兩個都是 8**
—— 所以「哪個是 x」在這一點上分不出來。分得出來的是**城鎮在哪一邊**:

```
陣列位置 index 935 = 30(城鎮圖塊)
以 party 的 index 832 為基準,935 − 832 = +103
```

| 先前的讀法 | 正解 |
|---|---|
| `+103` = 往南一格 → 城鎮在**南邊** | `+103` = 往東一格 → 城鎮在**東邊** |

實跑:

| 操作 | 結果 |
|---|---|
| 從起點按兩下 `Down`(往南走兩格)| **沒有進城**(兩次都只是地圖捲動)|
| 從起點按兩下 `Right`(先轉東、再往東走一格)| **進到城鎮畫面** |

**一次陽性 + 一次陰性,方向相反。** 這是本專案第一次用實跑推翻靜態結論。

> **判準**:兩個候選都能畫出「看起來合理」的地圖時,
> 不要再從圖像上找差別 —— 去找一個**兩者預測相反**的觀察。
> 這裡花的成本是兩次各 90 秒的實跑。
>
> 更該記的是**為什麼沒早點抓到**:先前檢驗尺寸時我拿
> 「重新切成 121 寬」當對照組,而那個對照組是錯的 ——
> 121 寬的 reshape 會把圖切碎(一眼就看得出不對),
> 所以它「被否證」只證明了 reshape 不對,**沒有碰到轉置**。
> **對照組要能區分你真正在猶豫的那兩件事**,不是隨便找一個會失敗的。

## 2. 城鎮畫面逐間吻合 `TOWNDATA.DAT`

進去之後畫面是:

```
Green Hamlet
A The Iron Blade      D Kor's Smithy       G General Goods
B Rolo's Resthouse    E Winsome Weapons
C Hamlet Hospital     F The Purple Rat
```

`TOWNDATA.DAT` 記錄 0–6 的 `town` 欄全是 `Green Hamlet`,`name` 欄依序是
`The Iron Blade` / `Rolo's Resthouse` / `Hamlet Hospital` / `Kor's Smithy` /
`Winsome Weapons` / `The Purple Rat` / `General Goods`。

**七間、順序、字母全中。** 三件事同時得到印證:

1. 45-byte 的記錄切分與 `town` / `name` 兩個字串欄的位置([`126`](126-shop-price-multiplier.md))
2. 建築清單的字母 = **檔案順序**,不是排序過的
3. **第 0 個城鎮 = `Green Hamlet`**,而它就是出貨存檔起點旁邊那一格

⚠ 但**其餘 12 個城鎮的座標對應仍然未解** —— 只印證了第 0 個。
`spec/11` 的「按座標排序取第 n 個」仍然是佔位,不要因為第 0 個對了就推定整串對。

## 3. 進城不需要按鍵

走上城鎮格**當下就切到城鎮畫面**。先前在城鎮格上試過 `<RETURN>` 與空白鍵
都沒有反應 —— 那是因為根本不需要,不是因為按錯鍵。

⚠ 這一條同時說明:[`139`](139-oracle-reaches-gameplay.md) §5 列的
「怎麼進城鎮」之所以問不出來,是因為**當時根本沒走到城鎮格**
(往南走的那兩格不是城鎮)。**一個「按什麼都沒反應」的觀察,
第一個假設該是「前提沒成立」,不是「鍵不對」。**

錯的是「目標格在哪一邊」。所以規則不必重解,只有方向的接線要改。
