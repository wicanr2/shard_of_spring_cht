## 1. 進迷宮的路徑是算出來的

用 [`131`](131-world-passability.md) 的八條可通行性規則在專案外部跑 BFS,
從出貨存檔起點算到 `(23,18)`,再依「先轉再走」([`139`](139-oracle-reaches-gameplay.md) §4)
轉成 27 個按鍵。三次實跑都走到同一個地方。

副產物:**時鐘的四級進位得到執行期印證** —— 走 25 步之後 `Hour` 由 4 變 7,
而每步推進最內層一格、10 格進一位([`107`](107-clock-is-four-levels.md)):
`4 + INT(25/10) = 6`…第 7 小時,吻合。

## 2. 四個陰性結果

| 按鍵 | 結果 |
|---|---|
| `ESC` | 畫面**逐位元組相同** |
| `E` | 畫面**逐位元組相同** |
| `Q` | 跳出 `Are you really sure you wish to Quit (Y/N) ?` |
| `Q` → `N` | 回到迷宮,畫面與按之前相同 |
| 方向鍵 | 在迷宮裡是移動(往南兩步走進走廊,看到一個青色物件)|

⚠ **有一次沒有重現的觀察**:某一輪按 `ESC` → `Q` → `E` 之後**回到了世界地圖**。
單獨測 `E` 沒有作用,所以那一輪發生了什麼**沒有解釋**。
記在這裡是為了下一輪知道有這條線索,**不要當成結論用**。

## 3. ⚠ 方法:截圖檔名重複用,會讓舊檔看起來像新結果

追這一項時我把 `p1` 這個檔名用了兩次。第二次的實跑還沒跑完,
而 `until [ -f p1.png ]` **立刻命中上一輪留下的那個檔** ——
我於是讀到一張三小時前的城鎮畫面,並且差一點據此寫下
「`E` 會離開迷宮」這個錯誤結論。

> **判準**:**每一輪實跑用不重複的截圖名**,或先刪掉舊的。
> 「檔案存在」不等於「這一輪產生了它」——
> 這與 `~/diagnosis-notes` 的「沉默相容於多個世界」是同一個形狀:
> **等待條件要能區分「還沒發生」與「上次就已經是這樣」。**

## 4. 畫面用了不只一組 CGA 調色盤

從截圖的 PLTE 直接讀:

| 畫面 | 索引 1 / 2 / 3 |
|---|---|
| 世界地圖(進城前) | 棕 `AA5500` / 紅 `AA0000` / **綠 `00AA00`** |
| 世界地圖(走一段之後)、城鎮 | 棕 `AA5500` / 紅 `AA0000` / **白 `FFFFFF`** |
| **迷宮** | **灰 `AAAAAA` / 洋紅 `AA00AA`** / 白 `FFFFFF` |
| 版權畫面 | 洋紅 / 灰 / 青 `00AAAA` |

**迷宮與世界地圖不是同一組色**,而且世界地圖自己也出現過兩種第 3 色。

⚠ 本專案的渲染目前用**一組固定的色**([`spec/04`](../spec/04-display-layout.md))。
這一條**會改變 remake 的外觀**,所以在 `CLAUDE.md` §1.2 的邊界之內
(「如果答案不會改變 remake 的行為,就不必解」—— 這一項會)。

⚠ 但它**不在「顯示卡怎麼收這些 bytes」那一側** —— 要解的是
「哪個畫面用哪一組色」,不是 CGA 暫存器的時序。
