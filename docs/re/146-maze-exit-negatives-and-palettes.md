## 1. 進迷宮的路徑是算出來的

用 [`131`](131-world-passability.md) 的八條可通行性規則在專案外部跑 BFS,
從出貨存檔起點算到 `(23,18)`,再依「先轉再走」([`139`](139-oracle-reaches-gameplay.md) §4)
轉成 27 個按鍵。三次實跑都走到同一個地方。

副產物:**時鐘的四級進位得到執行期印證** —— 走 25 步之後 `Hour` 由 4 變 7,
而每步推進最內層一格、10 格進一位([`107`](107-clock-is-four-levels.md)):
`4 + INT(25/10) = 6`…第 7 小時,吻合。

## 2. 四個陰性結果

| 按鍵 | 結果 |
|---|---|
| `ESC` | 畫面**逐位元組相同** |
| `E` | 畫面**逐位元組相同** |
| `Q` | 跳出 `Are you really sure you wish to Quit (Y/N) ?` |

⚠ **有一次沒有重現的觀察**:某一輪按 `ESC` → `Q` → `E` 之後**回到了世界地圖**。
單獨測 `E` 沒有作用,所以那一輪發生了什麼**沒有解釋**。
記在這裡是為了下一輪知道有這條線索,**不要當成結論用**。

## 4. 畫面用了不只一組 CGA 調色盤

從截圖的 PLTE 直接讀:

| 畫面 | 索引 1 / 2 / 3 |
|---|---|
| 世界地圖(進城前) | 棕 `AA5500` / 紅 `AA0000` / **綠 `00AA00`** |
| 世界地圖(走一段之後)、城鎮 | 棕 `AA5500` / 紅 `AA0000` / **白 `FFFFFF`** |
| **迷宮** | **灰 `AAAAAA` / 洋紅 `AA00AA`** / 白 `FFFFFF` |
| 版權畫面 | 洋紅 / 灰 / 青 `00AAAA` |

**迷宮與世界地圖不是同一組色**,而且世界地圖自己也出現過兩種第 3 色。

### ✅ 切換條件已解:各模組啟動時寫的那一個 byte

掃全部模組的 `out` 指令(`tools/ida/find_portio.py`),每一支**只寫一次** `0x3D8`:

| 模組 | 寫進 `0x3D8` |
|---|---|
| `WRLDMOVE`(世界地圖)| **`0x0A`** |
| `MAZEMOVE`(迷宮)| `0x0E` |
| `CMBT`(戰鬥)| `0x0E` |
| `MENU`(主選單)| `0x0E` |
| `MTEST` | `0x0E` |
| `TOWN` / `CAMP` / `CHARUTIL` / `START` | **沒有寫** —— 沿用前一個模組設的 |

`0x0E` 與 `0x0A` 差在 bit 2。效果就是**換一組色**;
依 `CLAUDE.md` §1.2,問到「造成什麼效果」就停,不追 CGA 暫存器本身。

⚠ `0x3D9`(顏色選擇)**沒有任何模組寫過**,所以亮度維持 BIOS 設模式時的狀態 ——
取原版實跑截圖裡的低亮度那一組。

⚠ **先前的實作只有一組色**,理由是 [`formats/07`](../formats/07-graphics.md) §5
讀到 `0x3D8 = 0x0E`。那句話是對的,**但它只讀了一個模組** ——
而用錯調色盤畫出來的地圖仍然是一張地圖,只是顏色不對。

> **判準**:一個「全域設定」的值,要問**是誰設的、有幾個地方設**。
> 讀到一處就寫進規格,等於假設了「只有一處」——
> 而那個假設在多模組的程式裡特別容易錯,因為每支模組都會自己設一次。
