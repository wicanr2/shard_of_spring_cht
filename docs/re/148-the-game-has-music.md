# 148 — 這款遊戲有音樂:十五段 BASIC `PLAY` 巨集

日期:2026-08-15
接續:[`147-leaving-the-maze.md`](147-leaving-the-maze.md)
子系統:**新** —— 先前十二個子系統(A–L)都沒有涵蓋聲音
輸入:`MAZEMOVE.EXE`、`USERLIB.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

兩支模組裡有 **15 段 BASIC `PLAY` 巨集字串**,是 PC 喇叭的樂譜:

| 模組 | 段數 | 位址 | 速度 |
|---|---:|---|---|
| `MAZEMOVE.EXE` | 10 | `0x04CBC`–`0x04DB0` | `T108` |
| `USERLIB.EXE` | 5 | `0x0180E`–`0x01868` | `T50` |

**信心等級:已確認**(直接讀檔;`PLAY` 巨集的語法是 MS BASIC 的公開規格)。

⚠ **本專案完全沒有記錄過這件事。** [`spec/03`](../spec/03-engine-plan.md) 的
里程碑 M0–M10 一個字都沒提聲音,`CLAUDE.md` §2.2 的十二個子系統也沒有。
不是「決定不做」,是**沒有發現**。

> **判準**:子系統清單是**當初憑檔案清單列的**,而檔案清單裡沒有 `.MID`、
> 沒有 `.VOC`,於是「有沒有聲音」這個問題從來沒有被問過。
> **一份「完整」的清單只在它當初的分類方式之內完整** ——
> 樂譜藏在 EXE 的字串表裡,不會出現在副檔名的統計裡。

## 1. `MAZEMOVE.EXE` 的十段

```
MB T108 O3 L8a
MB T108 O3 L16
MB T108 O3 L8 E F#GD
MB T108 O3 L2 G
MB T108 O4 L8 CC
MB T108 O4 L4 EC
MB T108 O4 L8 DC
MB T108 O3 L8 BA
O3 L8 G
O3 L3 G
```

接起來是一段旋律:`E F♯ G D | G | C C | E C | D C | B A | G | G`。

⚠ 它**緊鄰結局文字**(`0x04400`–`0x047B7`,「You have won! …」),
所以最可能是**通關時放的曲子**。⚠ 這是**位置上的推測**,不是讀到呼叫端。

## 2. `USERLIB.EXE` 的五段

```
MB T50 O3 L8 ML DEFE
MB T50 O3 L8 ML FE
MB T50 O3 L4 ML DE
MB T50 O3 L4 ML FF
MB T50 O3 L8 ML AG
```

`T50` 比前者慢一半,而 `USERLIB` 的匯出槽裡有**死亡**與**結局**兩個
([`66`](66-userlib-slot-semantics.md))—— 慢速的小調動機像是死亡/失敗的音效。
⚠ 同樣是推測,**沒有讀到哪個槽呼叫它**。

## 3. `PLAY` 巨集的語法(remake 要實作的部分)

MS BASIC 的公開規格,本專案用到的子集:

| 記號 | 意義 |
|---|---|
| `T<n>` | 速度,每分鐘 `n` 個四分音符 |
| `O<n>` | 八度(0–6),`O3` 的 C 是中央 C |
| `L<n>` | 預設音長:`n` 是分母(`L8` = 八分音符)|
| `A`–`G` | 音符;後接 `#`/`+` 升、`-` 降;後接數字則覆蓋該音的長度 |
| `MB` | music **background** —— 放進佇列,程式繼續跑 |
| `ML` | music **legato** —— 每個音佔滿它的時值 |
| 空白 | 無意義,忽略 |

⚠ **`MB` 與 `ML` 是狀態不是音符**,而且會殘留到後續的 `PLAY` 呼叫 ——
[`147`](147-leaving-the-maze.md) §4 把它們當成「字串的一部分」列出來,
那只在「一次播一段」時成立。

⚠ 最後兩段**沒有 `MB`/`T`** —— 它們沿用前面設好的狀態。
**所以這十段是一首曲子的續播,不是十首獨立的曲子。**
