## 1. 做法:走固定路線,存檔,比對 bytes

路線用可通行性八條規則([`131`](131-world-passability.md))跑 BFS 算出來,
按鍵序列照「先轉再走」([`139`](139-oracle-reaches-gameplay.md) §4)產生,
走完按 `S` 存檔,再把 `GROUPS.DAT` 第 5 筆與出貨檔逐位元組相比。

⚠ 寫的是 `workplace/dosbox/game/` 的複本(`CLAUDE.md` §8)。

## 2. 位移 35 / 37:走一條**只往南**的路線就分開了

出貨存檔在 `(8, 8)` —— 兩個座標相同,所以**在起點上這兩欄分不開**。
往南走六步之後:

```
位移 35:  8 →  8      ← 沒變 ⇒ 東西
位移 37:  8 → 14      ← +6  ⇒ 南北
```

> **判準**:兩個欄位在現有資料上同值時,**去製造一個它們不同的狀態**。
> 這與 [`144`](144-created-record-exposes-layout.md) §5 拆開 `'0'`/`'*'` 是同一招 ——
> 讓原版自己產生第三個樣本,比在同一份資料裡繼續找差別有效。

## 3. 每一個動作一格

三次量測,每次都把「時鐘推進的格數」與「按了幾個鍵」對起來:

| 操作 | 時鐘推進 | 遭遇倒數(位移 25)減少 |
|---|---:|---:|
| 只按 `S` 存檔,一步都沒走 | **1** | 1 |
| 6 次前進 + `S` | **7** | 7 |
| 18 次前進 + 2 次轉身 + `S` | **21** | 21 |

```
1 = 0 步 + 0 轉 + 1 存檔
7 = 6 步 + 0 轉 + 1 存檔
21 = 18 步 + 2 轉 + 1 存檔
```

**三筆都等於「動作數」,零例外。**

⚠ 「轉身也花時間」與「存檔也花時間」都**不直覺**,而先前的實作兩條都沒有。
症狀是**時鐘走得比原版慢**,而慢的時鐘**沒有症狀** ——
天色、遭遇倒數、食糧消耗全部一起變慢,玩起來只覺得「這遊戲比較寬鬆」。

> **判準**:一個「每 N 次做一件事」的計數器,要驗的是**分子與分母兩邊**。
> 我先前只驗了「時鐘會不會進位」(分母),沒驗「什麼動作算一次」(分子) ——
> 而分子錯了,整個遊戲的節奏就錯了,卻不會有任何一格畫面看起來不對。

⚠ 遭遇倒數(位移 25)與時鐘**永遠同步**,因為原版的 `dec ds:3658h` 就接在
時鐘進位那一段的最後([`107`](107-clock-is-four-levels.md) §1)。
實作要把兩者放在同一個函式裡,不要分開呼叫。
