## 1. 位移 90:五處程式碼指同一個地方

用位元組樣式 `BA 5A 00 B9 04 00`(`mov dx,5Ah` + `mov cx,4` = `MID$(rec, 90, 4)`)
掃全部九支 EXE,命中五處,分佈在三支模組:

| 模組 | 線性位址 | 前一條指令載入的字串 | 用途 |
|---|---|---|---|
| `CAMP` | `0x12889` | `0x79C8` = `Experience` | 長標籤角色表 |
| `CAMP` | `0x134EE` | `0x7BA0` = `Exp.  ` | **營地的角色卡** |
| `TOWN` | `0x122C2` | `0x7C68` = `Exp.  ` | 城鎮的角色卡 |
| `TOWN` | `0x10FD8` | — | **訓練所**(§3)|
| `CMBT` | `0x12E65` | — | **戰後結算**(§2)|

四處緊接著 `INT 3D:19`,而 `3D:19` = `CVS` 已由金幣定過
([`134`](134-groups-load-routine-and-gold.md) §1:`MID$(rec,19,4)` + `CVS` = 金幣)。
**同一組指令、同一個轉換,只有位移不同。**

決定性的是**標籤與欄位相鄰**:

```
0134E3  mov bx, 7BA0h        ; "Exp.  "
0134E6  INT 3F:6A            ; 印標籤
0134E9  mov bx, 7B7Eh        ; 角色記錄字串
0134EE  mov dx, 5Ah          ; 90
0134F1  mov cx, 4
0134F4  INT 3D:0A            ; MID$(rec, 90, 4)
0134F7  INT 3D:19            ; CVS
0134FA  mov bx, 1Ah / INT 3D:03
```

同一段程式先印 `Exp.`、再讀位移 90 —— **不需要從呼叫端參數順序反推語意**
(§2.1 條件 2 的反面做法)。位移的慣例由同一支常式的已知欄位釘死:
名稱是 `mov dx,2 / mov cx,0Ah`(位移 2–11)、種族是 `mov dx,0Eh / mov cx,1`(位移 14),
兩者都對得上 [`formats/01`](../formats/01-chars-dat.md)。

### 1.1 實跑印證:`Exp.` 印 `0`

營地按 `#` → `1` 叫出 `Segrono` 的角色卡:

```
Segrono          LVL: 1
Speed      11        H.P.   9/9
Strength   10        S.P.
Intellect   9        Exp.     0
Endurance   9        Stat.   OK
Skill      11
```

五個屬性值與 `CHARS.DAT` 第 1 筆位移 16/18/20/22/24 逐欄相同,`LVL` 對位移 40。

### 1.2 ⚠ 原版的「零經驗」不是 `00 00 00 00`

出貨的 25 筆記錄、以及**原版自己新造的角色**([`144`](144-created-record-exposes-layout.md)),
位移 90–93 一律是 `00 00 00 40`。照 MBF 解出來是 **2.7×10⁻²⁰**,不是 0 ——
而畫面印的是 `0`,因為顯示路徑取了整數部分。

實作上:remake 寫 `PutMBF(0)` 會得到 `00 00 00 00`,與原版不同位元組但同樣印 0。
**往返測試要比對「解出來的值」,不要比對這四個位元組**;
`Bytes()` 只在值真的變了才覆寫,沒打過仗的存檔因此仍然逐位元組相同。

> 這個欄位卡了很久,原因是 [`144`](144-created-record-exposes-layout.md) §6 寫的
> 「每一筆記錄都一樣,沒有變異量可以指認」—— 那是**從資料側找語意**的做法。
> **資料側沒有變異量時,不要去製造變異量(打一場勝仗),先去讀端找標籤。**
> 讀端只花了一次位元組掃描 + 兩次 `dump_range`。

## 2. 戰後結算:誰拿得到經驗

`CMBT.EXE` `0x12E20`–`0x12E9D`,對隊伍成員逐一跑(外層 `mov ax, 1` 起算,
上界是 `ds:34F8` = 隊伍人數):

```
012E20  mov bx, ax                     ; i
012E22  add ax, 9Eh                    ; i + 158
012E27  shl di, 1
012E29  cmp word ptr [di+6822h], 0     ; 第一個條件
012E2E  mov dx, 0
012E31  jle short …                     ; > 0 才 dx = −1
012E34  mov cx, bx
012E36  add bx, 80h                    ; i + 128
012E3E  cmp word ptr [di+6822h], 5     ; 第二個條件
012E43  mov bx, 0
012E46  jge short …                     ; < 5 才 bx = −1
012E49  and bx, dx                      ; 兩個都成立
012E4D  jnz …                           ; 否則跳過這個人
012E5F  add cx, 34E0h                   ; 角色記錄字串陣列 + 4×index
012E65  mov dx, 5Ah / mov cx, 4 / INT 3D:0A   ; MID$(rec, 90, 4)
        INT 3D:19                       ; CVS
        …                               ; 加上這一場的經驗
012E8D  INT 3F:5C                       ; MID$ 指派 —— 寫回去
```

### 2.1 兩個索引照 `A(列, 欄)` 拆開

主陣列的定址是 `0x6822 + (欄 × 15 + 列) × 2`([`43`](43-common-block-and-array-indexing.md) §1),
而隊伍成員是**列 9–13**([`103`](103-flee-is-leaving-the-field.md))。把兩個基底拆開:

```
158 + i  =  10 × 15 + 8 + i   →  欄 10、列 9…13       i = 1…5
128 + i  =   8 × 15 + 8 + i   →  欄  8、列 9…13
```

| 欄 | 屬性 | 條件 | 意思 |
|---:|---|---|---|
| **10** | **朝向**([`96`](96-facing-and-action-points.md) §3)| `> 0` | **還在戰場上** —— 逃走的人朝向被清成 0([`103`](103-flee-is-leaving-the-field.md))|
| **8** | **狀態**([`98`](98-status-level-and-a-sign-error.md))| `< 5` | 未陣亡(5 = `D E A D`)|

> **陣亡的人與逃走的人都不分經驗;活著留在場上但中毒／束縛的人照分。**

⚠ 第一個條件**不是生命值**。屬性 3 才是生命值,而這裡用的是屬性 10 ——
兩者在多數情況下同時成立(死了通常也不在場),
**只有「逃走但活著」那一種狀態分得開**,而那正是原版特別處理的情況。

> **判準**:`[di+常數]` 的常數要**照文件裡的定址公式拆**,不要用「這個值看起來像哪個屬性」去猜。
> 拆開只要一次除法,而猜錯會產生一條**執行起來完全正常**的錯規則。

`Experience:` 與 ` (per character)` 兩個字串([`95`](95-no-flee-command.md) §3)
說明結算畫面印的是**每人所得**,不是全隊總和。

### 2.2 總額與除數在這一段的前面

`0x12C54`–`0x12D0F` 先算好兩件事,寫回迴圈只是把結果加進每個人的記錄:

```
ds:967C = Σ(列 0…8) A(列, 欄 19)            怪物的經驗值總和,不篩死活
ds:9680 = #{ 朝向 > 0 且 狀態 < 5 }          有資格的人數
ds:967C = INT(ds:967C ÷ ds:9680)            每人所得
```

完整算式與三個執行期 API(`RND` / `INT()` / `MKS$`)見
[`152`](152-experience-settlement-formula.md)。

## 3. 訓練所讀同一個欄位

`TOWN.EXE` `0x10FD5`:

```
mov bx, 7114h                    ; 角色記錄
mov dx, 5Ah / mov cx, 4
INT 3D:0A / INT 3D:19            ; 經驗值
…
mov ds:66D0h, 28h                ; 位移 40
call loc_10079                   ; CVI → 等級
…                                ; 以等級索引一張表
INT 3D:03                        ; INT()(向下取整),不是相減 —— 見 re/152 §3
```

接著印 ` experience before gaining a level.`(字串在 `0x7180`)。

## 4. 戰鬥的鍵盤與行動點(實跑)

畫面右下角直接印出鍵盤模板:

```
        [ESC]
   [D][↑][ ?]
   [←][  ][→]
   [C][↓][ U]
        [ATK]
```

上面一行印 `MP= 13   FACING ↓` 與當前行動者的名字。
逐一按鍵、逐格記錄 `MP`:

| 按鍵 | MP | 結果 |
|---|---:|---|
| (開始) | 13 | `Richtatha`,面向 ↓ |
| `↑` | 12 | **轉身,扣 1** |
| `↑` | 12 | 前方是友軍 → **不動,不扣** |
| `A` | 9 | **攻擊,扣 3** |
| `A` | 6 | 扣 3 |
| `↑` | 6 | 仍被擋住,不扣 |
| `A` | 3 | 扣 3 |
| `Return` | 3 | **無作用**(與世界地圖一致,[`139`](139-oracle-reaches-gameplay.md))|
| `A` | — | MP 不足 → **換下一個行動者**(`Fire Hawk`)|

四項結論:

1. **`MP` = 行動點,而且等於速度** —— `Richtatha` 的速度是 13
   ([`100`](100-chars-attributes-closed.md) §1),開場 `MP= 13`。
   手冊 p.31「行動點 = 速度」因此拿到執行期印證。
2. **轉身 1、攻擊 3**,與手冊 p.31 相同。
3. **移動被擋住不扣點** —— 不是「花了點數但沒動」。
4. **點數不足以做下一個動作時自動換人**,不需要「結束回合」鍵。

⚠ 行動順序是 `Richtatha`(隊伍第 5)→ `Fire Hawk`(第 4),
**不是隊伍順序**;先攻規則見 [`102`](102-flee-exists-retracting-j.md)。

### 4.1 `S` 在戰鬥中是音效開關

戰鬥中按 `S`,訊息框跳出 `Sound is now off.` + `[Press ENTER]`。
**不是存檔。**([`149`](149-every-action-costs-one-tick.md) 量時鐘時按的 `S` 是在世界地圖上。)

> 這條差點寫錯結論:當時的存檔沒有變化,而「按了 `S` 但檔案沒變」
> 與「`S` 在這個畫面不是存檔」長得一樣。**是訊息框上的那一行字把它分開的。**

同時證實**遊戲有聲音而且可以關掉** —— [`148`](148-the-game-has-music.md)
只找到樂譜,沒找到開關。

### 4.2 全隊陣亡時原版怎麼寫檔

拿一支會輸的打法跑完(隊伍 HP 5–15,對上一群持盾敵人),名冊列變成
`D1 Segrono 0` / `D2 Hard Axe 0` / ` 3 Grod 9` / `D4 Fire Hawk 0` / `D5 Richtatha 0`
—— **`D` 前綴 = 陣亡**。全隊倒下之後,原版寫回:

| 檔案 | 變化 |
|---|---|
| `GROUPS.DAT` 第 5 筆 | **整筆清成 `0x20`**(隊伍解散)|
| `CHARS.DAT` 五筆 | 位移 28(生命)、32(法力)→ **0** |
| 同上 | 位移 38(狀態)→ **5**(`D E A D`)|
| 同上 | 位移 1 → **`'0'`**(由 `'5'` 變成「無隊伍」)|

位移 1 的三種值([`144`](144-created-record-exposes-layout.md) §5)因此全部有了**寫入端**證據:
`'5'` 入隊、`'0'` 解散、`'*'` 空槽。

## 5. 兩個順帶推翻的斷言

### 5.1 五個基本屬性有畫面標籤

[`100`](100-chars-attributes-closed.md) §2 寫「`CAMP` 的角色卡只印
`Level` / `Hit Pts.` / `Spell Pts.` / `Experience` / `Status` / `Skills`,
**五個基本屬性沒有畫面標籤**,中文化時這四個名字要另外決定」。

實際上名字有**兩個**來源:

```
TITLES.DAT       "Speed     :" "Strength  :" "Intellect :" "Endurance :" "Skill     :"
CAMP/TOWN.EXE    "Speed", "Strength", "Intellect", "Endurance", "Skill"
```

`TITLES.DAT` 從第一天就在 `CLAUDE.md` §4.4 的「純文字資料檔」清單上。

> **判準**:斷言「這個東西沒有名字」之前,要把**所有可能放名字的地方**掃過,
> 不只是當時正在讀的那一支。查一次 `grep -a` 的成本是幾秒。

譯名不受影響 —— `translations/glossary.md` 用的是手冊的
速度／力量／智能／體能／技巧,而畫面標籤與手冊用同一組詞。

### 5.2 營地有 11 個指令

畫面上的營地選單:

```
Camp:
P)rint char(s)      R)eorder        I)dentify
S)leep              T)rade          U)se an item
#)inspect char      D)rop           ESC to leave
C)ast spell         E)quip
                    H)unt
```

[`spec/11`](../spec/11-town-camp-roster.md) §4 只列了換裝備／施法／睡覺／檢視／丟棄,
而且寫「武器與防具分成兩個指令(`W` / `A`)」—— 畫面上是**單一 `E)quip`**,
`W`/`A` 若存在也是在它的子選單裡。已訂正。

⚠ `H)unt`(打獵)與 `I)dentify`(鑑定)是**新的功能**,先前的規格完全沒有。
`R)eorder`(調整隊形順序)直接影響戰鬥的站位([`spec/12`](../spec/12-combat-board.md))。
