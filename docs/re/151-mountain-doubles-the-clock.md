# 151 — 山地讓一步花兩格時鐘(起點或終點其一即可)

日期:2026-08-15
接續:[`149-every-action-costs-one-tick.md`](149-every-action-costs-one-tick.md)
子系統:**F. 世界地圖**
輸入:`GROUPS.DAT`、`WRLDMAP.BIN`、DOSBox 實跑(四條路線 → 存檔 → 比對 `GROUPS.DAT`)

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **一步的時鐘成本 = 2,只要起點或終點是山地(圖塊 7/8/9)**;其餘 1 | **已確認**(四次量測,含一次判別測試)|
| 2 | **山→山 也是 2,不是 3** | 已確認(第四次量測就是為了這個)|
| 3 | 轉身與存檔恆為 1,不受地形影響 | 已確認 |
| 4 | `GROUPS.DAT` 位移 59 隨**時鐘**變,與地形無關 | 證據充分 |

第 1 項是手冊 p.32「在丘陵上行走時間會過得比原來快兩倍」的實際形狀 ——
[`149`](149-every-action-costs-one-tick.md) §4 把它列為「未觀察到」,現在有了。

## 1. 四條路線

全部從出貨存檔的 `(8, 8)` 出發,路線用 [`tools/world_route.py`](../../tools/world_route.py)
的 BFS 算出來,走完按 `S` 存檔,再比對 `GROUPS.DAT` 第 5 筆的**遭遇倒數(位移 25)**
—— 它與時鐘同步遞減([`107`](107-clock-is-four-levels.md) §1),所以
`54 − 剩餘` 就是走了幾格時鐘。

| 路線 | 動作數 | 山地相關的步 | 倒數 | **時鐘格** | 差 |
|---|---:|---|---:|---:|---:|
| **A** 走到 `(41,16)` 停在山上 | 43 | 平→山 ×1 | 10 | **44** | +1 |
| **B** 41 步全平地(對照組)| 44 | 無 | 10 | **44** | **0** |
| **C** 走上山再退回平地 | 45 | 平→山、山→平 | 7 | **47** | +2 |
| **D** 走上山再往山裡走一步 | 44 | 平→山、山→山 | 8 | **46** | +2 |

(動作數 = 前進 + 轉身 + 存檔,依 [`149`](149-every-action-costs-one-tick.md)。)

## 2. 四個候選,量到第四條才分得開

| 候選規則 | A | B | C | D |
|---|:-:|:-:|:-:|:-:|
| 沒有山地效果 | ✗ | ✓ | ✗ | ✗ |
| 「**在**山上移動」才 ×2(看起點)| ✗ | ✓ | ✓ | ✓ |
| 「**走進**山地」才 ×2(看終點)| ✓ | ✓ | ✗ | ✓ |
| **起點或終點其一是山地 → 2** | ✓ | ✓ | ✓ | ✓ |
| 起點與終點**各加一**(山→山 = 3)| ✓ | ✓ | ✓ | ✗ |

**A + B + C 剩兩個候選,兩者只在「山→山」那一格分岔** ——
D 就是為那一格做的:預期 46(其一)或 47(各加一),量到 **46**。

> **判準**:兩個候選在現有量測上全部一致時,**去設計一個它們會給出不同數字的操作**。
> 這裡差別只有一格時鐘,而一格時鐘在畫面上完全看不出來 ——
> 是遭遇倒數這個**逐格可讀的計數器**讓它變得可量。

## 3. 對照組是必要的,不是形式

路線 B 沒有山地、動作數 44、時鐘也是 44 —— 它證明的是
**「一動作一格」在 44 個動作的長度上仍然成立**。
少了它,A 的 44 可以有兩種讀法:「山地多一格」或「這條規則在長路線上會漂」。

⚠ 而且 A 的 `+1` 一度有另一個解釋:**A 的存檔動作發生在山上**,
所以「在山上存檔要兩格」也能解釋 A。C 把它排除了 ——
C 在平地存檔卻仍然 `+2`,而 C 的兩個山地相關步剛好解釋那 `+2`。

## 4. 順帶:位移 59 跟著時鐘走,不跟地形走

四次量測全部在 `Hour 8` 結束,而位移 59(能見度)都從 3 變成 **4**。
四個終點的地形是 **7 / 2 / 2 / 9**(兩次山地、兩次平地)——
**地形不同而值相同,時鐘相同而值相同**。

所以 [`110`](110-display-offset-census.md) §1 把位移 59 退回消去法之後,
這是第一份**正面**證據:它是隨時間變化的量,對得上「能見度」。
⚠ 仍然沒有讀到寫入端,不標已確認。

## 5. ⚠ 遭遇不是只有「倒數歸零」一個觸發條件

[`150`](150-experience-is-offset-90.md) §4 那一場戰鬥發生在一條穿過四格山地的路線上,
畫面在第 44 鍵還是世界地圖、第 48 鍵已經是 `BATTLE!`。
照本篇的規則回推,第 48 鍵時的時鐘是

```
40 步平地 + 4 轉身      = 44
再 4 步,每步山地 ×2    = 52      → 倒數還剩 2
```

**倒數沒有歸零,戰鬥卻發生了。**([`129`](129-world-tile-dispatch.md) §4 讀到
某些地形值會「觸發遭遇檢查」,山地是不是其中之一未確認。)

所以:**倒數(位移 25)是遭遇的必要條件之一,不是唯一條件**。
實作上先照「歸零觸發」做,並在規格裡標出這個缺口 ——
⛔ 不要把「倒數歸零」寫成已確認的完整規則。
