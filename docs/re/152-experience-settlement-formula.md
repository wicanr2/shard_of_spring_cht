## 1. 三段迴圈 + 一次除法

`CMBT.EXE` `0x12C54`–`0x12E9D`。位址與運算元用
[`tools/int_seq.py`](../../tools/int_seq.py) 的位元組層讀法取得
——IDA 在這一段對不齊([`77`](77-runtime-arithmetic-api.md) §3)。

### 1.1 總額:九個怪物槽全部加起來

```
012C54  mov word ptr ds:967Ch, 0
012C5A  xor ax, ax                   ; i = 0
012C60  mov bx, ax
012C62  add ax, 11Dh                 ; 285 = 19 × 15 + 0  →  欄 19、列 i
012C67  shl di, 1
012C69  mov ax, [di+6822h]
012C6D  add ds:967Ch, ax             ; ← 累加
012C71  inc bx / mov ax, bx
012C77  cmp ax, 8
012C7A  jle 012C60                   ; i = 0…8,九個槽
```

列 0–8 就是怪物(隊伍在列 9–13,[`103`](103-flee-is-leaving-the-field.md)),
欄 19 是 `MONSTERS.DAT` 欄 8 搬進來的值([`83`](83-hp-is-attribute-3.md))。

⚠ **迴圈裡沒有任何「這隻死了沒」的判斷。** 九個槽無條件相加 ——
所以**逃走或還活著的怪物也計入經驗**。
屬性 19 全模組只有兩個使用點:`0x18322` 寫(開場從怪物資料搬進來)、
`0x12C69` 讀(這裡)。**沒有人在怪物死掉時清掉它。**

### 1.2 除數:有資格的人數,同樣兩個條件

```
012C7C  cmp word ptr ds:967Eh, 1
012C81  jz 012C86                    ; 否則走 012CDC
012C86  mov word ptr ds:9680h, 0
012C8C  mov ax, ds:34F8h / mov ds:9682h, ax   ; 上界 = 隊伍人數
012C98  … 朝向 > 0(欄 10)…  狀態 < 5(欄 8)… and …
012CC8  inc word ptr ds:9680h        ; ← 兩個條件都成立才 +1
…
012CDC  mov ax, ds:34F8h / mov ds:9680h, ax   ; 旁路:直接用隊伍人數
```

**與 `0x12E20` 寫回迴圈的兩個條件完全相同**([`150`](150-experience-is-offset-90.md) §2.1)——
分母與分子用同一組人,不會出現「有人分到但沒被算進除數」。

⚠ `ds:967E` 這個旗標**未解**;它為 1 時才數人,否則除數直接取隊伍人數
(含陣亡與逃走的)。兩條路的差別只有在「有人陣亡/逃走」時才看得出來。

### 1.3 除法

```
012CE2  mov bx, ds:967Ch / INT 3F:57      ; FAC ← 總額
012CEB  mov bx, ds:9680h / INT 3F:71      ; 除數
012CF5  INT 3F:57
012CFA  INT 3F:8D                          ; 除
012D00  mov bx, 1Ah / INT 3D:03            ; INT() —— 取整
012D08  INT 3F:77                          ; FAC → 整數
012D0F  mov ds:967Ch, ax                   ; ds:967C ← 每人所得
```

```
每人所得 = INT( Σ屬性19 ÷ 有資格人數 )
```

**這正是本引擎原本標成「具名假設」的均分。** 假設猜對了,但在讀出來之前它只是假設。

### 1.4 寫回:`MKS$(CVS(舊值) + 每人所得)`

```
012E52  mov bx, ds:967Ch / INT 3F:57      ; FAC ← 每人所得
012E5F  add cx, 34E0h                      ; 角色記錄字串陣列 + 4×i
012E65  mov dx, 5Ah / mov cx, 4 / INT 3D:0A   ; MID$(rec, 90, 4)
012E72  INT 3F:71
012E78  INT 3D:19                          ; CVS —— 舊經驗
012E7D  INT 3F:85                          ; 加
012E83  mov bx, 1Ah / INT 3D:1C            ; MKS$
012E8D  INT 3F:5C                          ; MID$(rec,90,4) = 那四個 byte
```

位移 90、長度 4 的讀端與寫端在**同一段**,中間只有一次加法 ——
[`150`](150-experience-is-offset-90.md) §1 的欄位定位到這裡閉合。

## 2. 金幣是另一段,吃的是屬性 13

`0x12D80`–`0x12E10` 是**另一個**迴圈,基底 `0C3h` = 195 = 欄 13 =
難度階級([`90`](90-monster-column-9-is-a-tier.md)),中間有 `INT 3D:34`(RND)
與 `ds:9464h`(擲骰偏移,[`136`](136-damage-coefficients-still-unresolved.md) §3),
累加到 `ds:96ACh`。結算畫面同時印 `Experience:` 與 `Gold:`([`95`](95-no-flee-command.md) §3)——
**這一段是金幣**。

⚠ [`150`](150-experience-is-offset-90.md) §2.2 曾把這一段當成經驗的累加迴圈,
因而寫下「累加迴圈讀的是屬性 13 不是屬性 19」。**經驗的迴圈在它前面 350 bytes。**

> **判準**:在一段連續的程式碼裡認出「某個迴圈」時,要先確認**它的輸出寫到哪裡**,
> 再去解釋它讀什麼。我當時從讀端(欄 13)往回推語意,而輸出端 `ds:96AC`
> 與經驗的 `ds:967C` 是兩個不同的變數 —— 看一眼就分得開。

金幣的完整算式**未解**(還有 `ds:96B4`/`96B8`/`93C0`/`9460` 四個變數沒有語意)。

## 3. 三個執行期 API

`BRUN30.EXE` 裡把 [`45`](45-int3d-family.md) §5 標成未解的兩個索引讀出來:

### `3D:34` → `0x1B2C2` = `RND`

```
01B2D6  mov ax, ds:234h / mov cx, ds:22Ch / mul cx
01B2E2  mov ax, ds:236h / mul cx / add bx, ax
01B2E9  mov ax, ds:22Eh / mul word ptr ds:234h / add bx, ax
01B2F2  add di, ds:230h / adc bl, ds:232h        ; 32-bit 乘加
01B2FE  mov ds:234h, dx / mov ds:236h, bx        ; 種子寫回
01B306  mov ax, 8800h / jmp 正規化
```

**線性同餘產生器**:`種子 ← 種子 × 常數 + 常數`,種子在 `ds:234/236`,
常數在 `ds:22C`–`ds:232`。最後套上指數 `0x88` 再正規化成 MBF ——
也就是回傳 `[0,1)` 的浮點數。**信心:已確認**(32-bit 乘加 + 種子寫回,不會是別的東西)。

### `3D:03` → `0x1ACB2` = `INT()`(向下取整)

只碰累加器的指數與符號位元組(`ds:1Ch`/`ds:1Dh`),
指數為 0 就直接返回(值是 0),負數走另一條分支多做一次
`mov byte ptr ds:1Ch, 80h` + `inc byte ptr ds:1Dh` ——
**負數的非整數要再減一**,這是 `INT()` 與 `FIX()` 的差別所在。

⚠ **這推翻 [`77`](77-runtime-arithmetic-api.md) §2 把
「`mov bx, 1Ah` + `INT 3D:03`」讀成亂數。** 兩處都錯:
`0x1A` 是**累加器的位址**(同篇 §1 自己寫著),不是「26」這個範圍;
而 `3D:03` 是取整不是亂數。

> **判準**:一個立即數在同一篇筆記裡有兩種讀法(位址 / 數值)時,
> **以已經定案的那一種為準**。`0x1A = 累加器` 是 §1 讀出來的結論,
> 而 §2 把同一個 `1Ah` 當成十進位 26 寫進表裡 —— 兩節隔了不到一頁。

### `3D:1C` = `MKS$`

用法固定是 `mov bx, 1Ah`(累加器)→ `3D:1C` → `3F:5C`(`MID$` 指派),
而且與 `3D:19`(`CVS`)成對出現在同一個運算式的兩端。**信心:證據充分。**

### 3.1 `INT(RND × N) + 1` 這個成語現在完整了

[`136`](136-damage-coefficients-still-unresolved.md) §3 從「17/17 後面接加法」
推出 `ds:9464h` 是 BASIC `INT(RND × N) + 1` 裡的 `+1`。
三個 API 都認出來之後,那個成語的**每一個零件**都有名字了:

```
INT 3D:34   RND
INT 3F:91   × N
INT 3D:03   INT()
ds:9464h    + 1
```

`136` 的結論不變,但它當時的檢定寫「亂數(`3D:03` **或** `3D:34`)」——
兩者其實是同一個成語的**兩個不同零件**,不是同一件事的兩種寫法。

## 4. 對實作的影響

| 項目 | 先前 | 現在 |
|---|---|---|
| 分配方式 | 具名假設「均分給生還者」 | **讀出來的規則**:`INT(總和 ÷ 有資格人數)` |
| 總額 | 只算**被打倒**的怪物 | **九個槽全部**,不篩死活 |
| 除數 | 生還者人數 | **有資格人數**(朝向 > 0 且 狀態 < 5)|
| 寫入 | 旁掛檔 | `CHARS.DAT` 位移 90–93 |

⚠ 「總額不篩死活」是一個**玩起來看不出來的差別**:多數戰鬥打到怪物全滅才結束,
兩種算法給一樣的數字。**只有怪物逃走的那一場會分岔。**
