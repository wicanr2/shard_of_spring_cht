# 153 — 傷害公式整段讀出來了,含力量加值與狂暴加倍

日期:2026-08-15
接續:[`152-experience-settlement-formula.md`](152-experience-settlement-formula.md)、[`136-damage-coefficients-still-unresolved.md`](136-damage-coefficients-still-unresolved.md)
子系統:**J. 戰鬥規則**
輸入:`CMBT.EXE`、`BRUN30.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **持武器:`傷害 = INT(武器傷害 × RND) − 護甲技能 − 防具值 + INT((力量 − 7) × k₁) + k₂`** | **已確認**(整段逐條讀通)|
| 2 | **`k₁` = 0.5** —— 對上手冊的 `INT((力量 − 7) / 2)`,而第二個使用點把它壓進 `(0,1)`(§6.2)| 證據充分 |
| 3 | **赤手空拳:`INT(力量 × RND) + 1 − 護甲技能 − 防具值`** | 已確認 |
| 4 | **空手道另有一條**:`INT((命中能力 − 5) × RND) + k₂` | 證據充分 |
| 5 | **狂暴(屬性 16)+ 第二次擲骰 > 75 → 傷害加倍**,訊息由 `hits` 變 `hacks` | **已確認** |
| 6 | 擲骰面數 `ds:977Eh` **≥ 76**(否則狂暴永遠不會觸發)| 證據充分 |
| 7 | `ds:9782h` 不是常數,是**每次攻擊擲一次的 `RND` 值** | 已確認 |
| 8 | 防具值:隊員走**背包格號 → `ITEMS` 欄4**、怪物**直接用欄 5 的值** | 已確認 |

第 1、3、7 項推翻 [`spec/01`](../spec/01-combat.md) §5 的
`(武器傷害 × R₁ − 屬性17 − 防具) × k₁ + R₂ + k₂` —— **力量整個漏掉了**,
而 `k₁` 乘的不是整個括號。

## 0. 為什麼現在讀得通

三件事在這一輪之前不成立:

1. [`152`](152-experience-settlement-formula.md) §3 認出 `3D:03` = `INT()`、`3D:34` = `RND`
   —— 先前把 `3D:03` 讀成亂數,於是每個 `INT()` 都被當成一次擲骰。
2. `3F:8F` 的目標從 `BRUN30` 的派工表讀出來是 **`0xB4AB`**,
   落在乘法 `0xB4A0` 的本體內 → **`3F:8F` = 乘(另一序)**,不是除法。
3. [`tools/int_seq.py`](../../tools/int_seq.py) 補上運算元解碼,
   API 呼叫與 `mov` 交錯印出來 —— 只印 API 看不出「加的是什麼」。

> **判準**:一段「工具備齊但還沒做」的工作([`77`](77-runtime-arithmetic-api.md) §2 自己這樣寫著),
> 要先確認工具**真的**齊了。這裡缺的是兩個 API 語意 + 一個運算元解碼器,
> 而缺其中任何一個,整段都會讀成另一個自洽的公式。

## 1. 命中擲骰(`0x136C5`)

```
0136C5  INT 3D:34                    ; RND
0136CA  mov di, 977Eh / INT 3F:91    ; × 面數
0136D2  mov di, 9464h / INT 3F:81    ; + k₂
0136DA  INT 3F:77 → ds:977Ah         ; 擲骰結果
0136FA  cmp ax, ds:9768h / jg 未命中
```

**`擲骰 = INT(RND × 面數) + 1`,大於命中值就落空。**
`INT(RND × N) + 1` 這個成語的四個零件在 [`152`](152-experience-settlement-formula.md) §3.1 都有名字了。

## 2. 第二次擲骰與 `ds:9782`(`0x1371E`)

```
01371E  INT 3D:34                    ; RND
013723  mov di, 9782h / INT 3F:7D    ; ds:9782 ← RND    ★ 存起來
01372D  mov di, 977Eh / INT 3F:8F    ; × 面數(另一序)
013735  mov di, 9464h / INT 3F:81    ; + k₂
01373D  INT 3F:77 → ds:977Ah         ; 第二次擲骰
```

⚠ **`ds:9782` 是那個 `RND` 的原始值(0…1 之間的浮點),不是常數。**
後面每一條傷害算式都拿它當「擲骰的比例」——
所以 `INT(武器傷害 × ds:9782) + 1` 就是 `1…武器傷害` 的擲骰。

⚠ **同一次攻擊只擲一次**,四個分支共用。

## 3. 防具值(`0x1374D`)

```
if 防禦者索引 > 8:                    ; 是隊員
    格號 = A(防, 欄 5)                ; 75 = 5 × 15
    ds:9788 = ITEMS[格號].欄4         ; [di+7684h]
else:                                 ; 怪物
    ds:9788 = A(防, 欄 5)             ; 欄 5 直接就是數值
```

**同一個欄位對隊員是背包格號、對怪物是數值。**
這與 [`74`](74-spell-and-item-columns.md) 的「分類不在資料裡,在呼叫端」
是同一件事的第三個實例。

## 4. 有沒有武器(`0x13780`)

```
013786  add di, 60                   ; 60 = 4 × 15 → 欄 4 = 武器背包格號
01378B  cmp word ptr [di+6822h], 3Ch ; 60
013790  jge → 空手路徑
```

**格號 ≥ 60 視為沒有武器** —— 未裝備的哨兵是 99([`formats/01`](../formats/01-chars-dat.md))。

## 5. 空手路徑(`0x13795`–`0x1387A`)

```
if 攻擊者索引 > 8  且  A(攻, 欄 14) == 1:
    取角色記錄的位移 45                ; 41 + 4 → 技能旗標第 4 格 = 空手道
    if 那一格 == 1:
        傷害 = INT((A(攻, 欄 9) − 5) × RND) + k₂     ; 欄 9 = 命中能力
if 傷害 仍是 −1(沒被設過):
    傷害 = INT(A(攻, 欄 6) × RND)                    ; 欄 6 = 力量
傷害 += 1 − A(防, 欄 17) − ds:9788                   ; 欄 17 = 護甲技能
```

⚠ **空手道那一條走的是「命中能力 − 5」,不是力量** ——
兩條路的量綱完全不同,而**兩者都會產生看起來合理的傷害數字**。

⚠ `A(攻, 欄 14) == 1` 的語意**未解**;它只決定要不要去查空手道旗標。

## 6. 持武器路徑(`0x1387D`–`0x1391B`)

```
武器格號 = A(攻, 欄 4)
武器傷害 = ITEMS[武器格號].欄4
FAC = INT(武器傷害 × RND)
FAC = FAC − A(防, 欄 17)              ; 護甲技能
FAC = FAC − ds:9788                   ; 防具值
FAC = FAC + INT( (A(攻, 欄 6) − 7) × ds:9460 )      ; ★ 力量加值
FAC = FAC + ds:9464                   ; k₂
傷害 = INT(FAC)
```

`0x138E8` 那條 `add bx, -7` 是**直接讀到的** —— 力量先減 7 再乘 `k₁`。

### 6.1 `k₁ = 0.5`

手冊 p.11 的力量加值是 `INT((力量 − 7) / 2)`([`140`](140-manual-stat-tables.md) §2)。
程式算的是 `INT((力量 − 7) × ds:9460h)`。**兩者要相等,`ds:9460h` 只能是 0.5。**

[`136`](136-damage-coefficients-still-unresolved.md) §4 把 `ds:9460h` 列為未解,
因為當時不知道它乘的是什麼 —— **一個未知係數只要知道它乘的是哪一項,
就可以拿獨立來源(手冊)把它定出來**,不必去檔案裡找那四個位元組。

⚠ 信心 **證據充分** 不是已確認:值本身仍然沒有從檔案裡讀出來(§2 的三條路線見 `136`)。
但 `−7` 這個偏移是讀到的,而手冊的公式也是 `−7` ——
**兩個獨立來源在同一個奇怪的常數上吻合**,巧合的機率很低。

### 6.2 第二個使用點:它被當成**機率**用,所以一定小於 1

`0x13EA0`:

```
013EA0  INT 3D:34            ; RND
013EA7  mov di, 9460h
013EAA  INT 3F:A1            ; 浮點比較(設旗標)
013EAF  jb  +3               ; RND < ds:9460 才往下走
013EB6  mov word ptr [di+6822h], 1
```

**`RND < ds:9460h` 是一次擲硬幣。** `RND` 回 `[0, 1)`,所以:

| 若 `k₁` 是 | 那個分支 |
|---|---|
| **1.0**(引擎先前的佔位)| `RND < 1` **恆真** → `jb` 是廢的,分支變成無條件 |
| ≥ 1 的任何值 | 同上 |
| **0.5** | 機率 50% 的硬幣 —— 一個會寫成這樣的東西 |

**所以 `k₁` 一定 < 1,而 1.0 被排除了。** 配上手冊的 `/2`,0.5 是唯一自洽的值。

> **判準**:一個常數被用在**兩種不同的運算**裡時,兩種用法各自給出約束,
> 取交集比只看一種強得多。這裡「當乘數」只說它是個數,
> 「當機率門檻」直接把它壓進 `(0, 1)`。

⚠ 順帶:`3F:A1` = **浮點比較**(後面接條件跳躍),先前未命名。

## 7. 狂暴加倍(`0x13943`)

```
013943  mov di, ds:93A6h / add di, 0F0h   ; 240 = 16 × 15 → 欄 16 = Berserking
01394D  mov bx, [di+6822h]
013951  cmp word ptr ds:977Ah, 4Bh        ; 第二次擲骰 > 75 ?
013959  jle → dx = 0                       ; 否則 dx = −1
01395C  and dx, bx / and dx, dx
013960  jnz → 加倍分支
—— 加倍分支 ——
013965  ds:979C$ = 'HK'                    ; 音效/動畫代碼
01397D  印 'and hacks for '
01398D  add ds:9786h, ax                   ; ★ 傷害 ×2
—— 一般分支 ——
013994  ds:97B8$ = 'HT' / 印 'and hits for '
```

**`hacks`(劈)與 `hits`(擊)是兩種訊息**,而 `hacks` 那一邊傷害加倍 ——
語意與數值互相印證,不是從數字猜的。

### 7.1 這給了擲骰面數一個下界

狂暴的門檻是**同一個擲骰**(`ds:977A`)大於 **75**。
若面數 `ds:977E` < 76,這個分支**永遠不會執行** ——
而狂暴是矮人的種族附贈技能([`140`](140-manual-stat-tables.md) §5),不可能是死碼。

**所以 `ds:977Eh` ≥ 76。** 配上「門檻寫 75」這個形狀,**100 是最自然的候選**,
但 ⛔ 仍然不要當成已知值填進去 —— [`136`](136-damage-coefficients-still-unresolved.md) §7
的警告(面數決定整個命中率的尺度)照舊。

## 8. 傷害 < 1

```
01391E  cmp word ptr ds:9786h, 1
013923  jl → 印 'for no damage.'、ds:977C = 1
```

**傷害小於 1 就是「沒有造成傷害」,不會扣血,也不會變成治療。**
[`spec/01`](../spec/01-combat.md) §5 把「原版是否夾在 0」列為未讀到 —— 讀到了。

## 9. 一個被推翻的常數:`DamageFaces = 26`

引擎裡有一個 `DamageFaces = 26`,出處是 [`77`](77-runtime-arithmetic-api.md) §2
把 `mov bx, 1Ah` 讀成「26 面骰」。`0x1A` 是**累加器的位址**
([`152`](152-experience-settlement-formula.md) §3),**26 這個面數不存在**。

傷害擲骰的「面數」是**武器傷害本身**(或力量、或命中能力 − 5),
每一條分支各不相同。

> **判準**:一個常數如果**只有一個出處**,而那個出處是「某條指令的立即數」,
> 就要回去確認那個立即數是**值**還是**位址**。
> 這個 26 從 `77` 一路活到引擎,中間沒有任何一步會讓它露餡 ——
> 因為 26 面骰算出來的傷害看起來完全正常。
