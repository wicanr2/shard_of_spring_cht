# 154 — 擲骰面數是 100:手冊把命中率寫成百分比,程式的擲骰必須重現它

日期:2026-08-15
接續:[`153-damage-formula-closed.md`](153-damage-formula-closed.md)、[`136-damage-coefficients-still-unresolved.md`](136-damage-coefficients-still-unresolved.md)
子系統:**J. 戰鬥規則**
輸入:`CMBT.EXE`、手冊 p.13 / p.49(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **`ds:977Eh`(擲骰面數)= 100** | 證據充分 |
| 2 | 狂暴的 `> 75` 因此是**四分之一的機率** | 證據充分 |

這關掉 [`136`](136-damage-coefficients-still-unresolved.md) §7 與
[`153`](153-damage-formula-closed.md) §10 的同一個未解項,也關掉
[`spec/07`](../spec/07-combat-scene.md) §3 最後一個標「佔位」的常數。

## 1. 論證只有三行

程式:

```
擲骰 = INT(RND × ds:977Eh) + 1        ; 均勻落在 1…N
命中  ⟺  擲骰 ≤ 命中值                 ; 命中值 = 技巧 × 4 (+30 +12)
```

所以命中的機率是 `命中值 ÷ N`。

手冊 p.13 / p.49 那張表的標題是 **`% CHANCE TO HIT BY SKILL`**,
內容是 `SKILL 3 → 12`、`SKILL 20 → 80` —— 也就是命中機率 = `技巧 × 4` **%**。

```
命中值 ÷ N  =  命中值 %  =  命中值 ÷ 100
⟹  N = 100
```

**表裡的數字既是命中值也是百分比,兩者相等只在 N = 100 時成立。**

⚠ 這是 [`153`](153-damage-formula-closed.md) §6.1 定 `k₁` 的同一種手法:
**程式給出算式的形狀,手冊給出那個量的單位,兩者一起把常數釘死。**
單看程式,`N` 可以是任何數;單看手冊,不知道它是不是擲骰決定的。

## 2. 兩個獨立的一致性檢查

| 檢查 | 結果 |
|---|---|
| [`153`](153-damage-formula-closed.md) §7.1 的下界:狂暴門檻是 75,`N < 76` 會讓那段變死碼 | **100 ≥ 76** ✅ |
| 狂暴的機率 `(100 − 75) ÷ 100` | **25%** —— 一個會被寫成 `> 75` 的整齊數字 ✅ |

⚠ 第二項是**形狀論證**不是證明:`> 75` 在 N = 100 下是四分之一,
而設計者寫門檻時多半想的是「四分之一」。若 N 是別的值,`75` 這個數字會很怪。

## 3. 為什麼先前卡著

[`136`](136-damage-coefficients-still-unresolved.md) §7 把這一項標成未解,
理由正確(⛔ 不要隨手填 100,面數決定整個命中率的尺度)。
卡住的原因是**去錯地方找**:三條路線都在找「這個變數的初值在檔案的哪個位移」,
而 [`42`](42-module-ds-and-the-66dc-boundary.md) §3 早就寫著**模組的變數大半不在檔案裡**。

本輪也再試了一次資料側:拿預測樣式 `00 00 00 80 00 00 00 81`
(MBF 0.5 接 MBF 1.0)掃 `CMBT.EXE` 全檔 —— **零命中**,與 `42` §3 一致。

> **判準**:一個常數解不出來時,先問「**它的值有沒有別的觀測後果**」。
> 面數的觀測後果就是命中率的尺度,而那個尺度手冊直接印出來了。
> 去檔案裡挖那四個位元組是「找定義」,讀手冊的百分比表是「找後果」——
> **後果常常比定義容易拿到**,而且拿到的是同一個答案。

## 4. 對實作的影響

`ToHitFaces = 100` 從**佔位**變成**有出處的值**。
[`combat.Unresolved`](../../engine/internal/combat/combat.go) 因此清空
—— 戰鬥規則裡不再有需要在執行時警告玩家的未解常數。

⚠ 但**魔法道具發動的分母仍然未解**:
[`spec/09`](../spec/09-magic-items.md) §5 的那一條原始碼還沒讀到,
引擎借用 `ToHitFaces` 是「有理由的選擇」,不是讀出來的規則。
借用的理由現在更強了(那是原版唯一的一顆骰),但性質沒變。
