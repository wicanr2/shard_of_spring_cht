# 157 — 魔法道具的成功率是百分比,不是 26 分之幾

日期:2026-08-15

輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **`ITEMS.DAT` 欄6 是百分比**(分母 100):`擲骰(100) ≤ 欄6` | **已確認** |
| 1b | ⚠ **那一支做的事是「道具損壞」,不是「發動」** —— 本篇原本的標籤錯了,見 [`190`](190-items-col6-is-break-chance.md) | **已確認** |
| 2 | 這一條的原始碼在 `CMBT.EXE` `0x17C67` —— [`spec/09`](../spec/09-magic-items.md) §5 標的「未讀到」關掉 | 已確認 |

第 1 項推翻 [`91`](91-e-closure.md) 的「分母是 26」與它算出來的機率。

## 1. 整段

```
017C5F  cmp dx, 1Ah                ; 物品編號 > 26 才走這條路
017C64  jmp 017CBA                 ;   否則跳過
017C67  INT 3D:34                  ; RND
017C6C  mov di, 977Eh / INT 3F:91  ; × 面數 = 100([`154`](154-die-is-d100.md))
017C74  mov di, 9464h / INT 3F:81  ; + 1
017C7C  mov bx, 1Ah / INT 3D:03    ; INT()
017C84  INT 3F:77 → ds:9E5Ah       ; 擲骰 1…100
017C92  mov bx, [di+7780h]         ; ITEMS 欄6
017C96  inc bx                     ; 欄6 + 1
017C97  cmp ax, bx / jl → 成立      ; 擲骰 < 欄6 + 1  ⟺  擲骰 ≤ 欄6
```

**`擲骰(100) ≤ 欄6`,所以欄6 直接就是百分比。**

⚠ **但這一支設的是旗標 `ds:930C`,不是「發動」** —— 它的消費端
(`0x11F4D`)印的是 `Item Breaks !`。分母讀對了、語意讀錯了,
訂正見 [`190`](190-items-col6-is-break-chance.md)。

⚠ `cmp dx, 1Ah` 這個 26 是**真的** —— 它是物品編號的門檻
(`MagicItemMin`)。同一段裡另一個 `mov bx, 1Ah` 是**累加器的位址**
([`152`](152-experience-settlement-formula.md) §3)。
**兩個 26 在相鄰的二十個位元組裡,意思完全不同。**

## 2. [`91`](91-e-closure.md) 的機率表要改

| 欄6 | `91` 寫的(分母 26)| 實際(分母 100)|
|---:|---|---|
| 100 | 必定成立 | 必定成立 ✅ 不變 |
| 0 | 永不成立 | 永不成立 ✅ 不變 |
| **7–15** | **約 27%–58%** | **7%–15%** |

⚠ **兩個端點都對,中間全錯。** `91` 當時是拿端點檢查那個分母的
—— 而 `100` 與 `0` 在**任何** ≤ 100 的分母下都會給出同樣的結論。

> **判準**:拿「飽和的兩端」去驗一個尺度參數,驗不出東西。
> 要驗尺度就得挑**中段**的樣本 —— 而中段正是 `91` 沒有獨立來源可對照的部分。

戒指與法杖的實際成功率因此**低得多**:`7` 是七次裡不到一次,不是四次裡一次。

## 3. 對實作的影響

[`spec/09`](../spec/09-magic-items.md) §5 先前寫「分母未解,引擎借用 `ToHitFaces`,
是有理由的選擇不是讀出來的規則」—— **現在讀出來了,而且借對了**。

⚠ 借對不等於當時有依據。那一輪的依據是「那是原版唯一的一顆骰」,
**這一輪才變成證據**。兩者的差別在於:前者若錯了,不會有任何症狀。
