## 1. 屬性 18 的生命週期

### 開場:清成 0

```
018316  mov word ptr [di+6822h], 0     ; di = 單位 + 0x10E(= 18 × 15)
```

### 第一次用:擲硬幣

`0x13E8E`:

```
013E8E  add bx, 10Eh                   ; 欄 18
013E96  cmp word ptr [di+6822h], 0
013E9B  jz  013EA0                     ; **只有還是 0 才決定**
013E9D  jmp 013ECF                     ;   已經有值就跳過
013EA0  INT 3D:34                      ; RND
013EA7  mov di, 9460h / INT 3F:A1      ; 與 k₁(= 0.5)比大小
013EAF  jb  013EB4
013EB4  mov word ptr [di+6822h], 1     ; RND < 0.5 → +1
013EBC  jmp 013ECF
013EC9  mov word ptr [di+6822h], FFFFh ; 否則 → −1
```

**這是 `ds:9460h` 被當成機率門檻的那個使用點**
([`153`](153-damage-formula-closed.md) §6.2)—— 也就是把 `k₁` 壓進 `(0,1)` 的證據。
兩者互相印證:一個 50% 的硬幣,配一個等於 0.5 的常數。

⚠ **`cmp … , 0` 那個閘門很重要**:值一旦定了就不再重擲,
所以同一個單位在整場戰鬥裡的偏好是**穩定**的,不是每步隨機。

### 用到的時候:選對稱的兩條分支

`0x13F3A`:

```
013F3A  cmp word ptr [di+6822h], 1     ; 屬性 18 == 1 ?
013F3F  jz  013F44                     ;   → 一條
013F41  jmp 013FD1                     ;   → 另一條
013F44  mov bx, [di+6822h]             ; di 沒加欄偏移 → **欄 0** = 戰場座標
013F52  cmp bx, [si+6822h]             ; 與另一個單位的同一欄比
013F56  jl  …
```

兩條分支的形狀對稱,差別在**先比哪一個座標軸** ——
所以 `±1` 是「移動時先試橫的還是先試直的」這一類的偏好。

⚠ 第 3 項標**證據充分**不是已確認:兩條分支的**內容**沒有逐條讀完,
只讀到「由 ±1 二選一」與「其中一條先比欄 0」。

### 反向

`0x140D6` / `0x1476C`(四支形狀相同的常式各一處):

```
0140C8  cmp word ptr [di+6AD4h], 21h   ; 某個陣列 < 33 ?
0140CD  jl  0140D2
0140D6  add di, 10Eh
0140DC  mov bx, [di+6822h]
0140E0  neg bx
0140E2  mov [di+6822h], bx             ; 屬性 18 ← −屬性 18
```

**遇到條件就反向。** 這正是「繞不過去就換一邊」的形狀。

## 2. 對 [`spec/12`](../spec/12-combat-board.md) §5 的意義

那一節寫「原版的 AI 未解,本引擎用可預測的佔位」。本篇沒有把 AI 解出來,
但確定了**它帶著一個每單位一份、開場擲硬幣、遇阻反向的側向偏好**。

⚠ **不要據此就去實作。** 知道「有一個 ±1 偏好」與知道「它怎麼影響選格」
是兩件事,而後者要把 `0x13F44`–`0x14070` 那一整段讀完。
⛔ 半解的 AI 比明講的佔位更糟 —— 佔位至少是可預測的。

## 3. 屬性 14:只知道兩件事

| 位址 | 動作 |
|---|---|
| `0x182A6` | 開場:由一段浮點運算的結果寫入(`INT 3F:81` → `3F:77` → `mov [di+6822h], bx`)|
| `0x137A0` | 傷害的空手路徑:`== 1` 才去查角色記錄的空手道旗標([`153`](153-damage-formula-closed.md) §5)|
| `0x118E0` / `0x1194C` / `0x11CA3` / `0x15540` | 另外四處讀寫,未讀 |

**「開場算出來的、而且用來分辨要不要查角色記錄」** 這兩點合起來,
最像「這個單位是不是隊員」的旗標 —— 但那是**推測**,
而 [`86`](86-scanner-fixed-conclusion-restored.md) 的教訓正是「別從一兩個使用點替屬性命名」。
**不命名。**
