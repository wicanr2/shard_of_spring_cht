# 159 — 先攻**每回合**重排:否則 `cmp ds:9314h, 2` 是死碼

日期:2026-08-15
接續:[`93-initiative.md`](93-initiative.md)
子系統:**J. 戰鬥規則**
輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **順序表每回合重建並重排** | 證據充分 |
| 2 | `ds:9314h` 是**回合計數器**,在排序之後 `inc` | 證據充分 |

[`93`](93-initiative.md) §3 把「這個排序每回合是否重跑」列為沒查
——[`spec/01`](../spec/01-combat.md) §2 據此標「未確認」,而引擎的
`ReorderEachRound = true` 是**實作決定**。現在它有依據了。

## 1. 排序前後的控制流

```
011E2E  mov word ptr ds:9312h, 0
011E34  xor ax, ax
011E3A  mov [di+6A7Ah], ax          ; ★ 順序表[i] = i —— **每次都重建**
011E43  ds:9378 = ax / cmp ax, 0Dh / jle 011E3A
011E4B  xor ax, ax / jmp 011EA4
011E50  ── 兩層迴圈的排序([`93`](93-initiative.md) §1)──
011EAA  jle 011E50
011EAC  inc word ptr ds:9314h       ; ★ 計數器 +1,**緊接在排序之後**
011EB0  mov word ptr ds:9352h, FFFFh
011EB6  ds:94D6 = ds:34F8 + 8       ; 隊伍人數 + 8 → 單位索引上界
011EBF  ax = 9 → 進入逐單位行動的迴圈
```

**順序表在排序之前被重新填成 `0,1,2,…,13`。**
若整場只排一次,這個重建是多餘的 —— 它存在本身就暗示會再來一次。

## 2. 決定性的論證:`cmp ds:9314h, 2`

`ds:9314h` 全模組只有一處寫(`0x11EAC` 的 `inc`),四處讀:

| 位址 | 比較 |
|---|---|
| `0x1249F` | `cmp ds:9314h, 2` |
| `0x14BA3` / `0x15563` / `0x156DE` | `cmp ds:9314h, 1` |

**若那一段整場只執行一次,`ds:9314h` 永遠是 1,`cmp …, 2` 就是死碼。**
一個模組不會為了一個永遠不成立的條件放四個位址的判斷,
所以那一段**每回合都會再執行**,而排序就在它裡面。

> **判準**:要判斷「某段程式跑幾次」,去看**依賴它的計數器被拿去比什麼**。
> 比較的常數越大,那段就至少跑過那麼多次 ——
> 這與 [`153`](153-damage-formula-closed.md) §7.1 用狂暴門檻 75 推出擲骰面數 ≥ 76
> 是同一種論證:**一個分支若永遠不成立,它就不該存在**。

⚠ 信心 **證據充分** 不是已確認:沒有找到「回合結束跳回 `0x11E2E`」的那條後向跳躍
(那段控制流可能走 BASIC 的 `GOSUB`/`RETURN`,不是 `jmp`)。
論證靠的是「死碼不該存在」,不是直接讀到迴圈。

## 3. 對實作的意義

`combat.ReorderEachRound = true` 從**實作決定**變成**有依據的選擇**。
理由也對得上:速度會被法術改動,不重排會讓那些法術沒有效果。

⚠ 順序表**重建**這件事同樣要照做:原版是「填 0…13 再排」,
不是「拿上一回合的順序再排一次」。**穩定排序下兩者結果不同** ——
上一回合的順序會當成同速時的次序,而原版沒有那個記憶。
