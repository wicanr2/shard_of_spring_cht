# 160 — 初始佈陣:隊伍每列三個,由 `(i−1) mod 3` 與 `(i−1) ÷ 3` 算出來

輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))、DOSBox 實跑截圖

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **佈陣是每列三個**:欄偏移 = `(i−1) mod 3 − 1`、列偏移 = `INT((i−1) ÷ 3)` | **已確認**(算式 + 實跑畫面)|

這關掉 [`spec/12`](../spec/12-combat-board.md) §1 的「初始佈陣是佔位」。

## 1. 程式碼

`CMBT.EXE` `0x11773`–`0x117CF`:

```
011773  mov word ptr ds:94BCh, 9        ; 隊伍從單位索引 9 起(docs/re/103)
011779  mov ax, 1                       ; i = 1
011780  mov bx, ax
011782  dec ax                          ; ax = i − 1
011783  mov cx, 3
011786  mov [bp-8], ax                  ; 留著 i − 1
011789  cwd / idiv cx                   ; ax = (i−1) ÷ 3、dx = (i−1) mod 3
01178C  dec dx                          ; dx = (i−1) mod 3 − 1   → −1 / 0 / 1
01178D  mov di, bx / shl di, 1
011791  mov [di+7978h], dx              ; ★ 欄偏移表
011797  mov bx, [bp-8]                  ; i − 1
01179A  INT 3F:57                       ; FAC ← i − 1
0117A1  mov di, 94BEh / INT 3F:89       ; ÷ ds:94BE
0117AB  mov bx, 1Ah / INT 3D:03         ; INT()
0117B3  mov di, 94C2h / INT 3F:81       ; + ds:94C2
0117BB  INT 3F:77
0117C2  mov [di+7962h], bx              ; ★ 列偏移表
0117CC  cmp ax, 9 / jle 011780          ; i = 1…9
```

**`idiv cx` 的 `cx = 3` 是直接讀到的** —— 那個 3 不是猜的。

### 1.1 `ds:94BE` = 3

列偏移那一半走浮點:`INT((i−1) ÷ ds:94BE) + ds:94C2`。
**同一個運算式的另一半剛剛用整數除法除以 3**,兩者要對得起來,
`ds:94BE` 只能是 **3** —— 否則欄與列會取自不同的分組,佈陣會散開。

⚠ `ds:94C2`(列的基準)仍未解,它只是把整塊陣型上下平移。

## 2. 實跑印證

[`150`](150-experience-is-offset-90.md) §4 那張戰鬥截圖上,五名隊員排成
**上排三個、下排兩個**:

```
[1][2][3]
   [4][5]
```

`(i−1) mod 3 − 1` 給 `−1, 0, 1, −1, 0`、`INT((i−1)/3)` 給 `0, 0, 0, 1, 1`
—— **與畫面逐格吻合**。

⚠ 下排是「靠左兩個」而不是置中,這也對得上:第 4、5 個的欄偏移是 −1 與 0。

## 3. 九個槽,不是五個

迴圈上界是 **9**,而隊伍只有五人。多算的四個位置不會有人站 ——
**但它說明這張表是「位置」不是「某某人在哪」**,兩者的差別在於
隊伍人數變動時位置不重算。

## 4. `3F:89` = 除(另一個進入點)

派工表([`tools/brun_api.py`](../../tools/brun_api.py))給 `0xB520`,
而除法的主進入點是 `0xB525` —— 相距 5 個位元組,落在同一支常式裡。
這是本專案第三次遇到「同一個運算有多個進入點」(`3F:8F` / `3F:95` 是乘)。
