# 163 — 戰鬥屬性 14 是**行動類型**:隊員由職業決定,怪物用擲骰

日期:2026-08-15
接續:[`158-attribute-18-is-a-coin-flipped-preference.md`](158-attribute-18-is-a-coin-flipped-preference.md)、[`153-damage-formula-closed.md`](153-damage-formula-closed.md)
子系統:**J. 戰鬥規則**
輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | **屬性 14 = 行動類型**,隊員由 `CHARS.DAT` **位移 15 的職業字元**決定:戰士 → **1**、巫師 → **2** | **已確認** |
| 2 | 怪物的屬性 14 是**擲出來的**:`INT(RND × ds:94B8) + 1` | **已確認** |
| 3 | 值域**不只 1 / 2** —— 行動選擇那一段分別比 **1、3、4** | **已確認** |
| 4 | 同一個分支還把**屬性 11(圖組)**設成 **41**(戰士)/ **57**(巫師) | **已確認** |
| 5 | 全模組對欄 14 只有**六個存取點**,六個都讀完了 | **已確認**(掃描分母見 §4)|

[`158`](158-attribute-18-is-a-coin-flipped-preference.md) §3 明列的那一項。

## 1. 定義端:隊員照職業分兩支

`CMBT.EXE` `0x118BD`–`0x11967`:

```
0118BD  bx = 94C8h                  ; 角色記錄字串
0118C0  dx = 15 / cx = 1
0118C6  INT 3D:0A  MID$             ; ★ MID$(記錄, 15, 1) = 職業那一個字元
0118CD  bx = 94CCh
0118D0  INT 3F:62  字串比較
0118D5  jz  0118DA                  ; 相等 → 分支 A
0118D7  jmp 011946                  ; 否則 → 分支 B

; ── 分支 A ──
0118DA  di = ds:94BCh               ; 單位索引
0118E0  di += 00D2h                 ; 210 = 欄 14 × 15
0118E6  mov [di+6822h], cx          ; ★ 屬性 14 ← cx
0118EC  bx += 00A5h                 ; 165 = 欄 11 × 15
0118F4  mov word ptr [di+6822h], 41 ; 屬性 11(圖組)= 41

; ── 分支 B ──
011946  di = ds:94BCh
01194C  di += 00D2h
011952  mov word ptr [di+6822h], 2  ; ★ 屬性 14 ← 2
01195A  bx += 00A5h
011962  mov word ptr [di+6822h], 57 ; 屬性 11(圖組)= 57
```

`CHARS.DAT` 位移 15 是職業字元 `'1'` = 戰士 / `'2'` = 巫師
([`formats/01`](../formats/01-chars-dat.md))。

### 1.1 分支 A 寫的 `cx` 是 1 —— 而且這不是循環論證

`cx` 在 `0x118C3` 被設成 `1`(`MID$` 的長度引數),之後沒有再被明確設定。
但「呼叫過兩支執行期 API 之後 `cx` 還是 1」不能只靠這個講。

> ✅ **比較的對象後來直接讀到了**:`ds:94CC` → `'1'`
> ([`165`](165-dgroup-string-map.md) §4)。下面那段論證因此是多的 ——
> **但它先於證據成立,而且結論一致**,所以留著:它用的判準
> (「看不相等那一支寫了什麼字面值」)下次還會用到。

**決定性的是分支 B 寫的那個字面值 2**:比較的對象若是 `'2'`,
那不相等的那一支(= 戰士)就該寫 1 而不是 2。**寫 2 的是不相等那一支**,
所以比較的對象是 `'1'`,相等那一支就是戰士 —— 而戰士要對得上
[`153`](153-damage-formula-closed.md) §5 的 `屬性14 == 1` 空手道閘門
(空手道是戰士的技能),所以分支 A 寫的必須是 **1**。

## 2. 怪物端:擲骰

`0x1827F`–`0x182AF`:

```
01827F  INT 3D:34  RND
018284  di = 94B8h / INT 3F:91 乘   ; × ds:94B8
01828C  bx = 1Ah   / INT 3D:03      ; INT()
018294  di = 9464h / INT 3F:81 加   ; + 1(docs/re/152 §3 的 +1)
01829C  INT 3F:77                   ; → 整數
0182A6  di += 00D2h → [di+6822h] = bx   ; ★ 屬性 14
```

`INT(RND × ds:94B8) + 1` —— 全遊戲通用的擲骰成語。
⚠ **`ds:94B8` 未解**(執行期變數,不在檔案映像裡)。由 §3 可知它 **≥ 4**。

⚠ `mov bx, 1Ah` 的 `0x1A` 是**浮點累加器的位址**,不是 26 面骰
([`152`](152-experience-settlement-formula.md) §3)。

## 3. 使用端:行動選擇

`0x15534`(每個單位輪到時):

```
015534  di = ds:9352h               ; 目前的行動順序索引
01553A  di = [di+6A7Ah]             ; 順序表 → 單位索引(docs/re/159 §1)
015540  di += 00D2h → ax = [di+6822h]
01554A  ds:9B0A ← ax                ; ★ 屬性 14
015553  bx += 105                   ; 105 = 欄 7 × 15
01555C  ds:9B0E ← [di+6822h]        ; 屬性 7(法力)
015563  cmp ds:9314h, 1             ; 回合計數器 > 1 ?
```

**屬性 14 與法力一起被讀進來**,而接下來的兩段都拿它分派:

| 條件 | 動作 |
|---|---|
| 第二回合起(`ds:9314 > 1`)| `ds:9B10`(= 屬性 14)比 **1** → `ds:98D8 ← 3`;比 **3** → `← 8`;比 **4** → `← 12` |
| 第一回合 | `ds:9B12`(= 屬性 14)比 **1** → 走擲骰那一支 |

**這是「值域至少 1–4」的證據** —— 若只有 1 / 2,比 3 與比 4 的兩個分支是死碼
(同一種論證見 [`159`](159-initiative-resorts-every-round.md) §2)。

⚠ `ds:98D8` 的 3 / 8 / 12 是什麼**未解**。量級像行動點數或攻擊次數,
但**沒有讀到它之後被誰用**,不要當成已知。

## 4. 掃描分母:欄 14 全模組只有六處

掃 `add reg, 0D2h` 且 24 bytes 內出現 `[…+6822h]`(欄 14 的基底 = 14 × 15 = 210):

| 位址 | 動作 |
|---|---|
| `0x118E0` | 寫 1(隊員,戰士)|
| `0x1194C` | 寫 2(隊員,巫師)|
| `0x11CA3` | 寫(隊員設定迴圈的收尾,`inc ds:94BC` 換下一個)|
| `0x137A0` | 讀 —— 空手傷害的 `== 1` 閘門([`153`](153-damage-formula-closed.md) §5)|
| `0x15540` | 讀 —— 行動選擇(§3)|
| `0x182A6` | 寫 —— 怪物擲骰(§2)|

**六處全部讀過**,與 [`158`](158-attribute-18-is-a-coin-flipped-preference.md) §3
列的四個未讀位址一一對應。

## 5. 為什麼這一次可以命名

[`86`](86-scanner-fixed-conclusion-restored.md) 的教訓是「別從一兩個使用點替屬性命名」,
而 [`158`](158-attribute-18-is-a-coin-flipped-preference.md) §3 據此**拒絕命名**屬性 14。
這一輪改變的是證據種類:

- 讀到的是**定義端**(值從哪來),不是使用端;
- 隊員那一支直接引用了**已經定案的欄位**(`CHARS.DAT` 位移 15 = 職業);
- 有**完整的掃描分母**(六處,§4),不是抽樣。
