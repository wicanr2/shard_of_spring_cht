## 1. 寬度 31

`mov dx, 1Fh` 在全模組只有三處,三處都緊接著 `imul`:

| 位址 | 算式 |
|---|---|
| `0x116B9` | `列 × 31 + 欄` → 查 `ds:6AD4`(怪物找空格,§3)|
| `0x173CE` | `列 × 31 + ds:9346 − 129` |
| `0x17590` | `列 × 31 + ds:9346 − 119` |

`0x116C7` 直接把算出來的索引拿去查 `ds:6AD4`:

```
0116B7  mov ds:93A2h, ax        ; 隨機的列
0116BA  mov dx, 1Fh             ; ★ 31
0116BD  mov cx, ax
0116BF  imul dx                 ; 列 × 31
0116C1  add ax, bx              ; + 欄
0116C5  shl di, 1
0116C7  mov dx, [di+6AD4h]      ; ★ 格值
0116CB  cmp dx, ds:92F6h        ; 與「空格」的值比
0116CF  jz  …                   ; 不相等 → 重擲
```

## 2. 隊伍的基準是 13,不是「置中偏下」

`0x1188C`–`0x118AF`:

```
01188C  mov bx, [di+7978h]      ; 欄偏移表(docs/re/160 §1)
011890  add bx, 0Dh             ; ★ + 13
011893  mov si, ds:94BCh        ; 單位索引
01189B  mov [si+6822h], bx      ; 欄 0(戰場 x)
01189F  mov bx, [di+7962h]      ; 列偏移表
0118A3  add bx, 0Dh             ; ★ + 13
0118A6  add dx, 0Fh             ; 15 = 欄 1 × 15
0118AF  mov [di+6822h], bx      ; 欄 1(戰場 y)
```

配上 [`160`](160-party-deploys-three-per-row.md) 的偏移(`−1 / 0 / 1` 與 `0 / 1`),
五個人落在 **x ∈ {12, 13, 14}、y ∈ {13, 14}**。

這關掉 [`160`](160-party-deploys-three-per-row.md) §5 的「`ds:94C2`(列的基準)未解」
—— **兩軸共用同一個字面值 13**,而 `ds:94C2` 只是列偏移在浮點那一段的加項,
最後仍然要再 `+13`。

## 3. 怪物:擲座標 → 檢查空格 → 不合就重擲

`0x11660`–`0x116CF`(見 §1 的片段)產生一組隨機 `(ds:93A0, ds:93A2)`,
查格值,不是空格就回去重擲。擺放本身在 `0x18139`:

```
018139  mov bx, ds:93A0h
01813D  mov [di+6822h], bx      ; 欄 0 ← 隨機欄
018143  add cx, 0Fh
01814A  mov dx, ds:93A2h
01814E  mov [di+6822h], dx      ; 欄 1 ← 隨機列
```

**所以怪物沒有陣型** —— 是一隻一隻找空格丟進去的。
[`spec/12`](../spec/12-combat-board.md) §1 的「怪物佈陣是佔位」因此可以改寫成規則,
但**兩個擲骰範圍是執行期變數,未解**(§5)。

## 4. 與手冊的 15×15 怎麼並存

手冊 p.33:「(隊伍的)位置會被放大成 **15×15 格的戰鬥畫面**,戰場是由許多圓點所圍成」。

**那一句講的是畫面,不是陣列。** 兩者可以並存:內部座標系寬 31,
畫面顯示其中一個 15×15 的視窗。支持這個讀法的還有:

- 隊伍在 x ∈ {12,13,14};若整個戰場只有 15 寬,隊伍會貼在**右下角**,
  而 [`160`](160-party-deploys-three-per-row.md) §2 的原版截圖是**下方置中**;
- 通行判定不比任何座標上下界(§5),完全靠格值 —— 這是「大陣列 + 用格值圍出實際場地」的形狀。

⚠ **這仍然是解釋,不是讀出來的。** 沒有讀到「畫面視窗有多大」「視窗怎麼跟著誰捲動」。

## 5. 通行判定沒有界限常數

掃全模組的 `cmp reg, imm`(8 位元與 16 位元兩種編碼)找 14 / 15 / 30 / 31 / 32,
**零命中**。而 [`158`](158-attribute-18-is-a-coin-flipped-preference.md) §1 讀到的是:

```
0140C8  cmp word ptr [di+6AD4h], 21h   ; 格值 < 33 ?
0140CD  jl  0140D2                     ;   → 可以走
0140E2  否則 → 屬性 18 取負(換一邊繞)
```

**能不能走由格值決定**(< 33),不是由座標範圍決定。
所以「戰場多大」這個問題在原版裡是**由格陣列的內容回答的**,
而那份內容是執行期建的,靜態讀不到([`42`](42-module-ds-and-the-66dc-boundary.md) §3)。
