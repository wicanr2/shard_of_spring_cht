## 1. 為什麼這件事值得做一支工具

[`42`](42-module-ds-and-the-66dc-boundary.md) §3 的結論擋住了一整類問題:
模組的變數大半是執行期配置的,`mov ax, 3798h` 這種運算元在檔案裡查不到內容。
那條結論**仍然成立** —— 但它有一個例外:

> **字串常數有初始值,而且初始值連同 DGROUP 位址一起寫在檔案裡。**

沿著記錄串走一遍就得到一張 **DGROUP 位址 → 文字**的表:

| 模組 | 取出的段數 |
|---|---:|
| `MENU` | 149 |
| `CMBT` | 193 |
| `CAMP` | 152 |
| `TOWN` | 101 |
| `MAZEMOVE` | 92 |
| `CHARUTIL` | 71 |
| `WRLDMOVE` | 46 |
| `START` | 3 |
| **`USERLIB`** | **0** |

`USERLIB` 的 0 是**正對照**:它是原生組語寫的([`63`](63-userlib-strings-and-l-correction.md)),
字串不走 BASIC 的記錄格式。工具在那裡回 0 是對的,不是壞了。

⚠ **這是樣式比對,不是解析器**:條件是「位址出現兩次 + 間距 = 長度湊偶數再 +4」。
沒有校驗碼,所以取出來的東西要用肉眼確認像不像字串;
**找不到某一段不代表它不存在**,只代表它不符合這個樣式。

⚠ 程式碼拿到的是**描述子位址 = 文字位址 − 4** —— 反組譯裡的 `mov bx, 8E7Ch`
要查的是 `ds:8E80`。工具兩種都印。

## 2. `ds:3798` = 模組代號

`MAZEMOVE` 對 `ds:3798` 只有七個存取點,四寫三讀:

| 位址 | 動作 | 對象 |
|---|---|---|
| `0x116CA` / `0x11926` / `0x1195C` / `0x122F1` | 寫(`INT 3F:61`)| `ds:8ECC` → **`"MAZE"`** |
| `0x113C8` | 比較 | `ds:8E94` → **`"DEAD"`** |
| `0x1144C` | 比較 | `ds:8EBC` → **`"WRLD"`** |
| `0x11573` | 比較 | `ds:8E7C` → **`"CMBT"`** |

三個比較都在模組開頭(`0x113C8`–`0x11573`),形狀是**「我是從哪裡回來的」**。
四個寫入都填 `"MAZE"` —— 也就是「離開這裡時,下一個回來的人會知道是誰送它走的」。

## 3. 因此:事件作廢只發生在**打完仗之後**

[`161`](161-maze-event-dispatch.md) §1 的作廢迴圈前面有兩個條件:

```
條件 A  事件目標 > 0
條件 B  字串比較(ds:8E7C, ds:3798)   ← 本篇解出:ds:3798 == "CMBT"
```

**條件 B = 「剛從戰鬥模組回來」。** 所以規則是:

> 打完一場由事件引發的戰鬥、回到迷宮時,**把所有目標相同的事件列作廢**
> (座標欄覆寫成 99);其餘情況一律不作廢。

這解釋得通:固定遭遇([`161`](161-maze-event-dispatch.md) §4 的 204 / 533)
打完就不該再打一次,而房間敘述不引發戰鬥,也就不會被作廢 —— **可以重複看**。

⚠ 「其餘情況一律不作廢」是從**這一個閘門**推的。
沒有掃過「別處有沒有第二個作廢入口」,所以第 3 項講的是**這條路徑**,
不是「全遊戲只有這一種作廢」。

## 4. `ds:94CC = '1'`:一個推論變成直接證據

[`163`](163-attribute-14-is-action-type.md) §1.1 用「分支 B 寫的字面值 2」
論證出比較對象是 `'1'`。工具直接印出:

```
ds:94D0(描述子 ds:94CC)  '1'
```

**推論與讀到的一致。** 這種事要記下來 —— 一個論證被獨立證據對上,
它用的判準(「看不相等那一支寫了什麼」)下次可以再用。
