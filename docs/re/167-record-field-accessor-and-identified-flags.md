## 1. 「操作碼」是位移

[`161`](161-maze-event-dispatch.md) §5 讀到 `ds:66C8`/`66CA`/`66CC`/`66D0`
成對出現,把第二個叫「操作碼」。它是**記錄裡的 1-based 位移**:

```
011085  bx = 71E6h(角色記錄) / dx = 66CCh / INT 3F:61   ; 引數一:記錄
01108E  ax = 2i + 54                                     ; 位移 54 + 2i = 背包第 i 格
011093  mov ds:66D0h, ax                                 ; 引數二:位移
011096  call                                             ; → ax = 該欄位的值
011099  mov ds:352Ch, ax                                 ; 道具編號
```

**買東西那一段直接把 `54 + 2i` 算出來當第二個引數**([`TOWN`](00-inputs.md) `0x10888`),
而 `54 + 2i` 正是背包格的位移([`formats/01`](../formats/01-chars-dat.md))——
所以那個欄位不是操作碼,是位移。

回頭核對先前記下的值,全部對得上:

| 值 | 記錄 | 對應欄位 |
|---:|---|---|
| 12 | `CHARS.DAT` | 角色編號 |
| 20 | `CHARS.DAT` | 智力(§4)|
| 38 | `CHARS.DAT` | **狀態** —— 解釋了 `> 1` → `incapacitated`([`166`](166-camp-hunt-identify-print.md) §7)|
| 54 + 2i | `CHARS.DAT` | 背包第 i 格 |
| 23 | `GROUPS.DAT` | **補給品** —— 打獵加的就是它([`166`](166-camp-hunt-identify-print.md) §2)|
| 85 | `GROUPS.DAT` | 逃跑旗標([`103`](103-flee-is-leaving-the-field.md))|

記錄由第一個引數決定:`ds:34DC` 是**隊伍記錄**、`ds:34E0 + 4i` 是**第 i 個角色記錄**。
所以同一個數字在不同呼叫裡指不同檔案的欄位 —— **要連記錄一起看**。

> **判準**:一個引數槽被填進「看起來像編號」的小整數時,先問
> 「它會不會是**位移**」。這裡是被一段**自己算位移**的程式碼揭穿的
> (`shl ax,1 / add ax,54`),而不是靠猜。

## 2. 位移 74–83 = 背包十格的已辨識旗標

**兩個地方寫它,而且寫法一模一樣。**

買東西(`TOWN` `0x108D3`):

```
0108D3  mov cx, [bp-6]        ; 背包格號 i
0108D6  add cx, 4Ah           ; ★ 位移 74 + i
0108D9  mov bx, 6EF8h         ; ds:6EFC = '1'
0108DF  INT 3F:5C  MID$ 指派  ; MID$(記錄, 74+i, 1) = "1"
```

鑑定成功(`CAMP` `0x1118B`):

```
01118B  mov cx, ds:70BEh      ; 背包格號 i
01118F  add cx, 4Ah           ; ★ 同一個 74 + i
011192  mov bx, 727Ah         ; ds:727E = '1'
01119B  INT 3F:5C  MID$ 指派
```

**「買來的東西不必鑑定」與「鑑定成功」寫同一格**,語意只有一種:
**這一格的道具已經辨識過了**。

[`144`](144-created-record-exposes-layout.md) §6 把位移 74–83 記成
「第二串十個旗標,語意未解」,而 [`formats/01`](../formats/01-chars-dat.md) 沿用了。
現在它有名字了 —— 而且**格數對得上**:背包 10 格、旗標 10 個。

⚠ **沒有讀到誰把它清成 `'0'`**。戰利品撿到的道具應該是未辨識的,
但那一段(戰後拾取)沒有讀。

## 3. 道具編號是 0-based

`TOWNDATA.DAT` 每間商店的販售範圍(位移 34/36,[`138`](138-towndata-building-types.md)):

| 商店 | 範圍 | `ITEMS.DAT` 的列 |
|---|---|---|
| The Iron Blade | 0–3 | 1–4:`Dagger` … |
| Kor's Smithy | 12–14 | 13–15(護甲)|
| **Potion Shoppe** | **21–26** | **22–27:`Heal potion`、`Speed potion` …** |
| General Goods | 47–48 | 48–49 |

26 間販售商店的**最小編號是 0**。而「藥水舖」賣的 21–26 對到第 22–27 列,
第 22 列正是 `Heal potion` —— **編號 21 = 第一瓶藥水**。

商店把選中的編號寫進背包格(`TOWN` `0x108BC`:`ds:352C` → 位移 54+2i),
所以**背包裡存的就是這個 0-based 編號**。

## 4. 分界定案,以及一個死掉的技能

[`166`](166-camp-hunt-identify-print.md) §3.1 列了兩個讀法各壞一半。**0-based 勝出**:

| 編號 | `ITEMS.DAT` 的列 | 技能 |
|---|---|---|
| 0–20 | 1–21 = **全部 21 件武器與護甲**(含 `Plate +2`)| 位移 47 = `Weapon lore` |
| 21–56 | 22–57 = 藥水 + 任務道具 | 位移 48 = `Potion lore` |
| > 56 | **沒有**(資料只到編號 56)| 位移 49 = `Item lore` |
| 99 | 空格 | — |

第一段與手冊 p.39「WEAPON LORE 可以辨別武器和護甲」**完全吻合**。

⚠ **但手冊的另外兩句對不上**:它寫「ITEM LORE 辨別各項特殊物品,
POTION LORE 辨別各種藥劑」,而程式把 `King's head`、`F-field key`、
`Teleporter` 這些特殊物品也丟進 `Potion lore` 那一段。
**`Item lore` 那一段接不到任何真實道具** —— 只接得到保留編號
(`59`/`60` = 無防具/無武器,[`formats/04`](../formats/04-spells-items-dat.md)),
所以它不是死碼,但對玩家而言是**一個永遠用不到的技能**。

⚠ 證據等級:程式碼是第 2 級、手冊是第 3 級([`CLAUDE.md`](../../CLAUDE.md) §6),
**低層級不可推翻高層級**,所以照程式走。但這一條值得由持有原版的人實測一次
——買一件藥水以外的 21–56 道具,用只會 `Item lore` 的巫師去 ID,看它准不准。

### 4.1 為什麼 [`166`](166-camp-hunt-identify-print.md) §3.1 當時不該裁決

那時手上只有「兩個讀法各有一段乾淨」。**裁決的關鍵不在道具表,在商店表**
—— 一個當時沒有被想到要去看的檔案。

> **判準**:兩個讀法都各壞一半時,**去找第三份資料**,
> 不要在兩份之間投票。

## 5. 鑑定的成功判定用智力

`CAMP` `0x11130`–`0x1116A`:

```
011130  di = 72CAh / INT 3F:91 乘   ; RND × ds:72CA
011136  bx = 1Ah / INT 3D:03        ; INT()
01113C  di = 72CEh / INT 3F:81 加   ; + ds:72CE
011142  (記錄, 位移 20)             ; ★ 智力
011156  call → ax
011160  di = 72D2h / INT 3F:91 乘   ; 智力 × ds:72D2
011165  INT 3F:A5(比較)→ 不過就印 'Failed'
```

**形狀是「擲骰 vs 智力 × 係數」。** ⚠ 三個係數
(`ds:72CA` / `72CE` / `72D2`)都是執行期變數,**未解** ——
所以機率算不出來,引擎仍然不編一個。
