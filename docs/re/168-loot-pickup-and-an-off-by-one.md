## 1. 撿道具的流程

`MAZEMOVE` `0x1394A`–`0x13A91`:

```
013943  ax = ds:34F8h                  ; 隊伍人數
013946  外層:ds:9560 從人數**遞減**到 1     ← 由隊尾往隊首
01394A  內層:ds:9562 從 0 到 9              ← 背包十格
013950  記錄 = ds:34E0[角色]
013966  位移 = 54 + 2i
013977  call → ax = 該格的值
01397A  cmp ax, 99                     ; 空格?
0139C5  … '<道具名> found an item.'
0139E2  (記錄, 位移 54+2i) ← 道具編號
0139FB  MID$(記錄, 75 + i, 1) = "0"    ; ★ 標成未辨識
013A91  十個人十格都滿 → 'Your party is full of items, please discard some from Camp.'
```

**外層遞減**是讀到的(`dec ax` / `cmp ax, 1` / `jl` 才離開),
所以**隊伍最後一個人先拿**。這與 `T)rade`、`E)quip` 的「由前往後」不同,
是原版的行為,照抄。

## 2. 清除端補上了

[`167`](167-record-field-accessor-and-identified-flags.md) §2 明列
「沒有讀到誰把它清成 `'0'`」。就是這裡:**撿來的東西是未辨識的**,
所以要花 `I)dentify` 去看它是什麼 —— 整條規則因此閉合:

| 來源 | 已辨識旗標 |
|---|---|
| 商店買的 | `'1'`(不必鑑定)|
| `I)dentify` 成功 | `'1'` |
| **地上撿的** | **`'0'`** |
| `T)rade` 傳過去 | 沿用來源那一格的值 |

## 3. 掃描分母:四個寫入端

掃全部十三支執行檔的 `add reg, 74` / `add reg, 75`,且其後 14 bytes 內有
`INT 3F:5C`(`MID$` 指派):

| 模組 | 位址 | 加的常數 | 是什麼 |
|---|---|---:|---|
| `TOWN` | `0x108D6` | **74** | 買東西 |
| `CAMP` | `0x1118E` | **74** | `I)dentify` 成功 |
| `CAMP` | `0x1088B` | **74** | `T)rade` 的接收端 |
| **`MAZEMOVE`** | **`0x139FB`** | **75** | **撿道具** |

**四個裡三個是 74。**

## 4. 為什麼區塊是 74–83 而不是 75–84

出貨的 `CHARS.DAT` 五筆(背包全空、狀態正常):

```
位移 74–83 = '0000000000'
位移 84–85 =  00 00        ← 狀態效果強度 = 0
```

若區塊是 75–84,第十格會落在**位移 84**,而那裡是 `0x00` 不是 `'0'`。
**所以區塊是 74–83。**

⚠ 這一步靠的是出貨資料裡的**一個位元組**。它成立是因為
`0x00` 與 `'0'`(`0x30`)長得不一樣 —— 換成別的欄位可能就分不開了。

### 4.1 後果

`i` 在兩邊都是 **0-based**(兩邊都用同一個 `i` 算出 `54 + 2i` 這個背包位移,
而 `i = 0` 時算出 54 = 第一格),所以撿道具寫的是 `75 + i`:

| 撿進第幾格 | 實際寫到 | 應該寫到 |
|---:|---|---|
| 0 | 位移 75(第 2 格的旗標)| 位移 74 |
| … | … | … |
| 8 | 位移 83(第 10 格的旗標)| 位移 82 |
| **9** | **位移 84 = 狀態效果強度的低位元組** | 位移 83 |

也就是:**撿到的東西會把下一格標成未辨識,而自己那一格不動**;
撿進第 10 格時,`'0'`(`0x30`)會寫進狀態效果強度 → 該值變成 **48**。

⚠ **這是一個可以實測的預測。** 讓一個背包只剩第 10 格的角色撿一件道具,
再看他的狀態效果強度。持有原版的人跑一次就知道。

## 5. remake 怎麼辦:不照抄

本專案的預設是**重現原版行為**([`162`](162-eldron-clan-riddle.md) §3 的
「同一個名字打四次也會過」就是照抄的)。**這一條不照抄**,理由是它與那個不同:

- 氏族謎題的漏洞是**可觀察的遊戲行為**,照抄玩家才玩到同一款遊戲;
- 這一條是**寫壞了另一個欄位**。照抄會讓本引擎產出的存檔帶著
  `狀態效果強度 = 48`,而原版讀回去會照那個值跑 ——
  **我們製造的破壞會跑到原版身上**。

所以引擎寫 `74 + 格號`(與另外三個寫入端一致),
並把差異記在這裡與 [`formats/01`](../formats/01-chars-dat.md)。
⚠ 若實測顯示原版其實是對的(= 我讀錯了),要回來改的是**這一個決定**,
不是那三個寫入端。
