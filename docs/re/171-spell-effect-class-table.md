## 1. `ds:7340` 是從檔案讀進來的

`0x107EF`:

```
0107EF  mov bx, ax
0107F1  add ax, 7340h
0107F4  INT 3F:B8   INPUT#
```

`INT 3F:B8` = `INPUT#`([`12`](12-api-3f61.md) 的 API 表),
而那一段的檔案是 `SPELLS.DAT`(`ds:938C` 的字串常數)。
之後全模組對 `ds:7340` 的存取都是 `[di + 7340h]`,`di = 法術編號 × 2`。

**值域也對得上**:程式裡出現的比較常數是 1、3、4、5、6、7、8、11,
而 `SPELLS.DAT` 欄3 的實際值域是 0–13([`formats/04`](../formats/04-spells-items-dat.md))。

## 2. 那個過濾是「不要群體傷害」

[`170`](170-monster-ai-casts-by-spell-family.md) §2 讀到第一回合選完法術之後:

```
0156ED  cmp word ptr [di+7340h], 1     ; 效果類別 == 1 ?
0156F8  且第一回合 → jmp 0155B0        ; 重選
```

而欄3 = 1 的**只有三個**:

```
 3  FIRE STORM
 8  TEMPEST
12  HAIL STORM
```

**就是 [`170`](170-monster-ai-casts-by-spell-family.md) §4 那三招。** 所以完整的規則是:

> **第一回合**:在自己的系別裡隨機挑一個攻擊法術,**挑到群體傷害就重選**;
> **第二回合起**:系別 1 / 3 / 4 **固定放**自己那一招群體傷害。

⚠ 這也解釋了為什麼那三招要另外寫死一條路徑([`170`](170-monster-ai-casts-by-spell-family.md) §4):
它們被第一回合的過濾排除了,不寫死就永遠放不出來。

⚠ 系別 2 與 5 沒有欄3 = 1 的法術,所以它們**在第二回合起沒有分支**
—— [`170`](170-monster-ai-casts-by-spell-family.md) §4 標「未讀」的那一格,
現在知道是**沒有東西可讀**,不是漏看。

## 3. 效果類別 → 屬性欄

`0x160A2`–`0x16104` 是一串同形的比較,每一支只做一件事:填 `ds:9B32`。

```
0160A8  cmp [di+7340h], 3  → ds:9B32 = 9
0160BE  cmp [di+7340h], 4  → ds:9B32 = 6
0160D4  cmp [di+7340h], 5  → ds:9B32 = 3
0160EA  cmp [di+7340h], 6  → ds:9B32 = 2
016100  cmp [di+7340h], 7  → 走另一條(防護)
```

`ds:9B32` 是**屬性欄號**([`spec/01`](../spec/01-combat.md) §1):

| 效果類別 | 屬性欄 | 語意 | [`formats/04`](../formats/04-spells-items-dat.md) 原本的說法 |
|---:|---:|---|---|
| 3 | **9** | **命中能力** | **未指認** |
| 4 | 6 | 力量 | 力量 ✓ |
| 5 | 3 | 生命值 | 生命值 ✓ |
| 6 | 2 | 速度 | 速度 ✓ |

**四個裡三個本來就對,所以第四個的讀法可信。**

### 3.1 法術名獨立佐證

欄3 = 3 的三個法術是:

| 法術 | 欄4 | 命中訊息 |
|---|---:|---|
| `CHILL` | −1 | Chilled |
| `CLUMSINESS` | −3 | **Becomes clumsy** |
| `WINGS OF VICTORY` | +1 | Gains courage |

**`CLUMSINESS`(笨拙)降的當然是命中能力**,而 `WINGS OF VICTORY`
(獲得勇氣)是它的反面 —— 欄4 的正負與 [`formats/04`](../formats/04-spells-items-dat.md)
「類別 3–6 時正負決定增減」也對得上。

### 3.2 ⚠ `ds:9B32` 有**兩個**寫入端

[`spec/09`](../spec/09-magic-items.md) §3 的線索寫著「`ds:9B32` 由
`INT(a ÷ b) + 1` 算出來(`0x15B50`–`0x15B80`)」。那個寫入端確實存在,
而且它讀的是 `ds:7384` —— **`7384 − 7340 = 68` = 34 個 word,正好是下一欄**,
所以那是 `SPELLS.DAT` 欄4(每點威力)。

**兩個寫入端不衝突,因為距離差很多**:

| 位址 | 寫入 | 與使用端的距離 |
|---|---|---|
| `0x15B80` | `INT(欄4 × ? ÷ ?) + 1` | 1,400 bytes 之前,用途**未確認** |
| `0x160B2`–`0x160F4` | 字面值 9 / 6 / 3 / 2 | **60 bytes 之前**,緊接 `0x16142` 的 `imul 15` |

`0x16142` 把 `ds:9B32` 乘 15 當欄號用(`A(列,欄)` 的算式),
而**設定它的是那條字面值鏈** —— 中間沒有別的寫入。

⚠ `0x15B80` 那一支在做什麼**沒有讀出來**。BASIC 變數重用很常見,
但這裡只主張「緊接使用端的那個寫入端是欄號」,不主張 `ds:9B32` 只有一種語意。

> **判準**:一張表裡有 N 格已經確認、一格未解時,
> **去讀那一格的產生端**(這裡是 `ds:9B32` 的四個賦值),
> 已確認的那幾格就是現成的對照組 —— 讀錯了它們會先不對。
