## 1. 六個 `INPUT#`,一欄一個

`CMBT.EXE` `0x107D0`–`0x10812`,索引是法術編號:

```
0107D4  bx = 索引×4 + 7274h   INPUT#    ; 欄1 法術名(字串描述子,間距 4)
0107E3  dx = 索引×2 + 72FCh   INPUT#    ; 欄2 法術系別
0107F0  ax = 索引×2 + 7340h   INPUT#    ; 欄3 效果類別
0107FB  ax = 索引×2 + 7384h   INPUT#    ; 欄4 每點威力
010804  ax = 索引×2 + 73C8h   INPUT#    ; 欄5 法力單價
01080E  ax = 索引×4 + 740Ch   INPUT#    ; 欄6 命中訊息(字串)
```

**這是一次讀完一列、拆成六個陣列** —— BASIC 沒有結構,
所以「74 筆 × 6 欄」在記憶體裡是六條平行的陣列。

## 2. 位址首尾相接,可以推算

`SPELLS.DAT` 有 **34 列**(33 個法術 + 哨兵,[`formats/04`](../formats/04-spells-items-dat.md)):

| 陣列 | 位址 | 元素 | 長度 | 下一個 |
|---|---|---|---|---|
| 欄1 名稱 | `ds:7274` | 描述子 4 B | 34 × 4 = 136 | `+0x88` → `72FC` ✓ |
| 欄2 系別 | `ds:72FC` | word | 34 × 2 = 68 | `+0x44` → `7340` ✓ |
| 欄3 效果類別 | `ds:7340` | word | 68 | → `7384` ✓ |
| 欄4 每點威力 | `ds:7384` | word | 68 | → `73C8` ✓ |
| 欄5 法力單價 | `ds:73C8` | word | 68 | → `740C` ✓ |
| 欄6 命中訊息 | `ds:740C` | 描述子 4 B | 136 | — |

**五個接縫一個不差。** 所以在反組譯裡看到 `[di + 73C8h]` 不必再追 ——
查一次這張表就知道是欄5。

> **判準**:同一批 `INPUT#` 讀進來的位址,**間距就是「筆數 × 元素大小」**。
> 反過來用:知道筆數,就能從一個已知欄推出其餘所有欄的位址。
> 這比逐個追每一條 `[di + 常數]` 便宜一個量級。

⚠ `ds:7274` 這個名稱陣列 [`170`](170-monster-ai-casts-by-spell-family.md) §1
已經用過(印法術名)。當時把它當成孤立的一件事,**沒想到它是這一排的第一個**。

## 3. 類別 1 不選目標

`0x14F20`:

```
014F26  cmp word ptr [di+7340h], 1     ; 效果類別
014F2B  jg  014F30                     ; ★ ≥ 2 → 走選目標那一段
014F2D  jmp 01505A                     ; ★ == 1 → 直接進群體傷害
```

`0x14F30` 之後那一段逐一讀單位的欄0 / 欄1(戰場座標)去找目標;
`0x1505A` 那一段沒有目標迴圈,直接:

```
01505A  INT(RND × ds:977E) + 1         ; ★ d100(docs/re/154)
015087  ax = 欄4[法術]
015096  bx = 欄5[法術]
0150A7  INT 3F:8D 除                   ; 欄4 ÷ 欄5
0150B6  ds:9A48 ← 結果
```

⚠ **`欄4 ÷ 欄5` 之後怎麼用沒有讀完**([`formats/04`](../formats/04-spells-items-dat.md)
說欄5 是「每一級的法力單價」,所以這個商像是**等級**)——
但本篇只讀到它被算出來,沒讀到它與 d100 怎麼合成傷害。
