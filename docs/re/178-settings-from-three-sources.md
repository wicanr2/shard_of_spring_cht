### 2.1 屬性擲骰:從樣本反推的兩個數字都錯了

```
屬性 = INT(RND × 6 + RND × 6 + 2)      支撐集 2…13,平均 7.5
```

[`156`](156-attribute-roll-shape.md) 那一輪用 15 個實測樣本(4…12、平均 8.4)
把常數約束到 `B = 4、A ≈ 4.9`。**兩個都不對。**

錯的地方是**把「觀察到的最小值」當成了下界**。真正的下界 2 出現的機率只有
`(2/6)² / 2 = 5.6%`,15 個樣本裡看不到它是**最可能的結果**(機率 42%)。

> **判準**:從樣本推一個分佈的**端點**,要先算「端點在這個樣本數下看得到的機率」。
> 看不到就不能拿沒看到當證據 —— 而中位數與平均那種**內部**統計量沒有這個問題。
> 兩者混在同一次反推裡,結果就是「平均對得很好、端點整個錯掉」。

⚠ 舊值與新值**都涵蓋得住出貨五人的屬性**,所以拿出貨資料做健全性檢查
分不出對錯 —— 涵蓋是必要條件,不是充分條件。

## 3. 初始法力 = 智能(第 3 級證據,要標清楚)

手冊 p.12 把兩件事寫在同一組句子裡:

> 智能(INTELLECT):學技能時所擁有的點數**及巫師一開始時的法力點數**。
> 體能(ENDURANCE):…同時,**它也是你一開始的生命點數**。

初始生命 = 體能這一條**另外有反組譯與實跑佐證**([`143`](143-character-creation.md));
初始法力這一條**只有手冊**。

⚠ **兩件事寫在同一行不代表證據等級相同。** 引擎照手冊實作並在註解裡標明等級,
[`CLAUDE.md`](../../CLAUDE.md) §6 的優先序仍然成立 —— 之後若反組譯讀到別的算式,
以反組譯為準。

## 4. `TITLES.DAT` 的格式

```
112 段,每段一行:"…"(雙引號包住),CRLF 分隔,結尾 0x1A。共 1,676 bytes。
```

⚠ 第 64 列 `"done.` **缺右引號** —— 原版資料就是這樣,不是抄錯。
解析器不能假設每一行都有成對的引號。

內容是 `CHARUTIL.EXE`(角色管理程式)的**整份介面文字**:選單、五項屬性標籤、
種族與職業選單、技能表、名冊與隊伍管理的提示。

順帶兩個對得上的:

| `TITLES.DAT` | 引擎 | |
|---|---|---|
| `"name (10 char)"` | `town.NameMaxRunes = 10` | ✓ |
| 種族修正的七個相異值 `+2 +1 −3 +3 +5 −5 −2` | `rules.Races` 的修正集合 | ✓ **完全同集** |

⚠ 種族修正在 `TITLES.DAT` 裡是**去重後的字串常數**(畫表格用),
不是一張矩陣 —— 它印證得了值域,印證不了哪個種族配哪個值。
