## 1. 錨點

`'Stats are up by:'` 的描述子在 `ds:7234`,印它的是:

```
011325  mov bx, 7234h
011328  INT 3F:6E              ; 印字串
```

**算式就在它下面**,一路到 `0x113DE`。

## 2. 迴圈邊界

```
01132E  mov ax, 1
011331  jmp  loc_113D3         ; 跳進 FOR 的測試
...
0113D0  inc  dx                ; 迴圈尾:計數 +1
0113D1  mov  ax, dx
0113D3  mov  ds:6EA6h, ax      ; ★ 兩處跳入:初始化 與 迴圈尾
0113D6  cmp  ax, 3             ; ★ 字面值 3
0113D9  jg   short loc_113DE   ; > 3 → 離開
0113DB  jmp  loc_11334         ; 否則回迴圈本體
```

初值 1、上界 3、每輪 +1 → **本體跑 3 次**。這是 BASIC `FOR I = 1 TO 3` 的標準版面
(測試放在迴圈尾、由前面 `jmp` 跳進去),`3` 是立即數不是變數,
所以**與等級、種族、職業無關**。

⚠ `0x11217 cmp ds:709A, 2 / jz`(職業分支)在 `0x11301` 匯流,
**屬性迴圈在匯流點之後** —— 兩個職業走同一段。

## 3. 迴圈本體

```
011334  mov bx, 71BEh / INT 3D:33   ; RND(1)        ds:71BE 初值 = MBF 1
01133A  mov di, 724Ch / INT 3F:91   ; × 5           ds:724C 初值 = MBF 5
011340  mov bx, 1Ah   / INT 3D:03   ; INT()         1Ah = 浮點累加器(re/152 §3)
011346  INT 3F:77                   ; → 整數
01134B  mov ds:724Ah, ax            ; roll = 0…4
...
011357  shl ax, 1                   ; ×2
011359  add ax, 10h                 ; +16   → {16,18,20,22,24}
01135C  mov ds:66D0h, ax            ; 服務呼叫的位移引數
01135F  call loc_10079              ; 讀 CHARS.DAT[位移](re/167 §1 的存取函式)
011362  inc ax                      ; +1
011363  mov ds:6818h, ax
011366  cmp ax, 14h                 ; > 20?
011369  jg  short loc_1136E
01136B  jmp loc_11374
01136E  mov word ptr ds:6818h, 14h  ; 夾成 20
...
011383  mov dx, ds:724Ah            ; 同一個 roll
011389  shl dx, 1 / add dx, 10h     ; 同一個位移
011390  mov ds:66CAh, ax
011396  call loc_10043              ; 寫回 CHARS.DAT[位移]
```

兩個常數都是我自己用 [`tools/dgroup_init.py`](../../tools/dgroup_init.py) 查的初值
([`177`](177-dgroup-init-stream-and-hunt-formula.md) 的做法):

```
71BE  00 00 00 81  MBF 1
724C  00 00 20 83  MBF 5
724A  沒有編譯期初值      ← 它是執行期變數(存 roll)
```

## 4. 位移對到哪五項

逐一比對 [`formats/01-chars-dat.md`](../formats/01-chars-dat.md)(已 RE-DONE 的欄位表):

| roll | 位移 | 欄位 |
|--:|--:|---|
| 0 | 16 | 速度 |
| 1 | 18 | 力量 |
| 2 | 20 | 智能 |
| 3 | 22 | 體能 |
| 4 | 24 | 命中能力 |

**五項屬性正好連續排在 16–24**,`roll×2 + 16` 掃過的就是這五格,沒有多也沒有少。

## 5. 對玩家的意義

有放回、無排重,所以三次的分布是:

| 結果 | 機率 |
|---|---|
| 三項各 +1 | 5×4×3 / 5³ = **48%** |
| 某一項 +2、另一項 +1 | **48%** |
| 某一項 +3 | 1/25 = **4%** |

也就是**過半數的升級會有某一項拿到 +2 以上**。夾上限 20 表示已經滿的屬性
會白白吃掉一次擲骰 —— 高等級角色的屬性成長會自然變慢。

## 6. 升級發的技能點 = 智能成長 + 1(順帶解出來)

屬性迴圈的出口 `0x113DE` 接的就是 `'You have N points left.'` 那一段:

```
0113E7  ds:66D0 = 59h ; call loc_10079   ; 讀 CHARS.DAT 位移 89 = 剩餘技能點
0113F9  ds:66D0 = 14h
0113FF  mov [bp-6], ax                   ; 暫存剛才那個值
011402  call loc_10079                   ; 讀位移 20 = 智能(**成長之後**)
011405  add ax, [bp-6]                   ; + 舊的剩餘技能點
011408  sub ax, ds:7248h                 ; − 智能(**成長之前**)
01140C  inc ax                           ; + 1
01140D  mov ds:725Ch, ax                 ; = 這次可分配的技能點
```

`ds:7248` 是**屬性迴圈之前**讀的智能:

```
01130A  ds:66D0 = 14h ; call loc_10079
011313  mov ds:7248h, ax
```

⚠ `ds:xxxx` 不產生 xref,所以用 [`tools/ida/find_dsref.py`](../../tools/ida/find_dsref.py) 掃運算元文字:
**掃了 4,417 條指令,`7248` 命中 2 處** —— 寫入只有 `0x11313` 這一個,
讀取只有 `0x11408`。中間沒有第二個寫入端,所以那個減法確實是「升級前後的智能差」。

```
新的可分配點數 = 舊的剩餘點數 + (智能成長) + 1
```

| 觀察 | 說明 |
|---|---|
| **每級至少 1 點** | `inc ax` 是無條件的 |
| **智能被選中就多拿** | 屬性迴圈 5 選 1 選到智能時,這一級多 1 點(選到兩次就多 2 點)|
| **沒花完會累積** | 起點是位移 89 的舊值,不是從 0 開始 |

⚠ 這也解釋了創角時 `位移 89 = 智能`([`144`](144-created-record-exposes-layout.md) §4)——
**同一條規則的起始情況**:第 1 級的「累計」就是智能本身。

### 順帶:`ds:6D28` 是一張描述子陣列

`0x1146A` 印技能名:

```
01146A  mov ax, 0Ah / imul ds:709Ah   ; 10 × 職業(709A = 1 或 2)
011471  add ax, ds:6D9Ch              ; + 技能編號
011475  add ax, 0FFF6h                ; − 10
011478  shl ax,1 / shl ax,1           ; ×4(描述子是 4 位元組)
01147C  add ax, 6D28h
```

職業 1 → 索引 0–9、職業 2 → 索引 10–19,而 §3 印屬性名用的是 `+ (roll+20)×4`
→ **索引 20–24**。所以 `ds:6D28` 是一張連續的描述子陣列:

```
0–9    戰士的十項技能名
10–19  巫師的十項技能名
20–24  五項屬性名
```

內容仍是執行期填的(靜態讀不到),但**結構確定**,而且那 20 個技能名
早就在 `TITLES.DAT` 裡([`178`](178-skill-costs-in-titles-dat.md))。
