# 187 — 商店買到的東西進誰的背包(E4,未關)

> 輸入:`TOWN.EXE`。掃描分母:`find_disp.py` 掃過 4,419 條指令。
> 信心:**證據充分**(流程與判斷式讀到);**收貨者的來源未知**。

## 1. 原版沒有「買給誰」的提示

`TOWN.EXE` 的字串表裡唯一的 `Which character #…` 屬於**訓練所**
(`ds:70B4`,'seeks advancement in his art')。購買流程的字串只有:

```
'Item to buy, ESC to leave, any key to page.'
'Cost is '  /  'That will cost   '  /  ' gold, Pay (Y/N)?'
'No more room!'
```

**選道具 → 問付不付錢 → 完成**,中間沒有問人。

## 2. 收貨的流程(`0x10850`–`0x108B3`)

```
bx = ds:6EE8            ; ★ 收貨的角色索引
bx = bx × 4 + 34E0h     ; COMMON 區的記錄字串陣列(docs/re/43)
                        ; ← 這一筆就是要收東西的那個人的記錄
for k = 0 …:
    位移 = 54 + 2k       ; 背包十格(docs/re/167 §2)
    if 欄位值 == 99:     ; 空格哨兵(docs/re/144 §3)
        放進這一格,結束
印 'No more room!'
```

所以「給誰」完全由 **`ds:6EE8`** 決定,而且**背包滿了會被擋下來** ——
引擎現在固定給第一位、且沒有滿的判斷,兩者都與原版不同。

## 3. 未解:`ds:6EE8` 從哪來

只有一個寫入點,`0x10822`(`mov ds:6EE8h, ax`),而它上游那一段
(`0x107D2`–`0x10820`)是一連串 `INT 3E`/`INT 3F` 的字串與浮點呼叫,
**反組譯在那裡對齊斷掉** —— BASIC 的 `CALL` 會把參數內嵌在 call 之後,
`unlock_module.py` 目前只處理 `INT` 的內嵌參數,不處理 `call` 的。

⚠ **不要據此猜「就是第一位」**:`ds:6EE8` 是個變數,不是常數 ——
如果答案是固定的,編譯器不會為它留一個變數。
