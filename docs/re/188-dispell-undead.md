# 188 — 戰鬥的 `D)ispell`:三道閘門、不死生物的判準、成功率

> 輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`(否則 `INT 3F` 的內嵌運算元會讓整段錯位,
> [`186`](186-monster-ai-target-placement-cast.md) §0)。
> 信心:**已確認**(位址逐條讀出;兩個常數走 DGROUP 初始資料串,
> [`177`](177-dgroup-init-stream-and-hunt-formula.md) 的方法)。

這一篇關掉 [`95`](95-no-flee-command.md) §4 留的第 2 個開放項
(「指令鏈裡的 `D` 語意未定」),並補上 `CHARS.DAT` 位移 87 的語意。

## 1. `D` 是 `D)ispell`,不是「說服」

[`95`](95-no-flee-command.md) 讀到 `D` 會檢查 `CHARS.DAT` 位移 51,
而位移 51 在**戰士表**是 `Persuasion`,所以當時的形狀猜是「說服」。
**猜錯的原因是查錯了那張表**:

| 技能 10 | 戰士表 | 巫師表 |
|---|---|---|
| 位移 51 | `Persuasion` | **`Priesthood`** |

([`94`](94-skill-tables.md) §1:同一段位移,職業決定用哪一張。)

`D` 那一支**要求施法者是巫師**(§2.3),所以它讀的一定是巫師表那一欄 ——
`Priesthood`(降魔術)。與 `CMBT` 自己的字串
`does not have the Priesthood and cannot dispell.` 完全吻合。

> **判準**:一段位移對到兩張表時,**先確定呼叫端限定哪一種職業**再查表。
> 查錯表的結論會自洽 —— 「說服」在戰鬥裡也講得通,沒有任何訊號說它是錯的。

## 2. 三道閘門(全部是「拿 1 個字元比 `"1"`」)

三道都走同一個成語:`MID$(記錄, 位移, 1)` 與 `ds:94CC` 字串比較,
而 `ds:94CC` 是長度 1 的字串常數、內容在 `ds:94D0` = `31h` = **`"1"`**。

記錄基底的算法在三處相同:`bx = (ds:9B50 − 8) × 4 + 34E0h`,
`ds:9B50` 是施法者的角色編號。

### 2.1 位移 51 —— 沒有 `Priesthood` 就擋(`0x169C8`–`0x169FA`)

```
mov  di, ds:9352h / shl di,1 / mov ax, [di+6A7Ah]   ; 施法者
mov  ds:9B50h, ax
… 記錄基底 …
mov  dx, 33h        ; 51
mov  cx, 1
INT  3D:0A          ; MID$(rec, 51, 1)
mov  bx, 94CCh      ; "1"
INT  3F:62          ; 字串比較
jnz  0x169FD        ; **不等 → 印錯誤**
jmp  0x16AC6        ; 相等 → 繼續
```

錯誤訊息在 `0x16A20`–`0x16AC3`:`does not have` / `the Priesthood` /
`and cannot` / `dispell.`(第 13–16 列)。

### 2.2 位移 87 —— 這場已經驅散過(`0x16AC6`–`0x16AF1`)

```
mov  dx, 57h        ; 87
INT  3D:0A          ; MID$(rec, 87, 1)
INT  3F:62          ; 與 "1" 比
jz   0x16AF4        ; **相等 → 印「has already dispelled this combat.」**
jmp  0x16B9C        ; 不等 → 繼續
```

**這解出了 `CHARS.DAT` 位移 87 的語意**:一場戰鬥只能驅散一次的旗標。
`0x16FD5`–`0x16FFE` 是寫入端 —— 跑完整輪之後無條件把它設成 `"1"`
(`INT 3F:5C` 是 `MID$` 的**指定**形式,`cx = 57h`、`ax = 1`)。

⚠ **設旗標與「有沒有真的驅散掉」無關** —— 只要走到那一步就算用掉了。

⚠ 旗標存在**角色記錄**裡,不是戰鬥屬性陣列 —— 所以它跨戰鬥留著。
原版在哪裡把它清回去**沒有讀到**(見 §5)。

### 2.3 位移 15 —— 不是巫師就擋(`0x16B9C`–`0x16BC7`)

```
mov  dx, 0Fh        ; 15 = 職業字元
INT  3D:0A / INT 3F:62 與 "1" 比
jz   0x16BCA        ; **相等(= 戰士)→ 印「is not a wizard and cannot dispell.」**
jmp  0x16C92        ; 不等 → 繼續
```

## 3. 不死生物 = 屬性 11 ∈ {65, 73, 81}

`0x16C92`–`0x16CF3` 掃全部怪物找有沒有目標:

```
迴圈 i = 0 … ds:943A − 1                 ; ds:943A = 這場的怪物數
  dx = (屬性 8[i] ≥ 5) ? 0 : −1          ; 還活著(狀態 < 5)
  di = (i + 0A5h) × 2                    ; 0A5h = 165 = 15 × 11 → **屬性 11**
  bx = (屬性11 == 41h)                   ; 65
  cx = (屬性11 == 51h)                   ; 81
  bx = bx OR cx OR (屬性11 == 49h)        ; 73
  bx = bx AND dx
  if bx ≠ 0 → 0x16D77(有目標,開始驅散)
迴圈結束 → 印「None of these monsters are undead!」(0x16CF5–0x16D74)
```

**屬性 11 是圖組**([`163`](163-attribute-14-is-action-type.md):隊員固定 41 / 57,
兩個值都是十進位 —— `0x118F4` 的立即數是 `29h`、`0x11962` 是 `39h`)。
所以「不死」在原版是**用圖組編號認的**,不是另一個旗標欄位。

### 3.1 換算回 `MONSTERS.DAT` 欄6 —— 信心:**證據充分**(不是已確認)

⚠ **怪物的屬性 11 怎麼從欄6 算出來,沒有讀到那一段。** 下面是推的:

| 依據 | 內容 |
|---|---|
| 隊員 | 戰士 41、巫師 57(讀到的) |
| 怪物欄6 | 「1級戰士」= 1、「1級巫師」= 3(`MONSTERS.DAT`) |
| 圖檔 | `MONST*.BIN` 每檔 **8 格**(`internal/original/gfx.go` 的 `MonstFrames`) |

同時滿足這三項的線性關係只有 `屬性11 = (欄6 − 1) × 8 + 41`
(1 → 41 與隊員戰士同組、3 → 57 與隊員巫師同組、步長 8 = 一個圖檔的格數)。

代進去,`{65, 73, 81}` 就是 **欄6 ∈ {4, 5, 6}**:

| 欄6 | 屬性 11 | 這一組有哪些怪 |
|---:|---:|---|
| 4 | 65 | **沒有任何一筆用這一組** |
| 5 | 73 | 骷髏、殭屍、食屍鬼、莫辛/瑟西恩/范迪加德、拉利斯 |
| 6 | 81 | 骷髏巫師、迪維爾、洛西安 |

5 與 6 正好是不死生物那兩組,**而 4 是空的** —— 與 [`186`](186-monster-ai-target-placement-cast.md) §1.1
的「錨點 8 永遠挑不到」同一種形狀。

⚠ 幽靈／邪靈／魅影(欄6 = 7 → 89)**不在**這個集合裡。
本作把它們算成「靈體」不是「不死」——`SPELLS.DAT` 的系別 5 就叫 `Spirit runes`。

> **推翻條件**:如果哪天讀到怪物屬性 11 的實際寫入端,而它**不是**
> `(欄6 − 1) × 8 + 41`,§3.1 整段作廢(§3 本身仍然成立 —— 那一段是讀到的)。

## 4. 成功率 = `d100 ≤ (智能 − 難度階級 + 1) × 3.6`

`0x16D77`–`0x16FD2` 是逐隻嘗試的迴圈(`ds:9D94` 是索引、`ds:9D62` 是上界),
每一隻重新驗一次「不死 且 活著」(`0x16DED`–`0x16E38`,與 §3 同形),
通過才擲骰(`0x16E66`–`0x16ECF`):

```
INT 3D:34            ; RND
mov di, 977Eh        ; ds:977E = 100(d100,re/154)
INT 3F:91            ; ×
mov bx, 1Ah / INT 3D:03   ; INT()
mov di, 9464h        ; ds:9464 = 1.0
INT 3F:81            ; +1            → d100,值域 1…100
… 取施法者記錄 …
mov word ptr ds:66D0h, 14h ; 20
call 0x10083         ; = CVI(MID$(記錄, 20, 2)) = **位移 20 = 智能**
add  di, 0C3h        ; 0C3h = 195 = 15 × 13 → **屬性 13(難度階級)**
sub  ax, [di+6822h]  ; 智能 − 階級
inc  ax              ; +1
INT  3F:57           ; → 浮點
mov  di, 9D98h       ; **ds:9D98 = MBF 3.6**
INT  3F:91           ; ×
INT  3F:A5           ; 比較
ja   0x16ED4         ; **大於 → 失敗**:'Ignores priest.'
jmp  0x16F12         ; 否則 → 成功:'dies.'
```

`0x10083` 是三行的取值常式:`MID$(str, ds:66D0, 2)` → `INT 3D:18`(`CVI`)。
`ds:66D0` 由呼叫端填 20,而 `CHARS.DAT` 位移 16/18/20/22/24 是五項屬性
([`formats/01`](../formats/01-chars-dat.md),順序:速度/力量/智能/體能/技巧)——
**位移 20 = 智能**。

`ds:9D98` 的初值由 `tools/dgroup_init.py CMBT.EXE --at 9D98` 讀出:
`66 66 66 82` = MBF **3.6**。

> **一致性檢查**:智能 20(上限)打階級 1 的怪 → 門檻 `20 × 3.6 = 72`,約七成;
> 智能 10 打階級 5 → `6 × 3.6 = 21.6`,約兩成。
> 難度階級越高越難驅散,方向合理。
