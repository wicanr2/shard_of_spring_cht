# 19 — BSAVE 容器,以及世界地圖尺寸定案

日期:2026-08-13
接續:[`18-text-inventory.md`](18-text-inventory.md)
子系統:**H. 圖形格式**、**F. 世界地圖**

## 結論

全部 52 個 `.BIN` 檔都是 **BASIC 的 `BSAVE` 容器**(52/52 零例外)。
扣掉標頭之後,世界地圖的尺寸**定案為 103 × 121**。

`STARTUP.BIN` 的標頭記著 `0xB800:0000`、長度 16384 ——
**那是 CGA 顯示記憶體的位址與大小**,等於原版自己告訴我們顯示模式。

## 1. BSAVE 容器(52/52)

```
+0x00   1 byte    0xFD          標記
+0x01   2 bytes   segment       原本存檔時的節區
+0x03   2 bytes   offset        原本存檔時的位移
+0x05   2 bytes   length        資料長度
+0x07   N bytes   資料
+0x07+N 1 byte    0x1A          EOF
```

| 檢查 | 結果 |
|---|---|
| 首位元組 `0xFD` 且 `length + 8 == 檔案大小` | **52/52** |
| 檔尾是 `0x1A` | **52/52** |

**信心等級:已確認。**

⚠ `.PIC` 檔(`MAZEITEM`／`WALKDRAW`／`WRLDITEM`)**不是** BSAVE ——
首位元組分別是 `0x0D`、`0x2B`、`0x42`,是另一種容器,未解。

### 1.1 標頭裡的 segment 是情報

`BSAVE` 記錄的是「這塊資料原本在記憶體的哪裡」,所以標頭直接洩漏用途:

| 檔案 | segment | length | 意義 |
|---|---|---:|---|
| `STARTUP.BIN` | **`0xB800`** | **16384** | **CGA 顯示記憶體整頁** |
| `WRLDMAP.BIN` | `0x54B7` | 24,926 | 一般資料段 |
| `MONST1`–`MONST22.BIN` | `0x27FF` | 734 | 22 個檔**同一個位址** → 輪流載入同一塊緩衝區 |
| `PICT1.BIN` | `0x3522` | 5,972 | |
| `PICT8.BIN` | `0x3A83` | 5,972 | |

`0xB800` + 16 KB 是 CGA 圖形頁的標準配置。
**`STARTUP.BIN` 因此是一份可直接用的 CGA 格式解碼樣本** ——
把它解對了,`PICT*.BIN` 與 `MONST*.BIN` 的像素佈局就有了參照。

22 個怪物圖共用同一個 segment,說明遊戲**一次只載入一隻怪物的圖**。

## 2. 世界地圖:103 × 121

### 2.1 先扣標頭

`WRLDMAP.BIN` 檔案 24,934 bytes,但 BSAVE 的 `length` 欄是 **24,926** ——
[`17`](17-world-and-maze.md) §1 把 7-byte 標頭與 1-byte EOF 一起算進去了,
所以格數算成 12,467,實際是 **12,463**。

**而 7 是奇數,所以標頭還讓 2-byte 交錯的奇偶性翻轉了。**
扣掉標頭之後,資料在 `data[0::2]`(31 種值),`data[1::2]` 是 **100% 的 0**。

| | 錯誤版 | 正確版 |
|---|---|---|
| 資料起點 | 檔案位移 0 | 檔案位移 **7** |
| 格數 | 12,467 | **12,463** |
| 圖塊在 | `d[1::2]` | `data[0::2]` |
| 可能的矩形 | 91×137、137×91 | **103×121、121×103** |

**判準:切分單位對了還不夠,起點錯一個 byte 會讓交錯資料整個換半邊。**

### 2.2 寬度裁決

12,463 = 11 × 11 × 103,所以兩邊都 ≥ 20 的矩形**只剩兩個**。

用 ASCII 圖肉眼比對:

- **寬 103** —— 左緣出現**一整條垂直連續的邊界圖塊**,陸塊與海岸線在垂直方向連貫 ✅
- 寬 121 —— 圖形逐列右移,邊界圖塊散落各處 ❌

**信心等級:證據充分。** 尚未達 RE-DONE(缺讀取端),
但「整條垂直邊界」是一個很難靠巧合出現的訊號。

## 3. 這一輪修正了什麼

| 先前 | 實際 |
|---|---|
| `WRLDMAP.BIN` 有 12,467 格,寬度候選 91／137 | **12,463 格,103×121** —— 先前沒扣 BSAVE 標頭 |
| 98-byte 圖塊檔的前 2 word 是尺寸 | 是 BSAVE 標頭的一部分(`0xFD` + segment 低半)|

第二條的偵測方式值得記:七個 98-byte 檔的「第一個 word」**完全相同**(`0x91FD`),
而真正的尺寸欄位不可能七個檔都一樣。**跨檔案的常數欄位是容器標頭,不是內容。**
