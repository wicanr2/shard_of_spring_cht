# 192 — 武器編號 59–62 是「自然武器」:`None` / `Hands` / `Bite` / `Fangs`

> 輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(表的寫入端與三個讀取端都讀到,索引算式一致)。

關掉 `translations/module-text/CMBT.tsv` 第 6/10 列(`Fangs` / `Bite`)的
「選用規則未讀」,同時補上 [`191`](191-poison-on-hit.md) §5 的第一個未解項。

## 1. 名稱表的基底是 `7494`,不是寫入端看到的 `7580`

寫入端([`191`](191-poison-on-hit.md) §5 停在這裡)只看得到四個**絕對位址**:

```
010463  bx = 9334h('None') ; dx = 7580h   → 指定
010472  bx = 92D8h('Hands'); dx = 7584h
010483  bx = 933Ch('Bite') ; dx = 7588h
010494  bx = 92E2h('Fangs'); dx = 758Ch
0104A5  bx = 92ECh('Hands'); dx = 7680h
```

光看這一段推不出索引 —— 步長 4 只說明「一格 4 bytes」。
基底要去讀取端拿(`0x135A3`):

```
013587  cmp cx, 8 / jl → 0x1358F      ; **cx ≤ 7 = 攻擊者是怪物**
013594  cx += 3Ch                      ; 60 = 15 × 4 → 屬性 4(武器編號)
01359B  bx = [di+6822h]                ; 武器編號
01359F  bx <<= 2                       ; × 4
0135A3  bx += 7494h                    ; ← **基底**
0135A7  INT 3F:6E                      ; 印
```

代回去:

| 位址 | `(位址 − 7494h) ÷ 4` | 名字 |
|---|---:|---|
| `7580` | **59** | `None` |
| `7584` | **60** | `Hands` |
| `7588` | **61** | `Bite` |
| `758C` | **62** | **`Fangs`** |

`7680` 落在**另一張表**(§2):`(7680 − 7590) ÷ 4` = **60** 的小寫名。

> **判準**:`mov dx, <絕對位址>` 這種寫入端**不帶索引資訊**。
> 要知道第幾格,得找到用 `基底 + 索引 × 元素大小` 讀它的那一支 ——
> 而那一支的基底不會出現在寫入端的任何一行(`7494` 與 `7580` 差 236)。
> 這也是 `find_dsref.py` 掃不到的原因:整張表沒有一次以 `ds:XXXX` 的形式出現,
> 連 `[reg+7580h]` 都沒有 —— 它只以**立即數**現身。
> `tools/ida/find_disp.py` 掃的是「任何位址文字」,對這種目標一次就中(7 處)。
>
> ⚠ **那支工具早就在 `tools/ida/` 裡**,這一輪卻先動手寫了一支功能重複的。
> `CLAUDE.md` §6 的三十秒檢查第 2 條(`grep tools/`)擋得住,而它沒有被執行。

## 2. 這幾格是 `ITEMS.DAT` 陣列的尾巴,不是另一張表

載入迴圈(`0x1085E`–`0x1089F`)一次填五個陣列,索引 `ds:9378`:

| 基底 | 步長 | 內容 |
|---|---:|---|
| `7494` | 4 | 名稱(字串描述子)|
| `7590` | 4 | 小寫名 |
| `7684` | 2 | 欄4(武器傷害 / 防具值)|
| `7702` | 2 | 欄5(加值)|

相鄰兩個基底的距離都對應 **63 格**(`7590 − 7494 = 4 × 63`、
`7702 − 7684 = 2 × 63`),而 `ITEMS.DAT` 只有 **57 筆**
([`190`](190-items-col6-is-break-chance.md) §2)。

**59–62 是檔案讀完之後在 `0x10463` 手工補上的四格。** 57/58 留白。

同一段也補了數字表(`7684 + 2i`):

| 編號 | 名字 | 欄4 |
|---:|---|---:|
| 59 | `None` | 0 |
| 60 | `Hands` | 2 |
| 61 | `Bite` | 3 |
| 62 | `Fangs` | 3 |

## 3. 與 `MONSTERS.DAT` 對上

`MONSTERS.DAT` 欄5 只有 **0–13** 與 **62** 兩群([`191`](191-poison-on-hit.md) §4),
而欄5 = 0 的怪物在建場時換成 **60**([`formats/03`](../formats/03-monsters-dat.md))。

| 欄5 | 屬性 4 | 顯示 | 誰 |
|---:|---:|---|---|
| 0 | 60 | `Hands` | 13 隻空手的 |
| 1–13 | 1–13 | `ITEMS.DAT` 的名字 | 其餘 56 隻 |
| 62 | 62 | **`Fangs`** | 眼鏡蛇、死亡蝮蛇、食屍鬼、坑蝮蛇、響尾蛇 |

**`Fangs` 那五隻正是 [`191`](191-poison-on-hit.md) 的中毒名單** ——
兩篇各自從不同的碼段讀出 62,結論互相印證。

**`None`(59)不是武器,是防具那一格的哨兵。** 角色的裝備欄位移 36 = `99`
(未裝備)時屬性 5 填 **59**([`75`](75-character-record-equipment.md) §1),
而屬性 5 查的是同一張名稱表 —— 所以 59 的 `None` 是「沒穿防具」要說的話。
同理 60 的 `Hands` 對應位移 34 = `99` 的「沒拿武器」。

⚠ **只有 `Bite`(61)找不到來源**:怪物欄5 是 0–13 與 62、角色走 0–56 與
59/60 兩個哨兵,沒有任何一條路徑產得出 61。與
[`186`](186-monster-ai-target-placement-cast.md) §1.1 的「錨點 8 永遠挑不到」、
[`188`](188-dispell-undead.md) §3.1 的「圖組 4 是空的」同一種形狀。
⛔ 不要為了「補滿」去編一條怪物用 `Bite` 的規則。

> ⚠ 這一段差點寫成「59 與 61 都是死格」—— 因為只掃了 `MONSTERS.DAT` **欄5**。
> **名稱表是武器與防具共用的**,少掃一個消費端就會把活著的格子判成死的。

## 4. 隊員走另一條路:未鑑定的武器印小寫名

`0x13587` 的 `jl` 只把**怪物**送去查表。攻擊者是隊員時走 `0x135B4`:

```
0135B4  bx = (ds:93A6 − 8) × 4 + 34E0h   ; 角色記錄基底
0135CF  ds:66D0 = 22h                    ; 34
0135DB  call 0x10083                     ; ax = CVI(MID$(記錄, 34, 2)) = 裝備武器的**背包格號**
0135DE  ax += 4Ah                        ; 74
0135E9  INT 3D:0A                        ; MID$(記錄, 74 + 格號, 1)
0135F0  與 ds:94CC = "1" 比較
0135F8  jz  → 0x135FD                    ; **已鑑定 → 名稱表(7494)**
        否則 → 0x13623                   ; **未鑑定 → 小寫名表(7590)**
```

位移 74–83 是背包十格的「已辨識」旗標
([`formats/01`](../formats/01-chars-dat.md)、[`167`](167-record-field-accessor-and-identified-flags.md) §2)——
這裡是它的**第四個消費端**:`ITEMS.DAT` 的兩個名稱欄
(`名稱,小寫名`)分別是鑑定前後要說的話。

兩條分支的索引算式相同(屬性 4 × 4),差別只在基底。
