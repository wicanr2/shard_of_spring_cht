# 194 — 兩個句子片段歸位:`MAZEMOVE ' is'` 與 `CAMP ' pts!'`

> 輸入:`MAZEMOVE.EXE`、`CAMP.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(兩段都逐行讀出組裝順序)。

`translations/module-text/` 裡有兩段一直標「引擎的版面對不起來」而**沒有說出它是哪一句**。
標成「對不起來」而不知道原句,與「還沒查」是同一件事 —— 這一篇把它們讀完,
結論仍然是不接,但**是知道了才決定不接**。

## 1. `MAZEMOVE:82 ' is'` —— 治療池訊息的繫詞

`0x13800`–`0x13888` 把治療池的回饋拼成一句:

```
013813  call loc_10043 → 角色記錄
013835  MID$(記錄, 2, 10)          ; 名字
013847  ds:9522 = ' is'            ; ← 這一段
01386A  ds:950E = 'healed'
013872  印 ds:9504                 ; 回復量
013880  ds:9518 = ' pts.'
```

**原句是 `<名字> is healed <N> pts.`**

引擎印的是「`<名字> 已治療 N 點。`」(`engine/maze_prompt.go`,
MAZEMOVE:80 + 81 已接)。中文的這一句**沒有繫詞可以放** ——
「是」擺進去只會壞掉。這一段因此在引擎裡沒有對應的字,不接。

⚠ 這與「引擎少做了一件事」不同:**該說的話一個字都沒少**,
少的是英文文法要求、中文不要的那個連接詞。

## 2. `CAMP:102 ' pts!'` —— 側欄數字的即時更新

`0x11F7A`–`0x1209F`:

```
011F7A  cmp ds:7482h, 5                  ; **效果類別 == 5(生命值)?**
011F84    是 → ds:70BE = 1Ch(28)        ; 記錄位移 = 當前生命值
          ds:773E = 22h(34)             ; 螢幕欄 34
011F93    否 → ds:70BE = 20h(32)        ; 記錄位移 = 當前法力
          ds:773E = 26h(38)             ; 螢幕欄 38

011FCC  ds:7740 = CVI(MID$(記錄, 位移, 2))      ; 當前值
011FE8  ds:7742 = CVI(MID$(記錄, 位移−2, 2))    ; **最大值**
011FEE  ds:7744 = ds:773C + 當前值               ; 增量 + 當前
012005  cmp 最大值, 新值 / 夾在最大值
012031  MID$ 寫回(記錄, 位移) = 新值
01207B  LOCATE(角色列 + 1, ds:773E)
        印 ds:773C(增量)+ ds:7746(' pts!')
```

**原句是側欄那一格上的 `<增量> pts!`** —— 直接蓋在角色列的生命值/法力欄位上,
當成一次性的視覺回饋。引擎把施法結果寫在訊息列(`ts.msg`),
側欄永遠顯示數值本身,沒有這個「暫時蓋掉」的位置。不接。

順帶確認 `CHARS.DAT` 的四個位移成對:**26/28 = 最大/當前生命值、
30/32 = 最大/當前法力** —— 讀最大值的方式就是「位移減 2」
([`formats/01`](../formats/01-chars-dat.md) 已列,這裡是第二個獨立佐證)。
