## 1. `E)quip` 的武器技能閘門(`CAMP 0x10A87`–`0x10B30`)

```
010A87  ds:352C = 背包格 → 道具編號
010AAE  ds:714C = CVI(MID$(記錄, 54 + 2i, 2))    ; **裝的那件的道具編號**
010AB4  編號 < 0 或 > 11 → 回選單                 ; **只有 0–11 是武器**
010ACE  cmp ds:714C, 0 / jg → 檢查                ; **編號 0(匕首)不檢查**

010AEC  MID$(記錄, 15, 1) 與 ds:715C = "2" 比     ; dx = −1 若**是巫師**
010B07  bx = [ds:714C × 2 + 6822h]                ; 查表 → 技能編號 − 1
010B0B  位移 = 表值 + 42                          ; = 41 + 技能編號(re/94)
010B15  MID$(記錄, 位移, 1) 與 ds:67DC = "0" 比    ; cx = −1 若**沒有那項技能**
010B27  or cx, dx / jnz → 印 'NO SKILL !'
```

**巫師 或 沒有對應技能 → `NO SKILL !`,裝不上去。**

### 1.1 查表的內容是從 `DATA` 敘述讀到的,不是推的

`0x12D46`–`0x12D64` 是 `RESTORE` + 12 次 `READ` 填 `ds:6822 + 2i`。
`DATA` 的原文就在 `CAMP.EXE` 的資料段裡(位移 `0x3E00` 附近的可列印區):

```
0,1,0,2,2,0,1,0,2,0,1,0
```

配上 `ITEMS.DAT` 的前 12 件(全部是武器):

| 編號 | 道具 | 表值 | 技能編號 | 技能 |
|---:|---|---:|---:|---|
| 0 | 匕首 | 0 | — | **不檢查**(`> 0` 的閘門擋在前面)|
| 1 | 小斧 | 1 | 2 | Axe |
| 2 | 短劍 | 0 | 1 | Sword |
| 3 | 釘錘 | 2 | 3 | Mace |
| 4 | 晨星錘 | 2 | 3 | Mace |
| 5 | 闊劍 | 0 | 1 | Sword |
| 6 | 戰斧 | 1 | 2 | Axe |
| 7 | 雙手劍 | 0 | 1 | Sword |
| 8 | 釘錘+1 | 2 | 3 | Mace |
| 9 | 劍+1 | 0 | 1 | Sword |
| 10 | 斧+1 | 1 | 2 | Axe |
| 11 | 劍+2 | 0 | 1 | Sword |

名字與技能一一對得上(斧→Axe、劍→Sword、錘→Mace),**而這是核對不是推導** ——
表本身是讀到的。

⚠ **匕首誰都能裝,包括巫師。** 那不是特例補丁,是 `cmp ds:714C, 0 / jg`
這一行的直接後果:編號 0 進不了檢查。

> **判準**:`READ`/`DATA` 填出來的表,**表值本身在執行檔的可列印區**。
> 與其從反組譯猜語意,不如直接把那一行 `DATA` 找出來 ——
> 這一段從「12 個未知數」變成「一行文字」只花了一次 `grep`。

## 2. `TOWN:54 Not enough IQ !` = 技能點數不夠(`TOWN 0x11610`–`0x11637`)

```
0113E7  [bp-6] = CVI(MID$(記錄, 89, 2))          ; 剩餘技能點數
0113F9  ax     = CVI(MID$(記錄, 20, 2))          ; 智能
011405  ax += [bp-6] − ds:7248 + 1
01140D  ds:725C = ax                              ; 可用的點數

0115F3  位移 = 技能索引 + 42                      ; 技能旗標
011608  已經是 "1" → 回去(學過了)
011617  bx = 技能索引 × 4 + 6D28h                 ; 技能名字串
011623  MID$(技能名, 22, 1)                       ; **括號裡那個數字**
011630  INT 3D:13  VAL()
011633  INT 3F:A6  比較 / jb → 'Not enough IQ !'
```

技能名的字面就是 `"1)  Sword           (2)"` —— **第 22 個字元是括號裡的成本**
([`178`](178-settings-from-three-sources.md) §1 已經把那組成本抽成
`town.SkillCost`)。

**規則:可用點數 < 該技能的成本 → `Not enough IQ !`。**

⚠ 「IQ」不是智能本身:`CHARS.DAT` 位移 89(剩餘技能點數)**創造時 = 智能**
([`formats/01`](../formats/01-chars-dat.md)),原版沿用了那個名字。
引擎的 `town.LearnNotEnough` 就是這一句。

⚠ `ds:7248` 沒有追(它在 `智能 + 剩餘點數 − ds:7248 + 1` 裡)——
引擎用的是 `SkillPts` 本身。**比較的形狀是讀到的,可用點數的完整算式不是。**

## 3. 兩個照明法術(`CAMP 0x124B6`–`0x124EF`,寫回在 `0x12E07`)

效果類別 12 裡風行術以外的兩個(魔法火炬、水晶燈術,
[`193`](193-wind-walk-teleports-to-8-8.md) §5 留的未解項):

```
0124B6  ax = ds:7484(欄4)
0124BB  imul ds:74CA(投入的法力)
0124C3  ÷ ds:7486(欄5)
0124D2  INT()                              ; INT(欄4 × 投入 ÷ 欄5)
0124D8  × ds:7866 = MBF **5**
0124DE  + ds:786A = MBF **20**
0124E4  INT 3F:77 → 整數
0124E7  xchg ax, bx                        ; ax = 結果、**bx 一路都是欄4**
0124E8  ds:365A = 結果                     ; 照明回合數
0124EB  ds:761C = 欄4                      ; 能見度
0124EF  call 0x12E07 → 寫回並印
```

`0x12E07` 把兩個值寫進隊伍記錄:

```
012E19  ds:66CA = 3Bh(59)   ← 能見度      = 欄4
012E38  ds:66CA = 2Dh(45)   ← 光源回合數  = 上面的結果
012E52  印 'You now have about' + 回合數 + ' turns of light.'
```

**規則:**

```
照明回合數 = INT(欄4 × 投入 ÷ 欄5) × 5 + 20
能見度     = 欄4
```

### 3.1 能見度那一項有獨立佐證

| 法術 | 欄4 | → 能見度 |
|---|---:|---:|
| 魔法火炬 | 3 | **3** |
| 水晶燈術 | 4 | **4** |

而 [`135`](135-groups-record-5-is-a-real-save.md) 從出貨存檔量到
「位移 59/61 = **3 / 2** = 有光 / 無光的能見度」—— **有光那一格正是 3**,
與魔法火炬的欄4 相同。兩個獨立來源對上。

水晶燈術的 4 比火炬亮一格,而它的法力單價一樣是 2、威力 4 > 3 ——
**同一個欄位同時決定亮度與持續回合**,所以「更貴的燈更亮也更久」是一致的。
