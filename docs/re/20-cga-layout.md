# 20 — CGA 像素佈局定案

日期:2026-08-13
接續:[`19-bsave-container.md`](19-bsave-container.md)
子系統:**H. 圖形格式**

## 結論

顯示格式是 **CGA 320×200、每像素 2 bit、掃描線分兩區交錯**。
用 `STARTUP.BIN` 解出的畫面結構完全連貫,佈局可辨識。

## 1. 格式

```
每列 80 bytes × 4 像素/byte = 320 像素
每像素 2 bit(4 色),高位在左:bit 7-6 = 第 0 個像素
偶數列:offset 0x0000 + (列 ÷ 2) × 80
奇數列:offset 0x2000 + (列 ÷ 2) × 80
總計   8192 × 2 = 16384 bytes = 16 KB
```

**信心等級:證據充分。**

三條互相獨立的支持:

1. `STARTUP.BIN` 的 BSAVE 標頭記著 `0xB800:0000`、長度 16384
   ([`19`](19-bsave-container.md) §1.1)—— 那是 CGA 圖形頁的標準位址與大小
2. 算術自洽:80 bytes × 4 像素 = 320,8192 ÷ 80 = 102.4 ≈ 100 列 × 2 區 = 200 列
3. **解出來的畫面有連貫的結構**:一條水平框線、一條垂直分隔線(約在第 39 欄)、
   左側是有外框的面板、右側是方塊狀的文字區

第 3 條是關鍵。**錯誤的佈局假設會讓畫面碎成斜線或雜訊**
(kb:「視覺產物一律 dump 出來肉眼比對」)——
交錯區搞反、或每列 bytes 數算錯,框線就不會是直的。

`CONFIG.SOS` 的內容是 `C,C, 1000 , 0`([`01`](01-inventory.md) §4.4),
第一個 `C` 與 CGA 相符,但那是**旁證不是證據**(未查讀取端)。

## 2. 這打開了什麼

`STARTUP.BIN` 解對之後,同一套佈局可以套到其他素材:

| 素材 | 資料 bytes(扣 BSAVE 標頭) | 待驗 |
|---|---:|---|
| `PICT1/2/6/7/8.BIN` | 5,972 | 尺寸未知 |
| `MONST1`–`MONST22.BIN` | 734 | 尺寸未知 |
| 98-byte 圖塊群(9 個) | 90 | 尺寸未知 |
| `DE*EFF.BIN`(10 對) | 1,060 | 尺寸未知 |

⚠ **不要假設它們也是整頁佈局。** 小圖通常是連續存放(不交錯),
而且可能自帶尺寸欄位。`docs/re/19` §3 記過一次教訓:
把容器標頭當成尺寸欄。**先扣 BSAVE 標頭,再找尺寸。**

90 bytes 的圖塊:若是 2bpp 連續存放,`90 = 寬bytes × 高`,
候選有 `2×45`(8 像素寬)、`3×30`(12 像素)、`5×18`(20 像素)、
`6×15`(24 像素)、`9×10`、`10×9`、`15×6`、`18×5`、`30×3`、`45×2`。
**九個同尺寸的檔可以互相印證** —— 正確的尺寸會讓九個都畫得出可辨識的圖案
(水、熔岩、門、牆…),錯的尺寸會讓九個都是雜訊。
