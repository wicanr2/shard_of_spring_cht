## 1. 結算之後有兩條掉落路徑

經驗與金幣結算完(`0x12E60` 起,[`152`](152-experience-settlement-formula.md))接著:

```
012F50  cmp ds:352Ch, 63h      ; **99 = 沒有指定的道具**
012F55  jl  → 0x12F5A          ; 有指定 → 路徑 A
012F57  jmp → 0x1305F          ; 沒有   → 路徑 B(隨機)
```

`ds:352C` 是道具編號,末尾 `0x1328C` 把它復位成 99。

### 1.1 路徑 A:指定的道具,**不問就塞進去**

`0x12F5A`–`0x1305C`:兩層迴圈(角色 `ds:9378` 由隊尾遞減、背包格 `ds:93B0` 由 10 遞減),
找到 `MID$(記錄, 54+2i, 2) == 99` 的空格就:

```
012FB6  印 <名字> + ds:96D8(' found ') + **小寫名**(ds:7590 + 4×編號)
012FF0  訊息框
013011  MID$(記錄, 54 + 2×格號) = 道具編號
013035  ds:93B0 = 0 / ds:9378 = 0        ; 把兩個迴圈計數歸零 → 離開
```

**沒有 Y/N**。用的是**小寫名**表 —— 撿來的東西是未鑑定的([`192`](192-natural-weapon-names.md) §4)。

### 1.2 路徑 B:隨機道具,**要問 Y/N**

`0x1305F`–`0x1328C`:先擲出編號(§3),再用同一組雙層迴圈找空格,然後:

```
013146  LOCATE 0Bh,17h
01315B  印 <名字>(ds:6A98 + 4×(角色索引+8))
013171  印 ds:96F2 = 'finds'          ; ← **CMBT:61**
013192  印 小寫名(ds:7590 + 4×編號)+ ds:971A('.')
0131C6  印 ds:96FC = 'Do you take it?'  ; CMBT:62
0131E8  印 ds:9710 = '(Y/N)'           ; CMBT:63
013202  讀輸入,與 ds:9724 = 'Y' 比
013217  jz  → 0x1321C                   ; **答 Y 才寫進背包**
01321C  MID$(記錄, 52 + 2×ds:93B0) = ds:352C
```

⚠ **引擎目前把 CMBT:58/59/60/62/63 全部接在金幣那一句上**(`engine/exp.go`)。
`Do you take it?` / `(Y/N)` 兩句原版**兩條路徑共用**,而 ` found `(CMBT:60)
其實是**路徑 A 的道具句**,不是金幣句。⚠ 那個接線要在實作掉落時一起訂正。

## 2. 迷宮:六個腳本事件各給一件固定道具

`MAZEMOVE` 的 `sub_1393E`([`168`](168-loot-pickup-and-an-off-by-one.md) §1 讀的那一支)
被**六處** `call` 到(`tools/ida/range_xref.py`),每一處在呼叫前把道具編號填進參數:

| 呼叫位址 | 編號 | 道具 |
|---|---:|---|
| `0x11B94` | 49 | 鑰匙 |
| `0x11E49` | 48 | 油燈 |
| `0x11E9F` | 50 | 銅鑰匙 |
| `0x11EF5` | **6** | **戰斧** |
| `0x12135` | 52 | 金鑰匙 |
| `0x13057` | 29 | 風暴戒 |

**四把鑰匙類 + 一件武器 + 一枚戒指** —— 與「鑰匙的欄6 = 0(永不損壞)」
([`190`](190-items-col6-is-break-chance.md) §3)一致:它們是解謎道具。

兩件對得上房間敘述:

| 事件 | `DT*TEXT.DAT` 的敘述 |
|---|---|
| `DT2` 第 202 條 | 「你在房間角落發現一把小鑰匙。」→ 鑰匙(49)|
| `DT3` 第 305 條 | 「一人的戰斧插在頭骨上……」→ 戰斧(6)|

⚠ **六處各由哪個事件觸發沒有解出來。** 已經縮小的部分:

- `ds:3532` 是**事件目標編號**(`0x115C4` 比 `0CCh` = 204 祭司、
  `0x115D9` 比 `215h` = 533 最終首領,兩個都對得上引擎既有的常數)
- `tools/ida/imm_range.py` 掃 100–800 的**全部立即數**,
  `cmp` 只有那**兩處** —— 所以其餘事件**不是用 `cmp ds:3532, N` 派工的**
- 六個呼叫端都在長長的線性腳本序列裡(`0x11B94` 前面還在填 `ds:372C` 的
  腳本怪物清單,[`180`](180-scripted-fight-monster-list.md)),
  往前 `range_xref` 兩個視窗都沒有遠處跳進來的邊

**下一步是讀 `sub_13EC6`**(`0x115AE` 的逐列比對常式,迴圈上界 105 =
事件表 106 列,[`60`](60-event-lookup-and-tile-19.md)):派工八成在它裡面
或它的回傳值上。

## 3. 隨機編號怎麼擲

### 3.1 值域是 **2–46**(已確認)

```
0130D3  ds:352C = 擲出來的值
0130D6  bx = (值 < 2)  ? −1 : 0
0130DF  dx = (值 > 46) ? −1 : 0
0130E8  or dx, bx / jnz → 0x1307A     ; **超出範圍就重擲**
```

`ITEMS.DAT` 編號 47/48 是火把與油燈、49–55 是鑰匙與王家印璽、56 是傳送器
—— **上界 46 正好把消耗品與解謎道具擋在外面**。
下界 2 也對得上:0 是匕首、1 是小斧,兩件最便宜的武器不掉。

⚠ 44–46 是精靈寶石 / 恐懼之眼 / 邪徽,**在範圍內** ——
所以上界不是「排除任務道具」,只是排除鑰匙那一段。

### 3.2 算式:兩個獨立的 `RND`,上限跟著這場的金幣走

`ds:96AC` 是**金幣的整數累加器**([`152`](152-experience-settlement-formula.md) §2:
每打倒一隻就 `ds:96AC += 這一隻的金幣`)。掉落用的就是它:

```
01305F  FAC ← ds:96AC                  ; 3F:57
013068  FAC ×= ds:96E8 = MBF **0.575** ; 3F:91
013070  bx  ← INT(FAC)                 ; 3F:77(四捨五入)
013075  ds:96AC = bx                   ; ★ G = round(總金幣 × 0.575)

01307A  FAC ← G
013083  變數81 ← FAC                    ; 3F:71 內嵌 81
013089  FAC ← RND                       ; 3D:34
01308E  FAC ×= 變數81                   ; 3F:95 內嵌 81   → G × RND₁
013097  FAC ×= ds:9460 = MBF **0.5**    ; 3F:91
01309C  變數82 ← FAC                    ; 3F:71 內嵌 82   → G × RND₁ × 0.5
0130A2  FAC ← RND                       ; 3D:34
0130A9  FAC ×= 變數81                   ; 3F:95 內嵌 81   → G × RND₂
0130B1  FAC ×= 0.5                      ; 3F:91
0130B6  FAC ← 變數82 + FAC              ; 3F:85 內嵌 82
0130BF  FAC += ds:96EE = MBF **2**      ; 3F:81
0130C4  FAC ← INT(FAC)                  ; 3D:03(截尾)
0130CC  bx  ← FAC                       ; 3F:77
0130D3  ds:352C = bx
```

**編號 = `INT( G×RND₁×0.5 + G×RND₂×0.5 + 2 )`,不在 2–46 就整段重擲。**

`3F:71`(`[內嵌變數] ← FAC`)、`3F:95`(乘的第三個進入點)、
`3F:85`(`[內嵌變數] + FAC`)三個索引的語意在
[`77`](77-runtime-arithmetic-api.md) §1 與 [`184`](184-levelup-hp-sp-growth.md) §7
已經定案 —— **內嵌編號 81 / 82 配對出兩個暫存**,不是猜的。

> **判準**:這三個索引一度被記成「未知,擋住實作」。它們**早就解過了**,
> 只是那一輪沒有 `grep docs/`([`CLAUDE.md`](../../CLAUDE.md) §6 的三十秒檢查)。
> 「感覺以前碰過」就是碰過。

### 3.3 兩個獨立 `RND` 相加是三角分佈,不是均勻

`RND₁ + RND₂` 讓結果集中在 `G×0.5` 附近,兩端稀疏。
⛔ **不能簡化成一次 `RND`** —— 值域一樣,分佈完全不同
([`156`](156-attribute-roll-shape.md) 記過同一個坑)。

⚠ 上限跟著**這場的金幣**走,所以硬仗掉好東西是資料驅動的,
不是另外一張難度表。
