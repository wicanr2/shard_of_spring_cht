# 202 — 迷宮事件的兩層派工,以及六件定點道具各屬於哪個事件

> 輸入:`MAZEMOVE.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(兩層跳表的位元組逐筆解出;基底用兩個已知事件反推並互相印證;
> 六件裡三件與房間敘述對得上)。

關掉 [`200`](200-loot-drops-mechanism.md) §2 的「六處各由哪個事件觸發沒有解」,
接線 `MAZEMOVE:84/85`。

## 1. 派工是兩層 `ON … GOTO`,不是一串 `cmp`

先前掃過 `MAZEMOVE` **全部** 100–800 的立即數,
`cmp ds:3532h, N`(事件目標編號)只有 204 與 533 兩處 ——
所以其餘事件不是用比對編號派工的。真正的機制在 `0x117D7`–`0x1182C`:

```
0117CE  ax = 事件目標編號
0117D2  ds:3532 = ax
0117D7  FAC ← ax
0117DC  di = 8F04h              ; **ds:8F04 = MBF 100**
0117DF  FAC ÷= 100
0117E4  INT()
0117F3  ds:8F02 = 結果          ; ★ **迷宮編號 = INT(事件編號 ÷ 100)**

011827  bx = ds:8F02
01182B  inc bx
01182C  INT 3F:5D + 內嵌跳表     ; ON bx GOTO
```

第二層在每個迷宮分支的開頭,形狀一樣:

```
011B1A  ax = 100
011B1D  imul ds:8F02h           ; 100 × 迷宮編號
011B21  bx = ds:3532h
011B25  sub bx, ax              ; ★ **事件序號 = 編號 − 100 × 迷宮**
011B27  INT 3F:5D + 內嵌跳表     ; ON 序號 GOTO
```

⚠ **`INT 3F:5D` 之後那一串「亂碼」是跳表本身**,不是資料殘骸。
IDA 不會把它切成指令,`tools/ida/raw_bytes.py` 才看得到:

```
01182C  cd 3f 5d 90 90 | 08 | eb 18 | 73 19 | 0a 1b | ab 1c | 7e 22 | 08 23 | f7 2b | 92 2c
        ^INT 3F:5D       ^筆數  ^八個 16-bit 位移
```

## 2. 位移的基底是 **`0x10010`**,不是 `0x10000`

跳表存的是**段內位移**,而線性位址 = `0x10010 + 位移`。
這個 `+0x10` 是拿兩個已知事件反推出來、再用第三個驗證的:

| 檢查 | 位移 | `+0x10010` | 那裡是什麼 |
|---|---|---|---|
| 頂層第 3 筆(迷宮 2) | `0x1B0A` | `0x11B1A` | 正是第二層 `ax = 100 / imul ds:8F02` |
| 頂層第 4 筆(迷宮 3) | `0x1CBB` | `0x11CCB`… | 同形(表在 `0x11CCB`) |
| 迷宮 2 的第 2 筆 | `0x1B2E` | `0x11B3E` | 事件處理常式的第一行 `mov ax, ds:3532h` |

**事件處理常式的形狀固定**:開頭 `a1 32 35`(`mov ax, ds:3532`,拿去取 DT 文字)、
結尾 `c3`(`retn`)。用這個形狀掃就能切出每一段的邊界 ——
⚠ 用「參數寫入緊接在 `call` 之前」去猜邊界**會差一格**,
因為 `mov ds:XXXX, <道具編號>` 是常式的**最後一段**,不是下一段的開頭。

## 3. 六件定點道具

`sub_1393E`([`168`](168-loot-pickup-and-an-off-by-one.md) §1 讀的「塞進背包」那一支)
被六處 `call`,把每一處放回上面切好的邊界裡:

| 事件 | 道具 | `DT*TEXT.DAT` 的房間敘述 |
|---:|---|---|
| **202** | 鑰匙(49)| 「你在房間角落發現一把小鑰匙。」 ✅ |
| **303** | 油燈(48)| 「某人的臥房。」 ✅ |
| **304** | 銅鑰匙(50)| 「一間小房間的角落。」 |
| **305** | 戰斧(6)| 「一人的戰斧插在頭骨上……」 ✅ |
| **314** | 金鑰匙(52)| 「空房間。」 |
| **705** | 風暴戒(29)| Eldron 的氏族謎題 |

**三件與房間敘述直接對得上**(小鑰匙、臥房裡的油燈、插在頭骨上的戰斧)——
那是獨立於跳表解讀的印證:如果基底差一格,這三件會全部錯位。

⚠ **705 是特例**:那一段是 `TargetRiddle`(Eldron 謎題)的處理常式,
`0x13042` 的 `mov ds:9270h, 1Dh`(29)在常式**內部**,不是進門就給 ——
它是**答對的獎賞**。引擎因此把它接在 `riddleKey` 的成功分支,不在踩格那一支。

⚠ 金鑰匙(314「空房間」)與事件 318「這扇門被一把金色的鎖鎖住了」是一對。

## 4. 對 remake 的影響

`maze.LootEvents` 五筆 + `maze.RiddleReward`;
`giveMazeItem` 照 [`168`](168-loot-pickup-and-an-off-by-one.md) §1
**由隊尾往隊首**掃(與戰後掉落的由前往後相反,兩支各自照抄),
標成未鑑定,全滿印 `MAZEMOVE:85`。

⚠ 順帶補上一個**只有話沒有東西**的缺口:引擎的謎題答對之後印
「Eldron 賜給你一枚戒指。」,而**戒指從來沒有進背包**。
