# 203 — 九個成員槽就是 3×3 陣型格;名冊三個畫面的表頭與提問

> 輸入:`CAMP.EXE`、`CHARUTIL.EXE`、`MAZEMOVE.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(字母範圍、空格條件、三個提問的位址逐行讀出)。

這一篇把最後十段 F3 收掉,而其中**三段先前被判成「不接」的理由是錯的** ——
不是版面問題,是**沒讀懂那個畫面在做什麼**。

## 1. `R)eorder` 是「搬到空格」,不是「兩人互換」

`CAMP:68/69/70` 是一句提問(`Enter new position for: <名字>  Letter?`),
底下接著 `CAMP:71/72/73` 的三行格子圖:

```
  A B C
  D E F
  G H I
```

`0x114D1`–`0x114F7`:

```
0114D1  輸入 與 ds:73AC = 'A' 比 → dx = (輸入 < 'A') ? −1 : 0
0114E0  輸入 與 ds:705A = 'I' 比 → cx = (輸入 > 'I') ? −1 : 0
0114EC  or cx, dx / jnz → 重問          ; **只收 A–I**
0114F7  bx = 輸入 − 41h                  ; **− 'A' → 0…8**
01151B  cmp word ptr [di+683Ch], 63h     ; 目標槽的值
011520  jl → 重問                        ; **< 99 = 那一格有人 → 不准**
```

**九格 = `GROUPS.DAT` 位移 1–18 的九個成員槽**,而
[`135`](135-groups-record-5-is-a-real-save.md) §3 記的「槽有 9 個、人數上限 5」
從此不再是未解:**九格是站位不是名額**,所以永遠有空位可以搬進去。

而 `PartyOffset` 的 `(i−1) mod 3` / `(i−1) ÷ 3`
([`160`](160-party-deploys-three-per-row.md))正是把槽號攤成三欄 ——
**格子圖的 3×3 就是戰場的 3×3。**

> **判準**:先前把 71/72/73 判成「原版的背包格子圖只有 9 個字母而背包是 10 格」。
> 那個判斷**連畫面都認錯了** —— 68/69/70 就在它們正上方,寫著
> `Enter new position for:`。⚠ **相鄰的段就是上下文**,
> 判一段「不接」之前先看它前後兩段在說什麼。

## 2. `(0 exits)` 的兩種寫法屬於兩個不同的提問

`CHARUTIL` 有三處 `(0 exits)`,而**空格不一樣**:

| 列 | 原文 | 位址 | 哪一個提問 |
|---:|---|---|---|
| 52 | `(0 exits) ? ` | `0x11B85` | **R)emove**(緊接著 `0x11C26` 的 `Is deleted !`)|
| 54 | `(0 exits) ?` | `0x11DA3` | **D)isband**(緊接著 `0x121E0` 的 `No party #` / `to disband !`)|
| 70 | `(0 exits) ? ` | `0x12668` | **I)nformation**(緊接在 `0x12504` 的兩欄表頭之後)|

引擎先前把 52 的寫法用在解散、而移除**根本沒有問話**(按一下 `R` 就刪掉,
不可逆且沒有確認)。現在三個提問各用各的。

## 3. 兩個表頭是兩個不同的畫面

| 列 | 原文 | 是哪一張表 |
|---:|---|---|
| 46 | `#) Name        Race   Class   Level   Status` | 名冊主畫面 |
| 69 | ` #) Name       Party         #) Name       Party` | `I)nformation` 裡「誰在哪一隊」,**兩欄並排** |

先前判成「原版靠空白補位對齊、引擎是像素定位,所以不接」。
**那個對立是假的**:引擎有 `ui.Cols`(全形算兩欄)——
把表頭整行畫出來、再**從同一行量出每一欄的欄號**給資料列用,
兩種字型下都對得齊,而且改表頭一定連帶改欄位。

⚠ 引擎的名冊比原版多一欄「隊伍」,因為它把原版的兩張表併成一張。

## 4. `One momement..`(MAZEMOVE:29/32)是**換迷宮檔**的等待

`0x123AC` 與 `0x12462` 兩處,形狀相同:印這一句 → 組檔名 → `call sub_134A2`(載入)。
兩處都在迷宮 5 的分支裡,而迷宮 5 有 `DG5MAZE.SQZ` 與 `DG51MAZE.SQZ` 兩層 ——
**這句話是跨層時要換讀另一個迷宮檔**([`60`](60-event-lookup-and-tile-19.md))。

引擎的 `crossLevel` 做的是同一件事,所以接在那裡。
⚠ 引擎讀檔是瞬間的,這一句與結果排在同一行,不是一個會停留的畫面。

## 5. `MAZEMOVE:82 ' is'` 的譯法訂正

治療池的原句是 `<名字> is healed <N> pts.`。
先前把 ` is` 逐字譯成「 是」,再判定「中文沒有繫詞可以放,所以不接」。

**問題出在譯法不是接線**:英文的 `is healed` 在中文是**體貌標記**,
不是繫詞 —— 對應的字是「**已**」。譯文改成「 已」之後,
引擎原本就在用的「`<名字> 已治療 <N> 點。`」正是這一句。

> **判準**:一段譯文「擺進句子裡不成話」時,先問**譯得對不對**,
> 再問接不接得上。逐字對照的機械譯法會製造出假的接線障礙。
