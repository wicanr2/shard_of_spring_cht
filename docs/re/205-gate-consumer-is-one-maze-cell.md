# 205 — 大門的消費端:迷宮 5 的**一格**從圖塊 9 改成 16

> 輸入:`MAZEMOVE.EXE`、`DG5MAZE.SQZ`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(寫入端逐位元組讀出;索引換算由陣列容量與迷宮資料兩邊互相印證)。

關掉 [`197`](197-daza-reveli-gate.md) §6 的「**誰讀位移 65**」——
唸對 `DAZA REVELI` 會把旗標寫進隊伍記錄,而在引擎裡門開了仍然過不去。

## 1. 消費端與寫入端條件相同

`MAZEMOVE` `0x1364B`–`0x13684`:

```
01364B  cmp word ptr ds:3534h, 5     ; 當前迷宮 == 5(docs/re/204 §1)
013650  bx = 0 / jnz +1 / dec bx     ; bx = 相等 ? −1 : 0
013656  cx = bx
013658  bx = 34DCh / dx = 66CCh / INT 3F:61   ; 綁定隊伍記錄
013663  mov word ptr ds:66D0h, 41h   ; **位移 65**
01366C  call loc_10083               ; CVI(MID$(記錄, 65, 2))
01366F  and ax, [bp-6]               ; AND (迷宮 == 5)
013674  jnz → 13679                  ; 兩項都成立
013679  mov word ptr ds:707Eh, 10h   ; ★ 效果只有這一行
01367F  INT 3F:54 / retf 2
```

**條件與 `CAMP` 那一邊一字不差**(迷宮 5 + 旗標),
所以旗標存在隊伍記錄裡就夠 —— 每次進迷宮都重跑這一段,不必改迷宮檔。

## 2. `ds:707E` 不是「寫了沒人讀」,它是**陣列的一格**

`ds:707E` 在**十二支模組裡只出現這一次**(`tools/ida/find_bytes.py`
逐位元組掃過,不是掃反組譯文字)。看起來像死寫入,實際上:

模組開場 `0x135A0` 一次清掉整個數值陣列區:

```
0135A0  mov di, 6822h / mov cx, 2046h / INT 3F:4D
```

`0x2046` bytes = 4131 word = **81 × 51**,正是一層迷宮的格數
(`.SQZ` 解出 81 列 × 每列 ≤ 51 格,[`formats/06`](../formats/06-maze.md) §1)。
所以陣列從 `ds:6822` 起,而

```
(0x707E − 0x6822) ÷ 2 = 1070
```

—— **編譯器把常數索引折算成了位址**。索引 `欄 × 81 + 列` 拆開:

```
1070 ÷ 81 = 13 …… 17     →  欄 13、列 17
```

> **判準:一個只被寫一次、沒有人讀的位址,先問它落不落在某個陣列裡。**
> 掃遍全部模組都找不到讀端,不代表沒有讀端 —— 陣列的讀端寫成
> `[di+6822h]`,基底是**陣列頭**,不是那一格。
> 同一個陣列區的容量(`INT 3F:4D` 的 `cx`)就是換算所需的全部資訊。

## 3. 那一格是走廊上唯一的阻擋

解開 `DG5MAZE.SQZ`,列 17 / 欄 13 的值是 **9**,而上下兩格是 0:

```
列 15    …  0  0  0  0 [0] 0  0  0  7
列 16    …  0  0  0  0 [0] 0  0  0  7
列 17    …  7  7  7  7 [9] 7  7  7  7     ← 門
列 18    … 22 22 22 22 [0] 2  2  2  2
列 19    … 22 22  2  2 [0] 2 22 22  2
```

一條沿著欄 13 的走廊,被夾在一整排牆(7)中間的**一格**封住。
可通行性的阻擋區間是 5–10([`formats/06`](../formats/06-maze.md) §2),
所以 **9 擋路、16 可通行** —— 開門就是把這一格放行。

**這是獨立於反組譯的印證**:如果索引換算差一格,落點幾乎一定是 0 或 7,
不會剛好是一個被牆包住、上下都是空地的特例值。

⚠ `DG51MAZE.SQZ` 的同一格是 0 —— 旗標只對 `DG5` 有意義,與程式碼的
「迷宮 == 5」一致。

## 4. ⚠ 兩邊的 Major/Minor 定義相反(**未解**)

原版乘 81 的那一軸有 **51** 個值(= 一列裡的第幾格),另一軸有 81 個值(= 第幾列)。
引擎的 `original.Maze` 把**解碼出來的第幾段**當成 `Major`
(`Cells[a*81+b]`,`a` = 段號),於是 `Majors` 是 82 而不是 51 ——
**兩者是轉置關係**。

引擎內部處處用同一套約定,所以自洽;會出問題的只有「從原版搬一個**絕對索引**進來」,
也就是本篇。換算因此集中在 `internal/maze/gate.go` 一個函式裡,
而 `TestGateCellIsTheClosedGate` 會在任何一邊改動時失敗。

⚠ 事件表的座標欄如果也是原版的軸,引擎現在可能把事件放在轉置後的位置。
`TestMazeDataStartsArePassable` 12/12 通過(轉置後 10/12),
但「落在可通行格」是很弱的判準。**這一項要單獨查**,列進 worklist。

## 5. 對 remake 的影響

`maze.OpenGate(grid, mazeFile, flag)`,在 `loadLevel` 讀完格線之後呼叫 ——
與作廢事件清單同一個位置,理由也相同:迷宮格線每次都是重讀的,
改在別處會在「走出去再走回來」之後失效,而門會**默默地關回去**。
