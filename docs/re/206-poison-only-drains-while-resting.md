# 206 — 中毒**只在營地睡覺**扣血;走路不扣

> 輸入:`CAMP.EXE`、`MAZEMOVE.EXE`、`WRLDMOVE.EXE`、`USERLIB.EXE`
> (SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**證據充分**(扣血那一段逐行讀出;「走路不扣」是三條結構性否證、
> 「戰鬥回合不扣」是屬性 8 的完整成語掃描,不是掃不到)。

[`191`](191-poison-on-hit.md) §5 記著「中毒的**持續效果**不在這一段」。
這一篇回答它:**持續效果只有一個地方,就是睡覺。**

## 1. 睡覺那一段(`CAMP` `0x12F91`–`0x130C3`)

逐角色跑,先把五個值讀進來:

| 來源 | 存到 | 語意 |
|---|---|---|
| `CHARS` 位移 38 | `ds:7B48` | 狀態 |
| 位移 28 | `ds:7B4A` | 當前生命值 |
| 位移 32 | `ds:7B4C` | 當前法力 |
| `GROUPS` 位移 23 | → `ds:7B50` | **補給品 ≤ 0 → 1**(缺糧)|
| `ds:7B48 == 1` | `ds:7B52` | **中毒** |

```
012FDA  狀態 == 5 → 整個跳過          ; 死人不參加
012FE6  [bp+8] 指到的值 == 0 ?
        是 → ds:7B4E = 2、法力 += 10
        否 → ds:7B4E = 1、法力 += 5

013072  中毒?
   是 → [bp+8] == 0 → 生命 −= (缺糧 + 1) × 小時數
                 否 → 生命 = 生命 − 缺糧 − 2
   否 → 生命 = 生命 − 小時數 × 缺糧 + ds:7B4E

0130C3  生命 < 1 → 生命 = 0、法力 = 0
        否則     → 生命 = min(生命, 最大值)、法力 = min(法力, 最大值)
```

**中毒每小時扣 1 點,缺糧再多扣 1 點**,與手冊 p.38 相符。
沒中毒時每小時扣掉「缺糧」點、再回復 `ds:7B4E`(1 或 2)。

⚠ `[bp+8]` 與 `[bp+6]` 是傳進來的兩個參數,**語意沒有讀**
(形狀像「休息的種類」與「小時數」)。所以**這一段沒有照抄進引擎** ——
引擎沿用既有的 `CampPoisonPerHour × CampSleepHours`,與上式在
「不缺糧」的情況下同值。改寫之前要先解出那兩個參數。

## 2. 走路不扣 —— 三條結構性否證

不是「掃不到」,是**沒有地方放得下**:

| # | 事實 | 怎麼查的 |
|---|---|---|
| 1 | `WRLDMOVE` **從不讀寫任何角色記錄欄位** | `ds:66D0`(記錄位移參數)在整支模組零命中 |
| 2 | `MAZEMOVE` 讀角色記錄只有治療池那一叢(位移 38 / 28 / 26) | 同一支掃描列出全部 10 個位移,見 [`155`](155-gem-puzzle-and-healing-pool.md) |
| 3 | `USERLIB` 的推進常式不碰角色資料 | 它讀的記錄位移只有 12 / 27 / 29 / 31 / 59 / 61(時鐘與能見度),而陣列區基底 `6822` 在整支 `USERLIB` 裡**位元組層級零命中** |

第 3 條是關鍵:每個動作要扣血的話,最自然的位置就是那支常式
(時鐘、遭遇倒數、火把都在裡面,[`204`](204-light-burns-per-turn-and-offset-83.md) §2),
而它連角色資料的位址都碰不到。

> **判準:「掃不到」與「放不下」是兩種強度不同的否證。**
> 前者要附掃描分母([`CLAUDE.md`](../../CLAUDE.md) §2.1),而且仍然可能漏;
> 後者是「這段程式碼從頭到尾沒有取得那份資料的途徑」——
> 不必列舉所有可能的寫法。

## 2.1 戰鬥回合也不扣

`CMBT` 用屬性陣列不是記錄,所以 §2 的三條否證對它不成立 —— 另外查:

**屬性 8(狀態)只在十處被拿去與常數比**(位元組層級掃「`add ?, 78h` +
`shl` + `cmp [di+6822h], N`」這個完整成語),其中:

| 常數 | 幾處 | 用途 |
|---:|---:|---|
| **5** | 7 | 「死了沒」|
| 2 | 1 | 回合開始掃「還有沒有人能動」|
| 0 | 1 | 同上,掃怪物那一邊 |
| **1** | **1** | `0x120B4`:輪到某個單位時的「這個人能不能行動」閘門 |

唯一比 1 的那一處(`0x120AD`–`0x120C4`)是:

```
0120A2  cmp 屬性10(朝向) < 0 ?          → dx
0120B3  cmp 屬性8(狀態) > 1 ?           → bx
0120BE  or bx, dx / jnz → 跳過這個單位的回合
```

**離場 或 狀態 > 1 → 跳過**。中毒(1)照樣行動,而且**沒有任何一處把它接到生命值**。

⚠ 順帶:命中的 `+30`(狀態 > 1,[`98`](98-status-level-and-a-sign-error.md))
**中毒也吃不到** —— `> 1` 從被縛起算。

## 3. 對 remake 的影響

**不實作「移動時扣中毒血」,戰鬥回合也不扣。** 引擎現況(只有營地睡覺扣)
與原版一致,不是缺口 —— worklist 上原本把它列成「寫了沒人讀」的缺口,
那個判斷是錯的。

⚠ 手冊 p.38 的「中毒每小時扣 1 HP」講的是**睡覺**那一支的公式,
不是「時鐘每過一小時就扣」。**手冊的句子沒有錯,是我們把它讀成了通則。**
