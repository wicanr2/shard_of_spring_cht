# 210 — 戰場站位看的是**槽號**,不是「隊伍裡的第幾個人」

> 輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(偏移表的填入與取用兩端逐位元組讀出,索引來源同一個變數)。

關掉 [`203`](203-formation-grid-and-roster-screens.md) §6 的第一項 ——
worklist §8.1 C 組的第 6 項。

## 1. 偏移表是**按槽號**填的

[`160`](160-party-deploys-three-per-row.md) §1 已經讀出填表那一段
(`0x11773`–`0x117CF`):迴圈 `i = 1…9`,把

```
欄偏移[i] = (i−1) mod 3 − 1        → ds:7978 + 2i
列偏移[i] = INT((i−1) ÷ 3) + 基準  → ds:7962 + 2i
```

寫進兩張表。**九個槽都算**,不是只算實際在隊的人數。

## 2. 取用那一端用的也是槽號

`tools/ida/find_bytes.py` 掃 `7879` / `6279`(兩個基底的位元組)——
**各只有兩處**:填入的 `0x11793`/`0x117C4`,取用的 `0x1188E`/`0x118A1`。

```
011843  bx = 34DCh / dx = 66CCh / INT 3F:61   ; 綁定**隊伍**記錄
011850  ax = i×2 − 1 → ds:66D0                ; ★ 成員槽的位移 2i−1
01185C  call …                                ; 讀出這一槽的角色編號
01185F  bx = ds:93B0 × 4 + 34E0h              ; 綁定那個角色的記錄
011873  ds:66D0 = 0Ch / call …                ; 讀位移 12
01187F  cmp ax, [bp-0Ah] / jnz → 跳過這一槽
011887  di = [bp-8]                           ; ★ **i(槽號)**
01188C  bx = [di+7978h] + 0Dh                 ; 欄偏移[i] + 13
01189A  [si+6822h] = bx                       ; 屬性 0(x),si = ds:94BC(單位編號)
01189E  bx = [di+7962h] + 0Dh
0118AB  [di+6822h] = bx                       ; 屬性 1(y)
0118B5  i++ / cmp 9 / jle → 011843            ; 迴圈 i = 1…9
```

**查表用的 `di` 就是槽號 `i`**,而寫入的目標 `si` 是**單位編號**
(`ds:94BC`,從 9 起,`0x11CAF` 每建好一個單位才 `inc`)。

兩個索引不同,而**這正是問題的答案**:

| 量 | 決定什麼 |
|---|---|
| **槽號 1–9** | 站在陣型格的哪一格 |
| 單位編號 9–13 | 在單位陣列裡是第幾個(先攻、目標編號都用它)|

## 3. 什麼時候看得出差別

只有**搬到有間隔的槽**時。營地的 `R)eorder` 讓玩家把人搬到 A–I 任何一個空格
([`203`](203-formation-grid-and-roster-screens.md) §1),所以這是玩得到的情況:

```
只有 A 與 G 有人(槽 1 與槽 7)

照槽號(原版)        照人數順序(引擎先前)
  [甲]  .   .           [甲][乙] .
   .    .   .            .   .   .
  [乙]  .   .            .   .   .
```

**兩人並排** vs **一個在前排一個在後排** —— 前排承受近戰、後排相對安全,
所以這不只是畫面差異。

## 4. 對 remake 的影響

`combat.Field.PartySlots`(每位隊員佔第幾個槽,與 `Units[PartyBase…]` 同序)
＋ `original.Group.MemberSlotNumbers()`。`Place()` 用它查偏移表;
沒有槽號資訊時退回舊行為(「隊伍裡的第幾個人」),不要變成 (0,0)。

⚠ **`MemberIDs()` 丟掉了槽號** —— 它回傳的是壓縮後的清單。
這一類「壓縮之後就找不回來的資訊」要在壓縮的同一個地方補一支對應的存取器,
否則下一個需要它的人會重新發明一次。
