# 212 — 世界地圖的定點事件**只有兩處**,其餘是地形觸發

> 輸入:`WRLDMOVE.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(掃遍整支模組對世界座標的比較,五處全部判讀)。

關掉 [`198`](198-islanda-archway-trigger.md) §5 的「`0x10D15` 之後那一串沒掃完」——
worklist §8.1 C 組的第 8 項。

## 1. 掃描分母:五處,不是「一串」

`tools/ida/find_bytes.py` 掃 `cmp word ptr ds:3518h/351Ah, imm`
(世界 x / y 與常數比,兩種編碼都掃)——**整支模組只有五處**:

| 位址 | 比什麼 | 是什麼 |
|---|---|---|
| `0x10C17` + `0x10C22` | y == 35 且 x == 86 | **定點事件 1**:切到 `MAZEMOVE` |
| `0x10C86` + `0x10C91` | y == 57 且 x == 70 | **定點事件 2**:拱門敘述([`198`](198-islanda-archway-trigger.md))|
| `0x10E42` | x > 70 | 遭遇區域(門檻,不是定點)|
| `0x10E4D` / `0x10E6A` | y ≤ 60 | 同上 |

**只有前兩組是「站在這一格會怎樣」。** 後三處是
[`169`](169-encounter-zone-selects-the-monster.md) §結論 4 的三區判定
(`x > 70 且 y ≤ 60 → 3`、`y > 60 → 6`、其餘 → 1),那一篇早就讀過。

> **判準:「那一串沒掃完」要先確認它是不是一串。**
> [`198`](198-islanda-archway-trigger.md) 當時看到拱門的 else 跳到 `0x10D15`,
> 就假設後面接著同型的檢查。實際上 `0x10D15` 起是**遭遇檢查**,
> 而定點事件在拱門的**前面**。掃「這個變數被拿去跟常數比的全部位置」
> 一次就把邊界劃清楚了 —— 比順著控制流往下讀便宜得多。

## 2. 進地城與進城鎮走的是**地形值**,不是座標

拱門前面那三段的形狀相同,比的是 `ds:CD60`(腳下的地形值)與 `ds:CD64`:

| 條件 | 目的地字串 |
|---|---|
| 地形 ≤ 29 且 `ds:CD64` | `MAZEMOVE`(`ds:CDC8`)|
| **座標 == (86, 35)** | `MAZEMOVE`(`ds:CDD8`)← 定點事件 1 |
| 30 ≤ 地形 ≤ 32 且 `ds:CD64` | `TOWN`(`ds:CDEC`)|

那三個「字串」在 `translations/source/module-WRLDMOVE.tsv` 第 15/16/17 列,
內容就是 **`MAZEMOVE` / `MAZEMOVE` / `TOWN`** —— **模組名**,不是敘述文字。
⚠ 這三段是模組轉交,不是事件。

**(86, 35) 是唯一一個不靠地形值的入口。** 它同時也在 `MAZEDATA.BIN` 的
13 筆入口表裡(→ DG1),所以引擎的 `enterMaze` 本來就進得去 ——
原版多這一條判斷的理由沒有查(§4)。

## 3. `0x10D15` 之後是遭遇,不是事件

```
010D15  cmp ds:3658h, 0        ; 遭遇倒數 == 0 ?  > 0 → 整段跳過
010D1F  以隊伍為中心掃 3×3
010D53    格值 ∈ {12, 13} 或 20 ≤ 格值 ≤ 32 → 旗標 ds:CF12 = −1
010DA5  左右兩格都是圖塊 10 → 旗標也設起來
010DE6  旗標沒設 → 跳過
010E42  區域 = 3 / 6 / 1(§1)
010E97  組模組名 → 切到 CMBT
```

補上 [`formats/02`](../formats/02-groups-dat.md) 位移 25 說明裡的
「歸零時掃 3×3 鄰域」缺的那一半:**掃的是地形值,而合格的地形有兩組**
(`{12,13} ∪ [20,32]`,外加「左右都是 10」這個特例)。
