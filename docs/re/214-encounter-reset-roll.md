# 214 — 遭遇倒數的重置:`INT(RND × 10) + 25`

> 輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(全模組掃過 `ds:3658` 的存取點;兩個常數從 DGROUP 初值讀出)。

關掉 worklist 的 **E6**(§8.1 C 組第 10 項)——
引擎兩處硬填 54 的佔位可以拆掉了。

## 1. 掃描分母:整個遊戲只有四處碰它

`ds:3658` 是遭遇倒數的記憶體副本(`GROUPS.DAT` 位移 25,
[`134`](134-groups-load-routine-and-gold.md) §2)。位元組層級掃過七支模組:

| 模組 | 位址 | 做什麼 |
|---|---|---|
| `USERLIB` | `0x10492` | **每個動作 −1**([`204`](204-light-burns-per-turn-and-offset-83.md) §2)|
| `USERLIB` | `0x10936` | 讀(狀態列)|
| `WRLDMOVE` | `0x10D17` | `== 0` → 進遭遇檢查([`212`](212-world-fixed-events-are-two.md) §3)|
| `MAZEMOVE` | `0x11157` | 同上,迷宮那一邊 |
| **`CMBT`** | **`0x132BA`** | **唯一的寫入**(除了 `MENU` 的載入)|

**寫入只有一處** —— 不必去猜「還有沒有別的地方會填」。

## 2. 算式

`CMBT` `0x13295`–`0x132BA`,接在戰後結算的最後(`ds:352C` 復位成 99 之後):

```
013295  INT 3D:34            ; RND
01329A  di = 9410h / 3F:91   ; FAC ×= ds:9410
0132A3  bx = 1Ah / 3D:03     ; INT() 截尾
0132AC  di = 9736h / 3F:81   ; FAC += ds:9736
0132B5  INT 3F:77            ; → 整數
0132BA  ds:3658 = bx
```

兩個常數走 DGROUP 初值(`tools/dgroup_init.py`):

```
ds:9410 → 00 00 20 84  MBF **10**
ds:9736 → 00 00 48 85  MBF **25**
```

**下一次遭遇 = `INT(RND × 10) + 25`,值域 25…34。**

⚠ 成語是 `INT(RND × N) + C` 不是 `Roll(N)`([`152`](152-experience-settlement-formula.md) §3.1)——
差別只在端點:`RND = 0` 給 25,`Roll(10)` 最小給 1。

## 3. 25 出現在兩支模組,互相印證

[`204`](204-light-burns-per-turn-and-offset-83.md) §3 讀到 `MENU` 的載入常式
把「剩餘 ≤ 2」的倒數補回 **25**(立即數 `19h`)。這裡的下界也是 25,
而它走的是 DGROUP 常數 —— **兩個不同模組、兩種不同的編碼方式、同一個數字**。

> **判準:一個常數在兩處以不同形式出現,比同一處讀兩次強得多。**
> 立即數與 DGROUP 常數是編譯器的兩條不同路徑,不會因為同一個誤讀而一起錯。

## 4. ⚠ 出貨存檔的 54 不在這個範圍內

第 5 筆的位移 25 = **54**,而重置的上界是 34、倒數只會遞減。
所以 54 **不可能**是這條規則產生的。

可能性(都沒有查):新隊伍的初值另有出處、出貨存檔是用開發期工具做的、
或者位移 25 在某個路徑上還會被加。⚠ **引擎的 `NewPartyEncounter = 54`
因此仍然是具名假設**,不要因為這一篇就把它改成 25。

## 5. 對 remake 的影響

`world.RollEncounter`,`scene.go` 兩處的 `= 54` 換掉。
