# 215 — 逐步選格:屬性 18 決定**先試哪一軸**,撞到就翻面

> 輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(兩條對稱分支、四支移動常式的入口、翻面的條件都逐位元組讀出)。

關掉 [`158`](158-attribute-18-is-a-coin-flipped-preference.md) 結論第 3 項
(「兩條分支的**內容**沒有逐條讀完」)—— 這是 worklist 的 **D5**,
也是 §8.1 C 組最後一項。

## 1. 兩條分支只差「先比哪一軸」

`0x13F3A` 依屬性 18 分岔,兩支的形狀一字不差,差別只在
取座標時加不加 `0Fh`(= 15 = 下一個屬性):

| 屬性 18 | `0x13F44` 起 | `0x13FD1` 起 |
|---:|---|---|
| **+1** | 先比**屬性 0(x)**,再比屬性 1(y)| — |
| **−1** | — | 先比**屬性 1(y)**,再比屬性 0(x)|

每一軸的比對都是同一個成語:

```
013F48  bx = [自己 + 6822h]            ; 自己的座標
013F4C  si = ds:6818h(目標單位)
013F52  cmp bx, [si+6822h]
013F56  jl  → call 0x14073             ; 自己 < 目標 → 往正向
013F73  jg  → call 0x142C1             ; 自己 > 目標 → 往負向
        相等 → 兩支都不呼叫
```

四支移動常式各對一個方向:`0x14073` 東、`0x142C1` 西、
`0x14394` 南、`0x143E0` 北。

先軸沒走成的話(`0x13F7D` 的 `cmp ds:956C, 1 / jg`)才輪到另一軸。

## 2. 移動常式:先轉身,格子站不了就**把偏好取負**

`0x14073`(往東)是四支的樣板:

```
014095  cmp word ptr [di+6822h], 2     ; 屬性 10(朝向)== 2(東)?
0140A1  and bx, cx                     ; 「不是朝東」AND「x 比目標小」
0140AA  dec word ptr ds:956C
0140AE  mov word ptr [di+6822h], 2     ; ★ 先**轉身**
0140B7  ax = 31 × ds:9348(y) + ds:9346(x) + 1   ; ★ 東邊那一格
0140C6  cmp word ptr [di+6AD4h], 21h   ; 與 **33** 比
0140CB  jl  → 0140D0                   ;   站不了
0140DA  bx = 屬性 18
0140DE  neg bx                         ; ★★ **取負**
0140E0  mov [di+6822h], bx
```

**要走的那一格站不了 → 屬性 18 翻面**,下一步就會先試另一軸。
這正是 [`158`](158-attribute-18-is-a-coin-flipped-preference.md) 結論 2
「某些條件下會被 `neg`」缺的那個條件。

⚠ 戰場格陣列的基底是 `ds:6AD4`、**跨距 31**(`b8 1f 00` = 31),
值 **≥ 33** 才站得上去。同一個 `[di+6AD4h] cmp 20h/21h` 也出現在
群體法術的掃描裡([`208`](208-group-spell-hits-everyone.md) §4 列為未解)——
兩處對得起來,那張表就是**可站立性**。

## 3. 這個偏好不是抖動,是「習慣」

三件事合起來才是完整的形狀:

1. **開場清 0**(`0x18316`),第一次要用時才擲 50% 硬幣
   ([`158`](158-attribute-18-is-a-coin-flipped-preference.md) §1)
2. **`cmp …, 0` 的閘門**讓它整場不再重擲
3. **只有撞到東西才翻面**

所以每隻怪有一個穩定的「先橫走還是先直走」的習慣,而牆與同伴會把它扳過來。

> **判準:一個「隨機決定一次就固定」的量,語意幾乎不會是抖動。**
> 抖動要每次重擲才有意義。看到 `cmp …, 0` 這種「只在還沒有值時才擲」的閘門,
> 就該去找「它在描述這個個體的什麼性質」,而不是「它在哪裡加了亂數」。

⛔ **不要改成每步重擲**:那會讓怪物在牆邊原地抖,而畫面上只像「AI 很笨」。

## 4. 對 remake 的影響

`combat.Unit.Bias`(屬性 18)+ `Field.axisBias` + `stepToward`;
`MonsterTurn` 依偏好挑先軸,走不成就翻面並結束這一步
(點數已經花在轉身上)。舊的 `approach()`(往差距大的那一軸走)刪掉。

⚠ **差距大小不參與決定** —— 原版只比大小、不比距離。
舊的佔位「往差距大的那一軸靠近」看起來更聰明,而那正是它錯的地方。
