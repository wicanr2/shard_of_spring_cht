# 218 — 四項具名假設逐項查證:三項定案、一項證明關不掉

> 輸入:`CAMP.EXE`、`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:逐項標在各節。

[`spec/14`](../spec/14-remake-worklist.md) §10 掛著四項「有具名假設頂著、
不擋開工」的規則。逐項查過之後:

| 項目 | 結果 |
|---|---|
| 補給品上限 `ds:6F10` | ✅ **255**,`CAMP` 執行期寫入 |
| 戰場高度 | ✅ **31**(31×31),從 DGROUP 佈局量出來 |
| 法術等級的取整 | ✅ **問題不成立** —— 原版沒有「等級」這個量 |
| `ds:1Fh` 會不會被間接寫入 | ⛔ **靜態關不掉**,而且這是結構性的 |

> **判準:「沒有編譯期初值」不等於「沒有值」。**
> 前兩項卡了很久,而卡住的理由一模一樣 —— 查了 DGROUP 初始資料串、
> 回報「不在裡面」,就停在那裡。**變數可以在執行期被程式碼寫**,
> 那要掃寫入端,不是掃初值表。

## 1. 補給品上限 = 255

`tools/ida/find_dsref.py` 掃 `ds:6F10`,五支模組的分母與命中:

| 模組 | 掃過的指令 | 命中 |
|---|---:|---:|
| `CAMP` | 6,126 | **4** |
| `TOWN` | 4,419 | 0 |
| `WRLDMOVE` | 2,885 | 0 |
| `MAZEMOVE` | 7,834 | 0 |

四處全在 `CAMP`,而**寫入只有一處**:

```
010306  c706 106f ff00   mov word ptr ds:6F10h, 0FFh     ; ★ = 255
```

用途兩處,都是同一個成語(比一比、超過就夾住):

```
01135F  add ax, ds:731Ch        ; 補給品 + 這次打獵的收穫
011363  ds:7356 = ax
011366  cmp ax, ds:6F10h
01136A  jg  → 1136F
01136F  mov ax, ds:6F10h        ; ★ 夾到 255
011372  ds:7356 = ax
```

`0x1201B` 是同一個夾法,夾的是 `ds:7744`(另一個量,沒有讀)——
所以 `ds:6F10` 是**一個放著 255 的變數**,不是專屬於補給品的欄位。

⚠ **上限只在營地打獵那條路徑上生效。** `TOWN` 一次都沒有碰它,
所以在酒館買補給品沒有經過這個夾子(買的那一段沒有讀)。

**信心:證據充分。** 缺的兩項:寫入點 `0x10306` 位在模組開場的一段
線性流程裡、沒有實跑確認它一定先於使用;以及沒有第二個來源
—— 手冊沒有寫上限([`docs/manual/raw/`](../manual/) 逐頁掃過,
只有「每人每晚耗一份」),`GROUPS.DAT` 位移 23 是 **2-byte** 欄位
([`formats/02`](../formats/02-groups-dat.md)),所以 255 **不是**欄位寬度的自然上限,
是遊戲自己訂的。

關掉這一項要的實跑:練出 `Hunting` 之後連打到補給品堆過 255
([`re/174`](174-oracle-confirms-the-camp-gates.md) §)。

## 2. 戰場是 31 × 31

寬 31 是 [`164`](164-board-stride-31-and-base-13.md) 讀出來的(`mov dx, 1Fh` + `imul`)。
高度先前「沒有任何座標界限的字面值可以量」——**因為它不在程式碼裡,在佈局裡。**

格陣列的基底是 `ds:6AD4`。`tools/ida/array_bases.py` 掃 `[reg+XXXXh]` 形式的
全部基底(16,416 條指令、557 筆),排序之後 **6AD4 上方最近的基底是 `ds:7256`**:

```
0x7256 − 0x6AD4 = 0x782 = 1922 bytes = 961 words = 31 × 31
```

**961 剛好是 31 的平方。** 兩個 31 來自**完全不同的地方** ——
一個是索引算式裡的立即數,一個是兩個陣列基底的差 ——
而它們吻合到沒有餘數。

⚠ 這條推論的前提是「兩個陣列在 DGROUP 裡相鄰、中間沒有填塞」。
它可能不成立,但**恰好整除**這件事本身就是證據:
若中間有填塞,差值不會剛好落在 31² 上。

四支移動常式的可通行判定([`215`](215-monster-step-axis-preference.md) §2)
讀的是**格值 ≥ 33**,沒有座標比較 —— 邊界是用地形圍出來的。
31×31 是**陣列的容量**,不是遊戲畫出來的框。

⚠ 手冊 p.33 寫「15×15」,對不上 31 也對不上視野 9
([`175`](175-battle-view-is-nine-tiles.md))。**手冊講的是哪個平台仍未解**。

**信心:證據充分。** 引擎的 `BoardH = BoardW = 31` 從具名假設升級成量到的值。

## 3. 法術沒有「等級」這個量

[`spec/09`](../spec/09-magic-items.md) §2 寫 `等級 = INT(投入 ÷ 欄5)`,並標明
「那個 `INT` 沒有讀到過」。查完的答案是:**那個 `INT` 讀不到,因為那個除法不存在。**

欄5(法力單價)的陣列基底是 `ds:73C8`。掃 16,416 條指令,**全模組只有 7 處**碰它:

| 位址 | 做什麼 |
|---|---|
| `0x10804` | `add ax, 73C8h` —— 取址(載入 `SPELLS.DAT` 時繫結)|
| **`0x14E20`** | **整數比較**(見下)|
| `0x15096` / `0x15B4E` / `0x16024` / `0x16645` | 效力算式 `round(欄4 × 投入 ÷ 欄5)` 的四個進入點([`201`](201-item-and-spell-fails.md))|
| `0x15751` | `dx = 欄5`、`shl` 成 2×、`dec` 成 2×−1(下游未讀)|

最低門檻那一處是**整數比較,不是除法**:

```
014E1A  di = ds:98D8            ; 選中的法術索引
014E1E  shl di, 1
014E20  bx = [di+73C8h]         ; 欄5
014E24  cmp bx, ds:93A2h        ; 與投入的點數比
014E28  jg  → 14E2D             ; 欄5 > 投入 → 失敗
```

所以 `CMBT:104–106`「那個法術至少需要 N 點法力」擋的是 **`投入 ≥ 欄5`**。
原版從頭到尾沒有算過「這次是第幾級」。

> **判準:一個量「怎麼取整」問不出答案時,先問「這個量存在嗎」。**
> 取整方式未決,前提是那個除法存在。這裡連除法都沒有,
> 所以未決的不是取整,是**規格多寫了一個中間量**。

⚠ **引擎的行為是對的,錯的是規格的說法。** `magic.Level()` 只被
`Level(s, invest) < 1` 這一個閘門用到,而

```
INT(投入 ÷ 欄5) < 1   ⟺   投入 < 欄5
```

兩者**恆等**(欄5 ≥ 1 時)。效力那一條走 `magic.EffectLevel`,
是從 `0x150AF` 讀出來的四捨五入,本來就沒問題。

**信心:已確認**(掃描分母 16,416 條;7 處逐條看過)。

## 4. `ds:1Fh`:靜態關不掉,而且這是結構性的

[`184`](184-levelup-hp-sp-growth.md) §5 已經做過的:13 支 EXE、273,301 bytes
逐 byte 掃過所有 **disp16 直接定址**的寫入編碼,`ds:1Fh` **零命中**;
71 處「把 `1Eh`/`1Fh` 載進暫存器」逐一看過,全是整數常數 30/31。

**再掃一次不會得到新東西** —— 掃不到的那一類是「執行期算出來的指標寫入」
(`ptr = <算式>` → `mov [bx], al`),它在靜態掃描裡沒有可辨識的樣式。
這不是掃描做得不夠細,是**這個方法答不出這個問題**。

> **判準:負面斷言要標出「用什麼方法能推翻它」,不是反覆用同一個方法確認它。**
> 「再掃一遍」對這一項是**重複問同一個問題**。要換方法。

能關掉它的實驗(還沒做):在 DOSBox 裡跑到一個**取整方式看得出差別**的地方,
比對觀察值與兩種取整的預測。升級的 HP 成長就是這種地方
([`184`](184-levelup-hp-sp-growth.md) §3:`四捨五入(屬性 × 兩次亂數取大 × 係數) + 加項`)——
截尾與四捨五入在半數以上的骰值會差 1。

⚠ 在那之前,`ds:1Fh = 0`(四捨五入)仍然是**證據充分**,不是已確認。
⛔ 不要因為「掃了很多次都沒中」就把它寫成已確認 —— 掃描次數不是證據等級。
