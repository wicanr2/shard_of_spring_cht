# 219 — `WALKDRAW.PIC`:隊伍的人形圖示,段號對朝向

> 輸入:`game/sharspri/WALKDRAW.PIC`(1,063 bytes)、`MENU.EXE`
> (SHA-256 見 [`00-inputs.md`](00-inputs.md))、四張原版實跑截圖。
> 信心:**證據充分**(三個朝向逐像素命中,第四個用排除法)。

補上 [`spec/14`](../spec/14-remake-worklist.md) §12-C 的第一條:
重製版在世界地圖與地城**用白框標示隊伍**,原版畫的是**人形**。

## 1. 圖在哪個檔

`WALKDRAW.PIC`,10 段 BASIC `DRAW` 向量巨集,與 `WRLDITEM.PIC` /
`MAZEITEM.PIC` 同族([`49`](49-h-closure.md) §3 的容器)。

`strings -a` 掃 13 支執行檔,**只有 `MENU.EXE` 含 `walkdraw`**
(`WRLDMOVE` 只含 `wrlditem.pic`、`MAZEMOVE` 只含 `mazeitem.PIC`)。
`MENU` 在載入時讀進 COMMON 的字串陣列,世界地圖與地城再取用 ——
這解釋了**為什麼兩個場景看到的是同一個人**。

⚠ **`cmd/convert` 從來沒轉它。** 引擎沒有東西可畫,才落回白框
—— 而白框是「⛔ 不拿別的圖冒充」那條紀律的正確後果,不是隨便畫的。

## 2. 段號對朝向

`python3 tools/draw_pic.py game/sharspri/WALKDRAW.PIC` 渲染 10 段:

| 段 | 內容 |
|---:|---|
| 0 | **帳篷**(紮營時取代人形)|
| 1–8 | **人形**:四個朝向 × 兩個步態 |
| 9 | 不是人形,用途未定 |

對應關係是**用原版實跑量出來的**,不是猜的。做法:

> **原版轉身不會移動**([`149`](149-every-action-costs-one-tick.md):
> 轉身也算一個動作,但位置不變)—— 所以連按四個方向鍵各拍一張,
> **四張之間唯一會變的就是人形本身**。

```
tools/dosbox_run.sh "…;key:Up;shot:f1-north;key:Right;shot:f2-east;
                       key:Down;shot:f3-south;key:Left;shot:f4-west"
```

四張互比,**有差異的像素只落在 x 72–86、y 83–97**(92 個像素)——
那就是隊伍那一格,證實了「只有人形在變」。

再拿每一張的那一格與八段逐像素比對(取各自最佳偏移下的含蓋率):

| 朝向 | 最佳命中 | 次高 |
|---|---|---|
| 北 | **段 2 = 95%** | 段 1 = 86% |
| 東 | **段 3 = 94%** | 段 4 = 83% |
| 南 | 段 7 = 93% | **段 6 = 92%** |
| 西 | **段 7 = 89%** | 段 8 = 81% |

北、東、西三個乾淨命中對應的段對;南在 93% / 92% 之間分不開,
**用排除法**落到剩下那一對。結論:

```
段 = (朝向 − 1) × 2 + 1 + 步態        朝向 1北 2東 3南 4西(docs/re/71)
```

| 朝向 | 段 |
|---|---|
| 1 北 | 1, 2 |
| 2 東 | 3, 4 |
| 3 南 | 5, 6 |
| 4 西 | 7, 8 |

⚠ **南那一列是排除法得到的**,不是直接量到的。要升級成「已確認」,
得找一格**周圍地形更單純**的位置重量一次 —— 現在那一格底下是樹,
樹的枝葉與人形的手腳重疊,四個朝向的含蓋率因此都被墊高。

> **判準:比對「畫在別的東西上面」的圖,要比含蓋率不要比相符率。**
> 第一次用「逐像素相同的比例」比,十段全部落在 55–70%,分不出高下 ——
> 因為那一格同時有地形與人形,而 sprite 只佔其中一部分。
> 改比「sprite 的像素有幾成在原版那一格是亮的」之後,最高的一項就跳到 95%。

## 3. 兩組色盤

同一張圖在兩個場景**顏色不同**:`WRLDMOVE` 寫 `0x3D8 = 0x0A`、
`MAZEMOVE` 寫 `0x0E`([`146`](146-maze-exit-negatives-and-palettes.md) §4)。
所以 `cmd/convert` 輸出兩份(`gfx/walk/` 與 `gfx/walk-maze/`)。

⚠ 只輸出一份的話,其中一個場景的顏色會是錯的,
而**畫面上仍然是一個人形,看不出哪裡不對**。

## 4. 對 remake 的影響

`engine/walk.go` + 世界地圖與地城的繪製。⚠ 人形同時是**朝向的顯示** ——
世界地圖是「先轉再走」,沒有它玩家按一次方向鍵不會動、卻不知道為什麼。

步態**只在真的位移時翻**(轉身不換腳),兩處的 `Step` 回傳值本來就把
轉身與位移分開,加在 `Moved` 那一支。

## 5. 仍未解

| 項目 | 狀態 |
|---|---|
| 段 9 是什麼 | 渲染出來不是人形也不是帳篷。沒查 |
| 兩個步態怎麼交替 | 引擎每走一步翻一次。**原版的規則沒有讀** —— 也可能是照座標奇偶 |
| 帳篷(段 0)的觸發 | 原版按 `C` 紮營時換成帳篷(QA 截圖),但引擎的營地入口還沒接(`spec/14` §12-B)|
| `MENU` 把它放進 COMMON 的哪個位址 | 沒讀。本篇靠檔名字串與畫面證據,不靠位址 |
