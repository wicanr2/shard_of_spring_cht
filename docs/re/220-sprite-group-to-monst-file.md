# 220 — 圖組編號 → `MONST` 檔號,以及它訂正的一條規則

> 輸入:`CMBT.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))、
> `MONSTERS.DAT`、22 個 `MONST*.BIN`。
> 反組譯前先跑 `tools/ida/unlock_module.py`。
> 信心:**已確認**(三條互相獨立的證據)。

關掉 [`spec/14`](../spec/14-remake-worklist.md) §12.1 的阻礙:
「圖組編號怎麼對到 `MONST*.BIN` 的哪一檔」。

## 1. 結論

```
圖組(屬性 11) = 檔號 × 8 + 25          →      檔號 = (圖組 − 25) / 8
```

| 單位 | 圖組 | 檔 |
|---|---:|---|
| 隊伍戰士 | 41 | **`MONST2.BIN`** |
| 隊伍巫師 | 57 | **`MONST4.BIN`** |
| 怪物 | `欄6 × 8 + 25` | **`MONST<欄6>.BIN`** |

也就是**怪物的檔號就是 `MONSTERS.DAT` 的欄6**,不必換算。

## 2. 三條證據

### 2.1 步長 8 是讀出來的

`CMBT 0x1155C`–`0x1159C` 是載入迴圈:內圈 0–45(每格 46 個 word)、
外圈 0–7(**八格**),寫進圖庫 `ds:7E5C`。載完一個檔之後:

```
01159C  add word ptr ds:9494h, 8      ; ★ 圖組編號 += 8
```

**一個檔 = 8 格 = 圖組 +8。**

### 2.2 兩個定點:寫死的檔名 + 讀出來的圖組

`CMBT` 的字串表裡有**兩個寫死的檔名**(`tools/dgroup_strings.py`):

```
ds:946C → 'monst2.bin'
ds:947A → 'monst4.bin'
```

其餘怪物走組出來的名字(`ds:94A6 'monst'` + 數字 + `ds:9496 '.bin'`)。

而隊員的圖組是**直接寫進屬性 11 的立即數**:

```
0118F4  mov word ptr [di+6822h], 29h     ; 41 = 戰士
011962  mov word ptr [di+6822h], 39h     ; 57 = 巫師
```

41 → 檔 2、57 → 檔 4,差 16 = 兩個檔 × 8 ✓ 與 §2.1 一致。

### 2.3 內容對照:七項全中

把 22 個檔的第 0 格渲染出來,與 `MONSTERS.DAT` 同編號的怪逐一對:

| 檔 | 圖 | 欄6 = 檔號的怪 |
|---:|---|---|
| 15 | 展翅的蝙蝠 | 蝙蝠、黑暗渡鴉 |
| 16 | 盤起的蛇 | 眼鏡蛇、死亡蝮蛇、坑蝮蛇 |
| 17 | 火焰 | **火元素** |
| 18 | 劍身 | **金屬元素** |
| 20 | 幽靈 | **靈元素** |
| 21 | 旋風 | **風元素** |
| 22 | 龍 | 幼龍、小龍、大龍 |

**七項全中。** 而且 `MONSTERS.DAT` 的欄6 **沒有 2 也沒有 4** ——
正是因為那兩個檔是隊員的圖。

> **判準:一個對應表對不對,拿「內容」驗比拿「算術」驗強。**
> 算術可以差一位而仍然自洽;火元素長得像火焰不會。

## 3. ⚠ 這訂正了 [`188`](188-dispell-undead.md) §3.1,也訂正了引擎的一條規則

`188` §3.1 推的是 `屬性11 = (欄6 − 1) × 8 + 41`(信心標**證據充分**),
換算出的檔號是 `欄6 + 1`。它有兩個看得出來的破綻:

| 破綻 | 說明 |
|---|---|
| 值域溢出 | 欄6 最大 **22**(龍族)→ 檔 23,而**只有 22 個檔** |
| 憑空多一個空組 | `188` 記「欄6 = 4 沒有任何一筆用這一組」—— 那是差一位的產物,4 其實是**隊員巫師**的檔 |

不死生物的圖組 `{65, 73, 81}` 換算:

| | 舊(`188`)| 新(本篇)|
|---|---|---|
| 檔號 | — | **5 / 6 / 7** |
| 欄6 | 4 / 5 / 6 | **5 / 6 / 7** |
| 內容 | — | 骷髏 / 骷髏巫師 / **幽靈** |

引擎的 `combat.UndeadClasses` 因此從 `{4,5,6}` 改成 **`{5,6,7}`**。

⚠ 舊版還為那個差一位寫了一句解釋:

> 「幽靈／邪靈／魅影(欄6 = 7)**不算**不死 —— 本作把它們歸成靈體。」

**那是替一個錯誤的數字編出來的解釋,而它讀起來完全合理。**

> **判準:當一個推論產生「剛好有一組是空的」或「剛好差一個」的結果時,
> 那多半是偏移錯了,不是資料真的有洞。**
> ⛔ 更不要回頭替那個洞編一套說法 —— 編得越順,越難被推翻。

## 4. 對 remake 的影響

`combat.SpriteFile` + `engine/board_sprite.go`:戰場改畫 17×17 的圖,
**一格 = 17 × 2**(整數倍;先前用文字行高算的 26 px,圖畫進去認不出是什麼)。
輪到誰的那一格畫一個框,與原版一致。

⚠ **八格只用第 0 格** —— 八格是同一個生物的動畫,而「哪一格對哪個狀態」
沒有讀到。挑錯格是看起來完全正常的錯誤。
⚠ 超出範圍的欄6 回 **0**(沒有圖,退回文字),⛔ 不夾到最後一個檔:
那會讓每隻沒有圖的怪都長成龍。
