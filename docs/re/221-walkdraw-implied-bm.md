# 221 — `WALKDRAW.PIC` 每段開頭的裸位移是隱含的 `BM`

> 輸入:`game/sharspri/WALKDRAW.PIC`(1,063 bytes)、`MENU.EXE`
> (SHA-256 見 [`00-inputs.md`](00-inputs.md))、四張原版實跑截圖。
> 信心:**已確認**(十段的載入迴圈讀過原始指令)。

## 1. 現象

`WALKDRAW.PIC` 的每一段都以一個**沒有指令字母的位移**起頭:

```
+0,+0c2r16h8u6f2g2d2g8br8bu1p1,2c3u7…      段 0(帳篷)
+8,-1c2r2bl2u4e1u3h1…                        段 3(朝東)
+4,0c2r2U3E1R1F1D2R2BM-2,-4…                 段 6(朝南)
```

`DRAW` 巨集的每個命令都是「字母＋數字」,`+8,-1` 不是合法的命令 ——
它是**上一個命令的運算元**,而那個命令不在檔案裡:遊戲端寫的是
`bm` ＋ 這一段,兩個字母由程式補上。

## 2. 證據:`MENU.EXE` 的載入迴圈

`MENU` 是唯一含 `walkdraw.pic` 字串的模組([`219`](219-walkdraw-segments.md) §1)。
那個檔名後面緊接著一個**兩字元的字串常數 `bm`**:

```
03680  0C 00 2E 78 10 00 2E 78 77 61 6C 6B 64 72 61 77   ...x...xwalkdraw
03690  2E 70 69 63 08 00 3E 78 02 00 42 78 06 00 42 78   .pic..>x..Bx..Bx
036A0  62 6D 08 00 44 78 0C 00 48 78 10 00 48 78 6D 61   bm..Dx..Hx..Hxma
```

(`02 00 42 78` = 長度 2、資料在 `ds:7842`;`bm` 就是那兩個位元組。)

讀進來的迴圈在 `MENU.EXE` 線性位址 `0x11B34`–`0x11B6E`:

```
011B34  mov  bx, 1
011B37  INT  3F:B6                  ; 對檔案 #1 動作
011B3C  mov  bx, 783Ah
011B3F  INT  3F:5A                  ; 指派字串(docs/re/132)
011B44  mov  bx, ds:6EB6h           ; 迴圈變數 i
011B48  shl  bx, 1
011B4A  shl  bx, 1                  ; ×4 = 字串描述子大小
011B4C  add  bx, 362Eh              ; &陣列[i]
011B50  mov  dx, bx
011B52  mov  bx, 783Ah
011B55  mov  ax, 783Eh              ; 兩個來源字串
011B58  INT  3F:55
011B5D  INT  3F:61
011B62  mov  ax, ds:6EB6h
011B65  inc  ax
011B66  mov  ds:6EB6h, ax
011B69  cmp  word ptr ds:6EB6h, 9
011B6E  jle  short loc_11B34
```

三件事同時成立:

| 讀到的 | 意義 |
|---|---|
| `cmp … 9` / `jle` | 迴圈跑 **10 次** —— 段數 10 是程式寫死的,不是解析出來的巧合 |
| `i×4 + 362Eh` | 目的地是 **10 個 4-byte 字串描述子**的陣列 |
| `INT 3F:55` 吃 `dx` ＋ 兩個字串(`bx`/`ax`) | 每一段都是**兩段字串接起來**才存進陣列 |

其中一個來源是剛從檔案讀進來的那一行,另一個是 `bm`。
所以陣列裡每一段的實際內容是 `bm` ＋ 檔案裡那一行。

## 3. 少了它會怎樣

`engine/internal/original/draw.go` 的 `drawTok` 要求每個命令都有字母,
認不得開頭那個裸位移就**整段跳過**——人形從畫布左下角開始畫,
右半邊被 17×17 的邊界裁掉。

逐段量亮點數(`draw_test.go` 的 `TestLeadingBareMoveIsAnImpliedBM`):

| 段 | 位移 | 套用 | 不套 |
|---:|---|---:|---:|
| 0 帳篷 | `+0,+0` | 48 | 48 |
| 1 北 | `+4,-1` | 68 | 58 |
| 2 北 | `+4,-2` | 68 | 55 |
| 3 東 | `+8,-1` | 48 | **34** |
| 4 東 | `+8,-1` | 50 | 35 |
| 5 南 | `+3,-2` | 66 | 56 |
| 6 南 | `+4,0` | 66 | 59 |
| 7 西 | `+8,-1` | 49 | **28** |
| 8 西 | `+8,-1` | 50 | 27 |
| 9 ? | `+2,-8` | 62 | 44 |

東、西兩個朝向少掉將近一半的筆畫。

> **判準:一組樣本裡有一個「剛好是零」的,它會把偏移錯藏起來。**
> 段 0 的位移正好是 `+0,+0`,而帳篷是唯一單獨顯示的一段 ——
> 拿它當樣本檢查,永遠看不出這個 bug。

第二個藏法在正規式本身:**只有 x 一定帶正負號,y 不必**(段 6 是 `+4,0`)。
BASIC 的 `M` 是相對還是絕對由 **x 的符號**決定,y 跟著走 ——
要求兩邊都有號的話,南向那一段會安靜地漏掉,而畫面上仍然是一個人形。

## 4. 修正後的量測

修正後重轉 `assets/gfx/walk/`,拿原版四個朝向的截圖重量含蓋率
(做法見 [`219`](219-walkdraw-segments.md) §2):

| 朝向 | 最佳命中 | 次高 |
|---|---|---|
| 北 | **段 2 = 94%** | 段 1 = 87% |
| 東 | **段 3 = 96%** | 段 4 = 84% |
| 南 | **段 6 = 92%** | 段 5 = 85% |
| 西 | **段 7 = 94%** | 段 8 = 84% |

四個朝向都有 7–12 個百分點的間隔,`219` §2 原本靠排除法定下來的南向
現在是直接量到的。段號對朝向的公式不變:

```
段 = (朝向 − 1) × 2 + 1 + 步態        朝向 1北 2東 3南 4西
```
