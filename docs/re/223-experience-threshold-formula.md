# 223 — 升級門檻是一條公式,手冊那張表是它截到百位的印刷版

> 輸入:`TOWN.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md);讀之前先跑
> `tools/ida/unlock_module.py`)、原版實跑四點、手冊 p.47。
> 信心:**已確認**(四個實測點與公式完全吻合;手冊二十列 = 公式截到百位,一列不差)。

## 結論

```
升到第 n+1 級所需的累計經驗 = INT( (1.8ⁿ + 2n) × 100 )
```

| n | 公式 | 原版實跑 | 手冊 p.47 |
|---:|---:|---:|---:|
| 1 | **380** | **380** | 300 |
| 2 | **724** | **724** | 700 |
| 3 | **1183** | **1183** | 1,100 |
| 4 | **1849** | **1849** | 1,800 |
| 5 | 2889 | — | 2,800 |
| 10 | 37,704 | — | 37,700 |
| 20 | 12,752,230 | — | 12,752,200 |

**手冊那一欄是公式截到百位** —— 二十列一列不差。而截尾在低等級差很多:
第 1 級真正要 **380**,手冊寫 300。照手冊實作的話,玩家在每一級都比原版早升,
而**畫面上沒有任何一個數字會顯示成錯的**。

## 1. 程式碼(`TOWN.EXE 0x10FF4`–`0x11047`)

```
010FF4  mov  word ptr ds:66D0h, 28h   ; 欄位 40 = 等級(CHARS.DAT 位移 40)
010FFA  call loc_10079               ; ax ← 等級
011000  mov  bx, ax / INT 3F:57      ; FAC ← float(等級)
011005  mov  si, 715Eh / INT 3F:27   ; FAC ← 1.8 ^ FAC     ds:715E = MBF 1.8
01100B  shl  ax, 1                   ; ax = 等級 × 2
01100D  mov  bx, ax / INT 3F:71 81   ; 暫存81 ← FAC(= 1.8ⁿ)
011013  INT  3F:57                   ; FAC ← float(等級 × 2)
011016  INT  3F:85 81                ; FAC ← 暫存81 + FAC  = 1.8ⁿ + 2n
01101A  mov  di, 6F5Ch / INT 3F:91   ; FAC ×= ds:6F5C = MBF 100.0
011020  mov  di, 715Ah / INT 3F:7D   ; ds:715A ← FAC
011031  mov  bx, 715Ah / INT 3D:03   ; ★ INT() —— **截尾**,不是四捨五入
011039  mov  bx, 7154h / INT 3F:71 81; 暫存81 ← 目前經驗
011040  INT  3D:03                   ; INT()
011043  INT  3F:A5 81                ; 比較
011047  ja   → 0x1104C               ; 門檻 > 經驗 → 印「你還需要 N 點」
        否則 → 0x11094               ; 升級(HP/SP 成長見 184)
```

`0x1104C` 之後接的正是 `mov ax, 7162h`(`The Guild decides you need` 的描述子)
與 `mov bx, 7180h`(` experience before gaining a level. `),
所以**這一段確實是訓練所的那道閘門**,不是別處的算式。

兩個常數的位元組:

| 位址 | 位元組 | MBF |
|---|---|---|
| `ds:715E` | `66 66 66 81` | **1.8** |
| `ds:6F5C` | `00 00 48 87` | **100.0** |

API 索引照 [`77`](77-runtime-arithmetic-api.md):`3F:57` 整數→浮點、
`3F:71`/`3F:85` 暫存與加、`3F:91` 乘、`3F:A5` 比較、`3D:03` = `INT()`。
`3F:27` 是次方(`3F:23` 的另一個進入點,[`152`](152-experience-settlement-formula.md) §2.2)——
**指數是累加器、底數是 `si` 指到的常數**,這個方向由結果反過來確認:
`等級^1.8` 對不上任何一個實測點,`1.8^等級` 四點全中。

## 2. 怎麼量的

訓練所在經驗不足時印 `The Guild decides you need N experience before gaining a level.`,
N 是**差額**。把角色的經驗調到門檻附近就能把門檻夾出來:

- Hard Axe 經驗 379 → `need 1` ⇒ 門檻 380
- Grod 經驗 380 → `You made a level!` ⇒ 門檻 ≤ 380

四個點分別取自第 1–4 級。⚠ 同一角色量兩次結果相同 ⇒ **不是隨機**。

## 3. 為什麼手冊會誤導

手冊 p.47 有 `ABSOLUTE` 與 `INCREASE FROM LAST LEVEL` 兩欄。
先前的判讀是「第 1 列的 INCREASE 欄不自洽,**累計欄才是可用的那一欄**」——
那個判讀對前半句成立,對後半句不成立:**兩欄都是印刷用的近似值**。

> **判準:一張表能自洽,不代表它是規則本身。**
> 手冊的二十列彼此自洽(每列都是同一條公式截到百位),
> 所以「拿它當規則」在任何自我檢查下都不會露出破綻 ——
> 露出破綻的唯一方式是**跑原版問一次「我還差多少」**。
> 這也是為什麼證據優先序把「人親自實測原版」放在反組譯之上([`CLAUDE.md`](../../CLAUDE.md) §6)。

## 4. 對 remake 的影響

`engine/internal/rules/rules.go` 的 `ExpForLevel` 由查表改成公式。

⚠ **型別要用 `float32`**:原版算的是 MBF 單精度,而 `float32(1.8)` 與
MBF 的 1.8 位元相同。用 `float64` 從第 11 級起會差 1–2 點。
