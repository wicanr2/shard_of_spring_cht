# 227 — `FASTCMBT.BIN` 與 `FASTWRLD.BIN` 同格式;戰場地形是從周圍地圖鋪出來的

> 輸入:`FASTCMBT.BIN`(836 bytes)、`FASTWRLD.BIN`(836 bytes)、`CMBT.EXE`
> (SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 信心:§1 **已確認**、§2 **已確認**、§3 **未解**(明列缺什麼)。

[`21`](21-tile-format.md) §4 把 `FASTCMBT.BIN` 列成「名字不像圖的檔案…很可能不是
`GET` 陣列」,而 [`spec/14`](../spec/14-remake-worklist.md) §12.4 第 9 項一直掛著
「要新 RE」。這一篇把格式那一半關掉。

## 1. 格式:9 張 17×17,與 `FASTWRLD` 逐項相同

兩個檔都是 836 bytes = BSAVE 標頭 7 ＋ 本體 828 ＋ EOF 1,而 828 = **9 × 92**。
按 92 bytes 切開之後,**九塊的前兩個 word 全部是 (34, 17)** ——
也就是 BASIC `GET` 陣列的寬(bit)與高([`21`](21-tile-format.md) §3)。

| 檔 | 九塊的標頭 | 每塊非零位元組 |
|---|---|---|
| `FASTWRLD.BIN` | 全部 (34,17) | 10–45 / 88 |
| `FASTCMBT.BIN` | 全部 (34,17) | 16–85 / 88 |

⚠ **「九塊的標頭全部對」正是 [`53`](53-world-tiles-towns-and-draw-renderer.md) §1
用來裁決 `FASTWRLD` 排法的判準**(連續 vs 交錯,只有連續讓九組都是 (34,17))。
同一個判準在這裡直接成立,所以 `original.DecodeFastWorld` 那支解碼器
不必改就能讀 `FASTCMBT.BIN`。

畫出來的九張(`' . : #'` 四階):齒輪狀的十字、實心圓塊、點狀地面、
稀疏點、磚牆、帶內凹的磚牆、方框迷宮紋、兩張斜線紋。

**載入端**:`CMBT.EXE` 檔案位移 `0x9386` 有字串 `fastcmbt.bin`(小寫),
與 `SPELLS.DAT` / `ITEMS.DAT` 相鄰。全套執行檔掃過一遍,
`fastwrld` 只出現在 `WRLDMOVE` / `WSIO`,`fastcmbt` 只出現在 `CMBT` ——
**兩個檔各屬一支模組**,不共用。

## 2. 戰場地形是從**周圍的地圖格**鋪出來的

格陣列在 `ds:6AD4`(31 寬,[`164`](164-board-stride-31-and-base-13.md))。
`0x108E0`–`0x10A60` 是雙重迴圈,把來源地圖的一格展開成戰場上的一塊,
判斷寫在 `0x10998`–`0x10A53`:

```
v = ds:93AE(來源格的地形值,取自 ds:3740 那張表)

v == 2 或 3 或 17 ≤ v ≤ 25      → 格 = ds:9300
7 ≤ v ≤ 12 或 v == 27           → 格 = ds:92FC
v == 5 或 6                      → 格 = v 本身
其餘                             → 格 = ds:9300
```

六個常數在 `0x10406`–`0x10424` 一次設定完,是字面值:

| 變數 | 值 | 用途 |
|---|---:|---|
| `ds:92F6` | 2 → 後來被 `0x10933` 改成 `ds:9300` | **空地**(怪物出場要求這一格,[`186`](186-monster-ai-target-placement-cast.md) §1)|
| `ds:92F8` | 5 | |
| `ds:92FA` | 6 | |
| `ds:92FC` | 7 | |
| `ds:92FE` | 12 | |
| `ds:9300` | 18 | 空地的實際值 |

`0x11000`–`0x110B4` 是一個**平滑化**的後處理:相鄰兩格是 5/6/7、
而第三格是 18 時,把那兩格也改成 18。

⚠ 這解釋了實跑截圖看到的樣子:戰場不是空白的棋盤,
**上下兩條水域**與中間的空地,對得上「隊伍站在世界地圖某一格附近」。

## 3. 還缺:格值 → 圖塊編號

寫進格陣列的值是 **2 / 5 / 6 / 7 / 12 / 18**,而 `FASTCMBT` 只有 **9 張圖** ——
所以**不是「值 − 1 = 圖塊編號」**(12 與 18 都超出範圍)。中間一定有一層對映,
而那一層還沒讀到。

⚠ 兩條看起來像答案但**不是**的線索,記下來免得下一輪再走一次:

- `0x1729B` 的 `add di, [si+6AD4h]` 配 `[di+7E5C]`,形狀像「用格值查圖」,
  但那是 [`226`](226-monster-cast-invest-and-target.md) §3 的**捲動**常式:
  外圈跑 46 次、跨距 48 word,它在搬螢幕緩衝的一整條,不是在畫一格。
- `0x13CDE` 的 `cmp [di+6AD4h], 20h` 與 `0x140C8` 的 `cmp …, 21h`:
  格陣列裡 32/33 這種值與地形無關(那一段在判單位),
  **同一個陣列裝了兩種東西**。

⛔ **在對映讀出來之前,引擎的戰場不畫地形。** 湊一個「5→第5張」的表
會在畫面上看起來完全正常,而那是自己發明的地圖。
