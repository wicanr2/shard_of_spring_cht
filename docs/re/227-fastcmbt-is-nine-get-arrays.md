# 227 — `FASTCMBT.BIN` 與 `FASTWRLD.BIN` 同格式;戰場地形是從周圍地圖鋪出來的

> 輸入:`FASTCMBT.BIN`(836 bytes)、`FASTWRLD.BIN`(836 bytes)、`CMBT.EXE`
> (SHA-256 見 [`00-inputs.md`](00-inputs.md))。
> 信心:§1 **已確認**、§2 **已確認**、§3 **未解**(明列缺什麼)。

[`21`](21-tile-format.md) §4 把 `FASTCMBT.BIN` 列成「名字不像圖的檔案…很可能不是
`GET` 陣列」,而 [`spec/14`](../spec/14-remake-worklist.md) §12.4 第 9 項一直掛著
「要新 RE」。這一篇把格式那一半關掉。

## 1. 格式:9 張 17×17,與 `FASTWRLD` 逐項相同

兩個檔都是 836 bytes = BSAVE 標頭 7 ＋ 本體 828 ＋ EOF 1,而 828 = **9 × 92**。
按 92 bytes 切開之後,**九塊的前兩個 word 全部是 (34, 17)** ——
也就是 BASIC `GET` 陣列的寬(bit)與高([`21`](21-tile-format.md) §3)。

| 檔 | 九塊的標頭 | 每塊非零位元組 |
|---|---|---|
| `FASTWRLD.BIN` | 全部 (34,17) | 10–45 / 88 |
| `FASTCMBT.BIN` | 全部 (34,17) | 16–85 / 88 |

⚠ **「九塊的標頭全部對」正是 [`53`](53-world-tiles-towns-and-draw-renderer.md) §1
用來裁決 `FASTWRLD` 排法的判準**(連續 vs 交錯,只有連續讓九組都是 (34,17))。
同一個判準在這裡直接成立,所以 `original.DecodeFastWorld` 那支解碼器
不必改就能讀 `FASTCMBT.BIN`。

**九張圖的身分:逐位元組等於那九個 98-byte 檔**(不是「看起來像」)。
把 `FASTCMBT.BIN` 按 92 bytes 切開,每一槽的**前 90 bytes 與對應檔案的
BSAVE 內容完全相同**,九槽九檔一個不差,順序也與
[`61`](61-i-closure-unused-tiles.md) §1 讀到的陣列槽位一致:

| 槽 | 檔案 | 內容 |
|--:|---|---|
| 0 | `EXITSPOT.BIN` | 四向星芒 |
| 1 | `BORDER.BIN` | 實心八角 |
| 2 | `WATER.BIN` | 水面 |
| 3 | `LAVA.BIN` | 岩漿 |
| 4 | `MAZEWALL.BIN` | 磚牆 |
| 5 | `DOOR.BIN` | 拱門 |
| 6 | `WINDSTRM.BIN` | 方形漩渦 |
| 7 | `HAILSTRM.BIN` | 青色斜線 |
| 8 | `FIRESTRM.BIN` | 洋紅斜線 |

**所以 `FASTCMBT.BIN` 是那九個檔的打包本** —— 迷宮那一支模組逐檔載入九次,
`CMBT` 一次載完。⚠ 這修正 [`61`](61-i-closure-unused-tiles.md) §2 的
「`FIRESTRM`/`HAILSTRM`/`WINDSTRM.BIN` 遊戲從不載入」:**那三個檔本身**確實沒被
開啟過,但**它們的內容有被載入**,就在這個打包本裡。

施法那一段(`CMBT 0x15946` / `0x15970` / `0x15994`)按法術編號把第 6/7/8 槽
逐 word 複製進 `ds:7AC4` 的 92-byte 暫存區再畫:

```
法術 3(FIRE STORM) → 來源 ds:7E00 = 7B20 + 92×8 → 槽 8 = FIRESTRM
法術 8(TEMPEST)   → 來源 ds:7D48 = 7B20 + 92×6 → 槽 6 = WINDSTRM
法術 12(HAIL STORM)→ 來源 ds:7DA4 = 7B20 + 92×7 → 槽 7 = HAILSTRM
```

**每個複製迴圈跑 0…45 = 46 word = 92 bytes**,正好一槽 ——
這反過來確認了「一張 92 bytes、基底 `ds:7B20`」的切法。
三個名字與三個法術逐一對上,是這條證據鏈的獨立佐證。

**載入端**:`CMBT.EXE 0x10753`,與世界地圖那三個檔同一個形狀
([`132`](132-world-tile-dispatch-corrected.md) §2):

```
mov bx, 7B20h  / INT 3F:57   ; ★ 載入位址 ds:7B20
mov bx, 9368h  / INT 3F:55   ; `fastcmbt.bin` 的描述子 + 路徑前綴
mov dx, 1Ah    / INT 3E:1A   ; 載入
```

**九張圖載進 `ds:7B20`,佔 828 bytes,到 `ds:7E5C` 為止。**
全套執行檔掃過一遍,`fastwrld` 只出現在 `WRLDMOVE` / `WSIO`,
`fastcmbt` 只出現在 `CMBT` —— 兩個檔各屬一支模組,不共用。

## 2. 戰場地形:來源是**隊伍周圍的 3×3 地圖格**

`ds:3740` 是 COMMON 區的變數([`43`](43-common-block-and-array-indexing.md) §4:
八支模組共用同一份 `MASTER.INC`,COMMON 的位移在每支模組裡相同),
`CMBT` 只讀不寫。**填的是送出戰鬥的那一支模組**,兩支的形狀一模一樣:

```
WRLDMOVE 0x10DFC   ax = i + ds:3518 ;  ax × 103        ; ★ 世界地圖的列寬
010E09             di += ds:CF18 + ds:351A − 208       ; −208 = −(2×103 + 2)
010E17             dx = [di×2 + 6822h]                 ; 從世界地圖陣列取一格
010E27             [ (i×4 + j)×2 + 3740h ] = dx        ; 存進 COMMON
                   兩層迴圈 i, j = 1…3
MAZEMOVE 0x11271 / 0x13B0D 同一個形狀(來源換成迷宮陣列)
```

**所以 `ds:3740` 是隊伍周圍的 3×3 格**(世界戰鬥給世界地形值、地城戰鬥給迷宮格值)。

`CMBT` 拿它跑**兩趟**:

```
第一趟 0x108E0–0x10A60     v = 3×3 的那一格
  v == 2/3 或 17 ≤ v ≤ 25            → 格 = 18(空地)
  7 ≤ v ≤ 12 或 v == 27              → 格 = 7
  v == 5 或 6                        → 格 = v
  其餘                               → 格 = 18
0x10933  ds:92F6 ← ds:9300           ; 空地的值從 2 改成 18
第二趟 0x10E12–0x10F93     ★ **覆寫**第一趟的結果
  v == 10                            → 格 = 6
  v == 11                            → 格 = 5
  27 ≤ v ≤ 29 或 35 ≤ v ≤ 38         → 格 = 18
  其餘                               → 格 = 18
0x11000–0x110B4                       ; 平滑化:5/6/7 夾在 18 中間的孤島也改成 18
```

⚠ **第二趟才是最後結果** —— 它把第一趟寫的 7(山脈那一類)全部改回 18。
所以世界戰鬥的戰場上**只會出現兩種地形**:海洋(11 → 格 5)與世界值 10(→ 格 6);
森林、草原、山脈一律是空地。地城戰鬥的來源是迷宮格值,而迷宮值裡沒有 10/11,
**所以地城的戰場一律沒有地形**。

每一格地圖攤成 **5×5** 格(`0x10E78`:`5 × i + 1`),3×3 攤開就是 15×15,
落在 31 寬的格陣列上以隊伍的 (13,13) 為中心 —— 與手冊 p.33 的「15×15」
和 [`186`](186-monster-ai-target-placement-cast.md) §1 的錨點範圍 6…20 對得上。

量完立刻還原,`game/` 全程唯讀。

⚠ **世界地圖的索引是 `x × 103 + y`**(`internal/world.Map.At` 的說明,
[`141`](141-world-map-axes-were-transposed.md) 裁決過)。改地圖做實驗時用錯這個約定,
patch 下去的是**一整條直行**而不是橫列 —— 隊伍走幾步就走出去了,
而畫面上看起來只是「什麼都沒發生」。

## 4. 對 remake 的影響

引擎照這個結果畫地形(`rules.BattlefieldCell` / `BattlefieldTile`、
`combat.Field.SetTerrain`、`engine/board_sprite.go` 的 `loadCombatTiles`):

- 一格地圖攤成 **5×5** 格,3×3 攤成 15×15,以隊伍基準 (13,13) 為中心
- **只有海洋與世界值 10 會長出地形**,其餘一律空地;地城戰鬥沒有地形
- 資產:`cmd/convert` 把 `FASTCMBT.BIN` 的九個槽轉成 `assets/gfx/combat/cN.png`

⚠ 地形**不影響任何規則** —— 原版的通行判定讀的是格陣列裡的單位(值 ≥ 32),
不是地形值。⛔ 不要讓它擋路。
