# 228 — 原版**有音效**:`CMBT` 的七個代碼與 20 個呼叫端

> 輸入:`CMBT.EXE`、`BRUN30.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md);
> 讀之前先跑 `tools/ida/unlock_module.py`)。
> 信心:**已確認**(常式、代碼、頻率與時值逐條讀出;呼叫端 20 個全部列出)。

[`216`](216-the-game-has-two-tunes.md) §5 把「有沒有音效(非樂曲)」列成**沒查**:
那一篇清點的是 `PLAY` 的樂譜字串,而 BASIC 的音效走的是**另一個敘述** —— `SOUND`。
這一篇把它查完。

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | 原版**有音效**:`CMBT` 有一支「代碼 → 一串 `SOUND`」的常式,20 個呼叫端 | **已確認** |
| 2 | `S)ound` 鍵切的是 `ds:9306` —— **音效的開關**,不是音樂 | **已確認** |
| 3 | 七個代碼:`BP` `HT` `HK` `BR` `DD` `PS` `FL`,各自的頻率與時值都讀出來了 | **已確認** |
| 4 | `HT`/`HK` 對到「命中/劈砍」兩種訊息、`DD` 對到死亡、`PS` 對到施法 | 證據充分(§4)|

## 1. `INT 3E:5E` = `SOUND`

`3E` 的派工表在 `BRUN30` 的檔案位移 **`0x443`**(`cs:0x243` + MZ 標頭 `0x200`,
[`06`](06-runtime-int-abi.md) §1),所以索引 `n` 的目標 = `[0x443 + 2n] + 0x10000`。

| 索引 | 目標 | 語意 |
|---|---|---|
| `3E:51` | `0x1F301` | **`PLAY`**(`bx` = 樂譜字串)—— 通關曲與死亡曲走它 |
| `3E:5E` | `0x1F1BC` | **`SOUND`**:`bx` = 頻率(Hz),`dx` = 指向**時值**的單精度變數 |
| `3E:5F` | `0x1F211` | 敘述結尾:呼叫端固定送 `bx = dx = 0FFFFh` |

時值的單位是 BASIC 的**時鐘節拍**(18.2 Hz),所以 `8` 拍 ≈ 0.44 秒。

## 2. 音效常式:`CMBT 0x184BB`,**20 個呼叫端**

```
0184BB  INT 3F:53                      ; SUB 開場
0184C0  cmp ds:9306h, 0FFFFh           ; ★ 音效開關;不是 −1 就整支跳過
0184CA  [bp+6] → ds:9FAA               ; 參數:兩個字母的代碼
        以下是一串 INT 3F:62(字串比較)的鏈
018685  INT 3F:54 / retf 2             ; SUB 收尾
```

`ds:9306` 的初值在 `0x10436` 寫 **1**,而 `S)ound` 的兩句話
(`Sound is now on./off.`,`CMBT.tsv` 第 52/53 列)切的就是它 ——
**原版那個開關關的是音效,不是音樂**(音樂只有結局與全滅兩處,擋不到)。

## 3. 七個代碼

| 代碼 | 序列 | 聽起來 |
|---|---|---|
| `BP` | `INT 3E:2B`(BASIC 的 `BEEP`)| 短嗶 |
| `HT` | `SOUND 120, 8` | 低沉的一擊 |
| `HK` | `SOUND 90, 6` | 更低、更短 |
| `BR` | `SOUND 80, 10` | 最低最長 ⚠ **`CMBT` 裡沒有呼叫端** |
| `DD` | `SOUND 45, 12` | 極低的長音 |
| `PS` | 迴圈 **7 次**:`SOUND 1200, .25` / `1175, .25` / `1150, .25` | 高音快速顫音 |
| `FL` | 迴圈 **3 次**:同上三音;接著從 `1100` **每次減 25** 掃到 `400`,每音 `.1` 拍 | 顫音 ＋ 下墜 |

`PS` 的迴圈變數在 `ds:9FCA`,從 1 起、`cmp ax, 7 / jle` → **7 圈**;
`FL` 同一個變數 `cmp ax, 3 / jle` → **3 圈**,之後 `ax = 0x44C`(1100)、
`add ax, 0FFE7h`(−25)、`cmp ax, 190h`(400)`/ jge` → 下掃 **29 個音**。
時值是 `ds:9FAE` = 8、`ds:9FB2` = 6、`ds:9410` = 10、`ds:9FC2` = 12、
`ds:9FC6` = 0.25、`ds:93D0` = 0.1(全部從 DGROUP 初值讀出,MBF 單精度;
`tools/dgroup_init.py CMBT.EXE --at <位址>`)。
比對不到任何代碼時走 `bx = 39 / INT 3E:11`。

⚠ **迴圈次數要從 `cmp`／`jle` 讀,不要從「幾組 `SOUND` 排在那裡」數。**
迴圈本體裡是三個 `SOUND`,而迴圈跑幾圈寫在別的地方 ——
兩者相乘才是聽到的東西。

## 4. 20 個呼叫端傳的是哪個代碼

每個呼叫端的形狀相同:`mov bx, <代碼描述子> / mov dx, <暫存> / INT 3F:61`
(字串指派,[`182`](182-ending-music-is-assembled-at-runtime.md) §1)→ `push` → `call sub_184BB`。

| 代碼 | 次數 | 呼叫端 |
|---|---:|---|
| `BP` | 9 | `0x12BF6` `0x134D9` `0x13C9E` `0x14FD4` `0x169B4` `0x172ED` `0x174AB` `0x1766D` `0x17834` `0x1791A` |
| `PS` | 6 | `0x159B8` `0x15EF1` `0x15FD9` `0x16480` `0x16593` `0x1675A` |
| `HK` | 1 | `0x13974` |
| `HT` | 1 | `0x139A3` |
| `FL` | 1 | `0x16949` |
| `DD` | 1 | `0x18764` |

**位置本身就是語意的旁證:**

- `0x13974` / `0x139A3` 這一對緊鄰**攻擊訊息**的兩個岔路 ——
  `and hacks for`(狂暴)與 `and hits for`(一般),[`153`](153-damage-formula-closed.md) §7。
  兩個代碼、兩句訊息、同一個分岔 → **`HK` = 劈砍、`HT` = 命中**。
- 六個 `PS` 全部落在 `0x159B8`–`0x1675A`,而那一段是**施法**的路徑
  ([`226`](226-monster-cast-invest-and-target.md) §3 的 `0x15534` 之後、
  [`195`](195-group-spell-round-gate-and-area.md) 的 5×5 範圍框在 `0x159C2`)。
- `0x18764` 的 `DD` 在一支 SUB(`0x18750`)的開頭,**播完就把死者清掉**:
  `[si+6AD4] = ds:92F6` 把它在戰場格(寬 `0x1F`)上換成空地,
  再對單位屬性陣列 `ds:6822`(每列 15 個單位)寫
  `屬性10 = −1`、`屬性0 = 0`、`屬性1 = 5`、`屬性3 = 0`。
  **所以 `DD` 是「某一個單位死了」,不是「全隊陣亡」** —— 一次死一個就響一次。
- 四個 `BP` 落在 `0x172ED` / `0x174AB` / `0x1766D` / `0x17834`,
  **緊接在四支捲動常式之前**(`0x172F7` / `0x174B5` / `0x17677` / `0x17136`,
  [`226`](226-monster-cast-invest-and-target.md) §3)。

⚠ `BR` 在 `CMBT` 裡沒有呼叫端(常式支援它,但這支模組不用)。
`BP` 的九處與 `FL` 的一處在 §6 逐條讀過 —— **結果是不接**。

## 5. 對 remake 的影響

引擎先前**只有音樂沒有音效**,而 `S)ound` 鍵切的是音樂 ——
兩件事都與原版相反。這一篇之後:

- `internal/music.Effect` 用同一個方波合成器產生 `SOUND` 的音;
  七個代碼的頻率與時值照抄
- 接上**四個有證據的觸發點**:命中、劈砍、死亡、施法
- ⛔ `BP` / `FL` / `BR` **不接** —— 理由見 §6。
  資料照抄進程式碼(它們是讀出來的事實),但不猜觸發時機

## 6. `BP` 與 `FL` 逐條讀過了 —— **結論是不接**(2026-08-20)

十個呼叫端的前 0x40–0x60 bytes 全部用 `tools/ida/raw_bytes.py` 讀過
(`INT 3F` 內嵌運算元讓 IDA 在這一帶切錯邊界,`dump_range` 不可信)。

### 6.1 五個 `BP` 是游標移動那一組

`0x172ED` / `0x174AB` / `0x1766D` / `0x17834` / `0x1791A` 的前文**幾乎逐 byte 相同**:

```
      … 45 次的迴圈(cmp ax, 2Dh / jle)
      bx = ds:35C0 / dx = ds:35C2 / cx = 0 / INT 3E:89
      bx = 927Ch / dx = 3 / INT 3E:58        ; PUT —— 把游標重畫上去
      dec(或 inc)ds:9346 / ds:9348          ; ★ 游標座標
      jmp  ────────────────────────────┐    ; **正常路徑跳過 BP**
      bx = 9676h('BP')… call sub_184BB │
      add ds:956C, …                   │
                                    ←──┘
```

`ds:9346` / `ds:9348` 就是檢視面板取用的那一對游標座標(§4 的 `0x129C6`),
`INT 3E:58` = `PUT`(§1 的表)。四個方向 ＋ 一個共用的收尾。

### 6.2 三個 `BP` 的閘門是「行動點數 < 3」

`0x13C9E` / `0x169B4` / `0x1791A` 前面都是同一句:

```
cmp word ptr ds:956Ch, 3
jl  → BP
jmp → 跳過 BP
```

**`ds:956C` 是當前行動者的剩餘行動點數**,這一點是讀出來的:
`find_dsref.py` 掃 16,416 條指令得到 36 處,裡面有
`dec`(−1)、`add …, 0FFFDh`(**−3**)、`add …, 0FFFEh`(−2),
以及與 `0 / 1 / 2 / 3` 的比較 —— **與已知的成本表對得上**
(移動 1 點、攻擊與施法 3 點,[`spec/01`](../spec/01-combat.md))。

### 6.3 為什麼還是不接

兩種讀法都與觀察相容,而它們**接到的位置完全相反**:

| 讀法 | BP 是什麼 | 支持 |
|---|---|---|
| A | **「這個動作做不到」的提示音** | §6.2 的「點數不足」閘門 |
| B | **「這個動作做完了」的提示音** | §6.1 的 BP 路徑**之後**才調整點數 |

⛔ **沒有第三條證據能分開這兩個。** 接錯了玩家聽到的是
「這裡本來就會嗶」,不會知道它嗶在錯的時機 —— 與 §5 同一條紀律。

要分開它們得靠**實跑**:在 DOSBox 裡打開音效,分別做一次
「點數足夠的移動」與「點數不足的嘗試」,聽哪一次嗶。
那是[`CLAUDE.md`](../../CLAUDE.md) §6 的第 1 級證據,**一次就能定案**。

### 6.4 `FL` 落在施法路徑上

`0x16949` 在六個 `PS` 的區間內(`0x159B8`–`0x1675A`),前文是
`INT 3E:42`(bx=0x0B)、`INT 3E:44`(bx=0x17)與 `ds:7322 = 1`。
波形也支持:`FL` 是 `PS` 的三音重複 **3 次 ＋ 一段下掃**,
形狀上像「更大的那一版施法音」。

⚠ `ds:7322` **未讀**,所以「哪一種法術」沒有答案。同樣不接。

> **判準:讀完十個呼叫端而不接線,不是白做。**
> 這一輪把 `ds:956C` 認出來(行動點數),把五個 `BP` 歸成同一組,
> 並且**把剩下的問題縮小成一次實跑就能回答的形式** ——
> 下一次不必再從十個位址重新開始。
