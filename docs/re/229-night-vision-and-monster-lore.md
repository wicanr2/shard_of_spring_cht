## 1. 夜視:`MAZEMOVE 0x11641`–`0x116C5`

進迷宮的初始化序列裡,清完逃跑旗標(位移 85)之後:

```
011622  ds:66C8 = 2 ; ds:66CA = 3Dh(61)  → 隊伍記錄位移 61 ← 2   ★ 預設
01163B  ax = ds:34F8h → ds:8ECA          ; 迴圈上界 = 隊伍人數
011641  ax = 1 → 進迴圈

011648  ax<<2 + 34E0h                    ; 第 i 位隊員的記錄描述子
011651  dx = 2Eh(46) / cx = 1 / INT 3D:0A ; MID$(記錄, 46, 1)   ← 夜視旗標
01165F  bx = 8E16h / INT 3F:62            ; 與 "1" 比較
01166A  dx = (相等 ? −1 : 0) → [bp−8]
011678  dx = 0Fh(15) / INT 3D:0A          ; MID$(記錄, 15, 1)   ← 職業
011681  INT 3F:62                         ; 與 "1"(戰士)比較
01168C  and dx, [bp−8] / jnz → 011696     ; **兩個都成立才繼續**

011696  ds:66C8 = 3 ; ds:66CA = 3Dh(61)  → 位移 61 ← 3          ★ 夜視
0116BA  ds:8DCC++ / cmp ds:8ECA / jle → 011648                   ; 下一位
```

`ds:8E16` 是長度 1 的字串描述子,內容在 `ds:8E1A` = `31h` = **`"1"`**
(`tools/dgroup_init.py MAZEMOVE.EXE --at 8E1A`)——
與 [`188`](188-dispell-undead.md) §2 的 `ds:94CC` 是同一個成語。

### 1.1 位移 61 是「沒有光時的能見度」

[`204`](204-light-burns-per-turn-and-offset-83.md) §2 定案:位移 **59 = 有光**、
**61 = 沒有光**。火把燒完之後畫面用的就是 61
([`213`](213-visibility-is-the-draw-radius.md):能見度就是繪製半徑)。

所以夜視的效果是:**火把滅了之後,看得到的範圍從 5×5 變成 7×7**。

### 1.2 獨立印證:出貨存檔的值就是 2

```
PARTY #5   位移 59(有光)= 3   位移 61(沒有光)= 2
```

**2 正是程式碼寫的預設值。** 出貨的那支隊伍裡沒有帶夜視的戰士 ——
這條印證與反組譯互相獨立(檔案內容 vs 程式碼),滿足
[`CLAUDE.md`](../../CLAUDE.md) §2.1 的條件 3。

⚠ 前四個槽的同一位置是 `20 20`(兩個空白)—— **空槽**,不是 0。

## 2. 怪物知識與策略:`CMBT 0x1291B`–`0x129C6` 決定面板的詳細度

### 2.1 入口:`?` 或 `/`

戰鬥的按鍵派工是一串字串比較(`INT 3F:62`):

```
0128FE  bx = 9606h('?')  → 相等 → 0x1291B
01290E  bx = 9622h('/')  → 相等 → 0x1291B
012918  兩個都不是       → 繼續比別的鍵
```

**兩個鍵都通到同一個處理常式。** 這關掉
[`spec/19-coverage`](../spec/19-module-text.md) 旁邊那一份稽核裡的
「`?` 還是 `/`」——**答案是兩個都是**。

### 2.2 詳細度怎麼算

```
01291B  di = ds:9352h(當下行動者)→ [di+6A7Ah] → 角色編號
012925  bx = (角色編號 − 8) × 4 + 34E0h      ; 記錄描述子(與 188 §2 同一個成語)
012930  INT 3F:61 → ds:9628h                 ; 把記錄字串指派給存取子
01293A  dx = 0Fh(15) / INT 3D:0A / 3D:13 / 3F:78
012952  ds:962Ch = ax                        ; ★ 職業編號(1 戰士 / 2 巫師)
012955  ds:962Eh = cx                        ; ★ 詳細度,初值 1(§2.3)

012959  cmp cx, ax                           ; 詳細度 == 職業,也就是「職業 == 1」
012963  dx = 2Fh(47) / INT 3D:0A / 3F:62     ; MID$(記錄, 47, 1) == "1"
01297C  and → jnz
012985  ds:962Eh = 2                         ; ★ 戰士 + 位移 47

01298B  cmp ds:962Ch, 2                      ; 職業 == 2(巫師)
01299B  dx = 32h(50) / INT 3D:0A / 3F:62     ; MID$(記錄, 50, 1) == "1"
0129B7  and → jnz
0129C0  ds:962Eh = 3                         ; ★ 巫師 + 位移 50
```

位移 47 = 技能 6、位移 50 = 技能 9(位移 = 41 + 技能編號,[`27`](27-chars-dat.md))。
**同一段位移在兩張表是不同技能**([`94`](94-skill-tables.md) §1),
而這裡兩個分支各自把職業釘死了:

| 分支 | 職業 | 位移 | 那張表的技能 |
|---|---|---:|---|
| 詳細度 2 | 戰士 | 47 | **策略**(`TACTICS`)|
| 詳細度 3 | 巫師 | 50 | **怪物知識**(`MONSTER LORE`)|

> **判準**:一段位移對到兩張表時,**先確定分支限定哪一種職業再查表**
> ([`188`](188-dispell-undead.md) §1 的同一條)。查錯表的結論會自洽 ——
> 「巫師 + 武器知識」在檢視面板裡也講得通,沒有任何訊號說它是錯的。

### 2.3 初值是 1

`cx` 在 `01293D` 被設成 **1**(`MID$` 的長度引數),之後只經過三個
`INT` 呼叫就在 `012955` 被存進 `ds:962E`。

⚠ 「那三個 API 不動 `cx`」**沒有逐一驗證**,所以信心是**證據充分**不是已確認。
但這一項對行為沒有影響:**兩個分支寫的是明確的 2 與 3**,
初值只要不是 2 或 3,面板的表現就一樣。而且第一個判斷是
`詳細度 == 職業` —— 初值若不是 1,那一行就不成句子。

## 3. 三個詳細度各印什麼

`ds:962E` 全模組只有 5 處(3 寫 2 讀,`find_dsref.py` 掃 16,416 條指令):

```
018957  cmp ds:962Eh, 2   ; ★ 詳細度 2
0189B1  cmp ds:962Eh, 3   ; ★ 詳細度 3
```

### 3.1 詳細度 2 —— `Seeks> `

```
018957  cmp ds:962Eh, 2         → bx = 布林
018962  cmp cx, 9               → ax = (cx < 9),也就是**被看的是怪物**
01896B  and ax, bx / jnz
018988  bx = 9FFEh              ; 'Seeks> '
018990  cx += 0E1h(225 = 15×15) ; → 屬性 15
018998  bx = [di+6822h]         ; 鎖定的隊員編號
0189A0  bx = 該編號 × 4 + 6A98h ; → 名字
0189AE  jmp 18BE1               ; **跳過詳細度 3 那一整段**
```

屬性 15 = 鎖定對象([`186`](186-monster-ai-target-placement-cast.md) §2),
與手冊 p.35 的 `TACTICS` 完全吻合。

⚠ **手冊寫「隊上有人會策略」,程式碼看的是「當下行動者自己會」。**
證據優先序([`CLAUDE.md`](../../CLAUDE.md) §6):反組譯是第 2 級、手冊是第 3 級 ——
**以程式碼為準**。差別看得出來:換一個人行動,面板就多一行或少一行。

### 3.2 詳細度 3 —— 整組數值

`0x189BB`–`0x18BE0` 印的字串,逐條查 DGROUP:

```
ds:A01C 'Speed:    '   ds:A02A 'Skill:    '   ds:A038 'Strength: '
ds:A046 'Magical:  '   ds:A054 'Armor rating:' ds:A066 'Attacks with:'
ds:A00E 'YES'          ds:A016 'no'
```

`Magical:` 的 YES/no 判的是 `屬性 7 > 0`(`0189C4`)——
與引擎既有的「屬性 7 = 法力」一致,是一條順帶的交叉印證。

**所以整組數值是巫師 + 怪物知識才看得到的。**
引擎先前對怪物**無條件**印這一組。

### 3.3 為什麼實跑截圖看不出來

2026-08-18 的 QA 截圖 `i1-inspect.png` 只有 `Fire Hawk` + `Status: OK` ——
而 `Fire Hawk` 是**隊伍第 4 位**([`139`](139-oracle-reaches-gameplay.md)),
不是怪物。那張圖證實的是「看隊員只印名字與狀態」,
**沒有測到怪物那一側**,所以詳細度的存在不會從那張圖上冒出來。

> **判準:一張截圖只證明它拍到的那一格。**
> 拿它推「面板就是長這樣」會把兩條規則合併成一條 ——
> 而合併之後的版本在那張截圖上完全成立。
