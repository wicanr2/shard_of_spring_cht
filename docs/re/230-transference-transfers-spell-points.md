## 1. 派工:類別 5 與 13 是同一組

`CAMP.EXE` 把效果類別(`SPELLS.DAT` 欄3)放在 `ds:7482`:

```
0x11982   類別 == 5  OR 類別 == 13  → 0x11EE5    ★
0x119A1   類別 == 8  OR 類別 == 9   → 0x120DB
0x119C0   類別 == 10                → 0x122B4
0x119CA   類別 == 12                → 0x12419    (再依列號分,re/193)
```

⚠ 這一段 IDA **切錯了指令邊界**(`INT 3F` 的內嵌運算元,
[`CLAUDE.md`](../../CLAUDE.md) §3.3),要用 `tools/ida/raw_bytes.py` 讀位元組 ——
與 [`201`](201-item-and-spell-fails.md) 是同一個坑:
**切不出來的那幾行往往正是判斷式**。

### 1.1 `CMBT` 沒有類別 13

掃 `cmp word ptr [di+7340h], imm` 的**全部 12 處**,值只有
`1 / 3 / 4 / 5 / 6 / 7 / 8 / 11` —— 沒有 13。
所以移轉術在戰鬥中放不出效果,它是營地法術。

⚠ 這是「掃到分母、值域裡沒有」的結論,不是「找不到」——
掃描範圍是 `CMBT.EXE` 全部 44,695 bytes。

## 2. 兩個類別只差一個位移

`0x11F79` 起:

```
011F79  cmp word ptr ds:7482h, 5
011F7E  jz  → 011F83
011F80  jmp → 011F92

011F83  ds:70BE = 1Ch (28)     ds:773E = 22h (34)     ; 類別 5
011F8F  jmp → 011FAD

011F92  ds:70BE = 20h (32)     ds:773E = 26h (38)     ; 類別 13
011F9E  ax = ds:74CA(投入)
011FA1  cmp ax, ds:773C(量) / jl → 011FAA
011FAA  ds:773C = ax                                  ; ★ 量 = min(量, 投入)
```

`ds:70BE` 之後就是存取子的位移引數:

```
011FB5  bx = 目標的角色記錄
011FBF  ax = ds:70BE          → ds:66D0 = 位移(28 或 32)
011FCB  call 10078            → ds:7740 = **目前值**
011FDD  bx = 位移 − 2         → ds:66D0 = 26 或 30
011FE7  call 10078            → ds:7742 = **最大值**
```

**`CHARS.DAT` 的佈局把這一段釘死了**([`formats/01`](../formats/01-chars-dat.md)):

| 位移 | 欄位 |
|---:|---|
| 26 | 最大生命 |
| 28 | 生命值 |
| 30 | 最大法力 |
| 32 | 法力 |

「位移 − 2 就是那一欄的最大值」對 28/26 與 32/30 **同時成立** ——
這不是巧合,是資料佈局本來就把「目前/最大」成對放。
所以類別 5 動生命值、類別 13 動法力,**不必再找第二個證據**。

### 2.1 手冊獨立印證

精訊 1987 中文手冊 p.33(`docs/manual/raw/scan-030-038.md`):

> 移轉術 TRANSFERENCE(3):將法力點數由一名巫師傳到另一名巫師身上。

原文的命中訊息是 `Gains power`。**手冊講的效果與位移 32 完全吻合。**

⚠ 手冊說「巫師傳到巫師」,而程式碼**沒有職業檢查**。
不必補一個 —— 戰士的最大法力是 0,第 3 道夾住會把新值壓回 0,
**限制是資料長出來的,不是規則寫出來的**。⛔ 不要加原版沒有的檢查。

## 3. 量與夾住

量的算法與其他法術**同一條**([`201`](201-item-and-spell-fails.md)、
[`209`](209-camp-spell-fails-same-rule.md)):

```
011F06  ...  bx = ds:74CA(投入)、ds:7484(欄4)、ds:7486(欄5)
011F4A  INT 3F:77                      ; 四捨五入(re/185)
011F4F  ds:773C = 量 = round(欄4 × 投入 ÷ 欄5)
```

三個變數的身分由**另外三處**釘住:`0x12185` / `0x12366` / `0x124BB`
都是 `mov ax, ds:7484h / imul word ptr ds:74CAh`(欄4 × 投入),
而 `0x11909` 是 `sub ax, ds:74CAh`(扣掉投入的法力)。

寫回之前:

```
011FED  新值 = 目前 + 量
011FF6  新值 < 3        → 新值 = 3                      ★ 下限是 3,不是 0
012004  最大值 < 新值   → 新值 = 最大值;量 = 最大值 − 目前
01201A  ds:6F10 < 新值  → 新值 = ds:6F10;量 = ds:6F10 − 目前
012030  寫回目標記錄的位移 28 / 32
```

⚠ `ds:6F10` = **255**([`218`](218-four-named-assumptions-audited.md) §1)。
那一篇把它叫「補給品上限」,而**生命值與法力用的是同一個變數** ——
它是通用的 255 上限,不專屬補給品。

⚠ 讀到的是 **`CAMP` 那一份**。`CMBT` 的治療走另一個模組,**沒有讀** ——
所以這一組夾住只套在營地施法(`engine/camp_actions.go` 的 `applyCampUnit`)。

### 3.1 為什麼是 1:1

移轉術的 `SPELLS.DAT` 欄4 = **3**、欄5(單價)= **3**,所以

```
量 = round(3 × 投入 ÷ 3) = 投入
量 = min(投入, 投入)     = 投入
```

**投入幾點就轉幾點。** 那道 `min` 在這個法術上永遠不會生效 ——
它擋的是「欄4 > 欄5 的法術憑空生出法力」,是一道**結構上的**保險。

> **判準:一道永遠不觸發的上限,問的是「它防的是什麼」不是「它有沒有用」。**
> 照抄進 remake,因為它描述的是這個效果類別的契約,不是這一個法術的巧合。

## 4. 對 remake 的影響

- `magic.EffTransference` 從「未解」改成**把法力轉給目標**,量 = `min(效力, 投入)`
- 新增 `magic.Restore`(下限 3 / 最大值 / 255),營地施法寫回記錄時套用
- ⚠ **只在「變多」時走那一組夾法**:原版那支常式的下限 3 待在回復的路徑上,
  而營地施不出會扣血的類別 5(欄4 < 0 的算戰鬥法術)。
  一律套的話,被扣到 0 的人會被「夾」回 3 點 —— 那不是回復,是憑空回血
- `combat.Unit` 與 `campUnit` 補上 `SP` —— 先前營地施法整條路徑不帶法力,
  所以就算解出來了也寫不回去
