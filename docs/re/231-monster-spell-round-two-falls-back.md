## 1. 第一格:答案在另一篇裡

[`170`](170-monster-ai-casts-by-spell-family.md) §6 的「剩餘的不確定」表寫著:

> `ds:7340` 旗標陣列的語意 | **未解**

而 [`171`](171-spell-effect-class-table.md) §1 已經讀出來:那個陣列是
`0x107EF` 用 `INT 3F:B8`(`INPUT#`)從 **`SPELLS.DAT`** 讀進來的**欄3**,
索引是 `法術編號 × 2`。值域(1/3/4/5/6/7/8/11)與欄3 的實際值域也對得上。

**所以 `[di+7340h] == 1` 是「效果類別 == 1」= 群體傷害**,
而那正是 [`171`](171-spell-effect-class-table.md) §2 講的「第一回合不要挑到暴風」。
引擎的 `pickMonsterSpell` 一直就是照這條寫的。

> **判準:兩篇筆記讀同一個位址而結論不同時,先問「它們是不是同一件事的兩個說法」。**
> `170` 從**呼叫端**看到它(「比 1 就重選」),於是叫它旗標;
> `171` 從**載入端**看到它(`INPUT#` 讀檔),於是知道它是欄3。
> ⛔ 兩篇都沒錯,錯的是 `170` §6 的表**沒有跟著 `171` 收掉** ——
> 「未解」清單過期的成本,是下一輪有人真的回去重查一次。

## 2. 第二格:`0x155AA` 那一條 `jmp` 落在哪裡

`0x15563`–`0x155AD`(用 `tools/ida/raw_bytes.py` 讀位元組,
`INT 3F` 讓 IDA 在這一帶切錯邊界):

```
015563  cmp word ptr ds:9314h, 1      ; 回合
015568  jg  → 01556D                  ; 第二回合起
01556A  jmp → 0155B0                  ; ★ 第一回合:隨機挑

01556D  ds:9B10 = 系別
015571  cmp 1 → 01557B  ds:98D8 = 3   (FIRE STORM)  → jmp 0155AD
015584  cmp 3 → 01558E  ds:98D8 = 8   (TEMPEST)     → jmp 0155AD
015597  cmp 4 → 0155A1  ds:98D8 = 12  (HAIL STORM)  → jmp 0155AD
0155AA  jmp → 0155B0                  ; ★★ 系別 2 / 5 落到這裡
0155AD  jmp → 015701                  ; 三個暴風的共同出口
```

**`0x155AA` 與第一回合那一條 `jmp`(`0x1556A`)去的是同一個位址 `0x155B0`。**

所以系別 2 / 5 第二回合起走的是**與第一回合完全相同**的隨機挑選,
不是「沒有分支就不施法」。

⚠ 那道「挑到群體傷害就重選」的過濾**要第一回合才成立**
(`0x156DE` 比 `ds:9314 == 1`),所以第二回合起沒有過濾 ——
但系別 2 / 5 本來就沒有欄3 = 1 的招,差別是零。

## 3. 引擎先前是錯的,而且沒有症狀

`internal/rules.MonsterSpell` 第二回合起直接回 `StormSpell[family]`,
而那張表沒有 2 與 5 → 回 **0** → `monsterCast` 判定「挑不到就不施法」。

**效果:系別 2(金屬)與系別 5(靈)的怪物從第二回合起再也不施法。**

⚠ **這個錯沒有任何症狀。** 一隻不施法的怪就是走過來砍人 ——
畫面正常、訊息正常、測試全綠,而且它連「變弱」都不明顯:
玩家沒有原版可以對照,不會知道那隻邪靈本來應該一直放法術。

> **判準:「沒有那一條分支」與「不做那件事」是兩回事。**
> 讀到 `cmp` 鏈的最後一個 `else`,要去看那條 `jmp` 落在哪裡 ——
> 落在「什麼都不做」和落在「回到預設路徑」長得一模一樣,
> 而**在筆記裡它們都會被寫成「沒有分支」**。

## 4. 對 remake 的影響

- `MonsterSpell` 第二回合起改成:**有暴風就放暴風,沒有就落回隨機挑**
- 群體傷害的重選過濾加上 `round == 1` 的條件(照原版的閘門)
- [`170`](170-monster-ai-casts-by-spell-family.md) §6 的兩列都撤掉
