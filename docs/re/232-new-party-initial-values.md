# 232 — 新組隊伍的初值:`CHARUTIL 0x12043`–`0x12132` 填**八個欄位**

日期:2026-08-20
接續:[`spec/15`](../spec/15-game-shell.md) §5.1、[`167`](167-record-field-accessor-and-identified-flags.md) §1、[`229`](229-night-vision-and-monster-lore.md) §1
子系統:**D. 角色與存檔**
輸入:`CHARUTIL.EXE`(SHA-256 見 [`00-inputs.md`](00-inputs.md))

關掉 [`spec/15`](../spec/15-game-shell.md) §5.1 的大半:
「新組的隊伍從哪裡開始」**不再是具名假設**。

## 結論

| # | 結果 | 信心 |
|---|---|---|
| 1 | `CHARUTIL` 有一段連續的初始化,對**隊伍記錄**(`ds:34DC`)寫**八個欄位**,全部是立即數 | **已確認** |
| 2 | 世界座標 **(8, 8)**、朝向 **3(南)** —— 與出貨 PARTY #5 相同 | **已確認** |
| 3 | 有光 / 無光的能見度**都是 2**;迷宮編號 **99**(不在迷宮);大門旗標 **0** | **已確認** |
| 4 | **金幣、補給品、時鐘不在這一段裡**,而且 `CHARUTIL` 沒有別的常數位移寫入 | **已確認**(掃描分母見 §3)|

## 1. 那一段長什麼樣

八次同形的迴圈,每一次都是:

```
mov dx, 34DCh / INT 3F:5B      ; 隊伍記錄
mov dx, 66C4h / INT 3F:61      ; 存取子引數一:記錄
mov word ptr ds:66C8h, <值>    ; 引數二:值
mov word ptr ds:66CAh, <位移>  ; 引數三:位移
call <寫入>
mov bx, ax / mov dx, 34DCh / INT 3F:61   ; 寫回隊伍記錄
```

存取子與 [`167`](167-record-field-accessor-and-identified-flags.md) §1 讀到的是同一支,
只是那邊是**讀**(`ds:66CC`/`66D0`)、這邊是**寫**(`ds:66C4`/`66C8`/`66CA`)。

## 2. 八個欄位

| 位址 | 位移 | 欄位([`formats/02`](../formats/02-groups-dat.md))| 值 |
|---|---:|---|---:|
| `0x12049` | 69 | **未命名** | 0 |
| `0x12068` | 35 | 世界 X | **8** |
| `0x12087` | 37 | 世界 Y | **8** |
| `0x120A6` | 41 | 朝向 | **3**(南)|
| `0x120C5` | 61 | 能見度(無光)| **2** |
| `0x120E4` | 59 | 能見度(有光)| **2** |
| `0x12103` | 65 | 拉利斯之門旗標 | 0 |
| `0x12122` | 83 | 當前迷宮編號 | **99**(不在迷宮)|

### 2.1 順帶印證兩件事

- **位移 61 = 2** 與 [`229`](229-night-vision-and-monster-lore.md) §1 讀到的
  「進迷宮時預設寫 2」**是同一個數字的兩個獨立來源** ——
  一個在 `MAZEMOVE` 的每輪初始化、一個在 `CHARUTIL` 的建隊伍。
- **座標 (8,8) 與朝向 3** 與出貨 PARTY #5 相同,所以
  [`spec/15`](../spec/15-game-shell.md) §5.1 當初「照抄 PARTY #5」的猜法**猜對了** ——
  但那是猜對,不是知道。現在是知道。

⚠ 位移 **59 這裡是 2**,而出貨 PARTY #5 是 **3** ——
那支隊伍是原廠玩過的,值被更新過。**新隊伍的初值是 2。**

## 3. 沒有寫進去的東西

`c706ca66`(`mov word ptr ds:66CAh, imm`)掃全模組 **9 處**:
八處在這一段,第九處是 `0x117E5` 寫位移 12(角色記錄,不是隊伍記錄)。

**所以金幣(19)、補給品(23)、遭遇倒數(25)、時鐘(27/29/31/33)、
火把回合(45)、迷宮座標(79/81)、逃跑旗標(85)都不在這裡。**

⚠ 這**不表示**新隊伍的金幣是 75、補給品是 20 —— 那兩個數字來自出貨的
PARTY #5,而這一段沒有寫它們。金幣是 MBF 單精度(4 bytes),
寫法本來就不同,所以「常數位移的字組寫入」這個掃法**結構上抓不到它** ——
⛔ 不要把「這個掃法沒掃到」讀成「沒有人寫它」。

> **判準:一次掃描只證明「這種形式的寫入」有幾處。**
> 金幣的型別不同、寫法就不同,而分母是同一個數字時最容易忘記這件事。

## 4. 對 remake 的影響

`engine`(`spec/15` §5.1 的具名常數)裡:

- `NewPartyX / NewPartyY = 8, 8`、`NewPartyFacing = 3` —— **從假設升級成已確認**
- 補上 `VisLit = VisDark = 2`、`MazeNum = 99`、`GateOpen = 0`
- `NewPartyGold = 75` / `NewPartyProvisions = 20` **仍然是具名假設**,而且
  現在知道它們**不在建隊伍那一段** —— 下一輪要找的是別的寫入形式
