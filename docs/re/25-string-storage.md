# 25 — 模組裡的字串怎麼存,以及為何靜態解不出指標

日期:2026-08-13
接續:[`24-tooling-conflict.md`](24-tooling-conflict.md)
子系統:**L. 中文化落點**

## 結論

模組本體的字串常數旁邊有規律的 **`長度(word) + 指標(word)`** 結構,
與 [`12`](12-api-3f61.md) 從 `3F:61` 解出的四位元組描述子同形。

但**那些指標在磁碟映像上解不出字串** —— 因為它們是**未重定位**的。
所以「靜態把字串對到使用點」這件事,在套用重定位之前做不到。

## 1. 觀察到的排列

以 `CMBT.EXE` 的 `monst2.bin`(模組 `+0x92AA`)為例,前後都是同一種形狀:

```
08 00 6C 94   0A 00 70 94   0E 00 70 94   "monst2.bin"
08 00 7A 94   0A 00 7E 94   0E 00 7E 94   "monst4.bin"
```

每組 4 bytes = `長度` + `指標`,三組一批,然後接字元資料。
`rndmonst.bin`、`fastcmbt.bin` 前面也是同樣的三組。

**信心等級:形狀已確認**(四個檔名處都一致);**語意未定**。

## 2. 指標為何解不出來

把指標當「模組內位移」去讀,得到的不是字串,而是更多描述子形狀的位元組:

| 描述子 | 指向的內容 |
|---|---|
| `len=10 ptr=0x9470` | 又是 `08 00 BA 95 01 00 BE 95 …` |
| `len=14 ptr=0x947E` | 又是 `08 00 C0 95 04 00 C4 95 …` |

這與 [`03`](03-bz-module-header.md) §3 已確認的機制一致:
**模組裡的指標是 linker 擺的佔位值,載入時才由重定位表修補。**
磁碟上的值指向「未重定位的位址空間」,拿模組映像去解當然解不開。

同一個道理已經在 [`06`](06-runtime-int-abi.md) §3 出現過一次
(`INT 3Dh` 會把自己改寫成 far call)——
**執行中的映像與磁碟位元組不同**,而這裡是它對資料側的對應。

## 3. 對中文化的影響

[`18`](18-text-inventory.md) 估算模組內嵌文字有 362 條、約 14,100 字元(佔全部 39%)。
本文顯示這一層**不能只改字元資料**:

- 每條字串至少有一個長度欄位要跟著改
- 指標欄位在重定位表裡也有對應項

因為專案做的是 **remake 而非 patch**(`CLAUDE.md` §7),
正解仍是「抽出來變成外部資源」——
但**抽取本身需要先套用重定位**,才知道哪個描述子對應哪段文字。

**可行的順序**:
1. 先做資料檔那 61%([`18`](18-text-inventory.md) §3 的捷徑)
2. 模組內嵌那 39% 等重定位模擬做出來再處理
