# 29 — `DE*EFF.BIN` / `.MST`:同一份資料的兩個標頭

日期:2026-08-13
接續:[`28-input-semantics.md`](28-input-semantics.md)
子系統:`CLAUDE.md` §2.2 的 **I. 法術效果表**

## 結論

十對 `DE*EFF.BIN` / `.MST` 的**資料本體逐位元組完全相同**,
唯一的差異在 **BSAVE 標頭的 segment 與 offset 欄位**(檔案位移 1–4)。

所以它們不是「母本與工作副本」,而是**同一份內容、記錄了兩個載入位址**。

## 1. 差異只有 4 個 byte,而且都在標頭

| 檔案位移 | 欄位([`19`](19-bsave-container.md) §1) | 差異 |
|---|---|---|
| `+0x00` | `0xFD` 標記 | 相同 |
| **`+0x01`–`+0x02`** | **segment** | **不同** |
| **`+0x03`–`+0x04`** | **offset** | **不同** |
| `+0x05`–`+0x06` | length(1060) | 相同 |
| `+0x07` 起 | **資料 1,060 bytes** | **完全相同** |

九對逐一比對,差異位置都是 `[1, 2, 3, 4]`,**零例外**。

`.BIN` 側九個檔的 segment／offset **全部是同一組**(`0x0FB9` / `0x2268`);
`.MST` 側則每個檔不同,但值有分組
(例如 `DE5` 與 `DE51` 完全相同、`DE0` 與 `DE7` 完全相同)。

**信心等級:已確認**(逐位元組比對)。

## 2. 這推翻了一個很自然的假設

看到 `.MST`(master)與 `.BIN` 成對出現,最自然的讀法是
**母本 vs 工作副本** —— 這正是 daemon_winter 的
`ALL_SS.DAT` / `nSS.DAT` 的關係。

**這裡不成立。** 母本與工作副本的差異會在**資料**裡,
而這裡資料一個 byte 都沒差。

**判準:兩個檔「成對出現且其中一個叫 master」不足以推出母本關係;
先比對資料本體。** 這次比對成本是九次 diff。

## 3. 對 remake 的意義

資料只有一份,所以**素材抽取只需要處理其中一組**。
但兩組的載入位址不同,代表原版在不同情境載到不同地方 ——
`.MST` 那一側的 segment 分組(`DE5`/`DE51` 同值、`DE0`/`DE7` 同值)
可能對應「哪些法術效果會同時存在」。**這是推測,未驗證。**

## 4. 內容本身仍未解

1,060 bytes 的資料,前兩個 word 在十個檔之間完全不一致
(`(42,48)`、`(6,2)`、`(4,49)`、`(19,35)`…)——
**所以不是 [`21`](21-tile-format.md) 的 `GET` 陣列標頭**,
那套讀法在這一組上不適用(同 [`22`](22-pict-and-monst.md) §3 的教訓:
一個格式在 N 個檔上成立,只證明它適用於那 N 個檔)。

檔名 `DE<n>EFF` 中的 `<n>` 與地城編號(`DG<n>MAZE.SQZ`)同域:
`0`–`7` 加一個 `51`,而 `MAZEMOVE.EXE` 引用了 `DE5EFF.BIN` 與 `DE51EFF.BIN`
([`23`](23-module-datafile-map.md) §1)。
**所以 `EFF` 比較可能是「地城 n 的某種效果資料」而不是全域法術表。**
⚠ 推測,未驗證 —— 子系統歸類可能要從 I 改到 G。
