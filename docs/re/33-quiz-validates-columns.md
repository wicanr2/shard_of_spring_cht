# 33 — 開機題庫是一組外部驗證來源

日期:2026-08-13
接續:[`32-dosbox-oracle.md`](32-dosbox-oracle.md)
子系統:**E. 規則資料表**、**J. 戰鬥規則**

## 結論

`MENU.EXE` 的開機題庫問的**正是我在 [`16`](16-rule-tables.md) 標成「疑似」的那些欄位**。
每一題都指名手冊的哪張圖表,而遊戲的資料檔就是那張圖表的機器可讀版 ——
**題目主題 ↔ 資料欄位**的對應因此成為一組獨立驗證。

用它把 `ITEMS.DAT` 的兩個欄位從**疑似**升級,並**修正**了欄 3 的語意。

## 1. 題庫涵蓋的主題

`MENU.EXE` 的題目各自指名一張手冊圖表:

| 題目主題 | 指名的圖表 |
|---|---|
| 某武器的最大傷害 | Weapons Chart, pg 7 |
| 某護甲的防護值 | Armor Chart, pg 7 |
| 某雜項道具的價格 | Miscellaneous Items, pg 7 |
| 某法術的最低法力 | Minimum Spell Points Chart |
| 某種族的智力修正 | Racial Modifiers Chart, pg 3 |
| 屬性的上限值 | Traits, pg 3 |
| 力量對應的傷害加值 | Chart, pg 11 |

**這張清單本身就是遊戲規則的目錄** —— 它列出了原版認為「玩家需要查表才知道」的機制。

## 2. 對回資料表

| 題目問的 | `ITEMS.DAT` 的那一列 | 相關欄位 |
|---|---|---|
| 小斧的最大傷害 | `Small axe, small axe, 6, 4, 0, 2` | **欄 3 = 4** |
| 鎖甲的防護值 | `Chain, chain mail, 40, 3, 0, 3` | **欄 3 = 3** |
| 油燈的價格 | `Oil lantern, lantern, 10, 33, 0, 100` | **欄 2 = 10** |

### 2.1 欄 2 = 價格(確認)

題目問「油燈的**價格**」,而該列欄 2 是 `10` ——
與 [`16`](16-rule-tables.md) §3 觀察到的「匕首 2、短劍 15、闊劍 30、雙手劍 100」遞增一致。

**信心等級:證據充分**(從疑似升級)。

### 2.2 ⚠ 欄 3 不是「傷害」,是**型別相依的主數值**

[`16`](16-rule-tables.md) §3 把欄 3 標成「疑似傷害」。**那只對武器成立。**

- 武器(小斧):題目問**傷害**,欄 3 = 4
- 護甲(鎖甲):題目問**防護**,欄 3 = 3

**同一個欄位,在武器上是傷害、在護甲上是防護。**
所以正確的說法是「該道具的主要數值,語意由道具型別決定」。

**判準:一個欄位在某一類記錄上成立,不代表它在整張表上都是同一個語意。**
這與 [`22`](22-pict-and-monst.md) §3(格式跨組不通用)是同一個形狀,
只是換到了**欄位語意**這一層 —— 而抓到它靠的是題庫同時問了武器與護甲。

## 3. 這個驗證的性質

⚠ **這是「題目主題 ↔ 資料欄位」的對應,不是實跑驗證。**
我沒有讓遊戲驗證答案,也沒有從程式裡取出預存答案 ——
**用的是題目文字所指名的圖表主題**。

它成立的前提是:手冊圖表與遊戲資料檔記載同一套數值。
這個前提很強(否則玩家查手冊會答錯),但**仍是前提**。

要升到**已確認**,還需要 [`32`](32-dosbox-oracle.md) 的實跑:
在 DOSBox 裡由持有原版的人依手冊作答,確認遊戲接受。
