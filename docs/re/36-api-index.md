# 36 — 執行期 API 索引:實際被用到的 125 個

日期:2026-08-13
接續:[`35-shared-impl-wrappers.md`](35-shared-impl-wrappers.md)
子系統:**B. 執行期介面**

## 結論

七支主要遊戲模組實際用到 **125 個派工索引**、合計 **6,429 次呼叫**。
機器可讀的索引表已產出:[`generated-api-index.json`](generated-api-index.json)。

三張表宣告的容量遠大於此(630 個進入點),
所以**模組只用到約五分之一的執行期 API**。

## 1. 數字

| | |
|---|---:|
| 派工表進入點(前 210 × 3) | 630 |
| **模組實際用到** | **125(約 20%)** |
| 合計呼叫次數 | 6,429 |
| 其中是共用實作的包裝 | 28 |

名次的相對順序可信,絕對值不可信。

## 3. 這對後續的意義

**解 API 語意不必做完 630 個,甚至不必做完 125 個。**
前十個涵蓋四分之三的呼叫,解開它們就能讀懂模組程式碼的主幹。

其中已解或部分解的有四個(`3F:61`、`3E:42`、`3E:44`、`3F:6E`／`3F:6A` 同族),
**剩六個未解**:`3E:79`、`3F:BC`、`3E:83`、`3F:55`、`3F:62`、`3F:BB`。

⚠ `3F:55`(`0x9DE5`)與 `3F:61`(`0x9DAF`)只差 `0x36` ——
[`13`](13-api-3e42.md) §3 記過「相鄰索引常對到相鄰實作」,
而 [`35`](35-shared-impl-wrappers.md) 解釋了成因。**這兩支可能同族。**
