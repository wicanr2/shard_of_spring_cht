# 37 — 兩個高頻 API 的內容

## 1. `3E:83` → `0x1093A`(374 次)

**整支只有兩條指令:**

```
mov  ds:0A08h, sp
retf
```

把目前的堆疊指標存進 `ds:0A08h`,然後遠端返回。

**信心等級:已確認**(指令完整可讀,無分支)。

`ds:0A08h` 這個寫入**出現在多支 API 的開頭**:
`3F:61`([`12`](12-api-3f61.md))、`3E:42`([`13`](13-api-3e42.md))、
`sub_11F6B`([`35`](35-shared-impl-wrappers.md) §4)。

所以 **`ds:0A08h` 是執行期的「已存堆疊指標」全域**,
而 `3E:83` 是把它更新一次就返回 —— 形狀像**讓出控制／設定回復點**。
⚠ 用途未定案。

## 2. `3E:79` → `0x13C9B`(624 次)

```
push si
mov  si, ds:0A3Ah        ; 取一個全域指標
or   si, si / jz  略過    ; 為 0 → 什麼都不做
cmp  si, 0BE8h / jz 略過  ; 等於某個哨兵值 → 什麼都不做
test byte ptr [si+31h], 80h
jz   略過                 ; 該結構 +0x31 的 bit 7 沒設 → 什麼都不做
push ax/bx/cx/dx
call sub_13BB8
```

**三道閘門都通過才做事**,否則直接返回。

**信心等級:已確認**(控制流完整)。

這是**條件式的鉤子**:每次呼叫先問「那個全域指標有效嗎、旗標開著嗎」,
成立才呼叫 `sub_13BB8`。624 次的高呼叫量與這個形狀相符 ——
**它被灑在很多地方,但多數時候什麼都不做。**

`ds:0A3Ah` 在 `BRUN30` 的啟動流程裡被清成 0(`0x1166F`,
見 [`04`](04-module-layout-entry.md) §3 附近那段),
所以預設是「關閉」。

⚠ `sub_13BB8` 做什麼、`+0x31` 的 bit 7 代表什麼,**都未解**。

## 3. 一個對讀碼有用的樣式

`mov ds:0A08h, sp` 是**執行期 API 的共同開場白**。
看到它就知道:這是一個從模組被呼叫進來的進入點,不是內部常式。

**判準:找 API 邊界時,掃這個開場白比逐個查派工表快。**
