# 40 — `BRUN30` 的自我識別,與 DS 基底只解出一半

日期:2026-08-13
接續:[`39-ds0a3a-and-xref-blind-spot.md`](39-ds0a3a-and-xref-blind-spot.md)
子系統:**B. 執行期介面**

## 結論

1. **`BRUN30.EXE` = Microsoft BASIC Compiler Runtime 5.60(1982–1987)**,
   直接讀自它自己的字串。**已確認**,而且這是一份**獨立對照來源**
   (`CLAUDE.md` §2.1 條件 3)—— 5.60 的行為有公開文件可查。
2. **DS 基底只在「單獨執行」那條路徑上解出來(`DS = CS`),
   當遊戲執行期用時是多少仍未知。** 不要外推。

## 1. 識別字串

`0x1191D`(檔案位移可由 §2 的換算得到):

```
Microsoft BASIC Compiler Runtime
Version 5.60
(C) Copyright Microsoft Corp. 1982 - 1987
```

**信心等級:已確認**(位元組直接讀出)。

這是目前為止唯一一份**產品層級的身分證**。
先前所有關於執行期的結論都是從指令逆推的;現在有了版本號,
凡是能對到 5.60 公開行為的結論就多一個獨立佐證來源。

⚠ 但**不得倒過來用**:公開文件說 5.60 有某功能,不等於這支二進位就是那樣接的。
文件只能當條件 3 的對照,不能取代條件 1(在 IDA 裡讀原始指令)。

## 2. DS 基底:解出來的那一半

`BRUN30` 單獨執行時的進入點路徑:

```
010000  jmp   start_0                 ; → 0x1013C
01013C  mov   ax, cs
01013E  mov   ds, ax                  ; ★ DS = CS
   …
01015C  mov   dx, 191Dh
01015F  mov   ah, 9
010161  int   21h                     ; DOS 印字串(DS:DX)
010163  mov   ax, 4C99h
010166  int   21h                     ; 結束
```

**驗證方式是拿內容對,不是信工具:**

| 假設 | `ds:191Dh` 的線性位址 | 那裡的位元組 |
|---|---|---|
| `DS = CS`(`0x1000`) | `0x1191D` | `Microsoft BASIC Compiler Runtime…` ✅ |
| IDA 預設的 `ds = 0FF0` | `0x1081D` | `8b 0c e3 0f 83 e9 04…`(程式碼) ❌ |

**所以 IDA 自動填的 `ds = 0FF0` 是錯的。**
`tools/ida/list_segs.py` 會把它印出來,但那是猜測值,**不可當結論引用**。

⚠ 順帶:這條路徑印完訊息就 `INT 21h AH=4Ch` 結束 ——
**它是「單獨執行 BRUN30」的錯誤路徑**,不是遊戲用它時走的路。

> ⚠ **本節的反證已作廢。** [`41`](41-ds-base-solved.md) 解出執行期的 `DS = seg002`
> (不是 `CS`),下表的落點是用錯基底算的。保留是因為 §4 的「兩種讀法」結論仍然成立
> ——那三個常數指向的結構在檔案裡是全零的 BSS,靜態讀不出內容。

## 3. 沒解出來的那一半(用錯基底的反證)

遊戲執行時 `BRUN30` 是被載入器 stub 搬進來的([`02`](02-loader-stub.md)),
DS 由 stub 設定,**不保證等於 CS**。

反證:[`39`](39-ds0a3a-and-xref-blind-spot.md) §3 的三個常數
(`0x0BE8`、`0x0B8E`、`0x10F0`)若當成 `DS = CS` 下的位址,落點是:

| 常數 | `DS=CS` 下的線性位址 | 那裡是什麼 |
|---|---|---|
| `0x0BE8` | `0x10BE8` | 程式碼,後面接字串 `"No Line Number in "` |
| `0x0B8E` | `0x10B8E` | 字串中段(`"ess "`)|
| `0x10F0` | `0x110F0` | 程式碼 |

**三個都不是同構的結構**(`+0x31` 分別是 `0x06` / `0xF1` / `0x46`,毫無規律)。

兩種讀法都還活著:

- **(a)** 執行期用的 DS ≠ CS,所以這三個位址要用別的基底算
- **(b)** 這三個值**不是指標** —— `3E:79` 對它們的處理正好是**不解參考**
  (`si == 0` 或 `si == 0x0BE8` 就跳過),所以它們可以只是標記值

⚠ **[`39`](39-ds0a3a-and-xref-blind-spot.md) §3 把「它們是內建裝置結構的位址」寫成假設,
現在要降級** —— 上表是反證,不是佐證。已在該節加註。

### 怎麼裁決

看載入器 stub([`02`](02-loader-stub.md))怎麼設 `BRUN30` 的 DS。
那是一段已經讀過的程式碼,只是當時沒問這個問題。**下一步的主題。**
