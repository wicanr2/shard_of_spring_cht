# 45 — `INT 3Dh` 這一族在做什麼

日期:2026-08-13
接續:[`44-int3d-is-used-after-all.md`](44-int3d-is-used-after-all.md)
子系統:**B. 執行期介面**

## 結論

`INT 3Dh` 的 24 個索引指到 `BRUN30` 的 `0x19Cxx`–`0x19Exx`,
與 [`38`](38-api-are-basic-primitives.md) 的算術族同一區。
它們共用一支**自由串列配置器**,而其中一支有數字轉字串的明確特徵。

**假設:這一族是字串與暫存值的操作。** 證據見 §3,尚未定案。

## 2. `3D:00` 的目標是 `0x0000`,這是對的

索引 0 的表項是 `0x0000` —— 看起來像壞值,但它與
[`06`](06-runtime-int-abi.md) §3 完全一致:參數為 `0` 時處理常式**根本不查表**,
走的是 5 bytes 就地改寫成 far call 的路徑。

**表項 0 用不到,所以填 0。** 一個「看起來壞掉的值」在讀懂機制之後
變成了機制正確的佐證。

## 3. 五支的內容

全部以 `mov ds:0A08h, sp` 開場 —— [`37`](37-api-3e79-3e83.md) §3 認出的 API 開場白。

### `3D:0D`(45 次):數字轉字串

```
019D1B  mov ds:0A08h, sp
019D1F  push dx
019D20  mov  dl, 20h          ; ★ 空白
019D22  or   bx, bx
019D24  jz   <零>
019D26  jl   <負>
```

**先放一個空白,再依正負分支** —— 那是 BASIC 印正數時前面加空白的慣例
(`PRINT 5` 印出 ` 5`,`STR$(5)` 也是 `" 5"`)。
**信心等級:證據充分**(常數 `0x20` + 三向分支的組合對這個慣例是特徵性的)。

### `3D:05` / `3D:1B`:配置 1 或 2 個單位

```
3D:05:  mov bx, 1 / call sub_1A08B / xchg bx, dx / pop word ptr [bx]
3D:1B:  mov bx, 2 / call sub_1A08B / xchg bx, dx / pop word ptr [bx]
```

同一個形狀,只差 `bx` 的 1 與 2。

### `3D:0A`(144 次):兩個值的邊界檢查

```
or  cx, cx / jl <錯誤>
dec dx / xchg dx, cx / jl <錯誤> / jz <特例>
```

兩個參數各自檢查下界 —— `MID$` / `LEFT$` 這類「起點 + 長度」的形狀。
⚠ **假設**,只有形狀。

## 4. 共用的配置器 `sub_1A08B`

16 處引用,`3F:55`(加法)也用它:

```
01A08B  or   bx, bx / jz <直接返回>
01A08F  cmp  word ptr ds:0F56h, 0     ; 自由串列頭
01A094  jz   <串列空>
01A098  call sub_19EB2
01A09B  si = ds:0F56h                 ; 取一個節點
01A09F  dx = [si]
01A0A1  ds:0F56h = dx                 ; 串列頭往後移
01A0A5  pop  word ptr [si]
01A0A7  [bx-2] = si                   ; 反向指標
01A0AA  [si+2] = bx
01A0AD  dx = ds:0EDCh                 ; 擁有者標記
01A0B1  [si+4] = dx
```

**這是自由串列配置器**:`ds:0F56h` 是串列頭,節點至少 6 bytes
(`+0`=next、`+2`=反向指標、`+4`=擁有者)。
**信心等級:已確認**(逐條指令讀出)。

`ds:0EDCh` 這個「擁有者」值,也出現在 `3E:51`(`0x1F324` 附近)——
兩支不同的 API 標記同一個東西,那是「目前的執行脈絡」。

## 5. 這推翻了什麼

[`38`](38-api-are-basic-primitives.md) §5 說「高頻端是 BASIC 基本操作,遊戲功能要往低頻索引找」。
那個結論成立,但**當時漏掉了整張 `3Dh` 表**(909 處呼叫)。
現在補上之後結論**沒有改變** —— `3Dh` 一樣是語言層的操作(字串、暫存值),
不是遊戲功能。

**方向仍然是往低頻索引找。** 但這一次是在完整的三張表上得到的,
不是在少了一張表的情況下。
