# 50 — `DG*MAZE.SQZ` 解開了:81 × 51 的文字地圖 + 跑長編碼

日期:2026-08-14
接續:[`49-h-closure.md`](49-h-closure.md)
子系統:**G. 地城與迷宮**

## 結論

`.SQZ` **不是壓縮的二進位** —— 是**純文字**,每列一行,配一種簡單的跑長編碼。

```
六個檔全部是 81 列 × 51 欄
`\r\n` 分行、`0x1A` 結尾
小寫字母與 `_` 是「跑長標記」,下一個字元是計數(值 = ord − 0x2A)
其他字元(數字、大寫、標點)各代表一格
```

**信心等級:已確認。** 六個檔的列數與欄寬完全一致,
解碼後渲染出房間、走廊、門的地城平面圖(§3)。

## 1. 怎麼發現它是文字的

第一步不是分析,是**看**:

```
DG6MAZE.SQZ  首 24 bytes: 5f 40 66 2d 5f 38 66 2d 5f 33 0d 0a …
                          _  @  f  -  _  8  f  -  _  3  \r \n
相異位元組 36 個,最常見的是 0x5F(`_`)
```

**36 個相異位元組、含 `\r\n`、`0x1A` 結尾 —— 那是文字檔的形狀,不是壓縮資料的形狀。**
壓縮資料的位元組分布會接近均勻,不會只用 36 種。

⚠ 副檔名 `.SQZ`(squeeze)誤導了整整一天,[`01`](01-inventory.md) 把它記成「壓縮法未知」。
**副檔名是二手資訊,位元組是一手的。**

## 2. 解碼規則是怎麼定出來的

### 失敗的三次嘗試

| 假設 | 否證 |
|---|---|
| 嚴格 `(符號, 計數)` 成對 | 486 列裡有 14 列是**奇數長度** |
| 6-bit 打包(`CHR$(n+32)`,各種切法) | 沒有任何切法讓列寬一致 |
| 局部搜尋找標記字元集 | 成本降到 20 就卡住,而且解出來的字元集毫無規律(過擬合) |

### 成功的做法:窮舉所有合法解析,取交集

關鍵是先從一列**奇數長度**的行看出混合結構:

```
DG6 第 27 列:  _>191_F     (7 個字元)
  _>  = 跑長 20
  1 9 1 = 三個字面格
  _F  = 跑長 28
  20 + 3 + 28 = 51 ✓
```

有了「列寬 = 51」這個錨,就可以**對每一列窮舉所有加起來等於 51 的解析**,
再看哪些字元在**所有**合法解析裡都是標記:

```
必為標記:  _ b d f
必為字面:  * , - . / 0-9 : ; < = > ? @ A-Z ]
```

**標記全是小寫字母(加 `_`),字面全不是** —— 這個分界乾淨到不像巧合,
而且它有道理:原始碼是 BASIC,產生器大概用 `CHR$` 分兩個區段。

## 4. ⚠(已解)那 20 列短 1 格

> **成因已查明**:[`55`](55-sqz-decoder-from-code.md) §3 —— 解碼器**沒有欄數檢查**,
> 50 格是合法的,第 51 格保持預設 0。**不是殘差,是我加了格式裡不存在的約束。**
> 本節保留原文,因為「標成未解而不是硬湊」這個處置本身是對的。

## 5. 尺寸的意義

81 × 51 = `(2×40+1) × (2×25+1)` —— **牆格表示法的典型尺寸**
(N×M 個房間需要 (2N+1)×(2M+1) 格來表示牆與角)。
所以地城可能是 **25 × 40 個格子**。⚠ **假設**,未驗證。
