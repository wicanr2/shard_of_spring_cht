## 1. `FASTWRLD.BIN` = 9 × 92

```
BSAVE len = 828 = 92 × 9        ← 與 [`52`](52-world-map-reader-and-shared-grid.md) §2
                                   派工鏈的 92-byte 間距完全相同
每組前兩個 word = (34, 17)       ← GET 陣列標頭:34 bit 寬 = 17 像素,17 列
```

**排法是連續的,不是 [`48`](48-monst-deinterleave.md) 的交錯** ——
兩種都試過,只有連續讓九組的標頭都是 `(34,17)`。

渲染後(`' .:#'` 由淺到深):

| 圖塊 | 樣子 | 判讀 |
|---:|---|---|
| 1, 2 | 稀疏散點 | **草原**(兩種變化)|
| 3, 4 | 密集叢塊 | **森林**(疏 / 密)|
| 5, 6 | 少量小方塊 | 疏林 / 沼澤?**假設** |
| 7, 8, 9 | **三角尖峰** | **山**(三種密度)|

**信心等級:證據充分。** 三角尖峰是山的通用畫法,而且 7/8/9 在地圖上**連成鏈**(§3)。

## 2. `TOWNDATA.BIN`:三重交叉驗證

224 bytes = **56 個 BASIC 單精度浮點**(MBF 格式),排成 **4 欄 × 14 列**,第 0 列全零。
⚠ **逐欄存**:索引 = 欄 × 14 + 列。寫成「列 × 4 + 欄」不會越界,只會安靜地讀到別欄
([`145`](145-town-coordinates-were-already-solved.md) §1)。

⚠ 兩軸的名字**訂正過**:欄 1 是**東西**、欄 2 是**南北**
([`141`](141-world-map-axes-were-transposed.md))。數值沒變。

| 欄 | 內容 | 值(列 1–13)|
|---|---|---|
| 0 | 未用 | 全 0 |
| 1 | **東西座標** | 9, 26, 91, 24, 51, 97, 114, 67, 35, 114, 44, 69, 88 |
| 2 | **南北座標** | 8, 26, 12, 12, 37, 26, 9, 52, 57, 23, 81, 85, 72 |
| 3 | **商店數** | 7, 4, 5, 6, 5, 7, 6, 4, 5, 4, 3, 3, 2 |

⚠ 值是浮點不是整數 —— 高位字落在 `0x82xx`–`0x87xx`、低位字全 0,
那是 MBF 單精度的形狀(指數在最高位元組)。當成整數讀會得到 33808 這種無意義的值。

### 三個各自獨立的驗證

1. **座標 → 圖塊**:用 `x × 103 + y`([`141`](141-world-map-axes-were-transposed.md) 訂正後的索引)
   取那 13 個位置,得到圖塊 **{30, 31, 32}**;
   而這三種圖塊在全圖 12,463 格裡**正好出現 4 + 5 + 4 = 13 次**。
2. **商店數 → 名稱數**:第 3 欄合計 **61**,
   而 `TOWNDATA.DAT` 裡有 **74** 個名稱 —— `13 + 61 = 74`,**完全相等**。
3. **兩欄的順序**:對調之後取到的是 `{1,2,3,11,30}`(草原與海洋),明顯錯誤。

⚠ **這張表在 [`52`](52-world-map-reader-and-shared-grid.md) 的現況欄裡標「未解」**,
而它就是在這一篇解掉的。引擎端引用了前者,於是用了一年的佔位 ——
見 [`145`](145-town-coordinates-were-already-solved.md) §2。

三個驗證分別用到**地圖位元組**、**文字檔**、**互斥的替代假設**,沒有共同的錯誤來源。

## 3. 整張地圖渲染

```
  3  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  6  ~~~~~PtTtTttTTt~TtT.,.TttTS~~~~~~~~~~~~~~~~~~~~~~~
  9  ~~~~tTtEtTTtTRPTttT,.,tTttttS~~~~~~~~~~~~~~~~~~~~~
 …
 60  ~~~~n^^^^^^^^nnnnnn^^.,.,.,.,.,.,.,.,.,.,.,.,.,.,.
 63  ~~~~nn^^^^^^^^^^^^^^n^n,.,.,.,.,.,.,.,.,.,.,.,.,.,
 87  ~~~~~~~.,...,.,.,.,.,.nnn^^^^^^^^^^^^nnnn.,..,.,.,
```

海洋包住大陸、**山脈連成鏈**、森林成塊、草原用 `.`/`,` 交錯鋪成 ——
**這是一個地理上連貫的世界**。錯誤的格子大小或索引順序會得到雜訊。

⚠ 這裡的「連貫」是**人眼判斷**,不是量化指標。
但它足以排除「格子是 byte」與另外三種索引順序 —— 那些渲染出來是純雜訊。

### 稀有圖塊的空間形狀

| 圖塊 | 處數 | 分布 | 判讀 |
|---:|---:|---|---|
| 10 | 30 | `(48–53, 92–95)` 一個**連續團塊** | 單一大型建築群 |
| 12 | 8 | `x=57–58` 的**垂直線** | 橋 / 關隘 |
| 13 | 1 | `(58, 70)`,**在那條線的正中間** | 那條線上的門 |
| 20, 21, 35, 36, 37, 38 | 2–14 | 散落單點 | 特殊地點 |

**12 與 13 的關係最有說服力**:8 格排成一直線,而唯一的 13 恰好在中央 ——
那是「一段通道 + 中間一個入口」的形狀。⚠ 判讀是假設。

## 4. `WRLDITEM.PIC` 的 23 段已渲染

寫了一支最小的 `DRAW` 解譯器(`tools/draw_pic.py`),支援
`U D L R E F G H`、`B`/`N` 前綴、`M±x,±y`、`C`、`S`、`TA`、`P`。

23 段渲染出來可以認出:**帶城門的圍牆建築、神殿、山洞口、塔樓、營帳**,
以及幾段方塊字形。例如第 2 段:

```
#################
#               #
#    #:###:#    #
#   # :   : #   #
#  #  :   :  #  #
# :::::::::::#  #
#  #  :   :  #  #
#  #         #  #
####         ####
```

**這證實了 [`49`](49-h-closure.md) §3 的判讀**:`.PIC` 是向量繪圖巨集,
而且世界地圖上那些**稀有的特殊圖塊是用向量畫的**,不是點陣 ——
所以它們不在 `FASTWRLD.BIN` 的 9 張裡。

⚠ **段索引 ↔ 圖塊值的對應未解。** 23 段對 20 種特殊圖塊,數量接近但沒有對上。
要定案得讀 `WRLDMOVE` 裡索引這個字串陣列的程式碼。
