# 55 — `.SQZ` 的解碼規則(從程式碼讀出),與那 20 列殘差的真相

日期:2026-08-14
接續:[`54-f-closure.md`](54-f-closure.md)
子系統:**G. 地城與迷宮**

## 結論

`MAZEMOVE.EXE` 的解碼迴圈把 [`50`](50-sqz-maze-format.md) 從資料側猜出來的規則
**逐項證實,並且補上兩件猜不到的事**:

1. **同一個圖塊值有兩種寫法** —— 字面(字元 = 值 + 42)或跑長(字元 = 值 + 95)。
   `_` 與 `*` 是**同一個圖塊值 0**。
2. **解碼器沒有欄數檢查** —— 所以 [`50`](50-sqz-maze-format.md) §4 那 20 列「短 1 格」
   **不是錯誤**,是那些列真的只有 50 格,第 51 格保持預設值 0。

## 1. 解碼迴圈(`MAZEMOVE.EXE` `0x13F07`–`0x14007`)

```
013F07  mov  word ptr ds:964Ch, 35h    ; 53  ← 跑長判別門檻
013F0D  mov  word ptr ds:964Eh, 2Ah    ; 42  ← 減去的基底
013F13  mov  word ptr ds:9650h, 0      ; 列 = 0

013F3E  cmp  word ptr ds:9650h, 50h    ; 列 > 80 就結束 → 共 81 列
013F48  …
013F52  int  3Fh, 0BBh                 ; 取一個字元的碼
013F57  sub  bx, ds:964Eh              ; ★ v = 字元碼 − 42
013F5D  mov  ds:9652h, ax
013F60  cmp  ax, 0FFE3h                ; v ≤ −29(即字元 ≤ 13,CR)
013F63  jle  <換列>

013F86  mov  ax, ds:964Ch              ; 53
013F89  cmp  ax, ds:9652h
013F8D  jle  <跑長>                    ; v ≥ 53
013F92  sub  ds:9652h, ax              ; ★ 圖塊 = v − 53
013FA5  sub  bx, ds:964Eh              ; ★ 長度 = 下一字元 − 42

013FC6  mov  di, 51h                   ; ★ 81
013FCB  imul di                        ; 欄 × 81
013FCF  add  di, ds:9650h              ; + 列
013FD3  shl  di, 1
013FD9  mov  [di+6822h], dx            ; 寫入
```

**規則:**

```
v = 字元碼 − 42
  v ≤ −29(CR)  → 換列
  v ≥ 53        → 跑長:圖塊 = v − 53,長度 = 下一字元 − 42
  否則          → 字面:圖塊 = v
```

**信心等級:已確認**(逐條指令,`CLAUDE.md` §2.1 條件 1、2)。

## 2. 兩種寫法對到同一個值

| 圖塊值 | 字面寫法 | 跑長寫法 |
|---:|---|---|
| 0 | `*`(42) | `_`(95)|
| 2 | `,`(44) | `a`(97)|
| 3 | `-`(45) | `b`(98)|
| 5 | `/`(47) | `d`(100)|
| 6 | `0`(48) | `e`(101)|
| 7 | `1`(49) | `f`(102)|
| 8 | `2`(50) | `g`(103)|
| 10 | `4`(52) | `i`(105)|
| 22 | — | `u`(117)|

**[`50`](50-sqz-maze-format.md) §2 的「標記全是小寫字母」不是巧合** ——
值 0–10 的跑長寫法剛好落在 `_`、`a`–`i`。
但那個規則**在值 ≥ 12 時會失效**:例如 `6`(54)是**字面的圖塊 12**,
而舊規則會把它當成跑長標記。這正是舊解法在某些列上出錯的原因。

## 3. 那 20 列殘差的真相

[`50`](50-sqz-maze-format.md) §4 記著「486 列裡有 20 列展開後是 50 格,成因未解」,
並且特別註明「沒有調參數去湊」。

**成因是:根本沒有欄數檢查。** `0x13F3E` 的迴圈只管**列**(0–80),
每一列寫多少格完全看檔案給多少 —— **50 格是合法的**,第 51 格保持 BASIC 陣列的預設值 0。

**所以那不是殘差,是我加了一個檔案格式裡不存在的約束。**
判準:**把「所有列等長」當成必然,是從自己的期待推規格,不是從規格推期待。**
當時標成「未解」而不是硬湊,是對的;但更好的做法是**先去讀解碼器**。

## 4. 陣列佈局

```
索引 = 欄 × 81 + 列          (column-major,81 列)
基底 = ds:0x6822             ← 與世界地圖同一個「當前地圖」陣列
```

[`52`](52-world-map-reader-and-shared-grid.md) §3 推論「`ds:6822` 是當前地圖,
各模組用自己的寬度」——這裡拿到直接證據:**`MAZEMOVE` 的乘數就是 81**。

其餘未定。

## 6. `MAZEITEM.PIC` 不是逐圖塊值索引

`MAZEMOVE` 的 `DRAW` 呼叫(`INT 3E:36`,四處)長這樣:

```
mov  bx, ds:8E3Eh
shl  bx, 1
shl  bx, 1
add  bx, 8868h        ; ← 字串陣列在 ds:0x8868
int  3Eh, 36h         ; DRAW
```

**結構與 `WRLDMOVE` 完全相同**([`54`](54-f-closure.md) §1),
但**索引不是圖塊值**:掃描偏移量 −6…+11,**沒有任何一個讓空行對上未使用的值**
(最少也有 6 處不合)。

**這是實質資訊,不是失敗**:迷宮是**第一人稱視角**,
`DRAW` 段畫的是「不同距離、不同角度的牆面」,不是「這一格是什麼」。
`WALKDRAW.PIC`(10 段)也支持這個讀法。
`ds:8E3Eh` 存的是**畫面元件編號**,不是地圖格值。
