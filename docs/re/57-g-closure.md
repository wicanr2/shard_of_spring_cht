## 1. `MAZEDATA` 的記憶體位址與欄位位移

`MAZEMOVE.EXE` 對 `ds:0x365C` 的八處存取,索引前的加值是:

```
0, 0Dh(13), 1Ah(26), 27h(39), 34h(52), 41h(65), 4Eh(78), 5Bh(91)
```

**全部是 13 的倍數** —— 八個欄位,每欄 13 個關卡。
[`51`](51-mazedata-and-world-entrances.md) §1 當時是拿兩種排法去試、挑能通過驗證的那一種;
**現在有了程式碼側的直接證據。**

## 2. 進入地城的查表(`0x1145E`–`0x114D0`)

```
01145E  迴圈 i = 0…12                       ; 13 個關卡
011462  bx = MAZEDATA[i + 0]                ; 欄 0
011466  cmp bx, ds:351Ah                    ; ← 隊伍的世界 Y
011479  cx = MAZEDATA[i + 13]               ; 欄 1
01147D  cmp cx, ds:3518h                    ; ← 隊伍的世界 X
011487  and                                 ; 兩者都相等才算命中
011490  ds:3534h = i                        ; 記下關卡索引

0114AE  MAZEDATA[i + 26]  → ds:351Eh        ; 欄 2 = 起始列
0114BE  MAZEDATA[i + 39]  → ds:351Ch        ; 欄 3 = 起始欄
0114CC  MAZEDATA[i + 52]  → ds:3520h        ; 欄 4 = ?
```

**這同時證實了 [`51`](51-mazedata-and-world-entrances.md) §2 的「欄 0/1 是世界座標」** ——
它們被拿去跟隊伍的位置比對。

⚠ **訂正 [`43`](43-common-block-and-array-indexing.md) §4**:
該節把 `ds:3518h` / `ds:351Ah` 標成「累加量」(只看到 `add ds:xxxx, ax`)。
**它們是隊伍的世界座標。** 錯在只看了寫入的形狀,沒看讀取端在跟什麼比。

## 3. 欄 4 = 起始朝向

`ds:3520h` 的**所有**存取(`tools/ida/find_dsref.py`,掃 7,834 條指令):
值域只有 **{1, 2, 3, 4}**,而且與位置變數成對出現:

| 位置變化 | 同時設定 |
|---|---|
| `dec ds:351Eh`(列 −) | `ds:3520h = 1` |
| `inc ds:351Ch`(欄 +) | `ds:3520h = 2` |
| `inc ds:351Eh`(列 +) | `ds:3520h = 3` |
| `dec ds:351Ch`(欄 −) | `ds:3520h = 4` |

而 §2 已確認 `ds:351Eh` = 列、`ds:351Ch` = 欄([`56`](56-maze-tile-classes-and-mazedata-columns.md) §3)。

**所以:1 = 北、2 = 東、3 = 南、4 = 西。信心等級:已確認。**

⚠ [`56`](56-maze-tile-classes-and-mazedata-columns.md) §5 用「該方向的鄰格可不可通行」測,
最好的一種慣例得 9/12,**正是這一種** —— 但當時我判斷 9/12 不足以定案,
所以標未解。**那個判斷是對的**:9/12 確實不能定案,而正確答案要從程式碼來。

## 4. `MAZEITEM.PIC` 第 k 行 = 圖塊值 k

`MAZEMOVE` 的 `DRAW` 派工([`55`](55-sqz-decoder-from-code.md) §6):

```
mov  bx, ds:8E3Eh      ; = |格值|
shl  bx, 1
shl  bx, 1
add  bx, 8868h
int  3Eh, 36h          ; DRAW
```

`MAZEITEM.PIC` 有 **34 行**,空行在 **0、10、18、19、33**。
而繪製程式碼**明確跳過 0 / 18 / 19**([`56`](56-maze-tile-classes-and-mazedata-columns.md) §2)。

| 空行 | 解釋 |
|---:|---|
| 0, 18, 19 | **程式碼明講不繪製** |
| 33 | 地圖上從未出現 |
| 10 | 有用到(20 次)但**沒有特例判斷** → `A$(10)` 是空字串,`DRAW ""` 什麼都不畫 |

**偏移 0,唯一的「例外」是 10,而它有機制上的解釋。**

⚠ [`55`](55-sqz-decoder-from-code.md) §6 說「掃描偏移 −6…+11 沒有一個對得上」——
**那個結論是錯的,因為當時的檢定條件錯了**:我要求「空行 → 該值未使用」,
但 0/18/19 是**用到但不繪製**。條件補上之後,偏移 0 立刻成立。
**判準:檢定沒過時,先檢查檢定條件本身,再談假設。**

## 6. 這一輪的方法

- 欄 4:上一輪用「鄰格可通行」測得 9/12,標未解 —— **那個處置是對的**,
