# 59 — `DE*EFF.BIN` 是地城的「特殊格事件表」

日期:2026-08-14
接續:[`58-key-dispatch-mechanism.md`](58-key-dispatch-mechanism.md)
子系統:**I. 法術效果表** → **實際是 G 的事件層**

## 結論

**`DE<n>EFF.BIN` 不是法術效果,是第 n 層地城的事件表。**

```
106 列 × 5 欄(column-major,元素 = word)

欄 0  觸發位置的「列」
欄 1  觸發位置的「欄」
欄 2  方向(0–4,與 MAZEDATA 欄 4 同一套慣例)
欄 3  目標:≥ 100 → DT 文字編號;< 100 → 目的地的「列」
欄 4  目的地的「欄」
```

**信心等級:證據充分**(三項獨立檢定,見 §2)。

⚠ `CLAUDE.md` §2.2 把 `DE*EFF` 放在「I. 法術效果表」,
[`29`](29-de-eff-pairs.md) 也說「內容未解,可能該歸到 G」——**那個懷疑是對的**。

## 1. 怎麼看出來的

`DE7EFF.BIN` 的前六列:

```
[ 2,  5, 2,   2, 10]
[ 2,  9, 4,   2,  4]
[14,  9, 2, 701,  0]     ← 701
[ 2,  4, 4, 702,  0]     ← 702
[10, 40, 3, 703,  0]     ← 703
[24, 21, 1, 704,  0]     ← 704
```

**701–704 正是 `DT7TEXT.DAT` 的記錄編號**([`51`](51-mazedata-and-world-entrances.md) §6)。
`DE7` ↔ `DT7`,編號前綴一致 —— 一眼就對上。

⚠ **排法先猜錯過一次。** `530 = 53 × 10`,用 53 當 stride 看起來成立,
但那樣「只有偶數欄非零」。真正的排法是 **106 × 5**,
`53` 那種讀法是把同一份資料用錯的 stride 切開。
**判準:出現「規律的空欄」時,先懷疑 stride 是真值的一半。**

## 2. 三項獨立檢定

### (a) 欄 3 的大值 ⊆ 對應 `DT` 檔的編號

| 檔案 | 欄 3 的大值 | 落在 `DT` 編號裡 |
|---|---|:-:|
| `DE1` | 101–108 | ✅ 完全相同 |
| `DE2` | 201–208 | ✅ |
| `DE3` | 301–319 | ✅ |
| `DE6` | 601–606 | ✅ |
| `DE7` | 701–705 | ✅(`DT7` 有 701–709)|
| `DE0` | 無 | — |
| **`DE4`** | 401–406 | ❌ `DT4` 只有 401、402 |
| **`DE5`** | 501, 503–525 | ❌ `501` 不在任何 `DT` 檔 |
| **`DE51`** | 502, 506–533 | ❌ `502` 不在任何 `DT` 檔 |

**6/9 完全吻合。** 三個例外引用了**不存在的文字**(`403`–`406`、`501`、`502`)。

⚠ 兩種可能:**開發時砍掉的內容**,或那幾個值另有意義。**未解。**
不要因為 6/9 就把例外當雜訊。

### (b) 欄 3 / 欄 4 當座標時全部合法

欄 3 < 100 的項目共 **384** 筆,其中 **369 筆**滿足 `欄3 ≤ 80 且 欄4 ≤ 50`
(迷宮是 81 × 51,[`50`](50-sqz-maze-format.md))。

15 個例外**全部**是 `[0, 0, 0, 0, <大數>]` 的形式 —— 那是陣列尾端未初始化的殘留,
不是資料項。**扣掉之後 369/369,零例外。**

### (c) 欄 2 的值域

九個檔案合計,欄 2 只出現 `{0, 1, 2, 3, 4}` ——
與 `MAZEDATA` 欄 4 的朝向([`57`](57-g-closure.md) §3:`1=北 2=東 3=南 4=西`)同一套,
`0` 多一個(疑似「不限方向」)。

## 4. `BSAVE` 位址的線索

九個檔的 `BSAVE` 標頭**全部**是 `seg=0x0FB9`、**`off=0x6822`**。

`0x6822` 正是[「當前地圖」陣列的基底](52-world-map-reader-and-shared-grid.md) ——
所以事件表**載入到陣列區的起點**,再由程式搬走或就地使用。
⚠ 搬移的細節未讀。

## 5. 對看板的影響

| 子系統 | 變化 |
|---|---|
| **I** | `DE*EFF` 的結構已解,但**它不屬於 I** —— 是地城事件,屬 G。I 剩 `FIRESTRM`/`HAILSTRM`/`WINDSTRM.BIN`(98-byte 圖塊,格式已在 **H** 解過)|
| **G** | 多了一層:事件表。⚠ G 已標 RE-DONE([`57`](57-g-closure.md)),而本文是**新增內容不是推翻** —— `DE*EFF` 當時不在 G 的輸入清單裡 |

⚠ **G 的 RE-DONE 判定要重新檢視**:若 `DE*EFF` 算 G 的一部分,
那 §2(a) 的三個例外就是 G 範圍內的未解項。
**已在 `CLAUDE.md` §2.2 把 G 改回「進行中」** —— 範圍變了,判定就要重來。
