# 61 — 子系統 I 收尾:九張圖塊裡有八張是遊戲不載入的

日期:2026-08-14
接續:[`60-event-lookup-and-tile-19.md`](60-event-lookup-and-tile-19.md)
子系統:**I. 法術效果表**

## 結論

`CLAUDE.md` §2.2 的 I 列原本掛兩組檔案,兩組都有結論了:

| 原本掛在 I 的檔案 | 實際歸屬 |
|---|---|
| `DE*EFF.BIN` / `.MST`(10 對) | **不是法術效果,是地城事件表 → 已歸 G**([`59`](59-de-eff-event-table.md)/[`60`](60-event-lookup-and-tile-19.md))|
| `FIRESTRM` / `HAILSTRM` / `WINDSTRM.BIN` | 17×17 圖塊(**H** 的格式),但**遊戲從不載入**(§2)|

**法術的規則本身在 `SPELLS.DAT`(E)與 `CMBT.EXE`(J)** —— 那是別的列。

**I 判定為 RE-DONE**(§4)。

## 1. 九張 98-byte 圖塊是同一個陣列的九個槽

| 索引 | 檔案 | `BSAVE` off | 內容 |
|---:|---|---|---|
| 0 | `EXITSPOT.BIN` | `0x52AE` | 四向星芒(出口標記)|
| 1 | `BORDER.BIN` | `0x530A` | 實心菱形 |
| 2 | `WATER.BIN` | `0x5366` | 點狀水面材質 |
| 3 | `LAVA.BIN` | `0x53C2` | 斜向岩漿紋 |
| 4 | `MAZEWALL.BIN` | `0x541E` | **磚牆** |
| 5 | `DOOR.BIN` | `0x547A` | **拱門** |
| 6 | `WINDSTRM.BIN` | `0x54D6` | 方形漩渦 |
| 7 | `HAILSTRM.BIN` | `0x5532` | 斜向落點 |
| 8 | `FIRESTRM.BIN` | `0x558E` | 斜向火焰 |

**九個 offset 等距 92**,與 `FASTWRLD.BIN` 的九張地形圖塊同一個間距
([`53`](53-world-tiles-towns-and-draw-renderer.md) §1)——
它們在作者端是**同一個陣列的九個槽**。

全部 17×17、2bpp,格式與 [`21`](21-tile-format.md) 相同,已渲染確認。

## 2. 只有 `MAZEWALL.BIN` 被載入

對整個出貨目錄(13 支 EXE + 全部資料檔)做位元組層搜尋:

| 片段 | 出現在幾個檔 | |
|---|---:|---|
| `MAZEWALL` | **1**(`MAZEMOVE.EXE`)| ✅ 被載入 |
| `STRM` | **0** | ❌ |
| `EXITSP` | **0** | ❌ |
| `LAVA` | **0** | ❌ |
| `BORDER` | **0** | ❌ |
| `WATER` | 2(兩個 `DT*TEXT.DAT` 的**內文**)| ❌ |
| `DOOR` | 6(五個 `DT` 內文 + `MENU.EXE` 的 `"check the drive door"`)| ❌ |
| **`ITEMS`** | **5** | **← 正對照** |
| **`SPELLS`** | **3** | **← 正對照** |

**正對照成立**(`ITEMS.DAT`/`SPELLS.DAT` 確實被多支模組引用),
所以 `STRM` / `EXITSP` / `LAVA` / `BORDER` 的 **0 命中是真的**,不是搜尋方法的問題。

⚠ 這正是 `~/diagnosis-notes/docs/02-query-returned-empty/` 講的紀律:
**下「不存在」的結論前先做正對照。** 沒有那兩列,這一節不能寫。

### 那遊戲怎麼畫門與水?

用**向量**。[`57`](57-g-closure.md) §4 已確認 `MAZEITEM.PIC` 的第 k 行 = 迷宮格值 k,
渲染出來就有鐵柵門、柱廊、樓梯這些東西。
**只有牆(格值 7)走點陣**,而那正是程式碼裡唯一被特例判斷的值
([`56`](56-maze-tile-classes-and-mazedata-columns.md) §2 的 `cmp ds:8E3Eh, 7`)。

**所以八張沒用到的 `.BIN` 是開發期的原始美術**,後來改成 `DRAW` 巨集。
⚠ 「後來改成」是推測;**已確認的只有「它們不被載入」。**

## 4. I 的四項條件

| # | 條件 | 狀態 |
|---|---|---|
| 1 | 在 IDA 裡讀過原始指令 | **不適用** —— 這三個檔沒有任何程式碼讀它們(§2 的窮舉搜尋 + 正對照)。依 `CLAUDE.md` §2.1 的但書,**已在筆記裡明寫為什麼留白** |
| 2 | 讀寫端點 | 同上 |
| 3 | 獨立資料印證 | 格式與 [`21`](21-tile-format.md) 的九檔族相同、九個 `BSAVE` offset 等距 92、渲染內容與檔名相符 |
| 4 | 筆記 | ✅ |

**I(法術效果表)判定為 RE-DONE**,結論是:
**這一列原本掛的檔案不屬於它**,重新歸位之後沒有剩下未解的東西。

⚠ 明確**不含**:
- 法術的**規則**(威力、消耗、目標)—— 屬 **E**(`SPELLS.DAT`)
- 法術在戰鬥中的**呈現**—— 屬 **J**
- 那八張圖塊「當初為何改成向量」—— 推測,不列入

## 5. 方法

這一列不是「解開」的,是**發現它掛錯東西**。

`DE*EFF` 從一開始就被檔名誤導(`EFF` = effect),
而 [`29`](29-de-eff-pairs.md) 當時就寫了「可能該歸到 G」——**那個懷疑放了很久沒被追**。

判準:**看板上的分類本身也是待驗證的假設。**
一列遲遲推不動時,先問「這些檔案真的屬於這一列嗎」,
而不是繼續在錯的框架裡找答案。
