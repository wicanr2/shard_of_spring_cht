# 64 — 模組怎麼呼叫 `USERLIB`:`3D:00` 的延遲繫結與匯出槽

日期:2026-08-14
接續:[`63-userlib-strings-and-l-correction.md`](63-userlib-strings-and-l-correction.md)
子系統:**C. 原生輔助程式庫**

## 結論

`INT 3Dh` 參數為 `0` 的 5-byte 形式([`45`](45-int3d-family.md) §2 的 346 處)
**就是模組呼叫 `USERLIB` 的方式**。

```
CD 3D 00 oo oo      ; oo oo = 匯出表的位元組位移
   ↓ 第一次執行時就地改寫
9A oo oo ss ss      ; far call,之後每次都是原生速度
```

匯出表的節區存在**呼叫端模組的 `ds:0x0A1E`**。
七支模組合計用到 **19 個槽**,全部落在 8-byte 的格線上。

## 1. 處理常式怎麼找到表(`BRUN30` `0x10080`)

```
010082  add  bx, 3
01008B  mov  si, [bx-2]              ; 索引(2 bytes)
01008F  mov  es, cs:word_10171       ; es = 呼叫端模組的 DS
010094  mov  es, word ptr es:0A1Eh   ; ★ es = 模組 DS 的 [0x0A1E]
010099  les  si, es:[si]             ; 從該節區的位移 si 取出 far 指標
01009C  mov  byte ptr [bx-5], 9Ah    ; 就地改寫成 far call
0100A0  mov  [bx-4], si
0100A3  mov  word ptr [bx-2], es
```

**`ds:0x0A1E` = 匯出表所在節區的選擇子。** 那是一個**執行期建立的結構** ——
`USERLIB.EXE` 的檔案裡沒有這張表(位移 `0x6B` 在它的 `bm` 節區裡是程式碼),
所以表是載入時由 stub 或執行期填的。

**信心等級:已確認**(逐條指令)。

## 2. 19 個匯出槽

346 個呼叫點的索引,**全部滿足 `(索引 − 3) mod 8 == 0`** ——
所以匯出表是 **8 bytes 一筆**,far 指標放在每筆的 `+3`。

|---|---:|---:|---|
| `0x11B` | 35 | **113** | 6 支 |
| `0x103` | 32 | **74** | 6 支 |
| `0x07B` | 15 | 48 | 5 支 |
| `0x0BB` | 23 | 34 | **7 支全部** |
| `0x0CB` | 25 | 11 | 3 支 |
| `0x0C3` | 24 | 10 | 3 支 |
| `0x083` | 16 | 8 | 4 支 |
| `0x0EB` | 29 | 8 | `MAZEMOVE`+`WRLDMOVE` |
| `0x06B` | 13 | 7 | 4 支 |
| `0x0FB` | 31 | 7 | 3 支 |
| `0x093` | 18 | 5 | `MAZEMOVE`+`WRLDMOVE` |
| `0x0E3` | 28 | 5 | `MAZEMOVE`+`WRLDMOVE` |
| `0x0B3` | 22 | 4 | `MAZEMOVE`+`WRLDMOVE` |

槽號有缺口(14、19、20、26、27 沒被用到)——
**`USERLIB` 匯出的比實際被呼叫的多。**

### 兩個乾淨的分群

- **槽 23**(34 次)是**唯一被七支模組全部用到**的 —— 最基礎的共用功能。
- **槽 17、18、21、22、28、29、33、34、36** —— **只有 `MAZEMOVE` 與 `WRLDMOVE` 用**。
  九個槽只服務兩支移動模組,那是**移動/繪圖的輔助函式**。⚠ 推測。

這與 [`39`](39-ds0a3a-and-xref-blind-spot.md) §4 用同一種方法找出
`3E:36` / `3E:55` 只有這兩支用的結果一致 ——
**「只有誰用」這個過濾器在這個遊戲上反覆有效。**

## 4. C 還缺什麼

**只剩一項:19 個槽各自是什麼函式。**

要解它得讀 `USERLIB.EXE` 的原生組語(30,813 bytes)。
入手點已經有了:[`63`](63-userlib-strings-and-l-correction.md) §3 的字串位置
(`Party Saved` 在 `ds:0x3152`、`Visibility =` 在 `ds:0x31BC` …)——
**從引用這些字串的程式碼往回找,就能把槽對到功能。**

不卡外部條件。

## 5. 方法

`3D:00` 這 346 處在 [`44`](44-int3d-is-used-after-all.md) 被找回來時,
只知道它是「延遲繫結的 far call」,不知道繫結到哪。

解開它靠的是**把索引值本身當資料看** ——
19 個看似隨機的數字(`0x6B`、`0x7B`、`0x83`…)全部同餘於 3 mod 8,
那個規律直接給出表的結構(8 bytes 一筆、指標在 +3)。

**判準:一組「索引」解不開時,先看它們的模數規律。**
表的項目大小會從索引的分布裡漏出來。
