## 1. 怎麼對上的

三段接起來:

1. **字串位址** —— [`63`](63-userlib-strings-and-l-correction.md) §2 的抽取器給出每段文字的 DS 指標
2. **引用點** —— 掃描立即數,但要找的是**描述子位址**(= 文字位址 − 4),不是文字位址
   ⚠ 先用文字位址掃,**0 命中**;減 4 之後 **11 處全中**
3. **槽號** —— [`65`](65-userlib-export-table.md) §2 的匯出表給出每個槽的進入位址,
   把引用點落在哪兩個進入點之間對回去

**沒有任何一步需要讀懂常式的邏輯。** 位址區間就夠了。

## 2. 兩個乾淨的叢集

**槽 34 一支就引用了 `Party Saved` + `CHARS.DAT` + `GROUPS.DAT` 三個字串** ——
存檔要寫兩個檔再報告完成,三個字串剛好對應那三個動作。

**槽 33 引用了五個字串**,而且是 `Hour:` / ` Day:` / `  In the Month ` / `Visibility =` /
` Player's Clock:` —— 那是一整條狀態列的所有欄位。

**一支常式引用多個彼此相關的字串,本身就是強證據。**
單一字串可能只是巧合落在區間裡;三個、五個同時落在同一區間不會是巧合。

## 3. 與呼叫者的一致性

| 槽 | 誰呼叫 | 合不合理 |
|---:|---|---|
| 34(存檔)| `MAZEMOVE` + `WRLDMOVE` | ✅ 只有在地圖/迷宮裡才能存檔 |
| 33(狀態列)| `MAZEMOVE` + `WRLDMOVE` | ✅ 時鐘與能見度只在移動畫面顯示 |
| 17(死亡)| `MAZEMOVE` + `WRLDMOVE` | ✅ 全隊死亡發生在探索中 |
| 21(結局)| `MAZEMOVE` + `WRLDMOVE` | ✅ 從世界地圖離開遊戲 |
| 35(訊息框)| 6 支 | ✅ 到處都要 |
| 23 | **7 支全部** | ✅ 最基礎的字串操作 |

**呼叫者的分布與判讀完全自洽** —— 這是第三個獨立的印證方向
(前兩個是字串內容與位址區間)。

## 5. 方法

這一輪的三步(字串 → 引用點 → 槽號)**每一步都用現成的東西**:
字串表是 [`63`](63-userlib-strings-and-l-correction.md) 做的、
匯出表是 [`65`](65-userlib-export-table.md) 做的、掃立即數的工具早就有。

唯一的新意是**「描述子位址 = 文字位址 − 4」這個 4**。
第一次用文字位址掃,0 命中;差一點就要下「引用不到」的結論。

判準:**掃描引用時,先確認「程式碼引用的是哪一個位址」** ——
指向文字的指標與指向描述子的指標差幾個 bytes,是格式決定的,不是可以猜的。
