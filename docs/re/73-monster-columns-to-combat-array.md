# 73 — 怪物欄位 → 戰鬥單位屬性:E 與 J 接起來了

日期:2026-08-14
接續:[`72-e-file-formats-from-readers.md`](72-e-file-formats-from-readers.md)
子系統:**E. 規則資料表** × **J. 戰鬥規則**

## 結論

`CMBT 0x181A0`–`0x18380` 把 `MONSTERS.DAT` 的十個整數欄**逐欄搬進 `ds:6822h`**,
而搬進去的位移全部是 **15 的倍數** —— 這直接證實
[`43`](43-module-ds-layout.md) 的「戰鬥時 `ds:6822h` 是 15 欄寬的陣列」,
並且給出**屬性列的編號**。

## 1. 搬移的形狀

```
0181DD  mov di, [bp-8]        ; 這個單位的索引
0181E2  add di, 2Dh           ; + 45  = 3 × 15
0181E5  shl di, 1
0181E7  mov [di+6822h], bx

0181ED  mov bx, [di+786Ah]    ; 怪物欄 7
0181F1  add dx, 4Bh           ; + 75  = 5 × 15
0181F8  mov [si+6822h], bx
```

**「單位索引 + n×15」** = BASIC 二維陣列 `A%(單位, n)` 的行主序位址
([`43`](43-module-ds-layout.md) §2 的同一條公式)。所以 `n` 就是屬性編號。

## 2. 對照表

| 屬性 `n` | 位移 | 來源 | `MONSTERS.DAT` 記錄位移 |
|---:|---:|---|---|
| 4 | 60 | 欄 5 推導(§3)| 25–26 |
| 5 | 75 | **欄 7** | 29–30 |
| 6 | 90 | **欄 2** | 19–20 |
| 7 | 105 | **欄 10** | 35–36 |
| 8 | 120 | 常數 `0` | — |
| 9 | 135 | **欄 3** | 21–22 |
| 10 | 150 | 常數 `3` | — |
| 11 | 165 | **欄 6** | 27–28 |
| 12 | 180 | 常數 `0` | — |
| 13 | 195 | **欄 9** | 33–34 |
| 19 | 285 | **欄 8** | 31–32 |

**欄 1 與欄 4 不在這張表裡**:欄 4(`ds:7834h`)在 `0x181A7` 被送進
`3F:57` / `3F:71` / `3F:91` / `3F:85` 一串字串常式 —— 形狀像**組出現訊息**
(「N 隻某某」),但沒有字串證據,**未解**。

**常數 `0` / `3` 佔掉三個屬性欄**,代表隊伍成員與怪物共用同一種單位結構,
那三欄對怪物不適用(玩家角色才有)。

## 3. 欄 5 走的是另一條路

```
01832E  mov ax, [di+7846h]        ; 欄 5
018332  mov ds:9F94h, ax
018335  cmp word ptr ds:9F94h, 0
018347  mov word ptr [di+6822h], 3Ch   ; = 0  → 屬性 4 設成 60
018350  cmp ds:9F94h, 1 / 01835A cmp ds:9F94h, 0Ch
018364  mov di, ds:9414h / mov bx, [di+7846h] / dec bx
01837F  cmp ds:9F94h, 0Dh …
```

`1`–`12` 一段、`13` 起另一段,而且會去讀**別的單位**的欄 5 再減一。
**分支結構已讀出,語意未解。**

## 4. ⚠ 這一節不是欄位語意

上面全部是**搬到哪裡**,不是**代表什麼**。
「欄 7 → 屬性 5」對翻譯與 remake 都還不夠用 ——
還要知道屬性 5 在傷害計算裡被拿去做什麼。

前三筆的資料放在這裡當日後對照:

```
#0 'Lvl  1 Fighter'  (7, 7, 7, 8, 2, 1, 1, 33, 1, 0)
#1 'Lvl  1 Wizard'   (7, 6, 6, 5, 0, 3, 0, 33, 1, 5)
#2 'Orc'             (6, 9, 7, 2, 2, 12, 2, 38, 2, 0)
```

⚠ **欄 8 的 33 / 33 / 38 落在 `MONST*.BIN` 的 46 張圖範圍內**
([`49`](49-h-closure.md) §4),形狀像圖號 —— **但這是形狀推測,不是證據**,
要拿完整 74 筆的欄 8 去對圖數才算數。不要當結論引用。

## 5. E 與 J 的現況

| 子系統 | 進展 | 還缺 |
|---|---|---|
| **E** | 三個檔的格式定案([`72`](72-e-file-formats-from-readers.md));十個怪物欄的**去處**定案 | 每一欄的**語意** |
| **J** | 戰鬥單位是 15 欄的二維陣列,**屬性 4–13、19 有了來源** | 傷害/命中/先攻公式 |

下一步明確:從屬性編號反查**戰鬥計算**裡的 `[reg+6822h]`,
看哪幾個屬性一起出現在同一段算術裡 —— 一起出現的就是同一條公式的輸入。
不卡外部條件。
