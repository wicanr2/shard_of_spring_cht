# 75 — 角色記錄的裝備欄:D、E、J 同一段程式碼一起推進

日期:2026-08-14
接續:[`74-spell-and-item-columns.md`](74-spell-and-item-columns.md)
子系統:**D. 角色/隊伍資料** × **E. 規則資料表** × **J. 戰鬥規則**

## 結論

`CMBT 0x11A20`–`0x11AC0` 把角色記錄搬進戰鬥單位陣列,
中間有一層**間接查表**:裝備欄存的**不是物品編號,是背包格號**。

## 1. 程式碼

```
011A21  mov bx, 94C8h / mov dx, 66CCh
011A27  int 3Fh; 61                    ; 角色記錄 → FIELD 緩衝區
011A2C  mov word ptr ds:66D0h, 22h     ; 記錄位移 34
011A32  call loc_10083                 ; CVI → ax
011A35  cmp ax, 63h                    ; = 99 ?
011A45  mov word ptr [di+6822h], 3Ch   ;   是 → 屬性 4 = 60
011A64  call loc_10083                 ;   否 → 再讀位移 34
011A67  shl ax, 1 / add ax, 36h        ;        位移 = 值 × 2 + 54
011A6C  mov ds:66D0h, ax
011A6F  call loc_10083                 ;        再讀一次
011A7B  mov [di+6822h], ax             ;        → 屬性 4

011A8A  mov word ptr ds:66D0h, 24h     ; 記錄位移 36
011AA4  mov word ptr [di+6822h], 3Bh   ; = 99 → 屬性 5 = 59
```

**兩層讀取**:位移 34 拿到的是**背包格號 i**,真正的物品編號在**位移 54 + 2i**。

## 2. `CHARS.DAT` 對得上

| 檢查 | 結果 |
|---|---|
| 檔案大小 | 2,350 ÷ 94 = **25.0** ✅ 整除 |
| 位移 34 的 25 筆值 | 前 5 筆 `99`、後 20 筆 `8224` |
| 位移 36 的 25 筆值 | 同上 |

`8224` = `0x2020` = 兩個空白 —— **後 20 筆是空欄位,不是角色**。
出貨檔裡只有 5 個預設角色。

前 5 筆**兩個欄位都是 `99`**,而 `99` 正是程式碼在比的那個值 ——
**預設角色出廠沒有裝備**,合理。

> ⚠ 這裡差點寫成「全檔只有這兩個位移是 99」。
> 實際做的掃描只掃了**奇數位移**(`range(1,93,2)`),而 34/36 是偶數 ——
> **那個「沒有其他位移是 99」的結論從來沒有被測到。**
> 保留這一段是因為它差一點就變成一條沒被驗證的斷言。

## 3. 定案的欄位

| 位置 | 語意 | 信心 |
|---|---|---|
| `CHARS.DAT` 位移 34 | **裝備武器的背包格號**(`99` = 未裝備)| **已確認** |
| `CHARS.DAT` 位移 36 | **裝備防具的背包格號**(`99` = 未裝備)| **已確認** |
| `CHARS.DAT` 位移 54 + 2i | 背包第 i 格的物品編號 | **已確認**(間接式直接讀出)|
| 戰鬥屬性 4 | **武器的物品編號** | 證據充分 |
| 戰鬥屬性 5 | **防具的物品編號** | 證據充分 |
| `MONSTERS.DAT` 欄 5 | **武器** | 證據充分([`73`](73-monster-columns-to-combat-array.md) §3 的 `0 → 60` 與這裡的 `99 → 60` 是同一條路)|

`60` 與 `59` 落在 `ITEMS.DAT` 的 57 列**之外** —— 陣列 `DIM` 到 63 格
([`72`](72-e-file-formats-from-readers.md) §3)。
**哨兵值不是隨便挑的,是挑在陣列內、資料外。**

那兩格也不是空的:`CMBT` 開場在 `0x10463` 把 `None`(59)/ `Hands`(60)/
`Bite`(61)/ `Fangs`(62)四個名字手工填進陣列尾巴
([`192`](192-natural-weapon-names.md)),所以「沒穿防具 / 赤手空拳」
在訊息裡各有一句話可印。

## 4. 這一段同時推進三個子系統

| 子系統 | 得到什麼 |
|---|---|
| **D** | `CHARS.DAT` 三個欄位定案 + 「後 20 筆是空的」|
| **E** | `MONSTERS.DAT` 欄 5 = 武器 |
| **J** | 戰鬥屬性 4 / 5 = 武器 / 防具;隊伍成員與怪物走**同一條**初始化路徑 |

「隊伍成員與怪物共用單位結構」在 [`73`](73-monster-columns-to-combat-array.md) §2
只是從「常數 `0`/`3` 佔掉三個屬性欄」推的;
這裡看到**兩邊填同一個屬性、用同一個哨兵**,升為已確認。

## 5. 還缺什麼

- `CHARS.DAT` 其餘 ~40 個欄位(名稱起點、種族/職業碼 `H1`/`D1`/`T1`/`E2` 的位置)
- `MONSTERS.DAT` 另外九欄
- 戰鬥屬性 1–3、6–19 的語意
- 傷害/命中公式本身

都是內部工作。**D 的存檔寫入端**仍需要動態觀察才能確認欄位是否還有別的寫法。
