# 80 — 存檔的寫入端:我把「只能動態觀察」寫錯了

日期:2026-08-14
接續:[`79-alignment-resolved-damage-formula.md`](79-alignment-resolved-damage-formula.md)
子系統:**D. 角色/隊伍資料與存檔**

## 結論

存檔常式是 `USERLIB` 槽 34,**原生程式碼,靜態就讀得到**。
兩個 `OPEN` 各自帶著記錄長度,15 個欄位的寫入點也全部列得出來。

**先前把 D 的寫入端記成「只能靠 DOSBox 動態觀察」是錯的**,
而正確答案的入口([`66`](66-userlib-slot-semantics.md) 定出槽 34 = 存檔、
[`65`](65-userlib-export-table.md) 給出每個槽的進入位址)**兩天前就已經在手上**。

> 這是本專案第三次踩同一個坑([`71`](71-k-closure.md) §6 是第二次)。
> **判準:要說「這個做不到 / 被卡住」之前,先把自己已經解出的東西過一遍。**
> 前兩次是漏查規則,這一次是**漏查自己的成果**。

## 1. 兩個 `OPEN` 直接給出記錄長度

```
0x10A1F  mov ax, 37A0h / INT 3F:55 / xchg dx,bx
         mov bx, 1 / mov cx, 5Eh      ; #1,記錄 94 bytes
         INT 3E:1E                    ; OPEN

0x10A41  mov bx, 316Ch / INT 3F:55 / mov dx,bx
         mov bx, 2 / mov cx, 5Ah      ; #2,記錄 90 bytes
         INT 3E:1E
```

| 檔 | 記錄長度 | 檔案大小 | 筆數 |
|---|---:|---:|---:|
| `CHARS.DAT` | **94**(`mov cx, 5Eh`)| 2,350 | **25** ✅ |
| `GROUPS.DAT` | **90**(`mov cx, 5Ah`)| 450 | **5** ✅ |

**兩個都整除。** `CHARS.DAT` 的 94 與 [`75`](75-character-record-equipment.md) §2
從檔案大小推出來的一致,但這次是**從程式碼讀出來的**,不是推的。

`GROUPS.DAT` 出貨時**整份是空白**(450 個 `0x20`),
所以它的記錄長度**不可能從資料側推**;只有讀取端/寫入端給得出來。

## 2. `GROUPS.DAT` 的欄位表

寫入的形狀,每個欄位一段:

```
mov dx, 34DCh / INT 3F:61      ; 取出累積中的記錄字串
mov bx, dx / mov dx, 3004h / INT 3F:61
mov ax, ds:XXXXh               ; ← 要存的值
mov ds:3008h, ax
mov word ptr ds:300Ah, NN      ; ← 記錄裡的位移
call loc_1003D                 ; MKI$ + MID$ 寫回
```

**`ds:300Ah` 全檔只被設定 15 次**,所以下表就是完整的:

| 位移 | 來源變數 | 已知語意 |
|---:|---|---|
| 25 | `ds:3658h` | — |
| 27 | `ds:3536h` | — |
| 29 | `ds:3538h` | — |
| 31 | `ds:353Ah` | — |
| 33 | `ds:353Ch` | — |
| **35** | `ds:3518h` | **世界座標 x**([`43`](43-module-ds-layout.md))|
| **37** | `ds:351Ah` | **世界座標 y** |
| **41** | `ds:3520h` | **朝向**([`76`](76-to-hit-formula.md) §1 的 `cmp ds:3520h, 1`)|
| 45 | `ds:365Ah` | —(寫兩次,`0x10567` 與 `0x109F5`)|
| 59 | `ds:3060h` | 前面由 `ds:35B4h` / `ds:35B2h` 二選一(`0x1080D` 的 `cmp ds:3534h, 63h`)|
| 79 | `ds:351Ch` | — |
| 81 | `ds:351Eh` | — |
| 83 | `ds:3534h` | — |
| 85 | `ds:3532h` | — |

三個欄位的語意由**別的子系統**獨立確定過(座標與朝向),
它們在這裡的位移是新的。

⚠ **位移 1–24、39、43、47–57、61–77 沒有出現** ——
那些位元組要嘛不存、要嘛由別處寫。**不要把上表讀成「記錄的完整佈局」。**

## 3. D 的四個條件

| # | 條件 | 狀態 |
|---|---|---|
| 1 | IDA 讀原始指令 | ✅ 兩個 `OPEN` + 15 個欄位寫入 + [`75`](75-character-record-equipment.md) 的讀取端 |
| 2 | 讀寫端點 | ✅ 讀端 [`75`](75-character-record-equipment.md)、寫端本篇 |
| 3 | 獨立資料印證 | ✅ 94 × 25 = 2,350、90 × 5 = 450 兩個都整除;`99` 哨兵([`75`](75-character-record-equipment.md) §2)|
| 4 | 筆記 | ✅ |

**D 仍不標 RE-DONE**,缺的是**欄位語意的覆蓋率**:
`CHARS.DAT` 94 bytes 裡只解出 3 個位置([`75`](75-character-record-equipment.md)),
`GROUPS.DAT` 90 bytes 裡只解出 3 個。

但**缺口的性質變了** —— 從「要動態觀察」變成「靜態工作沒做完」。
做法明確:`CHARS.DAT` 的欄位要從 `CHARUTIL`(建角色)與 `CAMP`(裝備/物品)
的寫入端去列,和本篇同一套方法。**不卡外部條件。**
