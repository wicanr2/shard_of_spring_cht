[`81`](81-chars-record-to-combat-attributes.md)(角色位移 → 屬性)可以**接起來**。

## 1. 兩個判別測試

### 測試 1:欄10 = 法力點數

| 群 | 筆數 | 欄10 |
|---|---:|---|
| 名字含 `Fighter` | 9 | **全部 0** |
| 名字含 `Wizard` / `Mage` | 11 | **全部 > 0**,依等級 `5, 12, 18, 24, 35, 40, 45, 50, 55, 65`(外加 `Skeleton Mage` 20)|

**20/20 分得乾乾淨淨,而且法師那一組隨等級單調上升。**

### 測試 2:欄8 = 生命值

遊戲自己提供了兩條等級序列,名字裡就寫著等級:

```
Fighter  Lv 1→33  2→65  3→80  4→120  6→129  8→160  10→175  12→200  15→225
Wizard   Lv 1→33  2→60  3→75  4→115  5→141  8→160  10→170  13→205  16→220
```

**兩條都嚴格單調遞增。** 頭目 `Siriadne !` 是 **5000**,`R A L I T H` 是 500。

### 測試 3:欄5 是物品編號(而且有特殊值)

`Cobra`、`Death Adder`、`Ghoul`、`Pit Viper`、`Rattlesnake` **五筆的欄5 都是 62**,
而 `ITEMS.DAT` 只有 57 列 —— **62 在資料之外、在 `DIM` 的 63 格之內**,
和 [`75`](75-character-record-equipment.md) §3 的 `60`/`59` 是同一種手法。

**五隻有毒的生物共用同一個假物品**,這種分群不會是巧合。

## 2. ⚠ 推翻 [`73`](73-monster-columns-to-combat-array.md) §4

那一節寫過:欄8 的 `33 / 33 / 38` 落在 `MONST*.BIN` 的 46 張圖範圍內,「形狀像圖號」。

**否證:`Siriadne !` 的欄8 是 5000。** 圖只有 46 張。

當時只看了前三筆,而前三筆剛好都在 46 以內。原文已標明
「這是形狀推測,不是證據,不要當結論引用」—— **標註起了作用,但標註不能取代測量**。

> **判準:從前 N 筆看出來的形狀,要拿全部 N 筆去否證,不是去確認。**
> 這一次只要看最後一筆就夠了。

真正的圖號候選是**欄6**(戰士 `1`、法師 `3`、龍 `22` —— 同類共用一個值),
但那還沒對過 `MONST*.BIN` 的 46 張圖,**標為假設**。
