# 85 — 掃描器把「屬性 0」和「判不出來」混成一類

日期:2026-08-14
接續:[`84-pursuit-not-initiative.md`](84-pursuit-not-initiative.md)
子系統:**J. 戰鬥規則**(訂正)

## 結論

從 [`73`](73-monster-columns-to-combat-array.md) 起一直在用的屬性掃描器,
在回溯 16 bytes 找不到 `add reg, imm` 時**預設 imm = 0**,
於是「這是屬性 0」和「我判不出來」變成同一個輸出。

`CMBT` 的 317 處 `[reg+6822h]` 存取裡,**97 處(31%)是判不出來的**,
而它們全部被記成了屬性 0。

**[`84`](84-pursuit-not-initiative.md) §2 關於屬性 0 的論證因此無效。**

> ⚠ [`86`](86-scanner-fixed-conclusion-restored.md) §3:本篇這張影響表**列得太窄**。
> 失敗吞進某一類會同時「灌水那一類」和「掏空其他類」,
> 所以凡是引用過**次數**的結論都要重看,不只是引用過屬性 0 的。

## 1. 影響範圍

| 結論 | 依據的資料 | 是否受影響 |
|---|---|---|
| [`73`](73-monster-columns-to-combat-array.md) 怪物欄 → 屬性 4–13、19 | 全部有明確的 `add reg, imm` | ❌ 不受影響 |
| [`81`](81-chars-record-to-combat-attributes.md) 角色位移 → 屬性 1–14 | 同上 | ❌ 不受影響 |
| [`76`](76-to-hit-formula.md) 命中公式(屬性 9、8、10、5、4)| 逐條指令讀出,不靠掃描器 | ❌ 不受影響 |
| [`83`](83-hp-is-attribute-3.md) 屬性 3 = 生命值 | `add di, 2Dh` 明確 | ❌ 不受影響 |
| **[`84`](84-pursuit-not-initiative.md) §2「屬性 0 / 1 = 戰場座標」** | 屬性 0 那一半來自掃描器的預設值 | ✅ **無效** |

**屬性 1 的那一半仍然成立**(`add di, 0Fh` 是明寫的),
但 [`84`](84-pursuit-not-initiative.md) 的論證是「屬性 0 與屬性 1 結構相同、緊鄰,像 x 與 y」——
**論證少了一半,結論就降級**:屬性 1 = 戰場座標由「證據充分」降為**假設**。

## 2. 反例:那個位置的屬性 0 是旗標,不是座標

```
013E92  mov di, bx / shl di, 1
013E96  cmp word ptr [di+6822h], 0     ; 位移 0
013EA0  INT 3D:34                       ; 亂數
013EAA  INT 3F:A1                       ; 與 ds:9460h 比
013EAF  jb  → 0x13EB4
013EB6  mov word ptr [bx+6822h], 1      ; 設成 1
013EC9  mov word ptr [di+6822h], 0FFFFh ; 否則另一個欄位設 −1
```

**被亂數決定、只取 0 / 1 / −1** —— 那是旗標的形狀,不是座標。

⚠ 但這一段的 `[di+6822h]` **本身也可能不是屬性 0**(`di` 是 `bx` 直接搬來的,
`bx` 從哪來要往上追)。**用一個同樣沒驗證的例子去推翻另一個,不會產生知識。**
這裡只主張:**[`84`](84-pursuit-not-initiative.md) 的證據不成立**,不主張屬性 0 是旗標。

## 3. 順帶:`ds:9460h` 是重複使用的暫存

[`79`](79-alignment-resolved-damage-formula.md) §3 的傷害公式裡有「× `ds:9460h`」,
而同一個位址在這裡是**亂數的比較對象**。

**同一個 DS 位址在不同段落有不同用途** —— 編譯器的暫存變數會被重複配置。
[`79`](79-alignment-resolved-damage-formula.md) §3 把它寫成公式的一個具名係數,
**應該改成「一個當下計算出來的係數」**,已在該篇標註。

## 4. 工具修正

`tools/ida/` 的屬性掃描要把兩種情況分開輸出。修正後的判準:

```
找到 add reg, imm(imm % 15 == 0)  → 屬性 imm/15
找到 add reg, imm(imm % 15 != 0)  → 不是屬性存取,略過
16 bytes 內找不到 add              → 判不出來,單獨列出,不併進屬性 0
```

> **判準:一個掃描器的「預設值」不能和它的某個有效輸出撞號。**
> `imm = 0` 同時是合法答案與失敗值,所以 31% 的失敗被讀成了「屬性 0 用得很多」——
> 而「屬性 0 用最多」正是我在 [`84`](84-pursuit-not-initiative.md) 去看它的原因。
> **失敗值撞號會讓失敗看起來像訊號,而且是最強的那個訊號。**
