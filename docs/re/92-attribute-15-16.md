# 92 — 屬性 15 是目標編號,屬性 16 是 `Hero` 的第二個旗標

日期:2026-08-14
接續:[`91-e-closure.md`](91-e-closure.md)

## 1. 屬性 16 ← `CHARS.DAT` 位移 49

和屬性 17([`87`](87-class-race-and-attribute-17.md))**同一個形狀、同一個閘門**:

```
011BC0  mov dx, 0Fh / cx = 1
011BC6  INT 3D:0A          ; MID$(角色記錄, 15, 1) = 職業碼
011BD1  INT 3F:62          ; 與 '1'(Hero)比
011BD6  jz  → 取值
011BE0  mov dx, 31h        ; 位移 49
011BE3  INT 3D:0A / 3D:13 / 3F:78
011BF2  add ax, 0F0h       ; 240 = 16 × 15
011BF9  mov [di+6822h], bx ; → 屬性 16
011C00  否則 → 屬性 16 = 0
```

所以 `CHARS.DAT` **位移 48 → 屬性 17、位移 49 → 屬性 16**,
兩者都**只有 `Hero` 才生效**。

出貨的五個角色:

| 角色 | 職業 | 位移 48–51 | 屬性 17 | 屬性 16 |
|---|---|---|---:|---:|
| `Segrono` / `Hard Axe` / `Grod` | Hero | `1100` | 1 | 1 |
| `Fire Hawk` | Wizard | `0100` | 0(閘門)| 0(閘門)|
| `Richtatha` | Wizard | `0001` | 0 | 0 |

**位移 48–51 是一串 0/1 旗標**,前兩個各餵一個屬性。
⚠ 旗標**代表什麼能力**仍未解;只知道屬性 17 進傷害公式當減項
([`79`](79-alignment-resolved-damage-formula.md) §3)。

## 2. 屬性 15 = 這個單位鎖定的目標編號

```
01468D  mov di, [di+6A7Ah]      ; 某個單位
014691  add di, 0E1h            ; 225 = 15 × 15 → 屬性 15
014699  mov di, [bx+6822h]      ; ★ 讀出來的值當成「單位索引」
01469D  mov dx, di
01469F  add di, 78h             ; 120 = 8 × 15 → 目標的屬性 8
0146A4  cmp word ptr [di+6822h], 5
0146AF  add dx, 96h             ; 150 = 10 × 15 → 目標的屬性 10
0146B7  cmp word ptr [di+6822h], 0
```

**屬性 15 的值被直接拿去當下一次陣列存取的索引** ——
一個屬性存的是另一個單位的編號,那就是**目標**。

**信心:證據充分**(索引用法是直接讀出來的;
「目標」這個詞是從用法推的,沒有字串佐證)。

這也解釋了為什麼屬性 15 有 15 處存取([`86`](86-scanner-fixed-conclusion-restored.md) §1)——
每個單位每回合都要決定打誰。
