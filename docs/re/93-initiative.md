# 93 — 先攻:依速度對行動順序表排序

日期:2026-08-14
接續:[`92-attribute-15-16.md`](92-attribute-15-16.md)
子系統:**J. 戰鬥規則**

## 結論

`CMBT 0x11E50`–`0x11EAA` 是一個**兩層迴圈的排序**,
拿**屬性 2(速度)**對 `ds:6A7Ah` 這張**行動順序表**排序,速度大的排前面。

**先攻解出來了。**

## 1. 程式碼

```
011E50  xor ax, ax                  ; 內層 j = 0
011E56  di = ds:9378h               ; 外層 i
011E5E  mov di, [bx+6A7Ah]          ; ★ 順序表第 i 項 = 單位編號
011E62  add di, 1Eh                 ;   + 30 = 2 × 15 → 屬性 2
011E67  mov dx, [di+6822h]          ;   速度[順序表[i]]
011E71  mov si, [si+6A7Ah]          ; ★ 順序表第 j 項
011E75  add si, 1Eh
011E7A  cmp dx, [si+6822h]          ; 比速度
011E7E  jge → 交換
011E8F  INT 3Fh; 13                 ; SWAP(兩個順序表元素)
011E94  ax++ / cmp ax, 0Dh / jle    ; 內層 0–13
011EA0  ds:9378h++ / cmp, 0Dh / jle ; 外層 0–13
```

**`0x0D` = 13 → 14 個位置(0–13)**,與 15 欄的單位陣列一致
([`43`](43-module-ds-layout.md))。

`ds:6A7Ah` 存的是**單位編號**,不是屬性 —— 排序動的是「誰第幾個動」,
不是單位本身。這也是為什麼別處(`0x1468D`、`0x14AE5`)拿它去索引單位。

## 2. 屬性 2 = 速度,兩條獨立的來源

| 來源 | 路徑 |
|---|---|
| 怪物 | `MONSTERS.DAT` **欄1** → `0x18158` 讀出 → 乘亂數、乘 `ds:9F96h`、加 `ds:9F9Ah` → `0x1819A` `add dx, 1Eh` → **屬性 2** |
| 角色 | `CHARS.DAT` **位移 16** → 屬性 2([`81`](81-chars-record-to-combat-attributes.md))|

⚠ 這**補上了 [`73`](73-monster-columns-to-combat-array.md) §2 那張表的缺口** ——
當時欄1 的去處是空白的,現在填上了(屬性 2)。

資料側:`Bat`/`Rat` 欄1 = 10、`Wind Elemental` 26、`Dark Raven` 20;
`Hill Giant` 4、`Shambling Mound` 6 —— **快的生物數值高**
([`82`](82-monster-columns-semantics.md) §測試 4)。

**怪物的速度是每次遭遇現骰的**(乘亂數),和生命值一樣
([`83`](83-hp-is-attribute-3.md) §1)—— 所以同一種怪物每次先攻不一定相同。

## 3. 排序的方向

`jge` → 交換,所以**大的往前** = **速度高的先動**。

⚠ 這個排序**每回合是否重跑**沒有查(要看 `0x11E50` 的呼叫端)。
「怪物速度現骰」若只在遭遇開始骰一次,那先攻順序整場固定;
若每回合重骰就每回合變。**兩種都合理,沒有證據不要選。**
