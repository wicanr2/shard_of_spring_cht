# 95 —(整篇作廢)找不到逃跑:三條路都指向「這個遊戲沒有逃跑指令」

> ⛔ **本篇結論錯誤。逃跑存在,訊息是 `'PARTY RAN!'`** ——
> 見 [`102`](102-flee-exists-retracting-j.md)。根因是 §1 的正規表示式有 `run` 沒有 `ran`。
> 保留全文是為了留下錯誤的形狀,**不要引用本篇任何結論**。

接續:[`94-skill-tables.md`](94-skill-tables.md)

## 結論

`CLAUDE.md` §2.2 給 J 的題目裡有「逃跑的判定」。
**找不到,而且三條獨立的線都指向「它不存在」。**

⚠ **這是「查詢回空」的結論,所以要先做正對照**(見 §4)。
標為**假設**,不標已確認。

## 1. 線一:沒有任何相關字串

`CMBT`、`WRLDMOVE`、`MAZEMOVE` 三支模組的文字清冊裡,
`flee` / `run` / `escape` / `retreat` / `withdraw` / `away` **一個都沒有**。

而同一份清冊裡**有** `Attacks with:` / `cast spells.` / `attacks ` / `dies.` ——
戰鬥的其他動作都有字串。

## 2. 線二:`CMBT` 只有兩處模組轉交

掃 `CMBT` 裡對 `WRLD` / `MAZE` / `TOWN` / `DEAD` / `WRLDMOVE` / `MAZEMOVE`
這些模組名字串的引用,**只有兩個叢集**:

| 位址 | 引用的模組名 | 判讀 |
|---|---|---|
| `0x12206`–`0x12230` | `DEAD` `WRLD` `WRLDMOVE` `MAZEMOVE` | **全隊死亡**的出口 |
| `0x132CB`–`0x13334` | `CMBT` `WRLD` `WRLDMOVE` `MAZEMOVE` | **戰勝結算**的出口(見 §3)|

**戰鬥只有兩個出口:贏、或全滅。** 逃跑需要第三條路,而沒有第三個叢集。

## 3. 線三:`Y/N` 那一支是戰利品,不是逃跑

`0x13212` 的 `Y` / `0x1325D` 的 `N` 比對,前面接的字串是:

```
0x9688 'Experience:'   0x9698 ' (per character)'
0x96C2 'Gold:'         0x96D8 ' found '
0x9700 'Do you take it?'   0x9714 '(Y/N)'
```

**那是戰後結算的拾取確認。** 我原本以為 `Y/N` + 模組轉交 = 逃跑確認,
拉出字串才發現不是。

> **順帶印證**:畫面上有 `Experience:` 與 `Gold:` 的結算,
> 支持 [`83`](83-hp-is-attribute-3.md) §2 把怪物欄8 判成**經驗值** ——
> 當時的理由是「屬性 19 只寫不讀 → 要帶出戰鬥」,現在看到帶出去做什麼了。

## 4. ⚠ 正對照:方法有沒有可能整組失效?

「查詢回空」不能直接當「不存在」。同一套方法在這一輪與前幾輪**有效地找到過**:

| 找什麼 | 結果 |
|---|---|
| 指令鏈的單字元 | `CMBT` 抽出 `1 2 3 4 D C S A U T Y N` 等([`70`](70-key-chains-all-modules.md))|
| 技能名稱 | 兩張各十項的表([`94`](94-skill-tables.md))|
| 模組轉交 | 兩個叢集(§2)|
| 戰後結算字串 | `Experience:` `Gold:` `Do you take it?`(§3)|

**方法在同一批檔案上一直有輸出**,所以「回空」比較可能是真的空。

**但仍有兩個沒排除的可能**:

1. 逃跑**不用字串也不用轉交** —— 例如走到戰場邊緣自動脫離,
   那會落在 [`84`](84-pursuit-not-initiative.md) 的移動程式碼裡,而那兩支子常式
   (`sub_14195` / `sub_143E5`)**還沒讀**
2. 指令鏈裡的 `D`(`0x128F4` → `0x1699B`)語意未定 ——
   它檢查的是 `CHARS.DAT` 位移 51(表 A 技能 10 = `Persuasion`,[`94`](94-skill-tables.md)),
   形狀像「說服」而不是「逃跑」,但**沒有定案**
