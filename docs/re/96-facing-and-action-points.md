# 96 — 屬性 10 是朝向,`ds:956Ch` 是行動點數

日期:2026-08-14
接續:[`95-no-flee-command.md`](95-no-flee-command.md)
子系統:**J. 戰鬥規則**

## 結論

[`84`](84-pursuit-not-initiative.md) §1 那兩支沒讀的子常式(`sub_14195` / `sub_143E5`)
是**轉身**,而它們同時解掉三件事:

1. **屬性 10 = 朝向**,用的是 [`57`](57-g-closure.md) 那套 `1北 2東 3南 4西`
2. **屬性 0 / 1 是 x / y 座標**,而且**軸向可以指認**了
3. **`ds:956Ch` = 行動點數**

## 1. 兩支子常式

```
sub_14195                          sub_143E5
014195 di = 攻擊者                  0143E5 同
01419B add di, 0Fh   → 屬性 1       0143EB 同
0141AD cmp dx, [si+6822h]           0143FD 同
0141B4 jge → cx = 0                 014404 jle → cx = 0
       否則 cx = −1                        否則 cx = −1
0141B7 add bx, 96h  → 屬性 10       014407 同
0141BF cmp 屬性10, 3                01440F cmp 屬性10, 1
0141D3 dec ds:956Ch                 014423 dec ds:956Ch
0141D7 屬性10 = 3                   014427 屬性10 = 1
0141DD call sub_1783E               01442D call sub_1783E
```

**兩支只差三個地方**:比較方向(`jge`/`jle`)、目標朝向值(`3`/`1`)。

「屬性 1 上比較大小 → 把朝向設成 3 或 1」——
[`57`](57-g-closure.md) §3 的編號是 **1 = 北、3 = 南**,
所以 **屬性 1 是南北軸(y)**,而 [`84`](84-pursuit-not-initiative.md) §1 的另一組
(`0x14028`,屬性 0)必然是東西軸(x,朝向 2 / 4)。

**屬性 0 / 1 = 戰場座標,從證據充分升為已確認** ——
這次不是「兩組結構相同」的類比,是**朝向值直接指認了軸向**。

## 2. `ds:956Ch` = 行動點數

| 位址 | 動作 | 變化 |
|---|---|---|
| `0x141D3` / `0x14423` | 轉身 | `dec`(−1)|
| `0x14682` | 另一個動作 | `add ds:956Ch, 0FFFDh`(−3)|
| `0x140EC` / `0x1699B` | 判斷 | `cmp ds:956Ch, 1` / `cmp ds:956Ch, 3` |

**轉身 1 點、行動 3 點**,不夠就不能做。
`0x1699B`(指令鏈的 `D` 通往的地方)開頭就是 `cmp ds:956Ch, 3` ——
**`D` 是一個要花 3 點的動作**。

## 3. 命中公式的 `+12` 解出來了

[`76`](76-to-hit-formula.md) §1 的命中公式有一項:

> 若 `屬性10[攻] = 屬性10[防]` → 命中 **+12**

屬性 10 既然是**朝向**,這一項就是:
**攻守雙方面向同一個方向時 +12** —— 也就是**從背後攻擊的加成**。

當時 [`76`](76-to-hit-formula.md) §4 把它列為「語意未解」,
還註明「怪物的屬性 10 是常數 3,所以怪物打怪物永遠 +12」——
現在看那句話的意思是:**怪物出場時全部面向南方**,
所以怪物之間互毆確實都算背後攻擊。⚠ 但怪物一轉身就不成立,
**那句「永遠」該撤掉**,已在 [`76`](76-to-hit-formula.md) 標註。
