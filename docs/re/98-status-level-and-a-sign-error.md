# 98 — 狀態與等級的位移,以及命中公式的一個反號

日期:2026-08-14
接續:[`97-j-closure.md`](97-j-closure.md)
子系統:**D. 角色資料** × **J. 戰鬥規則**(訂正)

## 結論

`CAMP` 的角色卡把標籤與記錄位移綁在一起,**規律是「標籤引用點 +14 bytes」**。

| 標籤 | 位移 | 驗證 |
|---|---:|---|
| `Hit Pts.` | **28** | ✅ 與 [`83`](83-hp-is-attribute-3.md) 的當前生命值一致 |
| `Spell Pts.` | **32** | ✅ 與屬性 7(法力)一致 |
| **`Level:`** | **40** | 新 |
| **`Status`** | **38** | 新 |

**兩個已知欄位落在同一條規律上**,所以另外兩個可信。

## 1. ⚠ 訂正 [`76`](76-to-hit-formula.md) §1:不等號反了

[`76`](76-to-hit-formula.md) §1 寫:

> `+ 30   若 屬性8[防] ≤ 1`

**方向是反的。** 重讀位元組:

```
0x1368D  83 bd 22 68 01   cmp word ptr [di+6822h], 1
0x13692  7f 03            jg  → 0x13697
0x13694  e9 08 00         jmp → 跳過
0x13697  83 06 68 97 1e   add word ptr ds:9768h, 1Eh   ← +30
```

**`jg` 這一側才是 `+30`**,所以正確的是 **`屬性8[防] > 1 → +30`**。

## 2. 反號一改,語意就通了

屬性 8 ← `CHARS.DAT` 位移 38([`81`](81-chars-record-to-combat-attributes.md))
= **狀態**(本篇)。`MENU.EXE` 裡有狀態表:

```
 OK,Poisoned,Bound,Still Air,Frozen,D E A D
```

**狀態 > 1 → 命中 +30。** 狀態表是
`OK(0), Poisoned(1), Bound(2), Still Air(3), Frozen(4), D E A D(5)`,
所以吃到 +30 的是**被縛、定身、凍結**(2 以上)——
⚠ **中毒(1)不在裡面**。動不了的目標更容易被打中,而中毒的人照樣會閃 ——
比「任何異常都 +30」更合理。

而原本的寫法(`≤ 1 → +30`)意思是「健康的目標更容易打中」,**明顯不合理**,
而我當時**沒有察覺** —— 因為那時屬性 8 還沒有語意,
一個沒有語意的數字**沒有辦法「看起來不對」**。

⚠ 本篇初稿把這一句寫成「中毒、被縛、定身、凍結的目標更容易被打中」——
**條件是 `> 1`,中毒是 1,不成立**。判斷式沒有錯,錯的是把它翻成中文那一句。

> **判準:語意是抓反號的主要工具。**
> 純位址推理(`屬性8 ≤ 1`)在兩個方向上讀起來一樣合理;
> 一旦知道它是「狀態」,錯的那個方向立刻刺眼。
> **所以「先把公式寫出來,語意之後再補」是有代價的** ——
> 補語意的時候要**回頭重讀**每一個比較,不能只把名字填進去。

順帶:[`96`](96-facing-and-action-points.md) §3 已經撤過一次
「怪物打怪物永遠 +12」;這一次是同一條公式的另一項。
**[`76`](76-to-hit-formula.md) §1 的三項裡有兩項被後續修正過。**

## 3. 修正後的命中公式

```
命中 = ( 屬性9[攻] − 欄5[防禦者防具] + 欄5[攻擊者武器] ) × 4
       + 30   若 狀態[防] > 1        (非 OK 狀態)
       + 12   若 朝向[攻] = 朝向[防] (背後攻擊)
```

三項全部有語意了。
