# 99 — 奇偶性把兩個記錄分開,`CHARS.DAT` 只剩四個未知欄位

日期:2026-08-14
接續:[`98-status-level-and-a-sign-error.md`](98-status-level-and-a-sign-error.md)
子系統:**D. 角色/隊伍資料**

## 結論

[`89`](89-record-offset-census.md) §3 的問題(兩個檔共用位移變數,清單混在一起)
**有一個乾淨的判別法**:

| 記錄 | 2-byte 整數欄位的位移 |
|---|---|
| `CHARS.DAT` | **全部是偶數** |
| `GROUPS.DAT` | **全部是奇數** |

驗證:已知的 11 個 `CHARS.DAT` 欄位(16, 18, 24, 26, 28, 30, 32, 34, 36, 38, 40)
**全偶**;[`80`](80-save-write-end.md) §2 從存檔常式讀出的 14 個 `GROUPS.DAT` 欄位
(25, 27, 29, 31, 33, 35, 37, 41, 45, 59, 79, 81, 83, 85)**全奇**。

**25 筆、零例外。**

## 1. 為什麼會這樣

`CHARS.DAT` 記錄的開頭是 **1 個字元 + 10 字元名稱**(位移 1–11),
所以第一個 2-byte 整數落在位移 12 —— **偶數**,之後每 2 bytes 一格,永遠是偶數。

`GROUPS.DAT` 的開頭欄位長度是偶數,所以第一個整數落在奇數位移。

**這不是巧合,是記錄前綴長度的奇偶決定的。**

## 2. 清點重新分家

[`89`](89-record-offset-census.md) 的 39 個位移:

| | 個數 | 位移 |
|---|---:|---|
| 偶 → `CHARS.DAT` | 15 | 12, 16, 18, 20, 22, 24, 26, 28, 30, 32, 34, 36, 38, 40, 84 |
| 奇 → `GROUPS.DAT` | 24 | 15, 17, 19, 21, 23, 25, 27, 29, 31, 33, 35, 37, 41, 45, 59, 61, 63, 65, 69, 79, 81, 83, 85, 89 |

⚠ **位移 15 是例外**:它是 `MID$` 讀的**單字元**職業碼([`88`](88-races-and-classes.md)),
不是 2-byte 整數。**奇偶規則只適用於整數欄位**,不適用於字元欄位
(名稱 2–11、種族 14、職業 15、技能旗標 42–51 也都不適用)。

**位移 23 = `Provisions:`**([`89`](89-record-offset-census.md) 的
`CHARUTIL`/`MENU` 都讀它)是奇數 → **`GROUPS.DAT`**,
也就是**補給品是隊伍層級的資源**,不是每人一份 —— 合理。

**位移 89 是奇數 → `GROUPS.DAT`**,而 `GROUPS.DAT` 記錄長 **90 bytes**
([`80`](80-save-write-end.md) §1),所以 89–90 正好是**最後一個欄位**。
先前 [`89`](89-record-offset-census.md) §5 用它推論「`CHARS.DAT` 的尾端有被用到」,
**那個推論作廢** —— 它根本不是 `CHARS.DAT` 的位移。

## 3. 這一輪新增的三個欄位

`CAMP` / `TOWN` 的角色卡印的是 `當前/最大`:

```
'H.P.   ' + [位移 28] + '/' + [位移 26]
'S.P.   ' + [位移 32] + '/' + [位移 30]
```

| 位移 | 語意 |
|---:|---|
| **26** | **最大生命值** |
| **30** | **最大法力** |
| 23 | 補給品(在 `GROUPS.DAT`)|
