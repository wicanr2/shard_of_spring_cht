# 顯示層與中文排版 — **READY**

畫布 **1024 × 768**,專案負責人裁定 2026-08-14。
`CLAUDE.md` §7 的「現在不要先決定畫布尺寸」條件已解除(H 項 RE-DONE)。

## 1. 核心決定:美術整數放大,版面重排,文字層原生解析度

原版是 CGA **320 × 200**([`re/20`](../re/20-cga-layout.md))。
整個畫面等比放到 1024×768 是**做不到也不該做**的:

| 倍率 | 結果 | 問題 |
|---:|---|---|
| 3× | 960 × 600 | 上下左右留白 64 / 168 px,而且文字仍是 3× 的點陣字 |
| **4×** | **1280 × 800** | **超出 1024×768** |
| 3.2× / 3.84× | 剛好填滿 | **非整數倍 → 像素藝術糊掉** |

所以走**分層**:

```
美術層   17×17 圖塊 → 4× → 68×68     整數倍,最近鄰取樣,不糊
文字層   TTF @ 1024×768 原生解析度    中文才有排版可言
```

**這是本規格最重要的一句話。** 把中文塞進 4× 的點陣字格會得到
「一個字 68×68 像素、筆畫全是方塊」的結果 —— 那不是復古,那是壞掉。
原版的英文點陣字之所以能放大,是因為拉丁字母筆畫少;中文不行。

⚠ 代價要講清楚:**畫面不再是原版的等比放大版**,而是重新編排的版面。
這是 `CLAUDE.md` §1「文化資產保存」的取捨 —— 保存的是**遊戲機制與內容**,
不是 1986 年 CGA 的像素密度。

## 2. 版面

原版結構([`re/20`](../re/20-cga-layout.md) §1 解出的畫面:一條垂直分隔線約在第 39 欄,
左側有外框的面板、右側方塊狀文字區;手冊 p.31 的商店截圖同構):
**左 = 主視野 / 清單,右上 = 隊伍狀態,右下 = 訊息**。

保留這個結構:

```
1024 × 768,外緣留白 24
        24                    636  660              1000
    24  ┌─────────────────────┬────────────────────┐
        │                     │  隊伍狀態           │
        │  主視野 / 清單       │  340 × 300         │
        │  612 × 612          │                    │
        │  = 9×9 圖塊 @ 4×    ├────────────────────┤ 348
        │  = PICT 153×153 @4× │  訊息列             │
        │                     │  340 × 288         │
   636  └─────────────────────┴────────────────────┘
   660  ┌──────────────────────────────────────────┐
        │  指令提示列  976 × 84                     │
   744  └──────────────────────────────────────────┘
```

| 區塊 | x | y | w | h | 內容 |
|---|---:|---:|---:|---:|---|
| 主視野 | 24 | 24 | 612 | 612 | 9×9 圖塊,每塊 17×17 @ 4× |
| 隊伍狀態 | 660 | 24 | 340 | 300 | 5 名角色 × 名稱/HP/SP + 金幣/食糧 |
| 訊息列 | 660 | 348 | 340 | 288 | 短訊息、即時戰鬥訊息 |
| **指令提示列** | 24 | 660 | 976 | 84 | 當前畫面可用的按鍵 |
| 敘述覆蓋層 | 112 | 254 | 800 | 260 | **見 §3**,長文用 |

⚠ 底部那條**不是為了填空才加的**。原版就有:手冊 p.31 的截圖右下角是
`Enter letter of item to buy / + for next page / ESC to exit`。
本專案把它從側欄移到底部整條,因為中文的按鍵說明比英文長。

### 為什麼主視野是 612

`153 = 9 × 17` —— **原版的圖畫區正好是 9×9 個圖塊**
([`formats/07`](../formats/07-graphics.md):圖塊 17×17、`PICT*.BIN` 153×153)。
612 = 153 × 4,所以:

- 迷宮 / 世界地圖:9×9 格視野,一格一塊
- 事件插圖:`PICT*.BIN` 整張填滿(⚠ **不是遭遇畫面** —— 五張分別是藏寶圖、
  NPC 場景、風景、死亡畫面、兜帽人物,見 [`re/127`](../re/127-pict-contents.md))
- 戰鬥:戰場是 **15×15**(手冊 p.33),**視野仍是 9×9,畫面捲動**

⚠ 「戰場 15×15、視野 9×9」是**手冊 + 檔案尺寸**兩個來源推出來的,
**還沒讀捲動的程式碼**。實作時若發現原版是縮小整個戰場而非捲動,以實際行為為準。

## 3. 敘述覆蓋層:長文不塞側欄

實測 87 段地城敘述([`translations/dungeon-text/`](../../translations/dungeon-text/)):

| | 顯示欄寬(全形算 2)|
|---|---:|
| 最長 | 207 |
| 中位 | 80 |
| 平均 | 83 |
| ≥120 欄 | 19 段 |

340 px 寬的側欄在 24 px 字下只有 **14 個全形字 / 行**,
207 欄的那段要 **8 行**,讀起來像在讀手機通知。

所以**房間敘述、劇情對白改用置中覆蓋層**:

```
800 × 260,**置中於畫布**(112,254),半透明底 + 邊框
內距 32 → 文字區 736 × 196
24 px 字 → 每行 30 個全形字(60 欄)
行距 34 px → 5 行
```

⚠ **是置中於畫布,不是置中於主視野。** 主視野只有 612 寬,放不下 800 的覆蓋層。
所以覆蓋層會**蓋住右欄的一部分**(x 從 112 到 912,右欄從 660 開始)——
那是 modal 的正確行為:它出現時遊戲暫停,底下的隊伍狀態本來就不需要同時可讀。

> 本節第一版寫「置中於主視野之上」,是**規格自己算不通** ——
> 800 > 612。M0 把版面畫成框跑起來才看出來。
> **判準**:版面規格寫完要用實際尺寸驗一次包含關係,
> 「置中於 X」在 X 比它小的時候沒有意義。

60 欄 × 5 行 = 300 欄 > 最長的 207 欄。**一頁就放得下,不必分頁。**

覆蓋層出現時遊戲暫停,按任意鍵關閉 —— 與原版行為一致
(原版也是顯示敘述後等待按鍵)。

⚠ **短訊息不要用覆蓋層。** 戰鬥的「Burnt for 12」這類即時訊息走右下訊息列,
覆蓋層只給「進入房間 / 遇到 NPC / 劇情觸發」這三種。
判準:**會讓玩家停下來讀的才蓋,一瞄就過的不蓋。**

## 4. 中文排版規則

### 字型

| 用途 | 大小 | 說明 |
|---|---:|---|
| 敘述覆蓋層 | 24 px | 主要閱讀字級 |
| 隊伍狀態 / 清單 | 20 px | 資訊密度優先 |
| 訊息列 | 20 px | |
| 標題 | 32 px | |

**用 TTF/OTF,不用點陣字。** Ebitengine 的 `text/v2` 直接吃
([`spec/03`](03-engine-plan.md) §1)。字型檔以 `embed` 打進執行檔。

⚠ **授權要選可再散布的**(思源黑體 / 思源宋體 或同級的開源字型)——
`CLAUDE.md` §1「公開產出只有引擎程式碼與翻譯文本」,字型會跟著散布。
**選字型時先看授權,不要等打包才發現不能附。**

### 斷行

中文**允許任意位置斷行**(不像英文要在詞邊界),但有兩條禁則:

| 禁則 | 內容 |
|---|---|
| **行首禁則** | `。，、；：？！」』）〕】》〉…—～%‰℃` 不可出現在行首 |
| **行尾禁則** | `「『（〔【《〈$#` 不可出現在行尾 |

處理方式:斷行點若違反禁則,**把前一個字一起推到下一行**(避頭尾)。

### 中英混排

譯文含大量 `中文(English)` 對照(glossary 硬規則 4),所以:

1. **英文與數字視為不可分割的單位**,不在字母中間斷行
2. `中文(English)` 這一整組**不拆開**,連同括號一起換行
3. 中英之間**不自動插入空白** —— 譯文裡的括號已經是視覺分隔

⚠ 第 2 點有實際後果:`中文(English)` 整組不拆,最長的一組
`巴利克鬥技場(Balik's Arena)` 是 27 欄 —— 名稱本身放得下側欄,
但**加上編號與價格的整列就放不下**。見 §5。

## 5. 清單放在主視野,不放側欄

側欄 340 px 只有 **30 欄**;主視野 612 px 有 **61 欄**。
**所有清單(商店品項、城鎮建築、法術、背包)都放主視野** ——
手冊 p.31 的截圖就是這樣:商品列在左側,右側是隊伍狀態。

實測(全部 57 個道具譯名 + 61 個商店譯名 + 13 個地名):

| | 欄 |
|---|---:|
| 道具名最長(`速度藥水`)| 8 |
| 整列最長(`A) 藍色權杖   250`)| 16 |
| 地名最長(`法師圖書館(Wizard's Library)`)| 28 |
| 主視野可用 | **61** |

⚠ 地名是**標題**,單獨一行,不放在清單列裡。

> 本節前兩版都把這個當成未決項,而**前提是錯的**:
> 第一版拿名稱長度去比欄數(算錯了),第二版改成整列 36 欄
> —— 但那 36 是把**地名**塞進清單列算出來的,而地名從來不放在列裡。
>
> **判準:一個未決項擱很久的時候,先回去問它的前提還成立嗎。**
> 拆解它只花了兩個量測。同一個未決項被錯誤診斷兩次,
> 就是「回去看前提」的訊號。

## 6. 調色盤

原版是 CGA 第三調色盤:**黑 / 青 / 紅 / 白**
(`0x3D8 = 0x0E`,[`formats/07`](../formats/07-graphics.md) §5)。

**預設沿用這四色**(文化資產保存)。介面元素(邊框、覆蓋層底、文字)
不受此限 —— 那些原版是用同一組色畫的,但 remake 的覆蓋層是新東西,
可以用半透明黑底 + 白字,不必硬擠進四色。

⚠ **不要「順手」把美術重新上色成 16 色或全彩。** 那是另一個專案。
