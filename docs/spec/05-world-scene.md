# 世界地圖場景 — **READY**(⚠ 可通行性除外,見 §5)

M2 的實作規格。資料格式在 [`formats/05`](../formats/05-world-map.md),
版面在 [`04-display-layout.md`](04-display-layout.md),本篇只講**這個場景怎麼運作**。

## 1. 地圖

```
103 × 121 = 12,463 格
索引 = y × 103 + x
每格 2 bytes,little-endian;地形值在**低位元組**(高位元組全 0)
```

⚠ 座標系是 **`y × 寬 + x`**。迷宮是 **`欄 × 81 + 列`**,兩者**不同**
([`00-index.md`](00-index.md) 實作前必讀第 4 條)。這是最容易寫反的一處,
而寫反了地圖仍然畫得出來 —— 只是轉了 90 度,看起來像「地圖本來就長這樣」。

### 2.1 值 0 = 地圖邊界

224 格**全部落在最外圈**(x=0 或 x=102 或 y=0 或 y=120),
內陸一格都沒有。**信心等級:已確認**(224/224,不是巧合)。

⚠ 但 224 ≠ 完整外圈的 444 格。實測拆解:

```
上緣整列  y=0        103 格   全部是 0
左緣整欄  x=0        120 格   全部是 0(不含已計入的角)
右緣落單  (102, 120)       1 格
下緣           0 格
                    ─────
                    224 格
```

右緣(x=102)與下緣(y=120)其餘格子**全是海洋(11)**。
所以它不是「畫一圈牆」,比較像**索引從 1 起算留下的第 0 列與第 0 欄**。

> 這個推論**沒有讀取端佐證**,不要據以實作。實作上只要知道
> 「值 0 沒有圖塊、不該出現在玩家可達的區域」就夠了。
> 右緣那一格落單的成因**未解**。

### 2.2 值 35–38 沒有圖塊來源,語意未知

36 格,散布內陸,**沒有一格在邊界**。`FASTWRLD` 只到 9、`WRLDITEM.PIC` 只到 32。

已排除:不是地城入口(那是 24/25/27/28,11 處已對上 `MAZEDATA.BIN`)、
不是城鎮(30/31/32,13 處)。

**信心等級:未知。不要猜,不要拿相鄰的圖塊去代。**
實作上以「缺圖」的明顯佔位符呈現(§4),讓它在畫面上看得見。

## 3. 視野

主視野 9×9 格([`04-display-layout.md`](04-display-layout.md) §2:
612 = 9 × 17 × 4,而 153×153 正是原版的圖畫區)。

**隊伍固定在正中央第 (4,4) 格,地圖捲動。**

⚠ 這是**設計決定,不是 RE 結論** —— 還沒讀 `WRLDMOVE` 的繪製迴圈。
另一種可能是視野以區塊為單位跳頁。若之後讀到程式碼證明是跳頁,以那個為準。

視野超出地圖邊界時填**值 0 的佔位符**,不做環繞。

## 4. 繪製

```
for vy in 0..8:
  for vx in 0..8:
    mx = party.x - 4 + vx
    my = party.y - 4 + vy
    tile = 界外 ? 0 : terrain(mx, my)
    畫 tile 的圖 於 (View.X + vx*68, View.Y + vy*68)
```

圖塊來源:

| 值 | 來源 |
|---|---|
| 1–9 | `FASTWRLD.BIN` 第 (值−1) 張 |
| 10–32 | `WRLDITEM.PIC` 第 (值−10) 段的 `DRAW` 向量圖 |
| 0、35–38 | **無來源** → 畫佔位符(見下)|

**佔位符必須看得出來是「缺」**,不能用黑色或海洋填 ——
那會讓未解的 36 格偽裝成正常地形,而 §2.2 的未知就此消失在畫面裡。
用洋紅色 `#FF00FF` 的網格塊。

> **判準**:未解的東西在畫面上要**刺眼**。
> 這與 `CLAUDE.md` 的「不要留白讓後人以為漏了」同一條原則,
> 只是搬到了顯示層。

## 5. ⛔ 可通行性:**未解,M2 不實作**

**沒有任何 RE 筆記記錄世界地圖的可通行性規則。**
已知的只有迷宮側:[`re/56`](../re/56-maze-tile-classes-and-mazedata-columns.md) §1
的「圖塊 5–10 阻擋」,**那是迷宮的圖塊編號,與世界地圖不同一套,不可套用**。

「海洋(55.6%)當然不能走」是**常識不是證據**。
本作有 `WINGS`(魔翼術)、`WIND WALK`(風行術)這類移動法術,
海洋能不能走可能是**有條件的**。

### M2 的處理

依 [`03-engine-plan.md`](03-engine-plan.md) §4「不要猜一個值填進去」:

- 移動**不做阻擋檢查**,四個方向都能走(除了地圖邊界)
- `Terrain.Passable` 這個欄位**不存在** —— 不提供一個假的答案
- 場景在踏上未知可通行性的地形時**不做任何特殊處理**,但轉換器會輸出
  地形值統計,供之後對照

**解這一項的方法**:讀 `WRLDMOVE.EXE` 位移計算之後、寫回座標之前的分支。
[`re/70`](../re/70-key-chains-all-modules.md) §3 已經讀到 `0x106A2` 附近的
`inc/dec` 與 `mov ds:3518h`,**阻擋檢查若存在就在那兩者之間**。

## 6. 移動

按鍵([`re/70`](../re/70-key-chains-all-modules.md) §1、§3):

| 鍵 | 方向 | 小鍵盤 |
|---|---|---|
| `1` | 北 (y−1) | ↑ |
| `2` | 東 (x+1) | → |
| `3` | 南 (y+1) | ↓ |
| `4` | 西 (x−1) | ← |

⚠ **朝向不同時只轉身,不位移**(`re/70` §3:`cmp ds:3520h, 1` 在位移之前)。
所以往北走的第一下若原本朝東,只會轉成朝北。**這一條要照做** ——
它會改變玩家的操作手感,也會改變每一步消耗的遊戲時間。

朝向編碼 `1`北 `2`東 `3`南 `4`西,與 `GROUPS.DAT` 位移 41 相同
([`formats/02`](../formats/02-groups-dat.md))。

指令鍵:`C` = 紮營、`S` = 存檔、`P` / `Q` / `J` 語意未解(`re/70` §4)。
**M2 只接方向鍵**,指令鍵留到對應場景存在之後。

## 7. 時鐘與遭遇倒數

每次**實際位移**(不含純轉身)推進時鐘一格
([`formats/02`](../formats/02-groups-dat.md) 的四級進位),並 `dec` 遭遇倒數
(`GROUPS.DAT` 位移 25)。倒數歸零時掃 3×3 鄰域做遭遇檢查
([`re/122`](../re/122-d-closure.md))。

⚠ **M2 不實作遭遇** —— 戰鬥是 M4。M2 只把時鐘與倒數推進做對,
並在訊息列顯示目前的值,讓 M4 接手時有東西可對。
