# 戰鬥場景(M4) — **READY**

對應 [`03-engine-plan.md`](03-engine-plan.md) 的 **M4**。
規則來源:[`01-combat.md`](01-combat.md)(已 READY)。
本篇補的是**執行期的形狀**:單位陣列怎麼建、回合怎麼推、亂數怎麼可重現。

## 1. 單位陣列

[`01-combat.md`](01-combat.md) §1 的 `A%(單位, 屬性)`,15 個槽:

```
索引 0–8    怪物(最多 9 隻)
索引 9–13   隊伍(9 起,人數上限 5)
索引 14     未使用
```

⚠ **索引順序不可以改。** 先攻表存的是單位編號,而怪物在前、隊伍在後
這件事被 [`01`](01-combat.md) §7 的逃跑判定直接依賴(掃 9…人數+8)。

引擎用一個 `[15]Unit` 的陣列,欄位對應 [`01`](01-combat.md) §1 的屬性表。
**屬性 14 / 18 未解,保留欄位但不使用。**

### 朝向 0 = 不在場

[`01`](01-combat.md) §7:逃跑不是指令,是「全隊朝向都 ≤ 0」。
所以 `Facing == 0` 是**離場**的表示法,不是「朝北」。
⚠ 這與 `GROUPS.DAT` 位移 41 的 1–4 是同一個編碼加上一個 0 ——
**不要把 0 正規化成 1**。

## 2. 亂數:可重現是驗收條件

[`03-engine-plan.md`](03-engine-plan.md) 的 M4 驗收是「用固定亂數種子跑,結果可重現」。

```
type Rand interface { Roll(faces int) int }   // 回 1..faces
```

- 引擎用固定種子的 PCG/LCG,**不是 `math/rand` 的全域來源**
- 命中與傷害的每一次擲骰都經過這個介面
- 測試用**腳本化的假亂數**(給定序列),讓公式本身可以逐項驗

⚠ **不要試圖重現原版的亂數序列。** 亂數是 `INT 3D:34`(`RND`),
它的線性同餘產生器沒有被解出來,而「同一顆種子產生同一場戰鬥」與
「產生和 1986 年一樣的戰鬥」是兩回事。規格要的是前者。

⚠ `INT 3D:03` 是 **`INT()`(向下取整)**,不是亂數([`re/152`](../re/152-experience-settlement-formula.md) §3)。
把它讀成亂數是這個專案踩過兩次的坑 —— 每個 `INT()` 都會被誤算成一次擲骰。

## 3. 三個係數,現在都有出處

[`01`](01-combat.md) §5 的 `k₁` / `k₂`(`ds:9460h` / `ds:9464h`),
以及擲骰的面數(`ds:977Eh`)。

| 常數 | 狀態 | 引擎 |
|---|---|---|
| `k₂` = `ds:9464h` | **擲骰的偏移**(`INT(RND×N)+1` 的那個 `+1`)| `DamageK2 = 0` —— **已被 `Roll()` 的 1…n 涵蓋**,不是佔位 |
| `k₁` = `ds:9460h` | **0.5** —— 它乘的是 `(力量 − 7)`,對上手冊 p.11 的 `INT((力量−7)/2)`([`re/153`](../re/153-damage-formula-closed.md) §6.1)| `DamageK1 = 0.5` |
| 面數 = `ds:977Eh` | **100** —— 手冊 p.13 把命中率印成百分比,而程式算 `擲骰 ≤ 命中值`([`re/154`](../re/154-die-is-d100.md))| `ToHitFaces = 100` —— **不是佔位** |

引擎的處理:

- 三個值都做成**具名常數**,不散在算式裡
- `combat.Unresolved` 現在是空的 —— **機制保留**,下一個未解的規則常數放進來
- 測試鎖的是**規則**不是數字:`TestToHitIsAPercentage` 逐列比對手冊 p.13 的
  三個百分比,面數一改就爆
- `ToHitFaces > BerserkThreshold` 另有一條 —— 面數若被改到 76 以下,
  狂暴會靜默地變成死碼,而畫面上只會看到「怎麼從來沒劈中過」

⚠ **不要挑一組「打起來手感不錯」的數字。** 三個常數現在都有出處,
但**出處都是「觀測後果」不是「檔案裡的位元組」** ——
模組的變數大半不在檔案映像裡([`re/42`](../re/42-module-ds-and-the-66dc-boundary.md) §3)。

⚠ `k₁` 的 0.5 是**靠手冊定的**,不是從檔案的位元組讀出來的
—— 程式讀到的是 `−7` 這個偏移,而手冊的公式也是 `−7`。

## 4. 一回合的流程

```
1. 建單位陣列(隊伍 ← CHARS.DAT;怪物 ← MONSTERS.DAT 依**區域編號**,見 §4.1)
2. 依屬性 2(速度)排先攻表,速度高的先動      ← §5
3. 依先攻表逐一行動,每個單位有行動點數
4. 全部行動完 → 檢查結束條件
5. 未結束 → 回到 2 或 3(見 §5 的警告)
```

### 4.1 遭遇的怪物:由區域編號挑

[`re/169`](../re/169-encounter-zone-selects-the-monster.md)。
**區域不是戰鬥的參數,是「你人在哪裡」的後果** ——
原版由送出戰鬥的那一支模組先填好(`ds:3656`),`CMBT` 才讀。

```
隨機挑一隻怪物;|MONSTERS.DAT 欄9(難度階級) − 區域| > 1 → 重挑
```

| 位置 | 區域 |
|---|---|
| 世界地圖 `x > 70 且 y ≤ 60` | 3 |
| 世界地圖 `y > 60`(Islandia)| 6 |
| 世界地圖其餘(起始區)| 1 |
| 迷宮 1 / 2 | 1 |
| 迷宮 3 / 6 | 3 |
| 迷宮 4 | 5 |
| 迷宮 5 樓層 `x < 25 且 y < 25` | 2 |
| 迷宮 5 其餘 | 8 |
| 迷宮 12 | 9 |
| 其餘迷宮 | 6 |

⚠ 判定是**絕對值**(原版有 `neg`),不是單邊 ——
寫成單邊會讓低階怪出現在高階區,而那在畫面上看起來完全正常。

⚠ **原版的重擲沒有上限**,湊不到會當掉。引擎加了上限(`monsterPickTries`),
耗盡時在提示列明講;⛔ **不用「取最接近的一隻」代替** ——
那會讓一個原版不會出現的怪物出現。

一場遭遇有幾隻、是哪幾隻,由 `RNDMONST.BIN` 決定([`re/225`](../re/225-encounter-monster-count-anchor.md)、
[`formats/08`](../formats/08-rndmonst-bin.md))—— **挑的是那張表的一列**,
不是直接挑一隻怪。⚠ 上一段的「重擲」指的也是重挑**列**。

**最終首領永遠不會隨機出現** —— 現在有更直接的理由:她**根本不在遭遇表裡**。
`RNDMONST.BIN` 的四個候選欄只用到怪物編號 0–62(55 種),`Siriadne !` 是 71。
以下這一段是原本的理由,結論相同:

`Siriadne !` 的難度階級是 **13**,
而區域最大是 9(`|13 − 9| = 4 > 1`)—— 她由事件 533 的腳本放上場
([`re/161`](../re/161-maze-event-dispatch.md) §4)。
⚠ 階級 **10** 的十二隻(元素生物、Great Dragon、Titan…)**在區域 9 挑得到**。

[`01`](01-combat.md) §3:轉身 1 點、其他 3 點。

## 5. ⚠ 先攻是否每回合重排:未解

[`01`](01-combat.md) §2 明寫「排序每回合是否重跑**未確認**」。

引擎**每回合重排**,理由:速度屬性在戰鬥中可能被法術改動,
不重排會讓那些法術沒有效果。⚠ 這是**實作決定,不是 RE 結論** ——
在 `combat.ReorderEachRound` 這個具名常數上標明,解出來時改一個地方。

## 6. 結束條件

| 條件 | 判定 | 出處 |
|---|---|---|
| 怪物全滅 | 索引 0–8 的屬性 3(生命值)全部 ≤ 0 | `'MONSTERS ALL DEAD'`([`re/95`](../re/95-no-flee-command.md))|
| 隊伍全滅 | 索引 9–13 的屬性 3 全部 ≤ 0 | `'PARTY DIES!'` |
| 隊伍逃離 | 索引 9–13 的**朝向**全部 ≤ 0 | `'PARTY RAN!'`([`re/103`](../re/103-flee-is-leaving-the-field.md))|

⚠ 「全滅」與「逃離」是**兩個不同的欄位**(生命值 vs 朝向),
不要合併成一個「還活著的成員數」。

## 7. M4 的範圍

**做**:單位陣列、先攻、行動點數、命中、傷害、死亡、三個結束條件、
固定種子的可重現性。

**不做**:法術(M6)、`Dispell`(M6)、戰場移動(**M10**,見下)、
戰後結算(經驗值 / 金幣 —— 經驗在 M8 補上)、怪物 AI 的目標選擇策略。

⚠ **戰場座標(屬性 0/1)在 M4 只存不用。** 移動與距離判定要先解
「攻擊的射程條件」,而 [`01`](01-combat.md) 沒有那一條。

### ✅ 這個封鎖已經解除(M10)

手冊 p.34 直接寫了那一條:`A` 是「攻擊**面前**的敵人」——
近戰、範圍是朝向的那一格。戰場規格在
[`12-combat-board.md`](12-combat-board.md),M10 已實作。

> **判準**:被標成「缺某條規則所以不做」的功能,**每次有新來源進來
> (手冊、實跑)都要回頭問那一條補上了沒**。這一項擱了四個里程碑,
> 而補上它的那句話在手冊裡只有半行。

## 8. 驗收

| # | 條件 |
|---|---|
| 1 | 同一顆種子跑兩次,逐回合的傷害序列完全相同 |
| 2 | 命中公式:狀態 > 1 加 30、同朝向加 12,兩條各有一個測試 |
| 3 | 傷害三條分支的**擲骰面數**各不相同(武器傷害 / 力量 / 命中能力−5);力量加值 `floor((力量−7)×0.5)` 只在持武器時加 |
| 4 | 生命值 < 1 時設為 0,且該單位不再行動 |
| 5 | 三個結束條件各有一個測試,且**逃離用朝向、全滅用生命值** |
| 6 | 先攻:速度高的先動;速度相同時順序穩定(不可依賴 map 迭代)|
| 7 | 三個常數各有註解指到出處;`TestToHitIsAPercentage` 逐列對上手冊 p.13 |
| 8 | 狂暴:屬性 16 非 0 **且**第二次擲骰 > 75 才加倍,兩個條件各有一個測試 |
