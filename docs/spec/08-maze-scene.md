對應 [`03-engine-plan.md`](03-engine-plan.md) 的 **M5**。
格式來源:[`formats/06`](../formats/06-maze.md)(已 READY)。
本篇補執行期:座標怎麼算、視野怎麼決定、事件怎麼觸發、關卡怎麼切換。

## 1. ⚠ 迷宮的索引順序與世界地圖**相反**

```
世界地圖   index = y × 103 + x
迷宮       index = Major × 81 + Minor
```

[`formats/06`](../formats/06-maze.md) §1。**寫反了迷宮仍然畫得出來,只是轉了 90 度** ——
而轉了 90 度的迷宮看起來仍然像一座迷宮,沒有任何錯誤訊息。

同一個陷阱在 [`spec/05`](05-world-scene.md) §1 已經標過一次;
這裡是**另一個方向**,所以兩邊都要各自寫測試。

### 座標欄位對照

三個來源的順序**一致**,都是 (Major, Minor)([`re/137`](../re/137-maze-coordinate-order.md)):

| 來源 | Major(乘 81)| Minor | 備註 |
|---|---|---|---|
| `GROUPS.DAT` | 位移 79 | 位移 81 | **Minor 是 1-based**,索引時 −1([`re/114`](../re/114-maze-coordinates.md))|
| `MAZEDATA.BIN` | 欄 2 | 欄 3 | 起點可通行 12/12(反過來 10/12)|
| `DE*EFF.BIN` | 欄 0 | 欄 1 | 觸發格是圖塊 19 的 63/75(反過來 0/75)|

⚠ **不要用「欄」與「列」這兩個字。** [`re/56`](../re/56-maze-tile-classes-and-mazedata-columns.md)/[`59`](../re/59-de-eff-event-table.md) 把 Major 叫「列」、
[`re/114`](../re/114-maze-coordinates.md) 叫「欄」—— 同一個東西兩個名字,而算式才是真相。
本規格與程式碼一律用 **Major / Minor**([`re/137`](../re/137-maze-coordinate-order.md) §3)。

> 本節第一版照 [`re/56`](../re/56-maze-tile-classes-and-mazedata-columns.md) 的中文名寫成「欄 3 / 欄 2」,
> 起點可通行率掉到 10/12 —— **是測試抓到的**。

## 2. 格值的行為

[`formats/06`](../formats/06-maze.md) §2 + [`re/56`](../re/56-maze-tile-classes-and-mazedata-columns.md):

| 格值 | 移動 | 繪製 |
|---:|---|---|
| 0 / 18 / 19 | 可通行 | **不畫** |
| 1–4 | 可通行 | 畫 |
| **5–10** | **阻擋** | 畫(7 是牆,佔非零格的 88%)|
| 11–28 | 可通行 | 畫 |
| **負值** | 可通行 | 畫 `|值|`;**踩上去會跨關卡**(§5)|

⚠ **阻擋的區間是 `5 ≤ 值 ≤ 10`,不是「≥ 5」。** 11 以上可以走。
⚠ 「不畫」與「阻擋」是**兩組獨立的規則**,不要合併成一張表 ——
19 是不畫但可走的隱形觸發格,合併就沒了。

## 3. 視野

主視野 9×9([`04-display-layout.md`](04-display-layout.md) §2),隊伍固定在正中央。

`GROUPS.DAT` 位移 59 / 61 是「有光 / 無光時的能見度」,**每個動作二選一**
寫進生效值([`re/204`](../re/204-light-burns-per-turn-and-offset-83.md) §2)——
不是載入時算一次。出貨存檔的值是 **3 / 2**。

在地面則兩個都不用,生效值改由**時**決定的天色(同篇 §2.2)。
⚠ 引擎的世界地圖目前不限視野,天色只算出來沒有消費端。

**視野半徑就是能見度**([`re/213`](../re/213-visibility-is-the-draw-radius.md)):
`MAZEMOVE 0x1078C` 把邊界算成「中心 ± `ds:35B2`」,兩軸各一次。
與隊伍的切比雪夫距離 > 半徑的格子不繪製。

⚠ 世界地圖用同一條規則,只是半徑取**天色**(同篇 §2)——
所以入夜的時候地面的視野是真的會縮的:白天 9×9、深夜 3×3。

## 4. 事件

`DE*EFF.BIN` 是 **106 × 5** 的欄主序表([`formats/06`](../formats/06-maze.md) §4)。
每次**實際位移之後**掃全表:

```
若 觸發 Major/Minor == 隊伍 Major/Minor 且 (方向 == 0 或 方向 == 隊伍朝向):
    若 目標 ≥ 100 → 顯示 DT 文字第(目標)號
    否則          → 傳送到 (目標, 欄4) 這一格
```

⚠ **方向 0 的語意未解**([`re/60`](../re/60-event-lookup-and-tile-19.md) §5 明列)。
引擎把 0 當「任何朝向都觸發」,理由是那是唯一不會讓事件永遠觸發不了的讀法。
具名為 `maze.DirZeroMatchesAny`。

⚠ **全表掃描是刻意的。** 原版的查表迴圈就是 `FOR i = 0 TO 105`
([`re/60`](../re/60-event-lookup-and-tile-19.md) §1),沒有索引結構。106 筆掃起來不花時間,
而**照抄迴圈比自己建索引安全** —— 建索引要先假設「同一格只有一個事件」,
而那件事沒有被驗證過。

## 5. 跨關卡的樓梯

格值為負 → 那一格的事件目標是 `501` / `502` 這種「沒有文字」的編號
([`re/60`](../re/60-event-lookup-and-tile-19.md) §3)。

引擎的處理:目標 ≥ 100 且**在 `DT` 檔裡查不到**時,視為跨關卡轉移。

⚠ **這一條是引擎的解讀,不是原版的機制。** 原版沒有「查不到文字」這個分支 ——
目標 N 一律走「第 N 段程式」(§5.5)。查不到文字只表示那一段程式不印文字。

用正確的 `DE*EFF` ↔ `DT*TEXT` 對應重掃(⚠ `DE51EFF` 配的是
**`DT51TEXT.DAT`**,不是 `DT5TEXT.DAT`,見
[`re/161`](../re/161-maze-event-dispatch.md) §6),查不到文字的只剩六筆:

| 檔案 | 目標 |
|---|---|
| `DE5EFF.BIN` / `DE51EFF.BIN` | `501` / `502` —— 一對互指,形狀就是兩層之間的通道 |
| `DE4EFF.BIN` | `403`–`406` —— **未解**,不確定是不是樓梯 |

⚠ **目標編號 → 哪一個關卡的對應未解。** `501`/`502` 是 `DG5` ↔ `DG51`,
但那是從「這兩個檔是同一地城的兩半」推的,不是查表讀出來的。
M5 的做法:**用 `MAZEDATA` 找出檔號相同的另一筆**;找不到就顯示
「跨關卡目標未解(編號 N)」而不是靜默留在原地。

## 6. 進出迷宮

| 動作 | 判定 |
|---|---|
| 進入 | 世界地圖上踩到地城入口(值 24/25/27/28),查 `MAZEDATA` 欄 0/1 = 該座標 |
| 起始位置 | `MAZEDATA` 欄 2(Major)/ 欄 3(Minor)、欄 4(朝向)|
| 離開 | **走到格陣列的界外**([`re/147`](../re/147-leaving-the-maze.md))。原版印 `Leaving maze ..` 切回世界地圖 |

⚠ **界外的判斷要放在可通行性之前。** `Maze.At()` 對界外回 `0`,而 `0` 是**可通行** ——
先判可通行會把界外當成空地或擋成撞牆,兩種都是**把玩家關在迷宮裡**,
而畫面上只看得到「走不動」。

⚠ 欄 4 的值域只有 `{1, 3}`([`re/56`](../re/56-maze-tile-classes-and-mazedata-columns.md)),
而朝向是 1–4。**十三個關卡只朝北或朝南**,這件事本身沒有解釋,照抄即可。

## 5.5 機關:觸發點就是事件目標編號

原版沒有「機關」這個型別:**每個事件目標編號各有一段自己的程式**,
絕大多數只印文字,五個編號的那一段多做了事
([`re/161`](../re/161-maze-event-dispatch.md) §3)。所以觸發點不是座標、
不是格值,**就是目標編號**:

| 目標 | 位置 | 機關 | 引擎 |
|---|---|---|---|
| **518** | `DE5EFF` 格 54/42、朝向 4 | 治療池 | `maze.KindPool` |
| **532** | `DE51EFF` 格 30/42、朝向 3 | 寶石謎題 | `maze.KindGem` |
| **705** | `DE7EFF` 格 24/33、朝向 3 | Eldron 的氏族謎題 | `maze.KindRiddle` |
| **204** | `DE2EFF` 格 57/14、朝向 1 | 山丘巨人挾持祭司 | `maze.KindScript` |
| **533** | `DE51EFF` 格 36/38、朝向 3 | 最終首領 Siriadne | `maze.KindScript` |

⚠ 這五個編號**同時也有 DT 文字**,原版是先印文字再做事 —— 敘述照樣要顯示。

⚠ **204 / 533 的內容未解**([`re/161`](../re/161-maze-event-dispatch.md) §4):
讀到的只有「有一段專屬程式」與 DT 文字,**沒有讀到怪物組成**。
引擎顯示文字並在提示列標未解,**不自行安排一場戰鬥** ——
那會是編的,而畫面上分不出哪一場是原版的。

### 5.6 事件的一次性:只在打完仗之後

原版會把事件列**就地作廢**(座標三欄覆寫成 **99**,落在值域外),
而閘門是 **「剛從 `CMBT` 回來」**([`re/165`](../re/165-dgroup-string-map.md) §3):

```
打完一場由事件引發的戰鬥 → 回到迷宮 → 把所有目標相同的事件列作廢
其餘情況一律不作廢
```

所以**房間敘述可以重複看**(不引發戰鬥),而固定遭遇打完就不再觸發。
⚠ 迴圈不提早跳出:同一個目標記在四個入口方向上時,四列一起消失。

引擎:`maze.DisableTarget(evs, target)`,**由戰鬥結束那一刻呼叫**。
⚠ 作廢**是否跨存檔保留**未解([`re/161`](../re/161-maze-event-dispatch.md) §7),
本引擎只留在記憶體 —— 讀檔會讓事件復活。
⚠ 目前迷宮內還沒有戰鬥(§7),所以這個函式**還沒有呼叫端**;
規則有測試護著,接上去時是一行。

### 寶石謎題

```
答案 = 'BBRG'(藍藍紅綠),原版收滿四個字元才比一次
答對 → 傳送到迷宮座標(欄 46、列 37)、面向西,並顯示訊息 544
答錯 → 訊息 545,座標不動
```

⚠ **答對的效果是傳送**,不是拿道具也不是開門。
⚠ 前綴不算對也不算錯 —— 原版還在收字元。

### 治療池

```
可用條件   GROUPS.DAT 位移 63(已使用次數) < 11,否則 'This pool is empty!'
選人       輸入 1…隊伍人數,0 離開
資格       狀態 ≤ 2(正常 / 中毒 / 束縛);> 2 印 "That character can't be helped here !"
治療量     INT(RND × N) + 1,夾在「離滿血還差多少」
```

⚠ **它治的是生命值,不是狀態** —— 中毒的人治完仍然中毒。
⚠ 計數器**跨迷宮共用**:它在隊伍記錄裡,不在迷宮資料裡。
`N`(`ds:950A`)= **5**([`re/178`](../re/178-settings-from-three-sources.md) §2,
DGROUP 的編譯期常數),所以治療量是 **1…5**。
⚠ 先前 `maze.PoolRollFaces = 8` 是具名佔位。

### Eldron 的氏族謎題

```
進度旗標(原版 ds:91E4)  0 → 訊息 707「去搜墓」
                        1 → 訊息 706 + 出題
                        2 → 訊息 705「你不需要我的幫助了」
出題      印 'The brothers are:',依序問 #1…#4
答案      MURTHIN / CERCION / LOTHIAN / VANDIGUARD
判定      4×4 全對全,只數對得上幾組,湊滿 4 就算過
答對      訊息 708(給一枚會發動 Tempest 的戒指)
答錯      訊息 709
```

⚠ **順序不拘,而且同一個名字打四次也會過** —— 那是原版判定的漏洞
([`re/162`](../re/162-eldron-clan-riddle.md) §3),照抄,具名為
`maze.ClanCheckCountsDuplicates`。

⚠ **旗標 0 → 1 由誰設沒有讀到。** 引擎用「踩過四座墓(事件 701–704)」,
具名為 `maze.RiddleReadyOnAllTombs` —— 那是**實作決定**,依據是訊息 707 的文字。

⚠ **旗標存在哪也未解**,所以引擎只留在記憶體裡:存檔不會記得你解過了。
⛔ 不要為了「能存」隨便挑一個 `GROUPS.DAT` 位移塞進去。

⚠ 戒指怎麼發給隊伍、Tempest 是哪一個法術編號,**未讀** —— 引擎只顯示訊息。

## 7. M5 的範圍

**做**:`.SQZ` 解碼、9×9 視野與視野半徑、移動與阻擋、事件掃描、
文字事件(顯示 `DT` 敘述)、座標傳送、跨關卡、進出迷宮、
三個會問問題的機關(§5.5)。

**不做**:寶箱與鐵柵門的互動(格值 25/27 的語意未解)、法術(M6)、
劇情事件 204 / 533 的內容(未解,§5.5)。

⚠ **迷宮內的遭遇後來做了**(2026-08-18):`startCombat` 的區域挑怪本來就有
迷宮分支(`rules.MazeZone`),只差 `stepMaze` 沒有呼叫它。M5 當時把它列在
「不做」是**範圍宣告**,不是規則沒解 —— 原版實跑在拉利斯走第三步就撞上一群。
