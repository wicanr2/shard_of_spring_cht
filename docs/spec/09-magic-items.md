# 法術與道具(M6) — **READY**

對應 [`03-engine-plan.md`](03-engine-plan.md) 的 **M6**。
規則來源:[`02-magic.md`](02-magic.md)、[`formats/04`](../formats/04-spells-items-dat.md)(皆已 READY)。
本篇補執行期:施法怎麼算、效果怎麼套、道具怎麼發動。

## 1. 施法的三個閘門

```
1. 職業是 Wizard(CHARS.DAT 位移 15 = '2')
2. 技能旗標:MID$(記錄, 系別 + 41, 1) ≠ '0'     ← 系別 = SPELLS.DAT 欄2
3. 法力足夠:當前 SP ≥ 投入點數
```

⚠ **第 2 條的索引是「系別 + 41」,不是「法術編號 + 41」。**
系別只有 1–5,對應 `Wizard` 技能表的前五項(五種 runes,[`formats/01`](../formats/01-chars-dat.md))。
三十三個法術共用這五個旗標。

## 2. 等級與威力

[`formats/04`](../formats/04-spells-items-dat.md):欄 5 是**每一級的法力單價**,欄 4 是**每點威力**。

```
等級 = INT(投入點數 ÷ 欄5)        ⚠ 投不到一級 → 施法失敗
威力 = 欄4 × 投入點數
```

⚠ **威力乘的是「投入點數」不是「等級」。** 兩者只在欄5 = 1 時相同,
而 33 個法術裡欄5 有 1 以外的值 —— 寫錯不會報錯,只會讓高階法術變弱。

⚠ **那個 `INT` 沒有讀到過。** 這兩條式子引的是 [`formats/04`](../formats/04-spells-items-dat.md)
的欄位語意,不是某一段反組譯 —— 所以「向下取整」是**具名假設**。
依 [`re/185`](../re/185-int3f77-rounding-audit.md),原版要向下取整時會自己打 `INT()`,
沒打就是四捨五入,**取整方式在這裡是未決的**。

⛔ 不要拿 `CMBT 0x150AF`(`re/185` §2 表列 #3)去套 —— 那一處算的是
**`欄4 ÷ 欄5`**,不是 `投入 ÷ 欄5`,而且它的下游用途本來就標著未讀
([`re/173`](../re/173-spell-pipeline-and-the-13-way-dispatch.md) §1)。
**兩個商長得像,但不是同一個。**

## 3. 效果類別

[`formats/04`](../formats/04-spells-items-dat.md) 的 1–13。引擎的分派:

| 類別 | 行為 |
|---:|---|
| 1 | 群體傷害:對敵方全體套威力 |
| 2 | 單體重擊 |
| **3–6** | **屬性增減**,欄4 帶正負:4 = 力量、5 = 生命值、6 = 速度 |
| 7 | 防護:提高狀態強度 |
| 8 | 復活 |
| 9 | 解毒(清狀態)|
| 10 / 11 | 解除束縛 / 束縛 |
| 12 | **非戰鬥效用**:風行術(列 22)= 全隊傳送到世界 (8,8) 並離開地城([`re/193`](../re/193-wind-walk-teleports-to-8-8.md));魔法火炬 / 水晶燈術是照明,**未讀**。⚠ 派工靠**列號**不是類別 |
| 13 | `TRANSFERENCE` |

### 目標選擇:類別 1 不選

[`re/172`](../re/172-spells-column-arrays.md) §3(`CMBT 0x14F26`):

```
效果類別 == 1  → **跳過**選目標那一段
效果類別 ≥ 2   → 先掃單位的戰場座標選一個目標
兩者之後       → 共同段:擲 d100、算 欄4 ÷ 欄5 → 依效果類別 13 路分派
```

⚠ **「沒有目標迴圈」不等於「打全部敵人」** —— 那一段的完整公式沒有讀完
([`re/172`](../re/172-spells-column-arrays.md) §4)。引擎目前對類別 1
套用到呼叫端給的整份目標清單,那是**實作決定**。

⚠ 群體傷害那條路徑擲的是 **d100**(`ds:977E`,[`re/154`](../re/154-die-is-d100.md)),
並算 `欄4 ÷ 欄5`(像是等級)—— **兩者怎麼合成傷害未讀**。

**類別 3 = 命中能力(屬性 9)**([`re/171`](../re/171-spell-effect-class-table.md) §3)。

類別 → 屬性欄的對應是**在 `CMBT 0x160A2`–`0x16104` 讀到的**,
一串同形的比較,每一支只做一件事:

```
效果類別 3 → ds:9B32 = 9   命中能力
效果類別 4 → ds:9B32 = 6   力量
效果類別 5 → ds:9B32 = 3   生命值
效果類別 6 → ds:9B32 = 2   速度
```

**四個裡三個本來就確認過,所以第四個的讀法可信。**
⚠ 這不是從 `Becomes clumsy` 推的 —— 本節上一版明文禁止那樣做,
而禁令是對的:那時沒有讀到對應。**解法是去讀產生端,不是放寬標準。**

### 套用那一段:`CMBT 0x16142`

```
016140  mov ax, 0Fh
016142  imul word ptr ds:9B32h      ; 欄號 × 15
016148  add di, ds:93A4h            ; + 目標單位索引
016152  add [di+6822h], bx          ; ★ A(目標, 欄) += 量
016156  cmp word ptr ds:9B32h, 3
01615B  jnz → 夾在 [3, 255]
01615D  jz  → **跳過夾住**
```

**欄 3 不夾住,其他欄夾在 `[3, 255]`。** 欄 3 是生命值 ——
生命值當然不能有下限 3,這個特例反過來印證了「`ds:9B32` 是欄號」。

⚠ `ds:9B32` **另有一個寫入端**在 `0x15B80`(`INT(欄4 × ? ÷ ?) + 1`),
用途未確認([`re/171`](../re/171-spell-effect-class-table.md) §3.2)。
本節主張的是「**緊接使用端的那個寫入端**是欄號」,不是「它只有一種語意」。

⚠ 類別 8 / 9 / 13 各只有一個法術,**群內無對照,結構上無法再分**。
引擎照字面實作(復活 / 清狀態 / 未實作),並在 13 的訊息裡標「未解」。

## 4. 狀態類法術

[`02-magic.md`](02-magic.md) §3:命中時同時寫兩個欄位。

```
狀態[目標]     = 欄2(系別)
狀態強度[目標] = 欄5 ÷ 投入點數
```

⚠ **強度是「單價 ÷ 投入」,不是「投入 ÷ 單價」。** 投得越多、值越小 ——
而狀態強度在傷害公式裡是**減項**([`01-combat.md`](01-combat.md) §5),
所以「值越小 = 被打得越痛」。這個方向反直覺,是照抄的。

## 5. 魔法道具

[`02-magic.md`](02-magic.md) §4:只有物品編號 **> 26** 才走這條路。

```
若 物品編號 > 26:
    法術  = 欄4        ← **照樣發動**,沒有發動判定
    投入  = 欄5
    擲骰(100) ≤ 欄6  → **道具損壞**,從背包移除
```

**欄6 是「壞掉」的機率,不是「發動」的機率**
([`re/190`](../re/190-items-col6-is-break-chance.md))——
`CMBT 0x17C67` 的判定式讀對了,但那一支設的旗標(`ds:930C`)的**消費端**
印的是 `Item Breaks !` 並把背包那一格清掉。

面數是 100([`re/154`](../re/154-die-is-d100.md):`ds:977E = 100`),
所以欄6 直接就是百分比([`re/157`](../re/157-magic-item-rate-is-a-percentage.md))。

⚠ 資料面的印證:火把／油燈欄6 = **100**(一用就沒了),
鑰匙類 = **0**(永遠不壞)。讀成「發動率」的話鑰匙**永遠打不開門**。

⚠ 這裡曾經寫成 26,理由是「與傷害公式的骰面同一個數」——
而傷害公式根本沒有 26 面骰,那個 26 來自把 `mov bx, 1Ah` 讀成面數,
`0x1A` 其實是浮點累加器的**位址**([`re/153`](../re/153-damage-formula-closed.md) §9)。

⚠ **同一段程式裡有兩個 26,意思完全不同**:
`cmp dx, 1Ah` 是物品編號的門檻(真的),`mov bx, 1Ah` 是累加器位址(不是數值)。

> **判準**:兩個地方出現同一個數字,不代表它們是同一件事。

⚠ 欄 4/5/6 對**裝備**是另一組語意(傷害 / 命中加值 / 雙重身分)。
判別靠**物品編號**,不靠欄位內容([`re/74`](../re/74-spell-and-item-columns.md):
「這一欄是什麼」問錯了,要問「誰在讀它」)。

## 6. M6 的範圍

**做**:施法閘門、等級與威力、九種可實作的效果類別、狀態類法術、
魔法道具的發動判定、`Dispell`([`01-combat.md`](01-combat.md) §8)。

**不做**:法術動畫(`FIRESTRM`/`HAILSTRM`/`WINDSTRM` 三張圖**遊戲從不載入**,
[`re/61`](../re/61-i-closure-unused-tiles.md))、
商店買賣介面(卡在 [`04-display-layout.md`](04-display-layout.md) §5 的欄寬未決)。

## 7. 驗收

| # | 條件 |
|---|---|
| 1 | 三個閘門各有一個測試:非 Wizard、技能旗標關著、法力不足 |
| 2 | 技能索引是**系別**+41 不是法術編號 —— 有一個測試會在寫錯時失敗 |
| 3 | 等級 = `INT(投入 ÷ 欄5)`;投不到一級 → 失敗 |
| 4 | 威力 = 欄4 × **投入點數**(不是等級)|
| 5 | 狀態強度 = 欄5 ÷ 投入(**投得多、值小**)|
| 6 | **只剩類別 13** 不套用效果、訊息含「未解」;類別 3 改命中能力([`re/171`](../re/171-spell-effect-class-table.md))|
| 7 | 魔法道具:編號 ≤ 26 不走這條路;`擲骰(100) ≤ 欄6` → **道具損壞**(欄6 是損壞率,[`re/190`](../re/190-items-col6-is-break-chance.md))|
| 8 | 33 個法術全部有分派(沒有 default 吞掉的)|
