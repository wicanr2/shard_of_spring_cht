## 1. ⚠ 先解掉一個假的未決項:清單放在主視野

[`04-display-layout.md`](04-display-layout.md) §5 把「商店清單放不下中文(英文)」列為未決,
理由是側欄只有 30 欄而整列要 36 欄。**那個前提是錯的**,兩個地方錯:

| §5 的假設 | 實際 |
|---|---|
| 清單在**側欄**(30 欄)| 清單在**主視野**(612 px = 61 欄)—— 手冊 p.31 的截圖裡商品列在左側,右側是隊伍狀態 |
| 列裡放的是**地名**(最長 28 欄)| 列裡放的是**道具名**(最長 8 欄);地名是**標題**,單獨一行 |

實測(全部 57 個道具譯名 + 61 個商店譯名):

```
道具名最長          8 欄   速度藥水
整列最長           16 欄   A) 藍色權杖   250
地名最長           28 欄   法師圖書館(Wizard's Library)
主視野可用         61 欄
```

**三個候選一個都不需要。** [`04`](04-display-layout.md) §5 已改寫。

> **判準**:一個「未決項」擱著很久的時候,先回去問**它的前提還成立嗎**。
> 這一項擱了好幾輪,而拆解它只花了兩個量測 ——
> 而且第一版的診斷已經被修正過一次(算欄寬用了字數),
> **同一個未決項被錯誤診斷兩次,是「回去看前提」的訊號。**

## 2. 城鎮

進入條件:世界地圖踩到城鎮格(值 30/31/32,13 處)。**踩上去就進去**,不必按鍵
([`re/141`](../re/141-world-map-axes-were-transposed.md) §3)。

座標 → 是哪一個城鎮:查 **`TOWNDATA.BIN` 的座標表**
([`formats/05`](../formats/05-world-map.md) §4、[`re/145`](../re/145-town-coordinates-were-already-solved.md)),
第 n 列對上 `TOWNDATA.DAT` 第 n 個出現的城鎮。
⛔ **不要**用「按座標排序取第 n 個」—— 那個排序是錯的,實跑證明過。

`TOWNDATA.DAT` 每個城鎮有數間商店,每間一筆記錄
([`re/126`](../re/126-shop-price-multiplier.md)):`town`(所屬城鎮)、`name`、`price_mult`(位移 38 的 MBF 倍率)。

畫面(對照 `TOWN.EXE` 的
`'Choose building to enter,  # to inspect character, (ESC exits)'`):

```
主視野          城鎮名(標題)+ 建築清單,一列一間
指令提示列      選建築 / 看角色 / 離開
```

⚠ **`price_mult` 是 MBF 單精度,`1.1` 存進去是 `1.100000023841858`**
([`re/126`](../re/126-shop-price-multiplier.md) §3:那個截斷誤差正是當初裁決這個欄位的證據)。
售價 = `INT(基準價 × 倍率)` —— **先乘再取整**,不要先取整再乘。

### 建築類別

[`re/138`](../re/138-towndata-building-types.md):位移 34 的**負值**標出四種特殊建築,
**正值**是販售的物品編號範圍(位移 34–36,含)。

| 位移 34 | 建築 | 位移 36 |
|---:|---|---|
| ≥ 0 | 商店 | 販售範圍的終點 |
| −1 | 治療所 | 0 |
| −2 | 酒館 | 傳聞編號 1–11 |
| −3 | 旅店 | 0 |
| −4 | 訓練所 | 0 = 武術、1 = 魔法 |

⚠ **每間店只賣自己範圍內的道具。** 先前的實作把 57 件全列進每一間 ——
而那看起來完全正常,玩家不會知道劍舖不該賣板甲。
**「多顯示一些」的錯誤沒有症狀。**

## 3. 商店:買與賣

```
售價 = INT(ITEMS.DAT 欄3 × 該店的 price_mult)
```

⚠ **欄 3 是基準價不是售價**([`formats/04`](../formats/04-spells-items-dat.md))。

買:選字母 → 扣金幣 → 進背包第一個空格(`CHARS.DAT` 位移 54–72,**十格**)。

⚠ **背包空格的哨兵是 `99`,不是 0**([`re/144`](../re/144-created-record-exposes-layout.md) §3)。
用 0 當空格會讓「找第一個空位」永遠找不到 → **買東西一律回「背包已滿」**,
而那句話在畫面上完全合理。
金幣不足時顯示 `'enough gold!'` 的中文對應。

⚠ **原版沒有賣出功能** —— 商店的指令列只有 `Item to buy, ESC to leave.`,
手冊 p.36 也只寫買([`re/142`](../re/142-town-service-prices.md) §4)。
所以 M8 不做賣出,**理由是原版沒有這件事**,不是公式解不出來。

### 旅店與食糧

`TOWN.EXE` 的字串給了流程,手冊 p.37([`re/140`](../re/140-manual-stat-tables.md) §6)給了效果:

| 字串 | 行為 | 效果 |
|---|---|---|
| `'Your rooms will cost … gold each night. How many nights (1-9, 0 exits)?'` | 住宿:每晚固定價 × 晚數 | **回 2 HP、10 SP**,並供餐(不耗食糧)|
| `"One day's food for the party costs … gold. How many rations (1-9, 0 exits)?"` | 買食糧:每份固定價 × 份數 → `GROUPS.DAT` 位移 23 | — |

⚠ **食糧買在酒館,不是旅店。** 手冊 p.37 明寫 `TAVERNS` 賣 `PROVISIONS`;
`TOWN.EXE` 那句字串沒指明建築,兩件事拼起來才對得上。

**基準價已解**([`re/142`](../re/142-town-service-prices.md)):住宿 **25**/晚、食糧 **2**/份。
在價格倍率恰好 `1.0` 的 Green Hamlet 讀到,所以畫面上的數字就是基準價。

> **判準**:量一個被係數乘過的量,先找**係數為 1 的樣本** ——
> 比量 1.1 倍再除回去省事,也少一個誤差來源(MBF 的 `1.1` 是 `1.100000023841858`)。

## 4. 營地

**原版的營地選單有 11 個指令**,畫面上一次全部列出來
([`re/150`](../re/150-experience-is-offset-90.md) §5.2):

```
Camp:
P)rint char(s)      R)eorder        I)dentify
S)leep              T)rade          U)se an item
#)inspect char      D)rop           ESC to leave
C)ast spell         E)quip
                    H)unt
```

### `R)eorder` 與 `T)rade`:效果由已解的資料結構決定

兩者的**操作介面**沒有讀到(只讀到選單上有這兩個字母),
但**效果**是既有結構的直接後果,所以做得出來:

| 指令 | 效果 | 依據 |
|---|---|---|
| `R)eorder` | 交換 `GROUPS.DAT` 的兩個成員槽 | 槽序**直接決定戰場站位**(`欄 = (i−1) mod 3 − 1`,[`re/160`](../re/160-party-deploys-three-per-row.md))—— 所以它不只是顯示順序 |
| `T)rade` | 把一格背包搬給另一個人 | 背包 10 格、哨兵 99([`re/144`](../re/144-created-record-exposes-layout.md) §3)|

⚠ `R)eorder` 要**同時動存檔的成員槽與引擎的成員切片** ——
只動一邊會讓存檔與畫面對不上,而畫面看起來完全正常。

⚠ `T)rade` 傳出去的那一格若正裝備著,要**先卸下** ——
與 `D)rop` 同一條(裝備欄存的是背包格號,指向空格不會報錯)。

### `H)unt` 與 `I)dentify`:閘門讀出來了,結果沒有

兩者共用 `CHARS.DAT` **位移 86 的「今天用過技能」旗標**
([`re/166`](../re/166-camp-hunt-identify-print.md) §1)。手冊 p.39 兩條都寫
「每天一次」,與旗標互相印證。

| | `H)unt` | `I)dentify` |
|---|---|---|
| 職業 | **戰士** | **法師** |
| 技能 | 第 9 格 `Hunting`(位移 50)| 依道具編號選 `Weapon`/`Potion`/`Item lore`(位移 47/48/49)|
| 地點 | **只能在野外**(`You're inside!`)| 不限 |
| 狀態 | 狀態 **> 1** → `That character is incapacitated.` | 同左 |
| 成功時 | 補給品(`GROUPS.DAT` 位移 23)+= N,**夾在上限** | 該道具變成已辨識 |

⚠ **閘門的順序不同**:打獵是「室內 → 技能 → 用過了 → 狀態」,
鑑定是「職業 → 用過了 → 狀態 → lore」。順序決定玩家看到哪一句話,照抄。

⚠ **兩者的結果都沒讀完**([`re/166`](../re/166-camp-hunt-identify-print.md) §6):
打獵的擲骰與鑑定的 `Failed` 分支都未解。引擎只做閘門並在訊息裡標未解,
⛔ 不自己編一個成功率。

lore 的分界已定案([`re/167`](../re/167-record-field-accessor-and-identified-flags.md) §4):
背包存的是 **0-based** 編號(商店的販售範圍最小值是 0,藥水舖賣 21–26)。

| 編號 | `ITEMS.DAT` 的列 | 技能 |
|---|---|---|
| 0–20 | 1–21 = **全部 21 件武器與護甲** | `Weapon lore` |
| 21–56 | 22–57 = 藥水 + 任務道具 | `Potion lore` |
| > 56 | **沒有真實道具** | `Item lore` |

⚠ 第一段與手冊完全吻合,但 **`Item lore` 對玩家而言是一個永遠用不到的技能** ——
手冊說它辨別「各項特殊物品」,而程式把那些丟進 `Potion lore` 那一段。
**照程式走**(反組譯是第 2 級證據、手冊是第 3 級),但值得實測一次。

辨識過的道具記在 `CHARS.DAT` **位移 74–83**(背包十格各一格,`'1'` = 已辨識)。
四個寫入端([`re/168`](../re/168-loot-pickup-and-an-off-by-one.md) §2):

| 來源 | 旗標 |
|---|---|
| 商店買的 | `'1'`(不必鑑定)|
| `I)dentify` 成功 | `'1'` |
| **地上撿的** | **`'0'`** —— 所以要花 `I)dentify` 才知道是什麼 |
| `T)rade` 傳過去 | 沿用來源那一格 |

⚠ **撿道具是由隊尾往隊首找空格**(原版外層迴圈遞減),與 `T)rade`/`E)quip` 相反。

⚠ **原版的撿道具寫的是 `75 + 格號`,差一格** —— 撿進第 10 格會把 `'0'`
寫進位移 84(狀態效果強度)。本引擎**刻意不照抄**:那會讓我們產出的存檔
把破壞帶回原版([`re/168`](../re/168-loot-pickup-and-an-off-by-one.md) §5)。
⚠ 這個差異**沒有實測過**,持有原版的人跑一次就能裁決。

### 仍未實作的三個

`P)rint char(s)`、`C)ast spell`、`U)se an item` —— 選單上列出來並標「未實作」,
不要假裝它們不存在。少一個指令的選單看起來很正常,**沒有人會發現漏了什麼**。

⚠ `P)rint` 是驅動 1986 年的並列埠印表機。依 [`CLAUDE.md`](../../CLAUDE.md) §1.2
的邊界(答案不會改變 remake 的行為就不必解),**不解也不做** ——
它的版面字串已經盤出來了([`re/166`](../re/166-camp-hunt-identify-print.md) §4),
要做就是把同一份內容顯示在畫面上,不是驅動印表機。

| 動作 | 寫回 |
|---|---|
| 裝備武器 / 防具 | `CHARS.DAT` 位移 34 / 36 = **背包格號**,`99` = 卸下 |
| 施法 | 走 [`09-magic-items.md`](09-magic-items.md) 的同一套規則 |
| **睡覺** | 手冊 p.38:**每人耗 1 份食糧,回 1 HP、5 SP**;沒得吃的人**扣 1 HP**;睡八小時 |
| ~~休息~~ | **已移除**。原版沒有這個動作,而它綁的 `R` 是原版的 `R)eorder` —— 自己加的東西佔著原版按鍵,會讓那個鍵的真實行為永遠測不出來 |
| **檢視背包 / 丟棄** | 手冊 p.39 的 `I)NSPECT` / `D)ROP`;丟掉的東西**拿不回來** |

⚠ **裝備時要由呼叫端指定「這一格當武器還是當防具」**,不是選了格子再判斷 ——
`ITEMS.DAT` **沒有**「這是武器還是防具」的欄位
([`formats/04`](../formats/04-spells-items-dat.md):「分類不在資料裡,在呼叫端」)。
用編號範圍去猜會在資料外的編號上默默猜錯。

⚠ 丟棄時要**同時卸下**指向那一格的裝備欄,否則裝備欄會指向一個空格 ——
那個錯誤不會報錯,只會讓角色空手打人而狀態欄看起來正常。

⚠ 睡覺缺糧時**扣的是吃不到的那個人**,不是全隊一起扣。

⚠ **中毒的人睡覺是淨損失**(手冊 p.38:中毒每小時扣 1 HP,睡八小時)。
介面上不要把睡覺說成一律有益。

⚠ 裝備欄存的是**背包格號不是物品編號**([`formats/01`](../formats/01-chars-dat.md) 位移 34/36)。
換裝備時要改的是格號,**不要把物品編號寫進去** —— 兩者都是小整數,寫錯不會報錯。

## 5. 角色管理

`CHARUTIL.EXE`:建立、刪除、改名、組隊。

| 動作 | 資料 |
|---|---|
| 建立 | 寫一筆 `CHARS.DAT`;名稱最長 **10 字**([`re/143`](../re/143-character-creation.md) §4:創造的提示是 10、改名才是 9)|
| 刪除 | 位移 1 寫 `'*'`(`'Is deleted !'`)|
| 改名 | 位移 2–11 |
| 組隊 | 位移 1 寫隊號 `'1'`–`'5'`,同時寫 `GROUPS.DAT` 的成員槽([`re/135`](../re/135-groups-record-5-is-a-real-save.md))|

⚠ **組隊要同時寫兩個地方**([`06-party-and-save.md`](06-party-and-save.md) §1):
角色的位移 1 與隊伍的成員槽。只寫一邊會讓載入時的一致性檢查噴警告 ——
那個檢查已經在 M3 做好了,M8 只要不弄壞它。

### 種族與職業(手冊 p.49,[`re/140`](../re/140-manual-stat-tables.md) §5)

| 種族 | 可選職業 | 附贈技能 | 屬性修正 |
|---|---|---|---|
| 人類 | 兩種都可 | 無 | +2 速、+2 智、+2 技 |
| 矮人 | 只能戰士 | Berserking / Axe | +1 力、−3 智、+3 體 |
| 巨魔 | 只能戰士 | Armored Skin | −3 速、+5 力、−5 智、+5 體 |
| 精靈 | 只能法師 | Item Lore / Weapon Lore | +5 速、−3 力、+3 智、−3 體、−2 技 |
| 地精 | 只能法師 | Spirit Runes | +2 速、−2 力、+5 智、−2 技 |

⚠ **職業限制是硬的**:五個種族裡只有人類能選。

### 創造流程(實跑,[`re/143`](../re/143-character-creation.md))

```
選種族 → 擲五項屬性(種族修正另一欄顯示)→ 重擲回合(按編號切換、ESC 執行)
       → 選職業(只有人類會問)→ 技能點數分配 → 輸入名稱
```

- **最終屬性 = 擲出的值 + 種族修正**(5/5 逐項算得出來)
- **初始生命 = 加完修正的體能**
- **技能點數 = 智能**,每項技能各有成本(劍 2 / 斧 2 / 釘錘 1 / 空手 2 / 夜視 2)

**算式的形狀已讀出**([`re/156`](../re/156-attribute-roll-shape.md)):

```
屬性 = INT(RND × A + RND × A + B)
```

兩次亂數用**同一個範圍**,而 `INT()` **只在總和之後做一次** ——
所以它是對稱三角分佈,不是均勻、也不是四顆骰。

⚠ `A`(`ds:6C2A`)與 `B`(`ds:6C2E`)**仍未解**(執行期變數)。
15 個實測樣本(4…12、平均 8.4)把它們約束到 `B = 4`、`A ≈ 4.9`;
引擎取 `A = 5`,是具名假設。

⚠ 先前用 `4d3` 的支撐集也吻合,但那是四顆骰的和,**峰度明顯更高** ——
支撐集相同而分佈不同,玩起來只覺得「極端值比較少」,沒有人會發現。

⚠ 技能成本只觀察到戰士表前五項;其餘與法師的十項未解,畫面上標出來。

## 6. 中文化:這一批畫面的字串

M8 讓 [`10-localization.md`](10-localization.md) §1 那 1,012 段裡的一部分**變得有落點**:
`TOWN` / `CAMP` / `CHARUTIL` 的選單與提示。

做法:**引擎自己的中文字串**,不從 EXE 抽。理由:
remake 的畫面與原版不是一對一(例如原版把提示放側欄、本專案放底部整條),
逐字搬會搬出對不上的東西。

⚠ 但**譯名仍以 [`glossary.md`](../../translations/glossary.md) 為準** ——
道具、法術、地名、狀態全部用既有譯名,不另造。

## 7. 訓練所:升級規則(已解)

手冊 p.37 + p.47–49([`re/140`](../re/140-manual-stat-tables.md)):

```
可以升級  ⟺  經驗 ≥ 該等級的累計門檻(手冊 p.47 的 ABSOLUTE 欄)
費用      = 0 —— 訓練「完全免費」
收誰      由 TOWNDATA.DAT 位移 36 決定:0 = 只收戰士、1 = 只收法師
升級加值  生命:手冊 p.49(戰士/法師兩欄不同);法力:p.48,只有法師有
```

⚠ 手冊 p.47 那張表的 `INCREASE FROM LAST LEVEL` 欄**第 1 列不自洽**
(寫 200,而累計欄是 300)。第 2 列起 18 列全部自洽 → **只用累計欄**。

⚠ 兩張成長表的欄名是「**最多**增加多少」,所以原版很可能是 1…上限之間現骰。
沒有讀到那段程式碼 —— M8 取上限,並在畫面上標成具名假設(`GrowthAssumption`)。

### 經驗值存在 `CHARS.DAT` 位移 90–93

4 bytes、MBF 單精度([`formats/01`](../formats/01-chars-dat.md)、
[`re/150`](../re/150-experience-is-offset-90.md))。訓練所讀的就是這一格:
`MID$(rec,90,4)` + `CVS` → 再讀位移 40 的等級 → 以等級索引門檻表 → 相減 →
印 ` experience before gaining a level.`。

經驗值的來源是 `MONSTERS.DAT` 欄 8(位移 31,[`formats/03`](../formats/03-monsters-dat.md)),
整段算式已讀出([`re/152`](../re/152-experience-settlement-formula.md)):

```
每人所得 = INT( 九個怪物槽的屬性 19 總和 ÷ 有資格人數 )
有資格   = 朝向 > 0(還在場上) 且 狀態 < 5(未陣亡)
```

⚠ 總和**不篩死活** —— 逃走的怪物照樣給經驗。

⚠ 原版的「零經驗」寫成 `00 00 00 40`(MBF 解出來是 2.7×10⁻²⁰,畫面印 0)。
存回時**只在值真的變了才覆寫那四個 byte**,否則沒打過仗的存檔會逐位元組改變。
