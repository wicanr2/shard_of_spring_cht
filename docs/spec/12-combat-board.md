# 戰場:格陣列 31 寬、行動點數與離場(M10) — **READY**

對應 [`03-engine-plan.md`](03-engine-plan.md) 的 **M10**。
RE 來源:[`re/140`](../re/140-manual-stat-tables.md) §1/§7(手冊 p.33–35、p.50)、
[`re/103`](../re/103-flee-is-leaving-the-field.md)(逃跑 = 全隊離場)、

## 0. 這一份解掉了 M4 明講的封鎖

[`07`](07-combat-scene.md) §7 把戰場移動列為不做,理由是
「移動與距離判定要先解**攻擊的射程條件**,而 [`01`](01-combat.md) 沒有那一條」。

**手冊 p.34 直接寫著那一條**:`A` 是「攻擊**面前**的敵人」——
近戰、範圍是**朝向的那一格**。封鎖解除。

> **判準**:一個被標成「缺某條規則所以不做」的功能,
> 每次有新來源進來(手冊、實跑)時要回頭問**那一條補上了沒**。
> 這一項擱了四個里程碑,而補上它的那句話在手冊裡只有半行。

## 1. 戰場

```
格陣列寬 31(索引 = 列 × 31 + 欄),畫面顯示其中 **9 × 9 圖塊**的視窗
四周一圈是「圓點」
```

**寬度 31 是讀出來的**([`re/164`](../re/164-board-stride-31-and-base-13.md) §1):
`mov dx, 1Fh` 在 `CMBT` 只有三處,三處都緊接 `imul`,而算出來的索引直接查格陣列 `ds:6AD4`。

✅ **高度 = 31,已量到**([`re/218`](../re/218-four-named-assumptions-audited.md) §2)。
先前寫「沒有任何座標界限的字面值可以量」是對的 —— **界限不在程式碼裡,在佈局裡**:
格陣列基底 `ds:6AD4` 到下一個陣列基底 `ds:7256` 相差 **961 words = 31 × 31**,
而 31 這個數字來自完全不同的地方(索引算式的立即數),兩者吻合到沒有餘數。

⚠ 通行判定仍然讀**格值**(`< 33` 走不過去),沒有座標比較 ——
**31×31 是陣列的容量,不是遊戲畫出來的框**,邊界是用地形圍出來的。

**視野 9×9 是量到的**([`re/175`](../re/175-battle-view-is-nine-tiles.md)):
實跑一場戰鬥,遊戲視窗內寬 153 px = 9 × 17、地形色塊 119 px = 7 × 17。

⚠ 手冊 p.33 的「15×15」**對不上視野(9)也對不上列距(31)**,仍未解。
⛔ 在量到之前不要再改這一句 —— 先前有一版把視野寫成 15,
那是**用新推論換掉舊推論**,而舊的才是對的。

⚠ 視窗跟著誰捲動**沒有讀到**,引擎跟著目前行動的單位。

⚠ **戰場上有地形**(實跑那一場的下半是一整塊水域,寬 7 圖塊),
不是空白的點陣 —— 所以「通行判定讀格值」(§1 的 `ds:6AD4`)存的
**就是地形值**,邊界是用地形圍出來的,而不是座標界限。

⚠ 圓點**不是裝飾**:隊員走上圓點,那一格變成四向箭頭的**出口**,
其他隊員只能從這個出口離場(手冊 p.33)。
⚠ 引擎用**座標**判最外圈,原版判的是**格值** —— 那份內容執行期才建,靜態讀不到。

### 1.1 初始佈陣:每列三個,基準 (13, 13)

**隊伍那一半是讀出來的**([`re/160`](../re/160-party-deploys-three-per-row.md)
的陣型 + [`re/164`](../re/164-board-stride-31-and-base-13.md) §2 的基準):

```
欄 = (i−1) mod 3 − 1 + 13     → 12 / 13 / 14
列 = (i−1) ÷ 3       + 13     → 13 / 14
```

五個人因此排成**上排三個、下排靠左兩個**,與原版截圖逐格吻合。
`mov cx, 3` + `idiv` 那個 3 是直接讀到的,兩軸的 `add bx, 0Dh` 也是。

### 1.2 怪物:擲座標找空格

原版**沒有怪物陣型**([`re/164`](../re/164-board-stride-31-and-base-13.md) §3):
擲一組隨機座標 → 查那一格是不是空的 → 不合就重擲,一隻一隻丟進去。

⚠ **兩個擲骰範圍是執行期變數,未解**,所以引擎用可預測的排列填 ——
不假裝那是原版的分佈。

⚠ 陣型的**基準列**(原版 `ds:94C2`)未解 —— 它只把整塊陣型上下平移。
⚠ **怪物那一半仍是佔位**,原版怪物的佈陣沒有讀到。

本引擎的座標:`(0,0)` 在左上,`x` 往東、`y` 往南 ——
與世界地圖的 `x*103+y` 是**不同的兩件事**,戰場是自己的小格盤,
不索引任何原版檔案,所以怎麼排都可以,取最不容易寫反的那一種。

## 2. 行動點數

```
每回合的點數 = 該單位的速度        (手冊 p.34)
前進 2   轉向 1   攻擊 3   施法/用物品/降魔 3
```

⚠ **施法、用物品、降魔做完直接結束該單位的回合**(手冊 p.35 三條都寫
「會取消行動能力」),**攻擊不會**。四者成本相同,
所以**不能用成本判斷要不要結束回合**([`rules.Action`](../../engine/internal/rules/rules.go))。

手冊 p.48 的「最多走幾格 / 最多攻擊幾次」是這條規則的後果,
18 列逐列吻合([`re/140`](../re/140-manual-stat-tables.md) §1)——
所以這裡實作的是**成因**,不是那張表。

### 2.1 實跑逐格量到的三件事([`re/150`](../re/150-experience-is-offset-90.md) §4)

原版把點數印在畫面上(`MP= 13`),所以每按一鍵就量得到:

| 行為 | 點數 |
|---|---|
| 轉身 | **−1** |
| 攻擊 | **−3** |
| 前方被友軍擋住 | **不扣**(不是「花了點數但沒動」)|
| 點數不足以做下一個動作 | **自動換人**,沒有「結束回合」鍵 |

開場的 `MP` 等於該角色的速度 —— `Richtatha` 速度 13、開場 `MP= 13`。
**「行動點 = 速度」因此不只是手冊寫的,是量到的。**

## 3. 攻擊

```
目標 = 朝向的相鄰那一格上的敵對單位
```

- 命中與傷害走 [`07`](07-combat-scene.md) §3 的公式,**不重複**
- **背後攻擊**:兩者朝向相同([`01`](01-combat.md) §4 的 `+12`)
- 那一格沒有單位、或是同陣營 → 這次攻擊不成立,**不扣點數**

⚠ 手冊 p.50 說背後攻擊是 `+3`,而手冊自己的表與反組譯都是 `+12`
([`re/140`](../re/140-manual-stat-tables.md) §3)。以 **+12** 為準。

## 4. 離場與逃跑

```
走上最外圈 → 該單位離場(朝向設 0)
全隊都離場 → 'PARTY RAN!'
```

這與 [`re/103`](../re/103-flee-is-leaving-the-field.md) 從反組譯讀到的
「逃跑不是指令,是狀態:沒有任何成員的朝向 > 0」**完全接得上** ——
反組譯給了判定,手冊給了怎麼觸發。

⚠ **離場 ≠ 死亡**。生命值與朝向是兩個欄位([`07`](07-combat-scene.md) §6),
合併會讓逃跑判定失效。

⚠ 原版的「出口」機制(第一個踩上圓點的人把該格變成出口、其他人只能從那裡走)
**本引擎簡化成任一外圈格都可離場**,並在畫面上標明 ——
出口的獨佔性沒有反組譯佐證,只有手冊一句話,而它影響的是難度不是規則正確性。

## 5. 怪物的行動

### 5.0 選招:已解([`re/170`](../re/170-monster-ai-casts-by-spell-family.md))

**戰鬥屬性 14 對怪物而言是「它會哪一系法術」**(1–5,對到 `SPELLS.DAT`
欄 2 的五個攻擊系別),而怪物出場時 `INT(亂數 × 5) + 1` 擲一次定終身。

```
第一回合    法術 = 系別基底(0 / 3 / 7 / 11 / 15)+ 擲骰(該系別的攻擊法術數)
            **挑到群體傷害(SPELLS.DAT 欄3 = 1)就重選**
第二回合起  系別 1 → 3 FIRE STORM
            系別 3 → 8 TEMPEST
            系別 4 → 12 HAIL STORM
            系別 2 / 5 **沒有分支**(它們沒有欄3 = 1 的法術)
```

⚠ **兩件事合起來才是完整規則**([`re/171`](../re/171-spell-effect-class-table.md) §2):
第一回合**不放**群體傷害,第二回合起**只放**它。
那三招被第一回合的過濾排除,所以才要另外寫死一條路徑 ——
不寫死就永遠放不出來。

⚠ 「重擲」與「沒東西可放」是**兩種不同的情況**,引擎用兩個回傳值分開
(`rules.MonsterSpell`)—— 用同一個 0 表示會讓系別 2 / 5 看起來像被過濾掉了。

⚠ **每個系別的張數只涵蓋攻擊法術**:系別 3 是讀到的常數 **2**
(`TEMPEST`/`STILL AIR`,跳過 `WINGS OF VICTORY`/`WINGS` 兩個增益)。
寫成整個系別會讓怪物放增益,而畫面上看起來像「怪物什麼都沒做」。

⚠ 系別 1 / 4 的張數**沒有讀到**(走未解的 `INT 3F:AD`),
填 3 與 4 是**由「只挑攻擊法術」推的**。

那三招正是 `FIRESTRM` / `WINDSTRM` / `HAILSTRM.BIN` 三張**從不載入**的圖
([`re/61`](../re/61-i-closure-unused-tiles.md))—— 圖是為這三招畫的,
DOS 版把呈現那一段拿掉了。

### 5.1 怪物 AI:出場、鎖定、施法

三條規則都由 [`re/186`](../re/186-monster-ai-target-placement-cast.md) 解出來,常數是讀的:

**出場位置**(D2)—— 八個錨點排成 3×3、中間留給隊伍,擲一個再抖動,不合就重擲:

```
repeat:
  i  = INT(RND × 7) + 1                  ; 錨點(ds:94B4 = 7.0)
  欄 = round( 錨欄[i] + INT(RND × 5) )    ; 抖動 0…4(ds:94B8 = 5.0)
  列 = round( 錨列[i] + INT(RND × 5) )
until 那一格是空的
```

⚠ 錨點表有 **8 列而擲骰只到 7** —— 第 8 列 (16,16) 永遠挑不到。照抄。
⚠ 錨點 6/11/16 加 0…4 接成 **6…20**,所以手冊 p.33 的「15×15」不只是畫面,
也是怪物實際會出現的範圍。
⚠ 原版的重擲**沒有上限**;引擎有(200 次後改線性掃描),那是實作決定。

**目標鎖定**(D1)—— 戰鬥屬性 15,**目標倒下或離場才重挑**,
重挑是 `INT(RND × 隊伍人數) + 9`(在隊員裡均勻隨機)。
手冊 p.35 的 `TACTICS`(精訊譯「策略」,戰士技能 6)看得到的就是這個欄位;
隊上有人會,怪物那一列就顯示「→ 誰」。

**施法時機**(D3)—— `法力 > 1` 且 `(回合 == 2 或 擲骰 ≤ 0.3)`。
法力是**硬門檻**,在 OR 外面;第二回合必定施法,第三回合又回到擲骰。
這與 [`re/170`](../re/170-monster-ai-casts-by-spell-family.md) 的「第二回合起固定放暴風系」接得上。

**逐步的選格**(D5)—— 屬性 18 是每個單位一份的**軸向偏好**
([`re/215`](../re/215-monster-step-axis-preference.md)):

```
+1 → 先試東西軸,不成再試南北;−1 → 反過來
該軸上比自己與目標的座標,決定往正向還是負向;相等就換另一軸
要走的那一格站不了 → 屬性 18 **取負**(下一步改先試另一軸)
```

⚠ 偏好開場擲一次 50% 硬幣,**整場不再重擲** —— 那是「這隻怪習慣先橫走
還是先直走」,不是每步的抖動。⛔ 改成每步重擲會讓牠在牆邊原地抖。

⚠ **差距大小不參與決定**。舊的佔位「往差距大的那一軸靠近」看起來更聰明,
而那正是它錯的地方。

## 5.2 施法(隊員)

`C` 開施法選單,施的是**目前輪到的那個人**,不是「全隊第一個會法術的」。
扣 3 點,而且**做完直接結束他的回合**。

⚠ 先前的實作掃全隊找第一個會法術的人 —— 在沒有戰場的 M4/M6 那樣可行,
到了 M10 就錯了:點數是**每個人各自的**,結束回合結束的也是**他的**。
**同一段程式在加進「輪到誰」這個概念之後語意會變**,不會編譯失敗。

⚠ 原版施法要用游標(`I`/`J`/`K`/`M` 移動 + `<SPACE>`)選格子(手冊 p.34)——
本引擎目前仍是「選法術 → 自動挑目標」,**目標選擇未做**。

## 5.3 原版的按鍵([`re/150`](../re/150-experience-is-offset-90.md) §4)

畫面右下角就印著模板:

```
        [ESC]
   [D][↑][ ?]        D)ispell   ?)說明
   [←][  ][→]
   [C][↓][ U]        C)ast      U)se an item
        [ATK]        A)ttack
```

| 鍵 | 動作 |
|---|---|
| 方向 | 面向不同 → 轉身;面向相同 → 前進(與世界地圖同一條規則)|
| `A` | 攻擊面前那一格 |
| `C` / `U` / `D` | 施法 / 用物品 / 降魔 |
| `S` | **音效開關**(`Sound is now off.`)—— **不是存檔** |
| `Return` | 無作用 |

⚠ `S` 這一格差點寫成「戰鬥中不能存檔」。當時的證據是「按了 `S` 但存檔沒變」,
而那與「`S` 在這個畫面根本不是存檔」**長得一模一樣** ——
分開兩者的是訊息框上那一行字,不是檔案。

## 5.4 戰後結算:誰分得到經驗

`CMBT` 的結算迴圈逐一檢查隊伍成員,兩個條件 `and` 起來
(索引照 `A(列,欄)` 拆開,[`re/150`](../re/150-experience-is-offset-90.md) §2.1):

```
屬性 10(朝向)> 0     還在戰場上
屬性  8(狀態)< 5     未陣亡
```

→ **陣亡的人與逃走的人都不分,活著留在場上但中毒／束縛的人照分。**

⚠ **第一個條件不是生命值。** 逃跑在原版是把朝向清成 0([`re/103`](../re/103-flee-is-leaving-the-field.md)),
而逃走的人生命值仍然大於 0 —— 用生命值判斷會多發給他們,**而畫面上完全看不出來**。
經驗值加在 `CHARS.DAT` **位移 90–93**(MBF 單精度),
結算畫面印 `Experience:` 與 ` (per character)` —— **顯示的是每人所得**。

**每一場給多少也解出來了**([`re/152`](../re/152-experience-settlement-formula.md)):

```
每人所得 = INT( 九個怪物槽的屬性 19 總和 ÷ 有資格人數 )
```

⚠ 總和**不篩死活** —— 累加迴圈裡沒有任何「這隻死了沒」的判斷,
所以**逃走的怪物照樣給經驗**。多數戰鬥打到全滅才結束,兩種算法給一樣的數字;
**只有怪物逃走的那一場會分岔。**

### 5.5 戰後金幣

管線的形狀讀出來了([`re/152`](../re/152-experience-settlement-formula.md) §2.3):

```
每隻怪物   FAC ← 難度階級 ^ ds:96B8 … 再一次次方 … × RND … + 1
全部加完   總額 × ds:96E8,再走一次 × RND × 0.5
```

⚠ **四個係數未解**,而且它們是執行期變數(不在檔案映像裡),
手冊也沒有任何一頁講金幣 —— **只能靠 oracle 實測解**。

引擎的處理:**每隻怪物擲 `1…難度階級`**,是具名佔位(`GoldAssumption`),
列在 `combat.Unresolved` 裡、戰鬥訊息列會顯示。

⚠ **不發金幣也是一個選擇,而且確定是錯的** —— 玩家永遠買不起東西,
整個經濟停擺。**有標示的近似值比確定錯誤的零好。**
⛔ 但不要因為「玩起來手感不錯」就調那個數;要改就是去實測。

## 7. 驗收

| # | 條件 |
|---|---|
| 1 | 行動點數 = 速度;前進扣 2、轉向扣 1、攻擊扣 3 |
| 2 | 點數不足時該動作**做不出來**,而不是變成負數 |
| 3 | 攻擊只打**朝向的那一格**;空格或同陣營時不扣點數 |
| 4 | 施法後該單位的回合直接結束;**攻擊後不會** |
| 5 | 走上最外圈 → 朝向設 0;全隊離場 → `PARTY RAN!` |
| 6 | 兩個單位不能站同一格;佈陣不把人放到最外圈(站圓點上等於開場就能離場)|
| 9 | 佈陣每列三個,下排**靠左**不是置中 —— 置中在畫面上同樣合理,所以要逐格對 |
| 7 | 同一顆種子跑兩次,整場的位置序列完全相同 |
| 8 | 施法扣的是**目前輪到的人**的點數,做完換下一個;點數不足時施不出來 |
| 10 | 怪物選招落在**自己系別的攻擊法術**範圍內;系別 3 挑不到兩個增益法術 |
| 11 | 第二回合起系別 1 / 3 / 4 固定放 3 / 8 / 12;系別 2 / 5 回 0(**讀到的缺口**,不是預設值)|
