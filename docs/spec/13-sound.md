# 聲音:`PLAY` 巨集(M11) — **READY**

對應 [`03-engine-plan.md`](03-engine-plan.md) 的 **M11**。
RE 來源:[`re/148`](../re/148-the-game-has-music.md)。

## 0. 這一項是**新發現的子系統**

`CLAUDE.md` §2.2 的十二個子系統(A–L)沒有聲音,[`03`](03-engine-plan.md) 的
里程碑 M0–M10 也沒有。**不是決定不做,是沒有發現** ——
樂譜藏在兩支 EXE 的字串表裡,而當初列子系統是照**檔案清單**列的,
清單裡沒有 `.MID` 也沒有 `.VOC`。

> **判準**:一份「完整」的清單,只在它當初的**分類方式**之內完整。
> 問「有沒有 X」的時候要問「X 如果存在,會長成什麼樣子」——
> 樂譜長成字串,不長成副檔名。

## 1. 樂譜

15 段 BASIC `PLAY` 字串,照抄進 [`internal/music/score.go`](../../engine/internal/music/score.go):

| 來源 | 段數 | 速度 | 推測用途 |
|---|---:|---|---|
| `MAZEMOVE.EXE` | **18** | `T108` | **通關曲** —— ✅ 呼叫端已讀到:目標 533(最終戰)的處理常式在執行期把 18 段組進 `ds:92F2 + 4k`([`re/182`](../re/182-ending-music-is-assembled-at-runtime.md))。⚠ 先前記 10 段,是用位元組範圍讀的,少 8 段 |
| `USERLIB.EXE` | 5 | `T50` | 死亡音效(`USERLIB` 有死亡與結局兩個匯出槽)|

⚠ 兩個「用途」都是**位置上的推測**,沒有讀到呼叫端。畫面上不要寫死用途。

## 2. `PLAY` 的子集

```
T<n>  速度(每分鐘幾個四分音符)     O<n>  八度      L<n>  預設音長的分母
A–G   音符,可接 # + - 與長度數字     P<n>  休止
MB    背景播放      ML  圓滑奏      MS  斷奏     MN  一般
```

⚠ **`MB` / `ML` 是狀態不是音符。** 而且狀態**跨呼叫殘留** ——
原版最後兩段沒有 `T`/`O`,靠的就是前面留下的值。
每段重建狀態會讓它們用預設的 `T120` 播出來,而**那聽起來仍然像一首曲子,只是不對**。

## 3. 合成

PC 喇叭是**方波**,所以 `Render` 產生 8-bit 單聲道方波:

```
一般   發聲 7/8 個時值,其餘靜音
ML     發聲 1(圓滑奏)
MS     發聲 3/4
```

⚠ `Render` 回傳的是 **PCM 位元組,不碰任何音訊裝置** ——
這樣它在沒有音效卡、沒有 `DISPLAY` 的環境裡測得起來。
**播放**是另一層,失敗只記一行警告,不影響遊戲。

## 4. 驗收

| # | 條件 |
|---|---|
| 1 | `O4 A` = 440 Hz;升半音是 `×2^(1/12)`;八度是兩倍 |
| 2 | `T108` 的四分音符 = `60/108` 秒 |
| 3 | 十段用**同一份狀態**依序解;解完速度仍是 108 |
| 4 | `MB` / `ML` 不會被當成音符;`F#` 的 `#` 不會被當成下一個音 |
| 5 | 音符後的數字覆蓋預設長度 |
| 6 | `Render` 的取樣數對得上總時值 |
| 7 | 音訊裝置開不起來時**只記警告**,遊戲照常跑 |
| 8 | 16-bit 立體聲的長度是 8-bit 單聲道的四倍;休止對應到 0 |

## 5. 接到哪裡

| 樂譜 | 觸發 |
|---|---|
| `Userlib`(五段,`T50`)| **全隊陣亡**。⚠ 用途是推測 —— 它慢一半,而 `USERLIB` 有死亡與結局兩個匯出槽 |
| `Ending`(18 段,`T108`)| **結局畫面**(`scene.go` 的 `bossFight` 分支)|

**全遊戲只有這兩首**([`re/216`](../re/216-the-game-has-two-tunes.md)):
十一支 BASIC 模組裡只有 `MAZEMOVE` 有樂譜,`USERLIB` 有另一組五段。
世界地圖、地城、城鎮在原版**沒有背景音樂** —— 沒有場景 BGM 可以接。

⚠ **「沒有背景音樂」不等於「沒有聲音」。** 戰鬥有一整套音效,
走的是 `SOUND` 不是 `PLAY`,所以掃樂譜掃不到它們 —— 見 §8。

⛔ **不要為了「有背景音樂比較完整」而循環播放通關曲。**

⚠ **寧可不接,也不要接到一個看起來合理的錯位置** ——
接錯了玩家聽到的是「這裡本來就有音樂」,不會知道它放錯了。

## 6. 建置環境

`ebiten/v2/audio` 底下的 `oto/v3` 走 cgo 連 **ALSA**,
所以 `tools/Dockerfile.go-build` 要有 `libasound2-dev`(image 已升到 `:5` —— 另含 `vorbis-tools` 與 AppImage 工具,見 §7.4 與 `tools/release.sh`)。

⚠ 少了它 `go vet` 會停在
`Package 'alsa', required by 'virtual:world', not found` ——
那個訊息**看起來像 pkg-config 壞了**,不像少一個 dev 套件。

## 7. 場景配樂(**非原版**,可切換)

原版沒有場景 BGM([`re/216`](../re/216-the-game-has-two-tunes.md))。
這一層是 remake 的增補,程式碼在
[`internal/music/cue.go`](../../engine/internal/music/cue.go) 與
[`engine/bgm.go`](../../engine/bgm.go)。

### 7.1 三條約束

| # | 約束 | 為什麼 |
|---|---|---|
| 1 | **預設不開** | 玩家第一次聽到的要是原版的樣子。`Mode` 的零值就是 `ModeOriginal` |
| 2 | **切得掉,而且切換時講清楚它是後加的** | 訊息寫「配樂:重製(場景配樂是後加的,原版沒有)」。⛔ §5 的理由在這裡同樣成立:玩家聽到音樂只會以為「這裡本來就有」 |
| 3 | **自己寫譜,用同一套 `PLAY` 語法與同一個方波合成器** | 不引進取樣音檔:聽起來與原版那兩首同源,而且不必處理任何第三方音樂的授權 |

⛔ **不拿通關曲來循環當 BGM** —— 那正是 §5 擋掉的做法。
重製模式放的是新寫的譜,原版那兩首在兩種模式下都只在原本的觸發點響。

### 7.2 三個模式

| 模式 | 內容 |
|---|---|
| **原版**(預設)| 只有通關曲與死亡曲;場景安靜 |
| **重製** | 原版兩首 **+** 六首場景配樂 |
| **關閉** | 全部靜音 |

**F5** 循環切換。挑功能鍵是因為原版的指令鏈全是字母
([`re/71`](../re/71-k-closure.md)),功能鍵不會撞到任何畫面的按鍵語意,
也不會被自由輸入(存檔命名、Daza Reveli)當成文字吃掉。

模式存在 `saves/config.json`,**與存檔分開** ——
配樂偏好不該綁在某一份存檔上,而且存檔有版本檢查,
為了一個偏好去動它的 schema 不划算。⚠ 設定檔讀不到或壞掉就用預設值繼續。

### 7.3 場景 → 配樂點

| 場景 | Cue | 調性 |
|---|---|---|
| 標題 / 主選單 | `CueTitle` | D 小調,`T92` |
| 城鎮 | `CueTown` | F 大調,`T112` |
| 世界地圖 | `CueWorld` | D 多利安,`T104` |
| 地城 | `CueMaze` | D 小調,`T76`,用休止留白 |
| 戰鬥 | `CueCombat` | D 小調,`T144` 斷奏 |
| 最終戰 | `CueBoss` | D 小調 + 半音進行,`T160` |
| 結局 / 全滅 | `CueNone` | 讓給原版那兩首 |

⚠ **順序就是優先序**,與 [`scene.go`](../../engine/scene.go) 的 `inputChain` 同一個道理:
戰鬥蓋在城鎮與迷宮之上 —— 在城鎮裡被襲擊時要聽到戰鬥曲。

### 7.4 曲子是資產,譜是真相

八首(六首場景配樂 + 原版兩首)都以 **OGG** 收在
[`internal/music/assets/`](../../engine/internal/music/assets/),
由 `//go:embed` 編進執行檔 —— 玩家不必另外下載,發行包也不必多一個資料夾。

```
譜(cue.go / score.go) --tools/music.sh--> WAV --oggenc--> assets/*.ogg --go:embed--> 執行檔
```

| 決定 | 理由 |
|---|---|
| 定稿之後落成檔案,不每次開機現算 | 循環播放要把整首 PCM 攤在記憶體(20 秒 ≈ 1.8 MB);OGG 壓完是十分之一以下,而且解碼是串流的 |
| 用 `oggenc`(vorbis-tools,在 build image 裡) | Go 沒有成熟的純 Go Vorbis **編碼器**;`ebiten/audio/vorbis` 只解不編 |
| `-q3`(≈112 kbps) | 音源是方波,壓太狠會在音頭產生前迴響(pre-echo)。⚠ 那是壓縮的假影,不是譜寫壞了 |
| 解碼用 `DecodeWithSampleRate` 不是 `DecodeF32` | 前者輸出 16-bit LE 立體聲,與 `RenderPCM16` 和 `ctx.NewPlayer` 對得上。⚠ 混用 float32 與 16-bit **不會編譯失敗,會放出噪音** |
| OGG 讀不到就退回現算 | 退路不是「以防萬一」,是**故障時的可觀察性**:安靜看起來跟「玩家把音樂關掉了」一模一樣 |

⚠ **改了譜要重跑 `tools/music.sh` 並把 `assets/*.ogg` 一起 commit。**
少了這一步的症狀是「改了譜但遊戲裡沒變」,而且**不會有任何錯誤訊息** ——
`TestEmbeddedOGGDecodes` 就是為了擋這個:它比對解碼長度與譜算出來的時值,
差超過 5% 就紅。

⚠ 原版那兩首的譜是**原版檔案裡的字串**([`148`](../re/148-the-game-has-music.md))。
轉成 OGG 只是換容器,**它仍然是原版內容** —— 與 `score.go` 同一個地位。

### 7.5 播放層

- 循環交給 `audio.NewInfiniteLoop`。⛔ 不要自己在 `Update` 裡看播完沒有 ——
  那會在每一圈之間留下一格的靜音,而那個縫在慢的曲子上聽得出來
- **一次性的曲子壓過循環曲**:`play()` 進來先 `stopBGM()`。
  兩者疊起來仍然聽得出旋律,所以不會有人當成壞掉,只會覺得音樂很奇怪
- 音效總開關(`S`)關掉時場景配樂也要**真的停** —— 循環曲不會自己結束

### 7.6 怎麼試聽

譜好不好聽沒有測試驗得出來,只能聽:

```
tools/music.sh --wav-only          # 只倒 WAV 到 workplace/music/
tools/music.sh                     # 順便重新產生 assets/*.ogg
```

倒出八個 WAV(六首場景配樂 + 原版那兩首)。**`cmd/musicdump` 不進發行包**
(`tools/release.sh` 只建引擎與轉換器)。

單元測試驗的是**結構**不是聽感:每一首都解得出音、有發聲的音、
全長落在 5–60 秒(太短的循環讓人抓狂,太長的就不是循環而是一首曲子)。
上下界是設計決定,不是量出來的。

## 8. 音效(原版有,走 `SOUND` 不走 `PLAY`)

RE 來源:[`re/228`](../re/228-combat-sound-effects.md)。
原版 `CMBT` 有一支「兩個字母的代碼 → 一串 `SOUND`」的常式,20 個呼叫端。
**`S` 鍵切的就是它** —— 原版那個開關管的是音效,不是音樂。

### 8.1 七個代碼(照抄,不改)

| 代碼 | 序列 | 接不接 |
|---|---|---|
| `HT` | `SOUND 120, 8` | ✅ 一般命中 |
| `HK` | `SOUND 90, 6` | ✅ 狂暴劈砍 |
| `DD` | `SOUND 45, 12` | ✅ 單位死亡(**一次死一個響一次**)|
| `PS` | 7 × (`1200` / `1175` / `1150`,各 `.25` 拍)| ✅ 施法 |
| `BP` | BASIC 的 `BEEP` | ⛔ 不接 —— 九個呼叫端沒有逐條讀 |
| `FL` | 3 × 同上三音 ＋ `1100`→`400` 每次 −25、每音 `.1` 拍 | ⛔ 不接 —— 只有一個呼叫端,語意沒讀 |
| `BR` | `SOUND 80, 10` | ⛔ 不接 —— `CMBT` 裡沒有呼叫端 |

**資料七個全部進程式碼**(它們是讀出來的事實),**觸發點只接四個**。
⛔ 不要為了「音效比較豐富」把 `BP`／`FL` 接到猜出來的位置 ——
與 §5 同一條:接錯了玩家不會知道。

時值的單位是 BASIC 的時鐘節拍,**18.2 Hz**;`8` 拍 ≈ 0.44 秒。

### 8.2 實作分界

- `internal/music` 出 **`Effect(code)` → `[]Note`**,再走既有的 `Render`／
  `RenderPCM16` —— 音效與樂曲用**同一個方波合成器**,
  因為原版也是同一個 PC 喇叭
- `internal/combat` 是純規則,**不碰音訊**:它把該響的代碼附進
  `Field.Sounds`(與 `Log` 平行),由引擎層取走再播
- 音效**不進 OGG**:單一首 0.2–0.7 秒,現算比解碼還便宜,
  而且沒有循環播放的記憶體問題(`internal/music/ogg.go` 的理由對它不成立)

### 8.3 驗收

| # | 條件 |
|---|---|
| 1 | 七個代碼的頻率與拍數與 [`re/228`](../re/228-combat-sound-effects.md) §3 逐項相符 |
| 2 | `PS` 是 21 個音(7×3)、`FL` 是 9 + 29 個音 —— **迴圈次數從 `cmp` 讀,不是數 `SOUND` 的個數** |
| 3 | 一般命中出 `HT`、狂暴出 `HK`,兩者不會同時出現 |
| 4 | 被打死的單位額外出一個 `DD`;一回合死兩個就有兩個 |
| 5 | 施法(玩家與怪物)出 `PS` |
| 6 | 玩家關掉聲音之後 `Sounds` 照樣填,但**播放層不播** —— 規則層不因音效開關而改變 |
| 7 | 沒有音訊裝置時照樣跑完整場戰鬥 |
