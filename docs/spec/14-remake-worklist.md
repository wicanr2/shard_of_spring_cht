## 0. 現在長什麼樣

```
go run . -slot 5      →  直接出現在世界地圖,隊伍是原版存檔的 PARTY #5
```

13,024 行 Go。所有**規則**都實作了:世界地圖、迷宮、戰鬥、戰場、法術、道具、
城鎮、商店、營地、名冊、創角、訓練、治療、經驗、音樂合成、439 段中文化。

缺的不是規則,是**把它們串成一款遊戲的那一層**:沒有開頭、沒有結尾、
沒有自己的存檔、九個場景靠 `Game` 上的一組旗標互相切換。

## 1. 順序與理由

```
A 遊戲外殼   →  B 自己的存檔  →  C 場景架構  →  D 戰鬥 AI
                                       ↓
                              E 補完指令  →  F 中文化剩餘  →  G 打包
```

**A 先做**,因為在它做完之前「玩一輪」這件事不存在,而**沒有可玩的整輪就沒有回饋迴路**
（`rulebook/60`：先建可重跑的 pass/fail loop）。現在要驗一條規則得用旗標與參數硬跳進去。

**B 緊接著 A**,因為 A 的「讀取進度」需要一個格式;而且現在的存檔**寫回原版 `.DAT`**,
與 [`03`](03-engine-plan.md) §2「寫自己的格式」相矛盾 —— 這一條放越久,綁上去的東西越多。

**C 在 A/B 之後**才有意義:場景邊界要等「開頭 → 遊戲 → 結尾」的完整路徑存在了,
才知道該切在哪。⛔ 先重構再補流程會照著現在的形狀切,把旗標式的結構固化成介面。

**D 獨立**,可以與 E/F 並行 —— 它只動 `internal/combat`。

## 4. C. 場景架構

[`03`](03-engine-plan.md) §2 規劃的 `Scene` 介面**沒有實作**。現在是
`Game` 上的一組欄位(`field` / `town` / `roster` / `create` / `cursor` / `castList` / `overlay`),
`Update()` 用一串 early-return 決定誰吃這次按鍵。

| | 項目 | 說明 |
|---|---|---|
| [ ] | C1 抽出 `Scene` 介面 | `Update(*GameState) Transition` / `Draw`。⚠ 介面要**窄** —— 場景之間只透過 `GameState` 與 `Transition` 溝通,不互相拿對方的欄位 |
| [ ] | C2 切成 vertical slice | 一個場景一個套件,內部自己分層(`rulebook/70`)。現在 11 個檔全在 `package main` |
| [ ] | C3 覆蓋層與提示列收斂 | 覆蓋層、訊息列、指令提示列現在各場景自己畫 |

⚠ **C 是重構,不是新功能。** 判準:做完之後**行為要一模一樣**,
而現有測試多半測的是 `internal/` 的規則層,擋不住場景層的回歸 ——
所以 C1 之前要先有一組「走一輪」的整合測試(見 §8)。

⛔ **不要為了「未來可能要換 UI」而先加抽象層。** 只抽現在真的有九個實作的那一層。

## 8. 貫穿全程:整合測試

`package main` 現在有 **28 個測試**(外殼 15 + 營地 13),全部直接呼叫方法、不開視窗。

⚠ **在此之前 `package main` 的測試從來沒真的跑過。** 匯入 ebiten 會在
`internal/ui` 的 `init()` 呼叫 `glfw.Init()`,沒有 `DISPLAY` 就 panic ——
那發生在任何測試跑起來之前,連空測試都擋。`tools/Dockerfile.go-build` 已加
Xvfb(image `:4`),`tools/go.sh` 的 test 分支自己起 X server。

⚠ **這個坑會假裝自己不存在**:一旦有過一次成功結果進 build cache,
`go test` 就回 `ok (cached)`——**綠燈是快取在說話**。⛔ 驗收一律帶 `-count=1`。

⚠ 接線斷掉的代價實例:`H)unt` / `I)dentify` 的規則層早就完成且有測試,
但營地的按鍵 switch 把這兩個鍵送進「未實作」分支 —— **鍵盤上按不到**,
畫面還印一句假的「本引擎未實作」。**規則層測得再密,接線斷了一樣是零。**

| | 項目 |
|---|---|
| [ ] | T1 無頭跑一輪:讀檔 → 走幾步 → 觸發戰鬥 → 打完 → 進城 → 買東西 → 存檔 → 讀回 |
| [ ] | T2 固定種子的行為快照(同種子同輸入 → 同狀態) |
| [ ] | T3 每個場景的按鍵表至少各有一條「按下去有反應」 |

**T1 是 C(重構)的前置條件** —— 沒有它,場景重構的回歸只能靠人眼。
