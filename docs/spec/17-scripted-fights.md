## 1. 規則

原版有**兩種**戰鬥怎麼決定怪物:

```
腳本清單 ds:372C + 2i(i = 0…7),哨兵 99
    ├ ds:372C < 99  →  照清單擺,不隨機挑
    └ ds:372C ≥ 99  →  走 re/169 的隨機挑怪(區域 + |階級 − 區域| ≤ 1)
```

隻數 = **從第 0 槽往後數,遇到第一個 ≥ 99 就停**(不是掃完八格)。

| 常數 | 值 | 出處 |
|---|---:|---|
| 清單長度上限 | **8** | [`re/180`](../re/180-scripted-fight-monster-list.md) §1 |
| 哨兵 | **99** | 同上 |

⚠ **哨兵 99 與背包空格、`LightPick`「沒有光源」是同一個值** ——
這款遊戲到處用 99 當「沒有」。⛔ 任何一處都不要把它當成 0。

## 2. 已解出的兩個事件

| 事件目標 | 組成 | `MONSTERS.DAT`(**0-based**)|
|---|---|---|
| **204** 祭司的巨人 | 1 隻 | `10` = `Hill Giant` |
| **533** 最終戰 | 3 隻 | `53`、`53` = `Great Dragon` ×2;`71` = `Siriadne !` |

⚠ **編號是 0-based**,與背包道具編號同一個慣例([`re/167`](../re/167-record-field-accessor-and-identified-flags.md) §3)。
引擎的 `MonsterDef` 索引要對齊,⛔ 不要在這裡 ±1。

⚠ **其餘 13 處寫入點還沒盤**([`re/180`](../re/180-scripted-fight-monster-list.md) §6)——
所以引擎的清單要做成**資料驅動的表**,不要為這兩個事件寫死兩段 `if`。
之後解出第三個事件時,應該只需要在表裡加一列。

## 3. 引擎怎麼做

```go
// 事件目標 → 腳本怪物清單(0-based MONSTERS.DAT 索引)。
// docs/re/180 §3。空清單 = 這個目標不指定怪物,走隨機遭遇。
var ScriptedFight = map[int][]int{
    204: {10},
    533: {53, 53, 71},
}
```

- 迷宮事件觸發時查表:查得到 → 用這份清單開戰;查不到 → 現行的隨機遭遇路徑
- 打贏 **533** → 設 `bossFight`(外殼已經接好,[`15`](15-game-shell.md) §7)→ 結局畫面
- 打贏 **204** → 祭司的後續。⚠ **祝福的實際效果未解**([`re/161`](../re/161-maze-event-dispatch.md) §4
  只讀到那句話的字串)—— 顯示文字,⛔ 不要自己編一個加成

## 4. ⚠ 三件未解,不要順手補

| 項目 | 引擎怎麼處理 |
|---|---|
| 三隻的**站位** | 沿用現有的怪物擺位(`combat.Place`,已標明是近似)。原版是擲座標找空格,兩個範圍未解([`re/164`](../re/164-board-stride-31-and-base-13.md) §3)|
| `Siriadne !` 的屬性有沒有被腳本加成 | **照 `MONSTERS.DAT` 第 71 列的基準值**,不加成。⛔ 不要因為「最終首領應該更強」就調 |
| 打完之後誰把清單重置回 99 | 原版沒找到重置點([`re/180`](../re/180-scripted-fight-monster-list.md) §6)。**引擎每次開戰前自己清空** —— 這是**刻意的差異**:殘留值會讓下一場多出怪物,而那個 bug 在原版裡有沒有真的發生沒有驗過 |

⚠ 最後一項要在程式碼裡註明「這一條刻意不照抄原版」,理由是原版的行為**沒有被驗證過**
—— 照抄一個沒驗過的可能 bug,比明講差異更糟。

## 5. 驗收

| # | 條件 |
|---|---|
| 1 | 目標 533 觸發 → 開一場 3 隻的戰鬥,兩隻 `Great Dragon` 一隻 `Siriadne !`(**用名字比對,不是用索引**——索引寫錯 ±1 也會湊出三隻)|
| 2 | 目標 204 觸發 → 1 隻 `Hill Giant` |
| 3 | 沒有腳本清單的迷宮格 → 仍走隨機遭遇,且**遭遇到的怪物階級符合該區域**([`re/169`](../re/169-encounter-zone-selects-the-monster.md))|
| 4 | 打贏 533 → 結局畫面 → 回主選單(外殼那一條驗收現在**真的走得到**了)|
| 5 | 連續兩場戰鬥:第一場是腳本的,第二場是隨機的 → 第二場**沒有殘留**第一場的怪物 |
| 6 | 全部不開視窗 |

⚠ 第 5 條是針對 §4 那個刻意差異的 —— 沒有它,清空邏輯壞掉不會有症狀。
