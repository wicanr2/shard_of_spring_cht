# 自己的存檔格式 — **READY**

對應 [`14-remake-worklist.md`](14-remake-worklist.md) 的 **B**。
取代現行「寫回原版 `.DAT`」的做法([`03`](03-engine-plan.md) §2 早就這樣規劃)。

## 1. 為什麼現在非做不可

現行的 `save()` 把狀態寫回 `CHARS.DAT` + `GROUPS.DAT`。那有三個問題,
**第三個是新發現的**:

| # | 問題 |
|---|---|
| 1 | 存檔與遊戲資料是**同一份檔案** → 多個存檔不可能存在 |
| 2 | 原版的欄位裝不下 remake 的狀態(見 §3)—— 那些狀態現在**只活在記憶體裡**,關掉就沒了 |
| 3 | **一次性事件會復活**:`maze.DisableTarget` 只改記憶體裡的 `level.events`,而那份每次進迷宮都從檔案重讀 —— **走出去再走回來,寶箱可以再開一次** |

⚠ 第 3 項不是 remake 的疏忽,是**原版用了一個 remake 不能用的做法**:
原版把「事件已觸發」寫回 `DE*EFF.BIN`,主選單的 `R)estore Mazes` 就是
從 `.MST` 母片還原它([`re/181`](../re/181-deeff-mst-is-the-master.md))。
`CLAUDE.md` §8 規定 `game/` 唯讀,所以引擎**必須**改記在自己的存檔裡。

## 2. 格式:JSON,一個檔 = 一份完整的遊戲

```
saves/<名稱>.json
```

| 決定 | 理由 |
|---|---|
| **JSON** 不是 gob | 這是文化資產保存專案 —— 玩家看得懂、修得動、出問題查得出來。存檔很小(25 角色 + 5 隊伍),省不了多少 |
| **一個檔 = 25 個角色 + 5 支隊伍 + 進度** | 照抄原版的模型:名冊是**跨隊共用**的(`CHARS.DAT` 25 槽、`GROUPS.DAT` 5 槽)。拆成「一隊一檔」會把共用名冊拆散,那是原版沒有的語意 |
| **多存檔 = 多個檔** | 原版的「5 個隊伍槽」不是存檔槽,是**同一個世界裡的五支隊伍**。這一點 ⛔ 不要弄混 |
| **必須有 `version`** | 未知版本 → **拒絕載入並講清楚**,⛔ 不要盡力解析。半懂的存檔會安靜地弄壞進度 |

⚠ **`saves/` 的位置**:預設在資產目錄旁邊,`-save <dir>` 可覆寫。
⛔ 這一版**不要**去做 OS 各自的設定目錄(XDG / `%APPDATA%`)——
那是打包(worklist **G**)的事,現在做會把兩件事綁在一起。

## 3. 要存什麼

### 3.1 原版就有的(型別直接用 `internal/original`)

```
chars   [25]original.Character     CHARS.DAT 的全部欄位
groups  [5]original.Group          GROUPS.DAT 的全部欄位
active  int                        目前玩的是第幾隊(1–5;0 = 沒有)
```

⚠ **⛔ 不要動 `internal/original` 的欄位定義。** 那些是 RE 結論的載體,
`docs/formats/` 逐欄對應它們。新的東西放 §3.2 的另一個型別。

### 3.2 remake 專屬(原版存在哪未解,或原版根本沒存)

```go
// Progress 是原版沒有欄位可以裝、或存放位置未解的狀態。
// ⚠ 每一項都要註明「原版存在哪」——未解就寫未解,不要留白。
type Progress struct {
    // 已作廢的一次性事件:迷宮檔名 → 目標編號集合。
    // 原版寫回 DE*EFF.BIN 本身(docs/re/181),remake 不能那樣做。
    DisabledEvents map[string][]int

    // 踩過的墓(事件 701–704),餵 Eldron 氏族謎題的進度。
    // ⚠ 原版存在哪**未解**(docs/re/162 §5)。
    Tombs []int

    // 氏族謎題解過了。⚠ 原版存在哪**未解**(同上)。
    ClanRewarded bool

    // 目前在哪座迷宮(nil = 在世界地圖)。
    // ⚠ GROUPS.DAT 有迷宮座標(位移 79/81),但**沒有「哪一座」**——
    // 原版的 ds:3534 是執行期變數(docs/re/169 §4)。
    MazeFile string
}
```

⚠ **`MazeFile` 這一項會改變行為**:現在關掉遊戲再開,人會在世界地圖上;
存了之後會回到迷宮裡。**這是修好一個缺口,不是加一個功能** ——
原版在迷宮裡也存得了檔(`GROUPS.DAT` 位移 79/81 就是為此存在的)。

### 3.3 ⛔ 不要存的

| 項目 | 為什麼 |
|---|---|
| 亂數種子 / 序列 | 專案負責人裁定不重現原版亂數([`07`](07-combat-scene.md) §2)。存了會讓「重載存檔重打同一場」變成刷分 |
| 戰鬥中的場面(`field` / `points` / `actor`)| 原版**不能在戰鬥中存檔**。⛔ 不要加一個原版沒有的功能 |
| 畫面狀態(`overlay` / `prompt` / `town` / `roster`)| 那是 UI,不是遊戲狀態 |

## 4. 匯入原版存檔

保留成**一次性匯入**,不是執行期格式:

```
主選單 → L)oad a Party → 沒有任何 saves/*.json 時,提供「從原版磁片匯入」
```

讀 `<assets>/save/CHARS.DAT` + `GROUPS.DAT` → 產生一份 `saves/imported.json`。
`Progress` 全部取零值(⚠ **等於「一次性事件都還沒觸發」** ——
匯入原版存檔會讓已開過的寶箱復活,**這一點要在畫面上講明**,
因為那份資訊在原版裡存在 `DE*EFF.BIN`,而我們不讀那個)。

## 5. 停止寫回 `.DAT`

⚠ **`internal/original` 的讀寫程式碼與那組逐位元組往返測試要全部保留**
([`06`](06-party-and-save.md) 驗收 6)——它們是 RE 結論的可執行證據,
而且匯入功能還要用。**只是不再是主存檔路徑。**

⛔ **不要刪掉 `writeChars()` / `save()` 的往返測試。** 刪掉之後,
`docs/formats/01`/`02` 的每一個欄位就再也沒有東西在守。

## 6. 邊界

⛔ **不要動的東西**:

- `engine/internal/original/` 的**欄位定義與既有函式簽章**(新增可以)
- `engine/internal/combat/`、`magic/`、`rules/`、`town/`、`maze/` 的規則
- `docs/`、`tools/`、`translations/`、`game/`、`original/`、`workplace/`
- 戰鬥、迷宮、城鎮的**行為** —— 這一段只換存檔,⛔ 順手改行為會讓回歸查不出來

## 7. 驗收

| # | 條件 |
|---|---|
| 1 | 存檔往返:存 → 讀 → 全部欄位相同(**含 `Progress`**)|
| 2 | 未知 `version` → **拒絕載入且訊息講清楚**,不是盡力解析 |
| 3 | **一次性事件不再復活**:觸發 → 離開迷宮 → 走回來 → 那個事件不再觸發;存檔 → 讀回 → 仍然不觸發 |
| 4 | 在迷宮裡存檔 → 讀回 → **回到迷宮裡的同一格**,不是世界地圖 |
| 5 | 兩份存檔互不干擾:存 A、存 B、讀回 A → A 的狀態 |
| 6 | 匯入原版 `.DAT` → 角色/隊伍/座標/金幣與現行讀檔路徑**逐欄相同** |
| 7 | `internal/original` 的逐位元組往返測試**仍然全綠**(沒被順手刪掉)|
| 8 | ⛔ `game/sharspri/` 底下**一個 byte 都沒被改** —— 有一條測試守著 |
| 9 | 全部不開視窗 |

⚠ 第 3 條是這一份規格**唯一會改變玩法**的地方 —— 沒有它,寶箱可以無限開。
⚠ 第 8 條是硬要求(`CLAUDE.md` §8),⛔ 不要只靠「我沒寫那個路徑」當保證。
