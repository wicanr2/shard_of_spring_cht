| 東西 | 在哪 | 狀態 |

| 有幾點可以花 | `original.Character.SkillPts`(CHARS.DAT 位移 89)| 已解 |
| 創角時發多少 | `town.SkillPoints(智能)` = 智能 | 已解([`re/143`](../re/143-character-creation.md) §3)|
| 升級時發多少 | `Train()` 已經在發:`智能成長 + 1` | 已解([`re/183`](../re/183-levelup-attribute-growth.md) §6)|

| 技能名 | `town.SkillName(職業, 編號)` | 已解 |
| 學會的旗標 | `Character.Skills` 10 格 `'0'`/`'1'` | 已解 |

⛔ **缺的只有一件事:玩家沒有任何地方可以把點數花掉。**
創角流程四步(種族 → 調整 → 職業 → 姓名)走完就結束,升級只是把數字加上去。
也就是說目前**每個角色的技能全都是空的**,而打獵、鑑定、法術系別全靠技能旗標 ——
`CanHunt` / `CanIdentify` 現在對任何角色都回「你沒有那項技能」。

## 1. 規則層:新增 `town.LearnSkill`

```go
// LearnSkill 讓角色學一項技能(編號 1–10),扣掉點數。
func LearnSkill(c *original.Character, n int) LearnResult
```

| 情況 | 結果 | 原版訊息 |
|---|---|---|
| 編號不在 1–10 | `LearnBadNumber` | `Mumble, mumble…` 一類 |
| 已經學過 | `LearnAlready` | ⚠ **未解**,見 §4 |
| 點數不足 | `LearnNotEnough` | ⚠ **未解**,見 §4 |
| 成功 | `LearnOK` | —— |

成功時:`Skills[n-1] = '1'`、`SkillPts -= SkillCost(職業, n)`。

⚠ **職業要從 `c.Class` 取**,不要由呼叫端傳 —— 兩張表同一格是不同技能,
傳錯職業會學到另一項而且畫面上看起來完全正常。

## 2. 畫面:一個共用的子流程,兩個入口

原版的字串鏈([`19-coverage.md`](19-coverage.md) §2-3):

```
You have N points left.
Enter skill, (0 exits)
```

所以是**一個迴圈**:印剩餘點數 → 列技能表(名稱 + 成本 + 學過沒)→
輸入編號 → 扣點 → 回到迴圈;輸入 `0` 離開。

**兩個入口共用同一段程式碼**:

| 入口 | 接在哪 |
|---|---|
| 創角 | `finishCreate()` 之後 —— 角色已經寫進名冊,帶著 `SkillPts = 智能` |
| 升級 | `trainMember()` 判定 `TrainOK` 之後 |

⚠ **點數可以不花完**(位移 89 存的就是「剩餘」,而且升級會累積)——
所以 `0` 隨時能離開,不要強迫花光。

⚠ 離開之後**要把角色寫回名冊**(`g.chars[c.ID-1] = *c`)並存檔,
否則下次載入時點數與技能都回到舊值。`trainMember` 現在已經有這一段,
**新的子流程要在寫回之前跑完**,不要各寫各的。

## 3. 版面

沿用營地 `P)rint` / 施法選單的做法(蓋掉主視野,不另開視窗):

```
阿爾:技能點 5

  1) 劍         (2)  ✓已學
  2) 斧         (2)
  3) 釘頭鎚     (1)
  …
  0) 結束

輸入技能編號:
```

`✓已學` 那一欄要有 —— 沒有它玩家會重複買同一項。

## 4. ⚠ 兩個未解,實作時要標明

| 未解 | 引擎怎麼做 | 為什麼這樣選 |
|---|---|---|
| 已學過的再輸入一次會怎樣 | **擋下並提示**,不扣點 | 旗標是二值的,再學一次拿不到任何東西;扣點等於白扣。⛔ 這是**具名假設**,程式碼要標明 |
| 點數不足會怎樣 | **擋下並提示**,不扣點 | 同上,而且扣成負數會讓位移 89 寫壞 |

⛔ **兩處都要在程式碼註解寫「這是假設,不是讀到的判斷式」**,
照 `docs/spec/16` §2 的先例。要裁決就去讀 `TOWN.EXE sub_11D09`
(輸入迴圈,[`re/183`](../re/183-levelup-attribute-growth.md) §7 列為未讀)。
