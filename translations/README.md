單一真相來源是 [`glossary.md`](glossary.md) —— **所有譯文以那份為準**,
表上沒有的新詞先加進去再用。落點總表在

## 0. 兩種覆蓋率,不要混

| 量的是什麼 | 用途 | 現況 |
|---|---|---|
| **原版文本的盤點**(下表)| RE 的完整性 —— 原版總共有多少字 | 439 / 1,476 段 |
| **remake 的介面覆蓋率** | 玩家在畫面上還看得到英文嗎 | **0 條**(`tools/check_ui_language.py`)|

⚠ **模組內文本已經全部譯完**(worklist 的 F1;清冊 828 段裡 `ui` 的 381 段)。
剩下的是把那些措辭**接回引擎**(F3)—— remake 有自己的介面字串
(`docs/spec/11` §6:逐字搬原版字串會搬出對不上的東西 ——
原版把提示放側欄、本專案放底部整條)。
那批譯文的價值在**還原原版的措辭**,不在「讓畫面變中文」。

> ⚠ 上表「段/筆」與 TSV 的**列數不相等**。`ITEMS.DAT` / `SPELLS.DAT` 的一筆記錄

**那個限制對 patch 原版成立,對 remake 不成立**:remake 把字串抽成外部資源,
沒有長度限制。

- ✅ **822 段全部接上了程式碼引用點**(1,085 個點,100% 覆蓋,

- ⬜ 還缺**把那 1,085 個引用點歸戶到函式 / 畫面**。

## ⛔ 這批檔案綁定 repo 維持 private

本目錄底下**每一份 TSV 的 `original` 欄都是原版英文**,
`source/dungeon-text.tsv` 更是 9 個地城全部敘述文字的完整原文(11,044 bytes)。
雙語對照是翻譯工作的必要形式,**在 private repo 下沒有問題**(專案負責人裁定,2026-08-14)。

代價是 repo **不能轉 public** —— 原版劇情文本已經在 git 歷史裡,
公開會違反 `CLAUDE.md` §1「不散布原版資料檔」。細節見 `CLAUDE.md` §10。

## 2. 檔案配置

```
translations/
├── glossary.md              ← 唯一真相來源
├── source/                  ← 從原版抽出的原文(*.tsv);towndata.tsv 譯文也在這
├── names/                   ← ITEMS / SPELLS / MONSTERS / TITLES 的譯文
└── dungeon-text/            ← DT0–DT7TEXT.DAT 的譯文,一檔一個地城
```

## 2.1 標點:半形 `,!?` + 全形 `：。、`

全部譯文(`module-text/`、`dungeon-text/`、`names/`)用**同一套**:

| 用 | 不用 |
|---|---|
| `,` `!` `?` 半形 | `，` `！` `？` |
| `：` `。` `、` 全形 | `:` |

冒號用全形是 [`docs/spec/06`](../docs/spec/06-party-and-save.md) §7 驗收 7 訂的;
其餘跟著本專案文件一貫的寫法。

⚠ **這條的理由不是美觀,是可比對。** `module-text/` 的 `wired` 欄要拿譯文
**逐字**去比引擎原始碼([`docs/spec/19`](../docs/spec/19-module-text.md) §6.1),
兩邊各用一種標點時畫面看起來完全正常,只有接線檢查會說「沒找到」——
而那句話看起來像「這段還沒接」,不像「標點不一樣」。
`tools/check_module_text.py` 有一條 `punctuation()` 擋這件事。

⚠ 改了譯文的標點,**`assets/` 要跟著重跑 `cmd/convert`** ——
`dungeon-text/` 與 `names/` 進的是 JSON 資產,不是原始碼,
不重跑的話遊戲裡看到的還是舊的(§4 的同一個坑)。

## 3. `fits` 欄怎麼讀

`fits = N` **不代表壞掉**。這一欄量的是**顯示欄寬**(全形 2、半形 1),
拿原文的欄寬當參考值,不是硬上限。

真正的硬上限只有定長欄位(`glossary.md` 硬規則 2):
`MONSTERS.DAT` 與 `TOWNDATA.DAT` 的 16 bytes、`CHARS.DAT` 的 10 bytes。
**這幾個目前 0 筆超標。**

其餘檔案(`TITLES` / `SPELLS` / `ITEMS` / `DT*TEXT`)是變長文字檔,
而 remake 由外部資源載入字串 —— **檔內位元組長度不構成任何約束**。
顯示欄寬超出原文的先記錄不強行縮短。技術棧雖已定案(Go + Ebitengine),
但**畫布尺寸與字型仍未定**,沒有那兩項就沒有欄寬預算 ——
現在縮短等於拿一個沒有根據的數字去砍譯文。

### ⚠ 專有名詞改用「中文(英文)」後,名稱欄寬近乎翻倍

目前 **111 筆**超出原文欄寬,最多 **+14 欄**
(`范迪加德商行(Vandiguard's)`、`奧德修斯酒館(Odysseus Pub)`、
`巴利克鬥技場(Balik's Arena)`)。

| 類別 | 原文最寬 | 譯文最寬 |
|---|---:|---:|
| 城鎮 / 商店 | 16 欄 | **28 欄** |
| 怪物 | 16 欄 | **22 欄** |

**這需要一個版面決定,不是可以忽略的數字。** 手冊 p.31 的商店截圖顯示
原版的品項欄大約 16 字寬,`奧德修斯酒館(Odysseus Pub)` 放不進去。

**畫布已定案 1024×768**([`docs/spec/04`](../docs/spec/04-display-layout.md)),
欄寬預算因此有了基準:

| 區塊 | 容量 |
|---|---:|
| 敘述覆蓋層(24px 字)| **60 欄 × 5 行** |
| 側欄清單(20px 字)| **30 欄** |

- 地城敘述最長 207 欄 → 覆蓋層 300 欄的容量,**一頁放得下,不必分頁**
- 商店清單:名稱最長 27 欄放得下,但**加上編號與價格的整列要 36 欄,超出 30**
  → 顯示方式三個候選仍**未決**,見 [`spec/04`](../docs/spec/04-display-layout.md) §5

### 抓到的真缺陷:兩批譯文對專有名詞的處理分裂

怪物表把 `Siriadne` / `Devir` / `Murthin` 等音譯成中文,地城敘述卻保留英文 ——
同一個角色在戰鬥畫面與房間文字裡變成兩個人。**已統一。**

現行規則是**專有名詞:中文(英文)對照**(glossary 硬規則 4,專案負責人裁定 2026-08-14)——
人名、地名、城鎮名、商店名、地城名一律適用,同一段第一次出現才加註;
普通名詞(`Orc`、`Dagger`)不加註。

> **判準**:分頭翻譯的批次之間,**專有名詞是最容易分裂的一項**,
> 因為每一批單獨看都自洽。收件時要跨批次掃同一個詞,不能只驗每一批內部。
>
> **判準二**:改了 `translations/` 的 TSV **不等於畫面會變** ——
> `assets/` 是 `cmd/convert` 的產生物,不重跑就還是舊詞,而兩邊各自都自洽、
> 沒有任何測試會紅。改完譯名要重跑轉換,並比對 `assets/` 的 diff 只有預期的那幾行。
